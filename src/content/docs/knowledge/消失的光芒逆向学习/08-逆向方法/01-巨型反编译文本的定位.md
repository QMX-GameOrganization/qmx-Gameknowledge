> 适用版本：方法本身与游戏版本无关。依据 `DL1/Tools/LogicResearch/native_functions.py` 与各教材中的“证据”小节。

## 要点

- `gamedll_x64_rwdi.c` 约 72 MB、`engine_x64_rwdi.c` 约 40 MB，不能整文件读入编辑器或脚本。作者先为它们建一份**函数索引**，之后按名字或按模式取任意函数。
- 每条证据记录**文件、行号、字节边界、来源 SHA256**。文件变了，哈希就对不上，证据立刻失效。
- 公开反编译与当前安装版 DLL 不是同一版本，地址、偏移、枚举都不能互相搬运。

## 函数索引

`native_functions.py` 的核心很短，逐行读文件，用一条正则匹配 Ghidra 风格的函数声明行（`FUN_xxxxxxxx` 或 `thunk_FUN_…`）：

```python
DECLARATION = re.compile(rb'^[A-Za-z_][^\r\n]*?\b((?:FUN|thunk_FUN)_[0-9a-f]+)\s*\(')

def build_index(source, output):
    ...
    with source.open('rb') as stream:
        for line_number, line in enumerate(stream, 1):
            digest.update(line)                       # 边读边算整个文件的 SHA256
            match = DECLARATION.search(line)
            if match:
                if previous is not None:              # 上一个函数到此结束
                    previous['EndOffset'] = offset
                    previous['EndLine'] = line_number - 1
                previous = {'Name': match[1].decode('ascii'), 'Line': line_number, 'Offset': offset}
                function_list.append(previous)
            offset += len(line)
```

它输出的 JSON 含 `Source`、`Sha256`、每个函数的 `Name/Line/Offset/EndOffset/EndLine`，同时检查函数名是否重复。设计上的几点：

| 做法 | 理由 |
| --- | --- |
| 以**二进制**方式逐行读（`rb`） | 不做解码和换行转换，字节偏移才是可靠坐标 |
| 记录 `Offset` 与 `EndOffset` | 取函数正文时 `seek` 到偏移直接读，不扫全文 |
| 边读边算 SHA256 | 索引与源文件绑定，源文件变更能被发现 |
| 函数名重复就抛错 | 避免静默覆盖 |

三个命令：

- `index`：建索引；
- `extract`：按函数名取正文，输出每行带原行号的文本（`行号: 内容`）；
- `search`：对**每个函数正文**按多个正则搜索，按“命中模式数多优先、函数短优先”排序，给出候选。

最后一个很实用：想找“同时包含 `CLIMBING_LENGTH` 字符串和某个常量的函数”，用 `search` 加 `--minimum 2`，候选就收敛到几个。

## 换行陷阱

任务教材写过一句话：源行按 `LF` 计数，避免 `CRCRLF` 被 `splitlines` 重复拆行。这是个真实的坑：反编译文本里可能混有 `\r\r\n`，用 Python 的 `splitlines()` 会把一个 `\r` 当作额外换行，行号全部漂移。作者的 `extract` 也特意把行尾 `\r` 去掉再按 `\n` 分行。凡是行号要写进证据的，都要先确定“怎样数行”。

## 证据 JSON：不要在多个文档里复制结论

教材的做法：

- 详细机制写在教学正文；
- 来源、原文摘录、字节边界、哈希写在对应的 `*_evidence.json`；
- 结论带 ID（如 `LocalAxisAcceleration`），索引文件只放 ID 与状态；
- 进度台账放在索引页，不在多个交接文件里复制完整结论。

这样做的目标是：**换一个会话（或换一个人）只需读“当前状态 + 一个 ID”就能继续**，不需要重新加载几十兆的反编译。

## 版本漂移

教材多次强调，下面这些**不能互相套用**：

- 公开反编译 C 的地址 / 偏移 与 当前安装版 DLL 的 RVA / 偏移；
- 旧版本的属性枚举编号 与 当前版本的属性名表（`0x104` 在两个版本里名字不同）；
- `FUN_` 名字本身：它们是反编译器按地址生成的，换一个版本地址就变。

找当前 DLL 的对应函数，用的是**导出符号、MSVC RTTI、链式展开信息（PE CHAININFO）**，而不是按地址推算。要让多个分片合成一个完整函数，需要读展开信息，而不是只看首个 unwind 块（见 6.2）。

## 值得学的点

- **索引 + 按需读取** 比“打开大文件”好用得多，处理其它超大日志、导出文件同理。
- **把坐标系固定为字节偏移**，行号只是衍生展示。
- **证据包含哈希**，让“过期的结论”可被机器发现。
- **搜索结果按命中数排序**，用多模式交集收敛候选。

## 常见坑

- 用文本编辑器打开 72 MB 的文件并保存，改变了换行。
- 用 `splitlines()` 计数行号。
- 把不同版本的地址当成同一函数。
- 只记录结论不记录哈希，源文件更新后不知道结论是否仍然成立。
