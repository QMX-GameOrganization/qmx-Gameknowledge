> 适用版本：Dying Light 1.55.0.0。依据 `DL1/Teach/Logic/教学.md` 第 2 节。教材同时使用公开反编译 C 和当前 DLL 的静态证据，两者版本不同，地址互不通用。**原游戏与 Unity 均未运行物理行为验收。**

## 要点

- 玩家用的是 ODE 系的 Walk/Fly 物理体：脚本配置决定参数，游戏层再覆盖加减速、尺寸和模式。
- “是否在地面”不是一个布尔，而是接触法线、接触高度上下界、坡角阈值、脚底和高度窗共同更新的一个状态字，还有特殊表面附着分支。
- 攀爬时物理类型会切换，但“类型 0”不等于关闭所有碰撞。
- 这一章最大的价值是**清单化的“没有闭合”**：知道哪里没查清，比知道哪里查清更能指导实现取舍。

## 配置链路

| 已证实事项 | 来源 |
| --- | --- |
| 物理类型 3 选择玩家 Walk 脚本，另一分支选择 zombie player 脚本 | `FUN_180ac81d0`（`gamedll_x64_rwdi.c:1109352`） |
| Walk/Fly 脚本由 `CODEPhysicsWalkFly` 预加载 | `preloadedscripts.phx:14` |
| 玩家脚本继承通用配置，开启静态与动态连续碰撞及 `PreciseCC` | `walk_player.phx:5` |
| 继承的主形状声明为 `YEllipsoid`，运行代码另有 `Box` 分支 | 默认配置、`engine_x64_rwdi.c:593704` |
| 通用配置：质量 80、额外重力 (0, −7, 0)、质点模式 | `odephysicswalkfly.phx:8` |
| 世界脚本声明重力 (0, −9.80, 0)，原代码另有一个构造默认值 | 不能当作所有场景的固定最终值 |

形状的处理特别谨慎：`YEllipsoid` 分支把水平半径和竖向半径交给一个**专用碰撞回调**创建自定义 geom；`Box` 分支另行建体。教材明确说不能仅凭名字断言精确曲面算法，也不能把 `duck_capsule_*` 调试字符串当作主形状是胶囊的证明。相关函数是 `FUN_1803d6fb0`（`engine_x64_rwdi.c:594044`）、`FUN_180398520`（`561608`）和接触结果写入处（`519724`）。

## 接触、台阶与坡角

| 行为 | 当前证据与边界 |
| --- | --- |
| 常规速度反馈驱动力 | 读当前速度、累计力、质量；预测分支先扣除刚加入的附着力；调用目标与导出名 `AddForce@IPhBody` 相同。部分分支直接调用 `SetLinearVel` 的内部实现 |
| 接触决定地面相关状态 | 接收接触位置与法线，记录法线 Y 最大项和接触高度上下界，结合坡角、脚底和高度窗更新状态字；另有特殊表面附着分支。不能简化为一个 `isGrounded` |
| 台阶辅助 | `StairHeight` 经脚本回调、Walk 槽 `+0x320` 写入完整对象 `+0xac0`。核心根据接触高度和前进方向决定是否抬高向上速度，**不是**已证实的三段扫掠算法 |
| 坡角阈值 | `MaxGroundDEGToWalk/Jump` 经槽 `+0x368 / +0x378` 保存角度，转弧度调用 `cosf`，写入接触状态判断使用的阈值 |
| 额外重力 | `SetExtraGravity` 写完整对象 `+0x360..+0x368`，主虚表 `+0x70` 返回该向量；跳跃与台阶辅助都读取它 |

两个对实现者直接有用的结论：

- 坡角阈值存的是**余弦**，比较时不需要每次反三角函数。把度数在配置加载时转成 `cos(rad)` 缓存，是常规优化，这里原作就是这么做的。
- 台阶辅助是“**抬升速度**”，不是“传送到台阶上”，所以角色上台阶时仍遵守碰撞和重力。

## 高度转起跳速度

原 `FUN_1803de4e0`（`engine_x64_rwdi.c:596349`）与当前 RVA `0x3dc720` 有同型表达式：

```text
S = 2 × Height × (−WorldY − ExtraGravityY)
v = Sign(S) × Sqrt(Abs(S))        // 写 body 竖直速度
```

这是 `v² = 2·g·h` 的变形，其中有效重力是世界重力和额外重力叠加。如果取世界重力 −9.8、额外重力 −7、跳跃高度 1，则 S = 2 × 1 × (9.8 + 7) = 33.6，v ≈ 5.80 米每秒。**这只是算术示例**，教材说明世界重力还有另一个构造默认值，并且前置状态与冷却检查不能省略，完整起跳许可、落地和特殊模式都没有恢复。

前面 4.1 提到跳跃模块提交的是“高度量”，物理层才把高度换成初速度，这一步就在这里。

## 姿态与攀爬：物理体不是一成不变

- `FUN_180aaa230` 把姿态计算出的完整高度乘 0.5，交给真实 `SetRadiusY`。各特殊高度值对应什么状态名还需核对。
- `FUN_180c2adf0` 的部分攀爬状态请求物理类型 0；`FUN_180c2fc40` 恢复 Walk 类型 3、速度和碰撞配置。**不能把类型 0 直接解释为关闭所有碰撞**。
- Walk 的具名辅助几何，尺寸与偏移可分别调整；游戏层有成对修改和恢复的消费者。
- `FUN_180c2c080` 含按高度步进的短线段 Raytrace 和第二次偏置探测，但还不能当作完整的挂边入口算法。
- `FUN_180c2aaa0` 通过事件 ID `0x21b / 0x231` 查询 `CLIMBING_LENGTH` 和 `ENABLE_DUCK`（见 1.1），保存时序参数。原 `ushort` 时间字段与半帧编码仍未闭合。

## 仍然没有闭合

教材显式列出：自定义形状的完整碰撞数学、全局连续碰撞与约束求解顺序、动态平台的挂载与速度继承、全部攀爬状态、受击中断恢复。因此：

- 不能先锁定 `CharacterController`；
- 不能只加一个 Rigidbody 就宣称对应原实现；
- 需要的能力清单是：玩法运动来源选择、动画运动增量、速度反馈驱动力、直接改速度、动态尺寸、接触状态与台阶辅助、攀爬物理模式切换。

## 保留的早期练习

教材还保留了三份早期练习代码：`KinematicMotor`、`ParkourProbe`、`ActionSession`。其中射线布局、碰撞接口、加速度积分和状态字段都是**教学设计**。`FindLedge` 的思路是：水平射线找正对角色的墙，在墙内侧从最大高度向下找顶部，再检查站立胶囊空间。测试覆盖：18.49 帧不允许蹲伏、18.5 帧允许、19 帧触发攀爬长度；顶部空间阻塞、顶面法线不合格、表面禁止跑酷三类探测失败。

## 值得学的点

- **配置继承 + 游戏层覆盖**：脚本给默认，运行时按状态覆盖。你的角色控制器也可以这样分层。
- **接触状态是一组量，不是一个布尔**。设计自己的角色控制器时，先决定要存哪些接触量。
- **用余弦阈值做坡度判断**。
- **写“没闭合清单”**：每个机制旁边的“仍未知”列，是实现时的风险登记表。

## 常见坑

- 把声明的坡角 50 度当作“能走 50 度的坡”。接触状态还受高度窗、脚底等条件影响。
- 在角色攀爬时关闭全部碰撞。
- 把 `YEllipsoid` 当胶囊。
