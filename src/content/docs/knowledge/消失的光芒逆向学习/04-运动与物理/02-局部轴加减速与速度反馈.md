## 要点

- 加减速不是对速度向量的长度限速，而是**把速度转进 body 局部坐标，三个轴各自趋近目标**，再转回世界。
- 当任一加速或减速参数不大于零时，这一阶段被跳过，直接采用目标速度。玩家配置里的 `-1` 就是这个分支。
- 驱动力来自**速度反馈**：先预测已有力在本步造成的速度，再用目标速度的差额换算成力。这避免把同一份累计力算两次。

## 反编译里的样子

`FUN_1803dc6d0`（`engine_x64_rwdi.c:595460`）里与加减速相关的片段：

```c

    *param_5 = fVar21; param_5[1] = fVar14; param_5[2] = fVar19;   // 直接采用目标速度
    goto LAB_...;
}
```

随后每个轴重复同样的比较：当前速度绝对值不大于目标且同向时用加速步长，否则用减速步长。这与教材描述一致：`+0xa54` 是加速参数，`+0xa58` 是减速参数，任一不大于零就走“直接采用目标速度”的分支（本专栏已在反编译文本里核对了这个分支的开头，没有核对整个函数）。进入函数时，速度先经 `FUN_180372600` 逆旋转到局部坐标，输出再经 `FUN_180370c30` 正旋转回世界。

## 逐轴规则

```csharp
private static float SolveAxis(float Current, float Target, float AccelStep, float DecelStep)
{
    bool IsAccelerating = Mathf.Abs(Current) <= Mathf.Abs(Target) && Current * Target >= 0f;
    float MaxDelta = IsAccelerating ? AccelStep : DecelStep;
    return Mathf.MoveTowards(Current, Target, MaxDelta);   // 不越过目标，但允许单步跨零
}
```

教材特别强调两点：不能改成向量长度统一的 `MoveTowards`；单步可以跨零，不额外拆分过零时刻。

本专栏用 Python 复写了这条规则（含 `MoveTowards` 的等价实现），验证教材的自测描述：

| 场景 | 结果 |
| --- | --- |
| 目标 4，加速度 2，从 0 开始 | 2.0 秒达到 4 |
| 从 4 松开，减速度 4 | 1.0 秒降到 0 |
| 当前 4，目标 −4，步长 0.2 / 0.4 | 异号，用减速步长，一步到 3.6 |
| 当前 0.1，目标 −4，步长 0.2 / 0.4 | 一步跨零到 −0.3 |

## 驱动力公式

```text
V预测   = V当前 + (F累计 − F附着已加入) × dt / m
F驱动   = (V目标 − V预测) × m / dt
V下一步 = V当前 + (F累计 + F驱动) × dt / m
P下一步 = P当前 + V下一步 × dt
```

“F附着已加入”指已经加入累计力、且该预测分支需要扣除的附着力。教学预览没有接触附着，所以显式传零，不代表原作附着力始终为零。

用 Python 验证教材算例：质量 80，dt = 0.1，当前速度 0，目标 4，加速度 2。

- 限速后的本步目标 = 0.2；
- 驱动力 = (0.2 − 0) × 80 / 0.1 = 160；
- 推进后速度 = 0.2。

如果累计力里已有同向 40：预测速度 = 40 × 0.1 / 80 = 0.05，驱动力只补 (0.2 − 0.05) × 800 = 120，推进后速度仍是 0.2。质量改为 160，同样的速度曲线对应的驱动力加倍（320）。这些都与教材一致。

这个形式可以理解为带前馈补偿的速度控制：目标速度是设定值，物理引擎里已有的力是已知扰动，驱动力补足差额，本步结束时速度恰好等于目标（算例里的 0.2）。外力被计入预测，所以不会和控制力重复叠加。这是本专栏的解读，教材只给了公式。

## 单位与前置条件

教材明确的约定：质量必须大于 0，进入计算的时间步必须大于 0，向量和标量均为有限数，`BodyRotation` 为单位旋转。速度单位米每秒，加减速米每二次方秒，力为牛顿。暂停帧由调用方跳过，**不用伪造的时间步替换 0**。

## 验证范围（照抄边界）

教材记录：独立 Python 双精度完成 10300 组单轴分支对照与 1000 组力关系检查。这**不是**float32 位级等价，也没有执行 Unity C# 或原游戏。预览积分会随时间步产生离散误差，不声明固定或可变帧率下位移完全一致。

## 值得学的点

- **逐轴限速而非向量限速**：局部轴的加速与减速可以不同，例如侧移比前进更容易刹停。向量限速做不到。
- **速度反馈用预测而不是直接叠加**：清晰区分“已知外力”和“控制力”。
- **用 `<= 0` 分支表示“跳过限速”**，把“关闭一个特性”编码在参数里而不是另开布尔。
- **算例当验收**：教材的 80 / 0.1 / 160 / 120 这些数，是可以直接复现的单元测试。

## 常见坑

- 把 `WalkAcceleration(-1)` 当真实加速度。
- 在世界坐标系里逐轴限速：原作显式转到 body 局部坐标。
- 驱动力与外力重复计算，造成速度过冲。
- 用 `Time.deltaTime == 0` 时仍然更新，除以零。
