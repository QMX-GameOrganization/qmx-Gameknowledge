> 适用版本：随机核依据旧反编译 C（`gamedll_x64_rwdi.c`），爆炸倍率依据当前 DLL 的指令。二者不是同一版本。完整暴击、护甲、部位、距离衰减与最终生命写入**没有闭合**。依据 `DL1/Teach/Logic/Combat/伤害边界与单机战斗集成.md`。

## 要点

- 随机数是 48 位线性同余发生器（LCG），乘数 `0x5DEECE66D`、增量 `0xB`，与 `java.util.Random`、POSIX `drand48` 用的常数相同。
- 取区间整数时用 `% 宽度`，保留了**模偏差**，教学内核照原样保留。
- 爆炸伤害倍率在当前 DLL 的指令里是一次 `mulss`：伤害包的 `+0x28` 乘以属性 `BlastDamageMul`（属性号 `0x106`）。
- 战斗集成的重点不在公式，而在**去重和事务边界**。

## 48 位 LCG

旧反编译 `FUN_181044f80`（`gamedll_x64_rwdi.c:1957088` 起）：

```c
int FUN_181044f80(int param_1, int param_2)        // [min, max) 区间随机整数
{
  if (param_1 == param_2) return param_1;          // 相等边界不消费状态
  DAT_181bd4a60 = DAT_181bd4a60 * 0x5deece66d + 0xb & 0xffffffffffff;
  return param_1 + (int)((uint)(DAT_181bd4a60 >> 0x10) & 0x7fffffff) % (param_2 - param_1);
}
```

同一文件附近还有两个相关函数（反编译所见）：一个取 `state >> 0x11` 再对 `param_1` 取模；一个用 `(int)(state >> 0x18) * 5.960464e-08`，其中 `5.96e-8` 就是 2⁻²⁴，得到 [0, 1) 的浮点数。

教学 C# 与之逐行对应：

```csharp
public ulong Advance()
{
    State = unchecked(State * Multiplier + Increment) & StateMask;     // 48 位掩码
    return State;
}
public int NextInt(int Minimum, int MaximumExclusive)
{
    if (Minimum == MaximumExclusive) return Minimum;
    int Width = checked(MaximumExclusive - Minimum);
    if (Width <= 0) throw new ArgumentOutOfRangeException(nameof(MaximumExclusive));
    int Sample = (int)((Advance() >> 16) & 0x7fffffff);                // 取高位 31 位
    return Minimum + Sample % Width;
}
```

用同样的常数，种子 12345，本专栏验证 `NextInt(0, 10)` 的前八个值是 `5, 3, 4, 9, 8, 7, 4, 5`，可作为自己复刻时的对拍向量。

几个设计取舍：

| 点 | 说明 |
| --- | --- |
| 取高位 | LCG 低位周期短，取 `state >> 16` 之后的高位更均匀。这是该类发生器的常识用法 |
| `% 宽度` | 保留了偏差，教材说明“保留原整数核的余数偏差” |
| 实例化状态 | 原作是**全局状态** `DAT_181bd4a60`，教学版改成实例，属于教学选择；原全局种子与各系统消费顺序没有还原 |
| 负宽度、溢出宽度 | 明确失败，仅承诺合法正宽度域 |

教材验证了 512 组独立大整数随机状态与 128 组整数区间对照。

## 爆炸倍率的消费

当前 DLL 在 `0x1809eda8a` 设置属性 ID `0x106` 调 getter，随后在 `0x1809eda9b` 用 `mulss` 乘伤害包 `+0x28`。当前版本的属性名表里 `0x106` 是 `BlastDamageMul`，`0x104` 是 `BulletRecoilFactor`，**不能直接套用旧 C 里 `0x104` 的名称**。

教学内核 `VerifiedBlastScaling` 只做这一次 binary32 乘法，调用方负责取到正确 owner 的倍率并确认原分支适用。它不补造距离、暴击或护甲，也不擅自夹倍率。算例：教学基值 1、倍率增量 0.5、加值 0.25，经 5.1 的公式得 1.75；输入伤害 40 乘 1.75 得 70。本专栏复算过：`(0.5+1)×1+0.25 = 1.75`，`40×1.75 = 70`。教材另有 128 组 NumPy float32 逐位对照。

处决的 70 是另一回事：处决伤害由教学宿主独立设为 70，没有调用爆炸倍率，也没有证明原处决实际伤害是 70。教材专门要求这两个例子分开理解。

## 战斗集成：去重与事务

教材把几个模块拼成一条链：

```text
动画事件（GIVE_GRAB_DAMAGE 局部 20 帧）
   └─ EventClock 派发 ─► ResolvedDamageAction ─► TeachingHealth.Receive
                                                    └─ 死亡边沿（生命从正到零）─► 教学任务状态 = 2
                                                                                   └─ started quest guard 判定通过
```

设计要点：

- **按稳定 `ActorId` 去重**：同一次发射实例持有一个目标集合，重复命中同一目标不重复扣血。多段攻击或多发弹丸需要各自建立发射实例，不能让同一个集合贯穿整场战斗。
- **取消后停止提交**。
- **死亡通知只在生命由正到零的边沿产生**，持续为零不重复通知。
- **生命上限降低时夹当前值，上限升高不治疗**——这是教学合同。
- **事件交付不是事务**：`EventClock.Advance` 先推进游标，接收器随后失败不会恢复。宿主应立即终止动作并取消其伤害，保留首错，不能重新 `Advance` 同一时刻去重试。教材明确：没有事件回滚或可靠重投。
- 低频命中结果对象 `DamageCommit` 不声称零分配。

## 值得学的点

- **随机数用自带的小状态机，不用全局 `Random`**：可复现、可存档、可对拍。
- **把“数学核”和“业务集成”分两个类**：前者可以用独立语言校验，后者体现架构取舍。
- **去重集合的生命周期=一次攻击**，不是角色。
- **死亡用边沿，不用电平**。

## 常见坑

- 用 `System.Random` 复刻，结果和原作不一致。
- 把旧版本的属性号当成当前版本的，导致把子弹后坐力当成爆炸伤害倍率。
- 忘记 `Minimum == Maximum` 时不消费状态，导致序列错位。
- 事件去重和目标去重混为一谈：它们解决不同入口的重复提交。
