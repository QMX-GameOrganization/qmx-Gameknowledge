> 适用版本：与游戏版本无关。每一项都能追溯到前面的章节。“优先级”是本专栏的判断：按“对自己项目的收益 ÷ 实现成本”排序，不是游戏本身的重要程度。

## 先学这五项

| 顺序 | 做法 | 一句话原理 | 章节 |
| --- | --- | --- | --- |
| 1 | 区间派发的事件时钟 | 用 `(prev, now]` 判定事件，游标只前进，低帧率不漏、重复调用不重放 | 3.1、3.2 |
| 2 | 属性“清零重算” | 基值、加值、倍率增量、当前值四槽；撤销等于少加一项，不靠减回去 | 5.1 |
| 3 | 候选副本 + 单点提交 | 所有修改先落在副本上，约束全过后一次赋值替换，失败零副作用 | 7.3 |
| 4 | 提供者/接收者 + 不可变快照 | 玩法层只提交“想要什么”，物理层决定实际结果，两边只靠快照通信 | 1.2、4.1 |
| 5 | 证据分级与负例 | 每个结论标明站在哪一级，每条规则配一个会失败的测试 | 0.2、8.2 |

这五项都不依赖这款游戏的具体内容，改个名字就能放进自己的项目。

## 按主题的完整清单

### 数据与配置

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 声明 / 消费 / 教学实现三层分开 | 配置值只代表设计意图，行为在消费者里 | 任何数据驱动系统的文档组织（1.2） |
| `!include` 差量继承 | 子预设只写与父级不同的行 | 怪物、武器、关卡的变体配置（1.1、6.1） |
| 枚举与代码同步，注释写明 | 脚本层 ID 与代码枚举一一对应，加载时校验数量 | 技能、状态、事件 ID（1.2、6.1） |
| 有序规则表 `Rule(Goal, Condition)` | 行为由表的顺序决定，改行为不改代码 | AI 决策、UI 状态优先级（6.1） |
| 参数带单位的注释 | 数据里写 `//[m]`，减少误用 | 所有数值配置 |
| 编译产物与源格式分离 | 作者写紧凑 DSL，引擎吃展开后的产物（`pxsl_line` 线索） | 任务/对话工具链（1.1） |

### 时间与事件

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 区间派发 | 掉帧时不漏事件 | 动画事件、音效、时间线、脚本触发（3.1） |
| 时钟只返回事件，不执行 | 纯逻辑可单元测试，副作用交业务层 | 与 ECS 事件缓冲对接（3.1） |
| 帧率放进数据 | 每个片段有自己的 FPS | 任何基于时间轴的资源 |
| 输出缓冲区由调用方复用 | 热路径零分配 | 音频调度、粒子事件（3.2） |
| 事件交付不是事务 | 游标推进后接收器失败不回滚，宿主应终止并保留首错 | 事件驱动的伤害、奖励（5.3） |

### 数值与状态

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 四槽属性模型 | 结果与应用顺序无关，撤销精确 | RPG 属性、buff 系统（5.1） |
| 倍率增量相加 | 多层加成可展示为“+25%” | 数值设计（5.1） |
| 布尔位覆盖 | bit0 当前值，bit1 默认值，最后写入生效 | 开关类状态（5.1） |
| 稳定压缩清理到期项 | 读写双指针，O(n)，保持顺序 | 任何“遍历中删除”（5.2） |
| 未知字段原样保留并标记 | 不丢数据，也不假装执行 | 配置解析器（5.2） |
| 定义/实例分离 | 配置不可变，存档只存实例 | 装备、物品（5.4） |
| 自带小状态机的随机数 | 可复现、可存档、可对拍 | 战斗、程序化生成（5.3） |
| DAG 构造时验证 | 成环与缺失前置在加载时报 | 技能树、科技树、任务依赖（5.5） |

### 运动与物理

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 逐轴局部限速 | 前进与侧移可有不同加减速 | 角色控制器（4.2） |
| 速度反馈驱动力 | 预测已有力造成的速度，只补差额 | 物理驱动的移动（4.2） |
| 动画位移转速度 | 位移经物理体，碰撞仍生效 | 带位移的攻击、翻越（4.1） |
| 接触状态是一组量 | 法线、高度上下界、坡角阈值共同决定 | 自制角色控制器（4.3） |
| 用余弦阈值判坡度 | 配置加载时算一次 | 地面判定（4.3） |

### 资源与格式

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 自描述顶点声明 | 布局是数据，不是硬编码 | 自定义网格格式（2.2） |
| 偏移直接存 | 不靠累计长度推导 | 二进制容器（2.2） |
| 指针修正表 | “哪些位置是指针”做成数据 | 序列化（2.1） |
| 名字哈希匹配 | 运行时不比较字符串 | 骨骼、资源引用（2.3） |
| Cayley 旋转三元组 | 3 个数表示旋转，没有冗余约束 | 动画压缩（2.3） |
| 外观作为规则表 | 权重、标签、递归子选项 | NPC 变体系统（2.5） |
| 缺源就报缺源 | 不生成占位资源冒充完整 | 资源流水线（2.5） |

### 工程方法

| 做法 | 原理 | 迁移场景 |
| --- | --- | --- |
| 函数索引 + 按字节偏移读取 | 巨型文本按需取证 | 大日志、大导出（8.1） |
| 证据带路径、行号、SHA256 | 文件变了，结论自动失效 | 任何需要复核的研究（8.1） |
| 机器码 oracle | 把原函数当黑盒执行对拍 | 重写旧系统时的回归（6.2、8.2） |
| 保留首错、不放宽断言 | 失败是信息，不是障碍 | 所有测试（0.2、8.2） |
| 每节固定“前置/证据/目标/代码/讲解/自测” | 读者知道每一节做什么 | 内部教程、培训（索引页） |

## 这套素材自己的局限

- 多数结论停在“静态核对”，没有到原游戏或 Unity 实测，很多处明确写着“待验收”。
- 完整的伤害链、碰撞求解、AI 攻击、任务动作都没有恢复；教学内核只覆盖已闭合的子集。
- 部分教学代码的命名风格（大驼峰局部变量、字段与参数重名）是作者的个人约定，迁移时按自己项目规范调整。
- 单个结论的数字（如 10300 组对照）是作者的验收项，不要当作覆盖率引用。

## 如何使用这张清单

1. 先选第一节的五项之一，在自己的项目里复现最小版本；
2. 照教材写一个“恰好违反规则”的测试，确认它会失败；
3. 再回到对应章节读“常见坑”，核对有没有踩到。
