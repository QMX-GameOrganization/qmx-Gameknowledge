> 适用版本：Dying Light 1.55.0.0。依据 `DL1/Notes/DL1网格格式逆向.md` 第九到十五节。本章的重点是“哪些东西已经还原、哪些明确没做”。

## 要点

- 一个角色的可见外观不是一份固定网格，而是由 part1 里的 **Skin 描述符**递归选出一组子网格与材质。
- 描述符里含随机选择与标签过滤。作者的工具只能“显式指定选择”，没有复现随机种子和全部标签逻辑，并且明说了。
- 贴图按材质的纹理哈希去库里找，而不是按包名猜。
- 形变（Morph）数据与角色头型/颜色预设不是一回事，交付的 shape key 不等于头型全部还原。

## Skin 描述符与递归选装

part1 开头：+0 是 `u16` skin 数，+4 是 `i32` 描述符表偏移，每项 48 字节。描述符 +44 指向相对 child 表，+29 是 child 数，每项 12 字节。

规则：

- `rawFeatures` 里 `ShowAll`（掩码值 1）与 `HideAll`（掩码值 2）二选一，同时存在时 `ShowAll` 优先。笔记强调这里的数字是位掩码值，不是位序号。
- 先处理当前 skin，再按 children 顺序深度优先处理子 skin。
- 候选数在 word2 低 7 位，bit7 是随机标志。单候选时 word0/word1 低 16 位直接是 skin index 与权重；多候选时低 28 位是带符号相对 record 起点的偏移，分别指向 `u16` index 数组与 weight 数组。
- 游戏还按 tags 过滤，并用线性同余随机数（LCG）选择。

**这是一种“数据驱动的衣橱”**：一个角色模板可以随机出不同的头、衣服、裤子，描述符只存规则，运行时抽签。对做 NPC 变体系统的人很有参考价值：规则表 + 权重 + 标签过滤 + 递归子选项。

工具 `dl1_appearance.py` 当前只“显式选择记录中的支路”。普通丧尸的选装组合就是手工指定的：

```text
Zombie_Slums: alpha_0, head_white_level_3, pants_a, torso_a, torso_a_01,
              slums_sleeves_a, head_white_b, uber_deform_a
```

可见实体是 `head_u`、`neck_u`、`pants_a`、`torso_a`、`torso_a_hand_l`、`torso_a_hand_r`。原运行时证据在 `engine_x64_rwdi.c` 的 `FUN_1804982e0` 与 `FUN_180492a60`。

还有一个隐藏细节：以 `sc_` 开头的网格（以及 `body_sc`、`head_sc`）使用 `shadow_caster*.mat`，**只用于游戏内阴影**，不属于可见角色，导出时必须排除。另外，surface override（`FUN_180492b40`）改的是物理表面 ID 与 flags，不控制几何可见性，别把它们混为一谈。

## 材质：诚实的近似

材质只还原了 base color、主法线和部分 emission。笔记列了一串“没做”：

| 内容 | 状态 |
| --- | --- |
| 血液、风场、环境光、高光等完整 shader | 未复现 |
| 缩放 UV 的细节法线 | 例如夜魔头的 `srf_skin_body_a_nrm`，只接主法线 |
| 睫毛/眼影混合 | 原 blend 是 ZERO + Destination × SourceColor，Cycles 用带颜色的 Transparent BSDF 对应，GLB 用已标明的 alpha 近似 |
| 头发 alpha | 原 alpha 只有 0 和 255，原 shader 做 alpha clip，预览阈值明确取 0.5 |

法线贴图格式也有坑：原始法线用 AG 两通道存储（X=A，Y=G），原头部 shader 用 `normalize(N + X*T + Y*B)`。转成 Blender 的法线贴图时，UV 改为 `(u, 1−v)`，法线换算为 `normalize(2A−1, −(2G−1), 1)`。

## 贴图：把“能打开”变成“契约”

2D 贴图 Format 对应：

| Format | 含义 |
| --- | --- |
| 2 | A8R8G8B8（对应 DXGI 87 BGRA8，DDS 掩码 00FF0000/0000FF00/000000FF） |
| 17 | DXT1（BC1） |
| 18 | DXT3（BC2） |
| 19 | DXT5（BC3） |

注意一个旧坑：旧脚本 `dds_bc.py` 的 BC4 分支不能用于 DXGI 77（它是 BC3）。

元数据位置：宽高在 0/2，Depth/ArraySize 在 4/6，MipCount 在 8（取低 15 位），Format 在 12。每层尺寸为 `max(1, base >> level)`，数据长度必须与全部 item1 精确相等，**不重新压缩**。

交付与验收：

- 32 个可见材质联合请求 114 个纹理哈希，导出 112 条完整 DDS，共 1105 层。
- `eyes_env_def` 的 ArraySize = 6（立方图），只保留原始 metadata/pixels，不解码，标记 `Decoded=false`。首个立方图导出失败的日志也保留了。
- `zombie_teeth_a_spc`（哈希 `0xD8941A6A`）在本地所有 rpack 里都缺，工具用 `--omit-texture` 明确记录，不生成占位图假装完整。
- `dl1_verify_textures.py` 独立核对 DDS 头（尺寸、mips、flags、pitch、depth、caps、PF FourCC 或 RGBA 掩码）与原 Format 一致，逐层核原 SHA，并用 Pillow 解码每层 RGBA。三个故意构造的负例都被拒绝：把 DXT5 改成 DXT3、BGRA 红蓝掩码互换、改动 metadata 中未解释的字节。

## Morph 形变数据

`MeshDump` 输出原 `MorphChannels/MorphBindings`。一个容易忽略的点是：Vector3 默认 JSON 序列化会得到空对象，**不能把空对象当成有效 delta**。普通丧尸 `head_u` 含 2228 个唯一源顶点、17 个 channel、共 37876 条 HALF4 记录（XYZ 逐 float32 位核对，W 为 0）。

验证闭环：从原始字节生成 17 个 shape key，独立读取 GLB 的 sparse/dense accessor，delta 最大差 5.96e-8 m；混合正负权重后位置差 9.7e-8 m；故意加入 0.001 m 错误的负例也被拒绝。

但是，形变几何不等于角色绑定预设。`CHR v4` 解析了 24 个 preset，`uber4-head_a` 存在，`u4_zm_head_c` 在本地 12 个 `.chr` 中都不存在，原 CHR 与网格 entity 名也不完全一致，不能盲按 index 套用。所以交付的 shape key 初始权重为 0，**不冒充头型和颜色完全还原**。

## 值得学的点

- **外观作为数据规则**：权重、标签、递归子选项，适合做 NPC 批量变体。
- **每类还原产物都配一份“未做清单”**，在 JSON 里用 `UnappliedAppearanceCommands` 这样的字段显式记录。
- **缺源就报缺源**。不生成占位资源让流水线看起来通过。
- **用 SHA 把贴图读取变成可复验的契约**，而不是依赖“用肉眼看对了”。

## 常见坑

- 把 shadow caster 网格带进可见角色。
- 把 Morph delta 的 JSON 空对象当作有效数据。
- 把“DDS 能被 Pillow 打开”当作头部契约正确。
