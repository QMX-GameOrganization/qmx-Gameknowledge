> 适用版本：Dying Light 1.55.0.0 的 `.rpack`（签名 `RP6L`）。依据 `DL1/Notes/DL1网格格式逆向.md` 第一、二、四到六节。原笔记标注为实测加社区工具源码参考。

## 要点

- 游戏资源按 `.rpack` 打包。容器自己只管“有哪些文件、每个文件由哪些 part 组成、数据在哪”，不关心内容。
- 内容格式由上层决定。一个网格资源恰好有 5 个 part，各管一块。
- 容器与网格里的指针都是 1 基偏移，读之前要减 1。1 基指针的一个常见好处是 0 可以保留表示“空”（推测，笔记未说明）。

![RP6L 与网格 part](/qmx-Gameknowledge/assets/dl1/dl1-rpack-mesh.svg)

## 容器：头与四张表

头部 4 字节签名 `RP6L`，随后 8 个 `u32`：version、compression、partAmount、sectionAmount、fileAmount、nameChunkLength、nameAmount、blockSize。

| 表 | 每项大小 | 关键字段 |
| --- | --- | --- |
| `sectionInfo` | 20 字节 | `filetype`、`offset`、`unpackedSize`、`packedSize`（段可压缩） |
| `partInfo` | 16 字节 | `sectionIndex`、`fileIndex`、`offset`、`size` |
| `fileInfo` | 12 字节 | `partAmount`、`filetype`、`fileIndex`、`firstPart` |
| 名字表 | 每名一个 `u32` 偏移 | 后接 `nameChunkLength` 字节名字串 |

读一个文件的路径是：`fileInfo` 给出这个文件由 `partAmount` 个 part 组成、第一个 part 在 `firstPart`；每个 part 在 `partInfo` 里指向某个 section 内的 `offset/size`；section 在 `sectionInfo` 里给出在包中的位置与压缩状态。version 为 1 时 offset 乘数为 1。

这个设计把“文件”拆成“若干 part”。笔记没有解释设计动机，下面是本专栏的推测：头部、顶点、索引可以分别放进不同 section，按不同方式压缩或对齐，也方便只读需要的部分。

## 网格：恰好 5 个 part

| part | 内容 |
| --- | --- |
| 0 | 网格树：头、名字串、节点表（每节点 208 字节） |
| 1 | 120 字节小结构，疑似表面或材质参数（外观 `SkinDefinitions` 在这里） |
| 2 | `MeshFixups` 修正表：指出 part0 内哪些偏移是 1 基指针 |
| 3 | 顶点缓冲，可含多个节点缓冲串联 |
| 4 | `u16` 索引缓冲，每节点局部编号 |

part2 这个设计值得细看。笔记的事实是：part2 指出 part0 内哪些偏移是 1 基指针。常见的用法（推测，笔记未写加载器行为）是读入内存后按表把这些偏移改写成真实地址，一遍线性扫描就把整棵树“链接”好。逆向时可以反过来用：想读 part0，先读 part2 知道哪些 8 字节槽是指针，不要靠值域猜。

### part0 头部

头部 128 字节，是 12 个 `u64` 槽加 8 个 `u32`：

| 槽 | 含义 |
| --- | --- |
| @0 | 网格名串指针 |
| @8 | 节点数组指针 |
| @16 | 表面参数指针 |
| @24 | 材质数据指针 |
| @40 | 碰撞树指针 |
| @72 | 动画脚本名指针 |
| @100 / @104 / @108 / @112 | 节点数 / 根节点数 / 表面数 / 骨骼数 |

### 节点结构 `MeshEntityInFile`（208 字节）

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | 3×4 矩阵 | 本地矩阵，按行存，平移在第四列 |
| 48 | 3×4 矩阵 | 全局逆绑定矩阵 `Reference` |
| 96 | AABB | 包围盒 |
| 120 | u64 | 名字指针 |
| 136 | u64 | NodeFormat 指针 |
| 196 / 198 | u16 | nodeIdx / parent（65535 为根） |
| 200 | u8 | type：1 静态、2 蒙皮、4 辅助、8 骨骼 |

一个角色网格里骨骼、蒙皮网格、辅助点都是“节点”，用同一结构、靠 `type` 区分。Jade 样本有 206 个节点，其中 15 个是蒙皮网格节点。

## 值得学的点

- **指针修正表**。把“哪些位置是指针”做成数据，而不是靠约定。自己设计二进制序列化格式时可以借鉴：加载时线性扫一遍就能还原引用，不需要边解析边猜。
- **统一节点结构**。网格、骨骼、辅助点放在同一层次的节点树里，父索引用 `u16`，层次关系就是数组。
- **LOD 与几何分层**。节点 +0x88 指向 LOD 表，每项 48 字节，下一章展开。

## 常见坑

- 忘记 1 基。所有指针字段读出来要先减 1，否则偏移全部错位一个字节。
- 以为 part 的顺序是任意的。网格固定 5 个 part，顺序即语义。
- 对旧样本的 20 字节静态顶点布局（3 个 half 位置 + half W + 4 个 sbyte 法线 + 2 个 half UV + 备用）做泛化。笔记明确写：此布局只适用于对应声明组，通用解码必须读声明表（见 2.2）。

## 自测

1. 一个文件有 5 个 part，它在容器里需要几项 `fileInfo`、几项 `partInfo`？（1 项，5 项）
2. 为什么 part2 要单独存在，而不是在 part0 里直接存真实指针？（文件内偏移要在加载后才能变成地址，修正表让加载器线性链接）
