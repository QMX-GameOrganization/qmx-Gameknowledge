> 适用版本：Dying Light 1.55.0.0。依据 `DL1/Notes/DL1网格格式逆向.md` 第七、八节，以 Jade 样本实测。

## 要点

- 顶点缓冲是一串紧挨着的二进制记录，每个顶点占多少字节、每个字段在什么位置，**写在声明表里**，不能从节点类型推断。
- 顶点块在 part3 里的位置由 `MeshInfo` 直接给出，不要用“上一块长度累计”来推。
- 索引是每个节点局部的 `u16`，再通过每个子网格自己的“调色板”映射到骨骼 entity 索引。

## 声明表

metadata +0x50 指向声明组表（1 基指针），+0x7C 是组数（`u32`）。声明组每项 16 字节：+0 元素表指针，+8 元素数。每个元素 4 字节：

```text
format  semantic  channel  reserved
```

偏移按声明顺序累计，所有 format 大小之和就是顶点步长。

| format | 含义 | 字节 |
| --- | --- | --- |
| 2 | float3 | 12 |
| 4 | byte4 | 4 |
| 15 | half2 | 4 |
| 16 | half4 | 8 |
| 31 | snorm byte4 | 4 |

| semantic | 含义 |
| --- | --- |
| 0 | position |
| 1 | weights |
| 2 | indices |
| 3 | normal |
| 5 | UV |
| 6 | tangent |
| 10 | color |

Jade 的唯一声明组是 40 字节：position 为 float3 @0，weights 为 unorm byte4 @12，indices 为 byte4 @16，normal 为 snorm byte4 @20，UV0 为 half2 @24，UV1 为 half2 @28，tangent 为 snorm byte4 @32，color 为 byte4 @36。

用伪代码表示步长计算：

```csharp
int stride = 0;
foreach (var e in group.Elements)
{
    e.Offset = stride;
    stride += FormatSize(e.Format);   // 2→12, 4→4, 15→4, 16→8, 31→4
}
```

因为步长来自声明，同一个解码器才能同时支持 20 字节的静态网格和 40 字节的蒙皮网格。

## 从节点到顶点

```text
节点 +0x88 ─► 几何 LOD 表（每项 48 字节）
                 ├─ +8  ─► MeshInfo
                 ├─ +16 ─► u16 子网格材质槽数组
                 └─ +24 ─► 子网格调色板表（每描述符 16 字节）

MeshInfo
   +0   u64  子网格索引数数组指针（1 基）
   +24  u32  顶点字节偏移（直接读，不累计）
   +40  u32  顶点数
   +44  u32  索引字节偏移（直接读）
   +48  u16  子网格数
   +50  i16  声明组索引
```

调色板描述符 +0 指向 `i16` 的 entity 索引数组，+8 是数量。**每个子网格有自己的调色板**，不能让整个节点共享一套。网格的蒙皮权重 `indices` 存的是调色板内的局部编号，要经调色板才能找到真正的骨骼节点。

## 调色板的作用（含推测）

笔记确认：每个子网格有自己的调色板，权重 `indices` 要经它映射到骨骼 entity。为什么要这样做，笔记没写。这里给一个常见的图形学解释，仅作推测：一次绘制能用的骨骼矩阵数有上限，大角色有 206 个节点，所以把网格拆成多个子网格，每个只引用一小批骨骼，`indices` 用 `byte4` 存批内局部编号就够了。

## 校验方法

- 每个节点解码后的包围盒，与节点自带 AABB 逐项吻合。
- `sc_hands` 实测中心约 (0.000, 1.002, 0.296)，半径约 (0.470, 0.075, 0.065)；期望值 (0.00, 1.00, 0.30)、(0.47, 0.07, 0.07)。
- 全局最大索引 3860，对应最大节点 hands 的 3861 个顶点。

这类校验不依赖渲染截图。笔记最后一节强调：“不从好看的截图反推字段正确”。

## 值得学的点

- **自描述格式**。顶点布局放在数据里，解码器不硬编码布局。你自己做程序化网格或自定义序列化时，可以借鉴：给每组顶点写一张小小的“字段表”。
- **偏移直接存，不推导**。`MeshInfo` 里存顶点和索引的绝对字节偏移，避免“累计长度”在中间有对齐或空洞时出错。
- **用几何自洽性当验证**。包围盒、最大索引、顶点数三者互相约束，比目测可靠。

## 常见坑

- UV 必须按每顶点 40 字节的跨距取，不能连续读 `vertexCount × 2` 个 half。
- 把相邻布局当契约。旧脚本用 `NodeFormat+0x58` 的位置，利用了样本中 LOD 与 MeshInfo 恰好相邻；换一个样本就读错。
- 不按调色板映射骨骼，直接把 `indices` 当全局骨骼编号。
