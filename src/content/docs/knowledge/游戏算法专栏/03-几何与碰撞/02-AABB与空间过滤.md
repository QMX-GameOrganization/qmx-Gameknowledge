## AABB 是粗过滤工具

AABB 是与坐标轴对齐的包围盒，可以用最小点和最大点表示。它不需要旋转信息，测试成本低，适合在精确检测之前快速排除不可能相交的对象。

两个 AABB 在三个轴上都重叠时才相交：

```text
a.min.x <= b.max.x 且 a.max.x >= b.min.x
a.min.y <= b.max.y 且 a.max.y >= b.min.y
a.min.z <= b.max.z 且 a.max.z >= b.min.z
```

任意一个轴没有重叠，就可以直接排除。

## 由中心和半径表示

也可以使用中心点 `center` 和半尺寸 `half`。这样更新对象移动时只需更新中心，尺寸变化时再更新半尺寸。

对于一个点 `p`：

```text
min.x <= p.x <= max.x
min.y <= p.y <= max.y
min.z <= p.z <= max.z
```

对于范围查询，可以先用 AABB 包围查询球，再做平方距离精确判断。

## 层级过滤

一个高效的 Gameplay 查询通常分多层：

```text
空间网格或 AABB
→ 阵营、标签、状态
→ 距离平方
→ 角度
→ 射线或形状投射
→ 业务规则
```

前面每层都要尽量便宜。昂贵的 Physics 查询和复杂的业务判断放到候选已经很少之后。

## 动态对象的更新

AABB 可以每帧更新，也可以只在对象移动或旋转超过阈值时更新。对于高速对象，需要考虑上一帧到当前帧的扫掠范围，否则单帧跳过薄障碍。

对象尺寸和旋转变化会影响 AABB。旋转物体使用世界轴对齐盒时，旋转会让盒子变大，粗过滤精度下降。可以根据查询场景选择 OBB、胶囊体或引擎碰撞查询。

## 与 Unity Physics 的关系

`Physics.OverlapSphere`、`Raycast` 和 `Collider.bounds` 已经由引擎维护了一部分空间结构。Gameplay 自己维护 AABB 或空间网格，适合承担：

- 目标选择和阵营过滤。
- 非物理对象查询。
- 自定义逻辑层的快速候选筛选。
- 大量简单数据的批量处理。

重复维护同一套物理空间索引会增加同步成本。先确认查询需求和 Profile 数据，再决定是否需要额外索引。

## 常见坑

- AABB 相交只代表包围盒相交，不代表真实形状相交。
- 用局部坐标的 bounds 与世界坐标位置直接比较。
- 旋转、缩放或骨骼变形后继续使用过期 bounds。
- 用一个静态盒子代表高速移动对象，导致穿透。
- 过滤层级顺序错误，让昂贵查询先执行。

## 练习

1. 实现 AABB 的相交、包含和点距离判断。
2. 用 AABB 对 1000 个目标做粗过滤，再用圆形范围做精过滤。
3. 给高速移动物体计算上一帧和当前帧的合并包围盒。
