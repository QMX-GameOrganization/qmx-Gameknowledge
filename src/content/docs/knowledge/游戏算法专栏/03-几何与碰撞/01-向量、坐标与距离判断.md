## 向量运算对应什么问题

- 点积表示投影、夹角和朝向关系。
- 叉积表示二维左右关系，或三维垂直方向。
- 向量长度表示距离，但开平方有额外成本。
- 归一化得到方向，但零向量不能直接归一化。
- 矩阵和 Transform 负责坐标空间转换。

Gameplay 中很多“看起来像业务逻辑”的判断，最后都可以还原成这些几何运算。

## 距离比较优先使用平方距离

如果只需要比较距离大小，可以使用：

```csharp
Vector3 delta = target - origin;
if (delta.sqrMagnitude <= radius * radius)
{
    // 在半径内
}
```

平方距离避免开平方，也更容易批量处理。需要显示距离、计算速度或进行归一化时，才读取真实长度。

## 视野角度

判断目标是否在朝向的扇形内，可以比较点积：

```csharp
Vector3 toTarget = target - origin;
float distanceSquared = toTarget.sqrMagnitude;
if (distanceSquared <= radius * radius && distanceSquared > epsilon)
{
    Vector3 direction = toTarget / Mathf.Sqrt(distanceSquared);
    bool inside = Vector3.Dot(forward, direction) >= cosineHalfAngle;
}
```

如果目标数量多，先用平方距离过滤，再做归一化和点积。`cosineHalfAngle` 可以预先计算。

## 坐标空间要统一

角色前方、相机前方、武器枪口和导航地图可能处在不同空间。判断前先明确：

- 输入数据在哪个空间。
- 方向向量是否归一化。
- Y 轴是否参与距离。
- 旋转使用世界空间还是局部空间。
- 目标位置是否需要投影到地面。

把世界坐标和局部坐标混用，通常会产生随父节点旋转或缩放变化的间歇性错误。

## 误差和比较

浮点结果很少适合直接用 `==` 比较。位置、角度和时间判断应使用容差，容差需要和单位、场景规模以及累积误差相匹配。

角度差最好归一化到 `[-180, 180]`，否则从 359 度转到 1 度会被误判为跨越 358 度。
