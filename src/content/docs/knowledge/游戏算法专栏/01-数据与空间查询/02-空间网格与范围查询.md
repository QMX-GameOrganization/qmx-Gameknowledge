## 为什么需要空间索引

如果每个单位每帧都遍历所有目标，查询成本是 O(n)。当单位数量为 n、查询者数量也接近 n 时，总成本会接近 O(n²)。很多玩法只关心附近目标，空间索引可以把全局查询变成局部查询。

均匀网格适合对象分布相对均匀、查询范围有明确上限的场景。它的实现成本低，也容易迁移到 Native 容器或 Job。

## 网格坐标

给定世界坐标 `(x, z)` 和格子边长 `cellSize`：

```csharp
int Cell(float value) => Mathf.FloorToInt(value / cellSize);
```

负坐标必须使用向下取整。直接转换为 `int` 会向零截断，导致负半轴的边界规则不一致。

```text
世界坐标       -0.1      0       0.1
FloorToInt      -1       0        0
```

格子键可以使用二维结构体，也可以把两个整数打包成一个 64 位整数。打包时要保证不同坐标不会发生碰撞。

## 插入和移动

每个对象需要记录自己当前所在的格子。移动后先计算新格子，只有格子发生变化时才从旧列表移除并加入新列表。

```text
对象记录 currentCell
每次更新：
  newCell = WorldToCell(position)
  if newCell == currentCell：跳过
  从旧格子移除对象
  加入新格子
  currentCell = newCell
```

对象从列表中移除时，可以使用“末尾元素覆盖被删除位置”的方式，把删除成本降到 O(1)。被移动的对象必须同步更新自己的列表索引。

## 半径查询

查询半径为 r 时，先计算覆盖范围的格子矩形，再遍历这些格子的对象，最后使用平方距离做精确过滤：

```csharp
float radiusSquared = radius * radius;
foreach (var candidate in cellsAroundQuery)
{
    Vector3 delta = candidate.Position - center;
    if (delta.sqrMagnitude <= radiusSquared)
        result.Add(candidate);
}
```

这里的顺序很重要：空间网格负责粗过滤，平方距离负责细过滤。若还需要视野判断，再对少量候选进行角度和射线检查。

## 去重和结果复用

查询圆形范围时，一个对象只应属于一个格子，所以正常情况下不会因为格子重叠产生重复。层级空间索引、多个标签索引或跨格子对象可能造成重复，需要使用查询标记或临时集合去重。

高频查询可以复用结果缓冲区：

```text
开始查询前清空 count
写入 result[0..count)
返回切片或 count
```

清空容量和清空元素不是同一件事。若结果只在本帧使用，可以只重置计数，避免重复初始化整块数组。

## 选择格子大小

格子太大时，查询会拿到过多候选。格子太小时，查询要遍历过多格子，移动更新也更频繁。格子边长通常从典型查询半径、对象尺寸和分布密度开始估计，再用实际数据测量。

不要用一次测试的平均值决定格子大小。应同时观察：

- 平均查询耗时
- 最差查询耗时
- 单格最大对象数
- 移动更新次数
- 内存占用

## 适用边界

- 对象分布均匀时，均匀网格通常简单有效。
- 对象分布极不均匀时，可以考虑稀疏字典、四叉树或分层网格。
- 物理碰撞需要交给 Physics 查询时，Gameplay 索引可以承担目标筛选和逻辑过滤。
- 对象数量很少时，直接遍历可能更简单，也可能更快。

## 练习

1. 实现 2D 平面空间网格，支持插入、移动和半径查询。
2. 分别测试 100、1000、10000 个对象，比较全表遍历和空间网格。
3. 加入对象跨格子移动、负坐标、销毁和查询结果复用。
4. 用 Profiler 记录查询候选数，而不是只记录最终耗时。
