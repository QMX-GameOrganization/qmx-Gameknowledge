## 调度器维护什么

一个调度器通常维护三类信息：

- 什么时候执行。
- 执行哪一项。
- 执行后如何重新安排。

技能冷却、路径请求、AI 感知、延迟伤害、资源预加载和网络重试都可以抽象成“在某个时间点处理一个任务”。

## 优先队列适合按时间取任务

如果任务的执行时间不同，优先队列可以让队首始终是最早到期的任务：

```text
push(task, dueTime)
while 队首.dueTime <= now：
    task = pop()
    执行 task
    如果需要重复：push(task, nextDueTime)
```

取出和插入通常是 O(log n)。任务数量不大时，简单列表扫描可能更容易维护，也可能有更好的常数。选择前先测量任务数量和调用频率。

优先队列中的任务取消有两种常见方式：

- 直接从堆中删除，需要维护索引，更新复杂度较高。
- 标记取消，取出时跳过，也叫惰性删除。

惰性删除要定期清理过期条目，避免取消任务长期占用内存。

## 时间轮

当大量任务只需要近似到期时间，可以把时间划分成槽位。当前时间推进时，处理当前槽位中的任务，再把重复任务放回未来槽位。

时间轮的优势是插入和到期处理可以接近 O(1)，适合大量冷却、心跳和短定时器。它的精度由槽位大小决定。技能冷却可以允许几十毫秒误差时，时间轮通常比每个任务单独创建 Coroutine 更容易集中管理。

## 固定步和现实时间

调度器要明确使用哪种时间：

- `Update` 时间适合表现和输入相关任务。
- `FixedUpdate` 时间适合物理和固定模拟。
- 服务器 Tick 适合同步逻辑。
- 非缩放时间适合暂停菜单或真实时间计时。

把不同时间源混在一个调度器里，会导致暂停、倍速和网络重连时出现难以解释的偏差。

## 分帧预算

调度器可以同时限制：

- 本帧最多执行多少任务。
- 本帧最多消耗多少毫秒。
- 每类任务最多占用多少配额。

只限制数量可能让单个任务过重，只限制时间又会受到帧间测量误差影响。对高风险任务可以同时设置节点展开数、对象数量和时间预算。

## 生命周期和回调

延迟任务执行时，目标对象可能已经销毁。任务应保存稳定 ID 或弱引用式的有效性检查，而不是假设原始对象一定存在：

```text
执行任务前：
  检查场景版本
  检查对象 ID 是否仍有效
  检查任务版本是否仍是最新
  再调用业务执行器
```

调度器负责决定“何时调用”，执行器负责决定“当前是否允许执行”。

## 练习

1. 使用堆实现一个按到期时间执行的任务队列。
2. 加入取消、重复任务和场景版本检查。
3. 用时间轮实现大量简单冷却，并与 Coroutine 方案比较调试和性能。
4. 为路径请求和 AI 感知增加独立预算。
