## 先区分状态、决策和动作

一个 AI 系统至少包含三个层次：

```text
感知事实：看到了谁、距离多少、生命多少
决策结果：选择追击、攻击、撤退或巡逻
动作执行：移动、播放动画、释放技能
```

状态机、行为树和 Utility AI 主要解决决策组织问题。它们不负责替代感知、路径搜索和动画执行。

## 状态机

有限状态机适合状态数量有限、转移关系清楚的角色：

```text
巡逻 → 发现目标 → 追击 → 进入攻击范围 → 攻击
  ↑        ↓          ↓          ↓
  └──── 目标丢失 ← 路径失败 ← 受击打断
```

状态应明确进入、更新、退出和可打断条件。状态退出时清理订阅、定时器和路径请求，避免旧状态继续写入事实。

层级状态机可以把共同逻辑放在父状态，例如所有战斗状态共享受击处理。状态数量快速增长时，可以把“状态”与“能力条件”拆开，减少转移表爆炸。

## 行为树

行为树用组合节点组织决策：

- Sequence 要求子节点按顺序成功。
- Selector 依次尝试子节点直到成功。
- Decorator 修改条件、重复或超时。
- Leaf 执行感知、移动或技能动作。

行为树的关键是节点返回值和运行状态。`Running` 表示动作仍在继续，不能在下一次 Tick 里重复初始化。节点退出时要取消它发起的异步任务。

## Utility AI

Utility AI 为候选行为计算分数，再选择分数最高者：

```text
score = healthCurve(生命) * weight
      + distanceCurve(距离) * weight
      + threatCurve(威胁) * weight
```

曲线把原始值映射为 0 到 1。分数系统适合多个行为都“有一定合理性”的情况，例如选择攻击目标、掩体或技能。

需要加入滞后或切换成本，避免分数轻微变化导致行为频繁抖动：

```text
只有新行为分数 > 当前行为分数 + switchMargin 时才切换
```

## 决策频率

决策系统不一定每帧 Tick。可以根据距离、可见性、战斗状态和屏幕重要性分级：

- 关键角色每帧或固定步更新。
- 近处战斗单位高频更新。
- 远处单位低频更新。
- 不可见单位只执行简化模拟。

决策频率降低后，感知结果、路径结果和动作状态都要允许一定延迟。系统需要明确哪些状态变化可以延后。

## 结构选择

| 场景 | 常见选择 |
| --- | --- |
| 少量清晰状态 | 有限状态机 |
| 任务步骤和条件组合 | 行为树 |
| 多个行为竞争 | Utility AI |
| 复杂角色 | 层级状态机与行为树、Utility 组合 |

选择标准是状态和决策是否容易解释、调试和扩展。运行时性能需要用具体行为数量和 Tick 频率测量。

## 自测

- 状态、决策结果和动作执行分别由谁负责？
- 行为树节点返回 `Running` 时，下一次 Tick 应该保留什么状态？
- Utility AI 如何避免两个行为在分数接近时来回切换？
- AI 被销毁时，路径和感知任务如何结束？

## 练习

1. 为一个敌人实现巡逻、追击、攻击和撤退状态机。
2. 将目标选择改成 Utility 评分，并加入切换滞后。
3. 为行为树节点增加运行状态、超时和取消。
4. 让远处单位降低感知和决策频率。
