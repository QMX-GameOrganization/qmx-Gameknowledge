## 这套资料解决什么问题

通用算法专栏按照数据结构和算法类别组织，适合建立完整的算法地图。游戏项目面对的是另一种问题：对象会持续生成和销毁，查询发生在每帧，结果需要满足实时预算，数据还要和 Unity 的生命周期、资源系统、Job System 以及网络状态协作。

本专栏沿用通用专栏的学习方式，但把每个算法放回游戏运行时中解释。每篇都尽量回答五件事：

1. 游戏里遇到的具体问题是什么。
2. 算法维护了什么状态和不变量。
3. 数据规模增长后，CPU、内存和延迟如何变化。
4. Unity Gameplay 中怎样接入、分帧和调试。
5. 什么时候应该换一种算法或直接使用引擎系统。

## 第一轮怎么读

第一轮建议按 `00 → 01 → 02 → 03 → 04 → 05` 阅读。每篇文章先看问题建模和复杂度，再读实现细节。读完一篇，至少把示例改成一个可以在 Unity 场景中运行和计时的小实验。

如果目标是 Gameplay，可以优先完成：

```text
容器与数据布局
→ 空间网格与范围查询
→ A* 与路径重建
→ 多单位寻路与分帧
→ AABB、射线与视野
→ 优先队列与时间调度
→ 状态机、行为树与 Utility AI
→ 批处理、缓存与 Job/Burst
```

## 统一的学习验收

每个主题都用下面的问题自测：

- 数据由谁创建、拥有和释放？
- 查询的对象规模和调用频率是多少？
- 最坏情况下的耗时和内存是什么？
- 能否限制单帧工作量？
- 结果是否允许延迟、缓存或近似？
- 场景切换、对象销毁和异步任务发生时，不变量是否仍然成立？
- 改动前后是否有可复现的测量数据？

本专栏的重点是从“会写算法”走到“能把算法放进一个有生命周期、有性能预算的游戏系统”。
