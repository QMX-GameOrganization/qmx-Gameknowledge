## 先找重复工作

性能优化的第一步是识别重复计算：

- 每个对象都查询同一份静态数据。
- 没有变化的对象仍然每帧更新。
- 多个系统重复计算相同距离或可见性。
- 结果已经可以复用，却被重新生成。

可以先给系统画出数据流：

```text
输入变化 → 标记脏对象 → 批量更新 → 生成共享结果 → 消费结果
```

## 脏集合

如果只有少量对象发生变化，就维护脏集合，而不是遍历全部对象：

```text
对象位置变化 → 加入 dirtySet
本次处理 → 遍历 dirtySet
处理完成 → 清除标记
```

需要防止同一对象被重复加入。可以在对象上记录版本号或 dirty 标志。场景切换和对象销毁时要清理集合中的无效 ID。

## 批量处理

批量处理把相同操作集中执行，减少函数调用、重复查询和临时状态：

```text
先收集所有位置
再批量计算空间索引
再批量处理距离和过滤
最后一次性提交表现更新
```

批量处理适合数据结构统一、分支较少的逻辑。复杂对象行为仍然可以保留在对象层，批量系统负责前置查询和结果准备。

## 缓存和失效

缓存必须同时设计失效条件。常见版本包括：

- 地图版本
- 目标位置版本
- 通行规则版本
- 配置版本
- 感知结果版本

缓存键越简单，命中率越高，但错误复用的风险越大。缓存数据越多，内存和失效维护成本越高。记录命中率和失效率，才能判断缓存是否值得保留。

## 分帧更新

分帧更新把工作分布到多帧：

```text
本帧处理 [0, 100)
下一帧处理 [100, 200)
循环轮询直到全部完成
```

需要考虑：

- 结果延迟。
- 对象在等待期间被销毁。
- 输入和地图发生变化。
- 高优先级对象插队。
- 一帧预算耗尽后的恢复位置。

分帧不是简单地把循环切成几段。它要求任务拥有可保存、可取消和可验证的状态。

## 测量口径

优化前后至少记录：

- 平均帧时间。
- 最差帧和 P95、P99。
- 主线程、Job、渲染线程耗时。
- GC Alloc 和内存峰值。
- 每类对象的处理数量。
- 查询候选数量和缓存命中率。

保持场景、输入、设备和构建配置一致。Editor 中的结果适合定位趋势，最终结论应在目标 Player 上复测。

## 练习

1. 把一个全量 AI 更新循环改成脏集合更新。
2. 把目标选择拆成批量候选查询和逐对象决策。
3. 给路径请求增加每帧预算和可恢复状态。
4. 使用 Profiler 验证最差帧是否改善。
