## 如何验证自己的实现

源码专栏里最有用的一个方法是：**用数据包里的 JSON 当“真值”做单元测试**。

数据包 `density_function/overworld/offset.json / factor.json / jaggedness.json` 是 `TerrainProvider` 展开后的结果，格式是递归的 `{ coordinate, points: [{ location, value, derivative }] }`。写一个小解释器，对随机的 `(continents, erosion, ridges)` 求值，与你自己实现的样条对比：

```python
# 摘自 scripts/mc-source-figures/verify_port.py
def ev(sp, ctx):                       # sp: JSON 里的样条或常数
    if isinstance(sp, (int, float)): return float(sp)
    x = ctx[sp['coordinate'].split('/')[-1]]
    ...                                # 找区间 → Hermite 公式（与第 4 页一致）
```

本专栏的 Python 移植用这个办法验证过：`offset / factor / jaggedness` 三条样条与 JSON 的最大差在 1e-6 量级。你的 C# 实现应该达到同样的结果。

## 实现自检清单

| # | 检查项 | 对应页 |
| --- | --- | --- |
| 1 | `depth = g(y) + offset`，`offset` 的单位是 128 格 / 1.0 | 5 |
| 2 | 样条的第三个坐标是**折叠后的** `ridges_folded` | 4 |
| 3 | `sloped_cheese` 里 `factor` 乘在 `(depth + jaggedness·half_negative(jagged))` 上，再 `4·quarter_negative` | 5 |
| 4 | `base_3d_noise` 幅度在 ±0.3 量级（与 `depth` 单位匹配） | 5、7 |
| 5 | `final_density` 的顶层是 `slide` → `range_choice` → 后处理，而不是 `sloped_cheese` 直接用 | 6 |
| 6 | 洞穴只在 `sloped_cheese ≥ 1.5625` 时求值 | 6 |
| 7 | 低频场（`continents` 等）只依赖 (x,z)，且每 4×4 格算一次 | 10 |
| 8 | 角点插值误差：与逐方块结果比较，不一致的方块应 < 1%，且只在地表附近 | 10 |
| 9 | 所有随机数由“种子 + 名字 / 坐标”派生，改变生成顺序结果不变 | 2、7 |
| 10 | NOISE 阶段不读邻居区块的方块，可以并行 | 2、10 |

## 动手练习（由易到难）

**练习 1：竖直剖面。** 实现 `depth(y) = g(y) + c`，对不同的 `c` 画剖面线，确认地表高度 ≈ `63.5 + 128 · (c + 0.50375)`。
验收：图与第 5 页的图 03 一致。

**练习 2：Hermite 样条。** 实现带斜率的 `Spline`，支持常数和嵌套样条，支持线性外推；加载 `offset.json` 做单元测试。
验收：1000 个随机输入，与 JSON 的差 < 1e-5。

**练习 3：`sloped_cheese`。** 用练习 2 的样条构建 `offset / factor / jaggedness`，加上 `base_3d_noise`（可以用任意 3D Perlin，幅度调到 ±0.3），画 x–y 剖面。
验收：`factor = 6 / 3 / 1.5 / 0.7` 的四张剖面与图 07 上排趋势一致；去掉 `quarter_negative` 后悬挑明显减少。

**练习 4：`FlatCache` + `Interpolated`。** 为区块做 5×5 的二维缓存和 5×5×49 的角点数组，做三线性插值填充。统计：密度函数调用次数、与逐方块结果的差异方块比例。
验收：调用次数下降到约 1/80，差异比例 < 1%。

**练习 5：`range_choice` 洞穴。** 实现 cheese 洞穴并用 `range_choice` 当闸门。
验收：浅层和空中没有洞穴噪声调用（用计数器验证）；洞穴剖面类似图 14。

**练习 6：群系。** 实现 `ParameterPoint` 与 `fitness`，6~10 个群系，群系网格 4×4×4，查询时做 8 角抖动取最近。
验收：边界参差自然（图 18 右）；`continents` 低的地方一定是海洋群系。

**练习 7：地表规则。** 实现 `sequence / condition / block` 与 `stone_depth`、`biome`、`y_above` 三个条件，加惰性缓存。
验收：山顶、洞穴顶、洞穴底的“表层三格”规则一致。

**练习 8：并行。** 把练习 4 的角点密度改成 `IJobParallelFor`，把练习 3 的样条数据放进 `NativeArray`。
验收：同一种子，单线程与多线程结果逐字节相同；多线程耗时显著下降。

**练习 9：结构。** 用 `random_spread` 给小房子决定起点（`f(种子, 格子坐标, 盐)`），房子存成“方块位置列表”，落地时只写落在当前区块内的部分；再用一个 2D 玩具做 Jigsaw 拼图（见第 12 页图 21）。
验收：房子跨区块边界时拼起来无缝；同一种子无论区块生成顺序如何，房子位置不变。

**练习 10：计划刻与流体。** 实现 `Schedule(pos, delay)` 的最小堆（同位置去重）、`neighborChanged` 的队列化通知，再用 `amount` 模型做水（`tickDelay = 5`，`dropOff = 1`）。
验收：平地上的水流出 7 格（对照第 13 页图 22）；拿走水源后下游依次萎缩；稳定的水面不消耗任何计算。

**练习 11：刷新。** 做一个漏斗式刷新：类别上限 → 区块过滤 → 随机点 → 距离 / 光照 / 地面检查 → 按权重抽取。加一个消失规则（远处立即消失、近处不消失）。
验收：玩家周围 24 格内不刷新；上限能随“可刷新区块数”缩放；单次尝试的成本与区块里的合法位置数无关。

**练习 12：光照。** 先做方块光的洪水填充；再加“先减少、后增加”的两条队列；再把放置 / 破坏方块只记录位置、帧末批量处理；最后加天空光的“每列最低光源高度”。
验收：对照第 15 页图 24，砌墙 / 拿走火把的结果与队列处理次数一致；批量处理比逐格处理少得多；开阔平原不把天空光逐格传播。

**练习 13：客户端网格（第 16 页）。** 给 16³ 的段做面剔除：邻居用 1 格边界的快照；平滑光照取四格平均；段网格的 `VisGraph` 用 36 位位集（先在 2D 玩具里做 9×9 个段）。
验收：段边界无缝；对照第 16 页图 25，三个相机位置剔除掉的段一致。

**练习 14：区块等级（第 17 页）。** 写 `level = 31 + 切比雪夫距离`，按等级决定目标 `ChunkStatus`；用按等级分桶的队列调度，玩家移动时把变化的区块换桶；每帧限量卸载。
验收：玩家静止时队列最终为空；玩家瞬移时由近及远展开；每帧卸载数不超过上限。

**练习 15：造型函数（第 18 页）。** 先做矿脉（线段上的球串 + `BitSet` 去重，`size = 17` 的方块数分布约 16~29），再做 `Straight` 树干 + `Blob` 叶片，最后用势场加阈值做一个晶洞。
验收：矿脉方块数分布与第 18 页图 30 一致；同一种子重复放置结果完全相同。

**练习 16：下界与末地（第 19 页）。** 下界：一个 `BlendedNoise` 加 `slide(0.9375, 2.5)` 封顶封底，海平面 32 以下填岩浆；末地：实现 `end_islands`（主岛圆锥 + 25×25 候选岛的 `max`）。
验收：下界顶部与底部为实心；末地半径 1024 格内只有主岛，之外有成团的岛，整体分布与第 19 页图 35 一致（想逐点对照游戏，需要在游戏里用同一个种子核对，专栏没有做过）。

**练习 17：扩散与爆炸（第 20 页）。** 做随机刻（每段每帧抽 N 个方块）驱动的草蔓延；用预约刻堆做叶子距离重算；用 1352 条射线做爆炸，对比泥土 / 石头 / 黑曜石里的坑。
验收：爆炸在泥土里半径 4 平均炸掉约 240 格，石头约 27 格，黑曜石 1 格（含爆心）；砍掉原木后叶子陆续消失，不会同一刻全部消失。

## 常见误区

| 误区 | 正确理解 |
| --- | --- |
| `offset` 样条的第三个输入是原始 `ridges` | 是折叠后的 `ridges_folded`（第 4 页） |
| `FinalDensity = SlopedCheese + Base3DNoise` | 这个和是 `sloped_cheese`；真正的 `final_density` 还有 `slide`、洞穴、`squeeze`、`noodle`（第 5、6 页） |
| 洞穴和地形并列做 `min` | 洞穴在 `range_choice` 的深层分支里，浅处不算（第 6 页） |
| `ChunkStatus` 的 `range` 是“写多远” | 它是“启动前要求周围多大范围的区块到达什么状态”（第 2 页） |
| `Marker` 自带逻辑 | 它只是编译用的记号，`compute` 只转发（第 3 页） |
| `BlendedNoise` 的混合系数在 [0,1] 之内 | 约 86% 的点在区间之外，所以大多数时候是在 `min` / `max` 里硬选一个（第 7 页） |
| `quarter_negative` 是为了防止悬崖 | 恰恰相反：它让空气侧更松，噪声能撑出实心，才有悬崖、拱门（第 5 页） |
| 用绝对高度决定“表层三格泥土” | 用 `stone_depth`（离空气的距离），山顶和洞穴同样适用（第 9 页） |
| 噪声的 `amplitudes` 为 0 只是权重为 0 | 对应的 `ImprovedNoise` 根本不创建，求值直接跳过（第 7 页） |
| 随机数每次调用 `Random.Next` | 要从“种子 + 名字/坐标”派生，才与顺序无关（第 2、7 页） |
| 矿脉的方块数等于 `size` | `size` 是球串长度，实际方块数约 16~29（`size = 17`）（第 18 页） |
| 下界和末地用另一套生成引擎 | 同一套 `NoiseChunk`，只是配置和路由不同（第 19 页） |
| 爆炸威力随半径线性增长 | 取决于周围方块的抗性：石头里几乎不随半径变化（第 20 页） |
| 叶子衰减是每片叶子都在随机刻里检查 | 只有距离为 7 的叶子才进随机刻（第 20 页） |

## 综合自测

1. 一个 `y = 90` 的方块，在 `factor = 4`、基础地表 `y = 85`（`offset` 对应 85）的柱子上，大概率是实心还是空气？如果 `factor = 0.7` 呢？
2. 为什么海岸线附近要把 `factor` 调大？
3. 画出 `final_density` 的顶层结构，并指出哪些部分在 cell 角点求值、哪些部分逐方块求值。
4. `range_choice` 的闸门阈值 1.5625 对应的 `squeeze(0.64·x)` 输出恰好是多少？为什么它和 `squeeze` 的饱和点重合？
5. 区块 A 在 `CARVERS` 阶段要读哪些区块？为什么是这个范围？
6. 群系查表为什么用“区间距离的平方和”，而不是欧氏距离到某一个点？
7. 说出三种让 `min(a, b)` 不去求值 `b` 的情形。
8. 给定 `size_horizontal = 2`，cell 宽度是多少？每个区块的角点数怎么变？

参考答案：

1. 地表之上 5 格，`factor = 4` 时空气侧每格密度只变化 `4 × 0.0078 × 1 ≈ 0.031`，5 格约 -0.16，噪声 ±0.3 有可能翻成实心，所以不确定但偏空；`factor = 0.7` 时每格 0.0055，5 格才 -0.027，是否实心几乎只取决于噪声的符号，约各占一半，因此容易出悬挑。
2. 大 `factor` 让地表几乎不受 3D 噪声影响，海滩更平整。
3. `min(squeeze(0.64 × interpolated(blend_density(slide(range_choice …)))), noodle)`；`interpolated` 内的整棵子树只在角点求值；`× 0.64`、`squeeze`、最外层的 `min`，以及 `beardifier` 的加和，在 `cacheAllInCell` 填 cell 时逐方块求值。
4. `0.64 × 1.5625 = 1`，`squeeze` 的 `clamp(-1,1)` 正好在输入为 1 时饱和。两个数互为倒数，很可能是有意的设计，但源码没有说明。
5. 以它为中心 17×17 个区块（±8），因为洞穴起点最远可在约 7 个区块外，隧道最长 112 格。
6. 参数点是一个“盒子”（区间乘积），目标点落在盒子里距离为 0；用平方和是对盒外偏离的惩罚，同时比开根号更省，也便于 R-Tree 剪枝。
7. 左边的值小于 `b.minValue()`；`b` 的区间下界已经大于 `a` 的区间上界；这个 `min` 本身位于没有被选中的 `range_choice` 分支里，整个 `min` 都不会被求值。
8. `cellWidth = 8`；每区块水平方向 2+1 = 3 个角点，角点数是 3 × 3 × 49 = 441（垂直方向不变）。
