## 要点

所有优化归结为三个方向：

| 方向 | 思路 | 代表手段 |
| --- | --- | --- |
| **少算** | 同样的结果不重复算，变化慢的东西不逐点算，用不到的分支不算 | cell 插值、四种缓存、区间短路、闸门、提前退出 |
| **分开算** | 把依赖拆清楚，互不依赖的部分并行 | 共享不可变函数图 + 区块私有缓存、`ChunkStatus` 依赖金字塔、后台线程池 |
| **存得省** | 变化缓慢或重复的数据用更粗或更紧凑的形式保存 | 群系 4×4×4 网格、`PalettedContainer`、高度图增量更新 |

一个贯穿始终的事实：**一个 16×16×384 的区块有 98304 个方块，但真正“昂贵”的密度函数只在 1225 个角点上求值，约少 80 倍。**其余所有优化都是围绕这个核心展开的。

## O1：cell 角点三线性插值

![区块里的 cell 格点](/qmx-Gameknowledge/assets/mc-source/15-chunk-cell-lattice.png)

主世界的噪声设置是 `size_horizontal = 1`、`size_vertical = 2`，`NoiseSettings` 里 `cellWidth = QuartPos.toBlock(1) = 4`、`cellHeight = QuartPos.toBlock(2) = 8`。一个区块被切成 4 × 48 × 4 个 cell，每个 cell 是 4×8×4 个方块。

| 做法 | 每区块密度图完整求值次数 |
| --- | --- |
| 逐方块 | 16 × 16 × 384 = **98 304** |
| 只在 cell 角点 | (4+1) × (48+1) × (4+1) = **1 225**（少约 80 倍） |

角点之间用线性插值：先沿某一轴，再沿另一轴，最后第三个轴，一共 7 次 `lerp`。

![逐方块 vs cell 插值](/qmx-Gameknowledge/assets/mc-source/10-cell-interpolation.png)

这张图用移植算法算了同一块 96×192 的剖面：左边每格都算，第二幅只在 4×8 的角点算再插值，红点是角点；第三幅是两者判定不同的方块（红），只有 **0.43%**，而且只出现在地表等值线附近；最右是插值后的密度场，黑线是 0 等值线，在角点之间线性变化。

### 为什么这样可行，以及它的前提

插值的前提是：**被 `interpolated` 包住的函数在 cell 尺度（4×8×4）内变化平缓**。地形密度满足这一点，因为组成它的东西都是低频的（样条输出、`depth` 渐变、`BlendedNoise` 的主能量集中在几十到上百格的波长）。

反过来也要注意：插值发生在 `min / max / range_choice` 等“折角”运算**之后**，所以这些运算产生的尖角会被抹平（图 14 里洞穴边缘变圆）。游戏接受这种误差，因为它只改变边缘 1~2 格，不会改变整体形状。

这也回答了你笔记里的采样频率问题。`BlendedNoise` 里频率每翻一倍，贡献的振幅就减半（源码里低频层的权重是高频层的 2^r 倍），所以能量主要集中在长波长；超过 Nyquist 极限（4 格间距对应波长 8 格）的成分占比很小，插值后被抹平的只是这部分细节。你在规划里把 octave 从 4 层降为 3 层，做的是同一件事：**噪声的最高频率要与 cell 尺寸匹配**。

### 两条插值路径

`NoiseChunk` 里实际有两条使用插值的路径，都建立在“角点 slice”上：

1. **增量路径**：`doFill` 里依次调用 `updateForY / updateForX / updateForZ`，每层循环只更新受影响的中间值（Y 最外、Z 最内）。矿脉等 `interpolated` 节点走这条路。
2. **整个 cell 一次性填满**：`finalDensity` 被 `cacheAllInCell` 包着。每次 `selectCellYZ` 选定一个 cell，就对这个 cell 的 128 个方块各算一遍“最终密度”（这时 `Interpolated` 直接对 8 个角点做 `lerp3`），把结果存进数组；之后 `doFill` 读的、含水层读的、矿脉读的，都是同一份。

## O2：相邻 cell 共享角点

相邻的两个 cell 共用一整面角点：水平方向 5 个（z）× 垂直方向 49 个（y）。`NoiseChunk` 保存两层 YZ 平面 `slice0`、`slice1`，每层 5 × 49 个值：

```java
initializeForFirstCellX();           // 填 slice0
for (cellX in 0..3) {
    advanceCellX(cellX);             // 填 slice1（下一层 x 的角点）
    for (cellZ ...) for (cellY ...) {  // 这一列 cell 用 slice0 与 slice1 的角点
        selectCellYZ(cellY, cellZ);
        ...
    }
    swapSlices();                    // slice1 变成 slice0，复用同一块内存
}
```

整个区块共填 5 层 slice，每个角点只算一次。如果每个 cell 各自重算 8 个角点，需要 768 × 8 = 6 144 次，共享后是 1 225 次，又少约 5 倍。

## O3–O6：五种缓存标记

函数图里有五种 `Marker`，`NoiseChunk.wrapNew` 会把它们换成不同的缓存对象。它们回答的是同一个问题：**这个子树的值，在哪个“范围”内是可以复用的？**

| 标记 | 复用范围 | 实现 | 典型用法 |
| --- | --- | --- | --- |
| `Interpolated` | 一个 cell 内用角点插值代替求值 | `NoiseInterpolator`：两层 5×49 的 slice | `final_density` 的主体项（`blend_density(slide(…))`；`× 0.64`、`squeeze`、与 `noodle` 的 `min` 在它外面）、`noodle` 的 4 个噪声、矿脉的 3 个噪声（共 8 个 `Interpolated` 节点） |
| `FlatCache` | 与 y 无关的函数，整个区块只在 5×5 个 quart 点上预先算好 | 构造时就把 `(noiseSizeXZ+1)²` = 25 个点算完，之后按 `(x>>2, z>>2)` 查表；表外的点退回直接求值 | `continents / erosion / ridges / shift_x / shift_z / offset / factor / jaggedness` |
| `Cache2D` | 同一列 (x,z) 上连续多次求值只算一次 | 只记住上一次的 `(x,z)` 与结果 | 叠在 `FlatCache` 里面，作为表外点的退路；以及 `factor` 的单列重复访问 |
| `CacheOnce` | 同一个点被多个父节点引用时只算一次 | 用计数器（单点用 `interpolationCounter`，批量用 `arrayInterpolationCounter`）判断“是否还是同一个点” | `lerp` 的混合系数、`spaghetti_roughness`、`entrances`、`pillars` |
| `CacheAllInCell` | 一个 cell 内 128 个方块的结果一次性算完存数组 | 选中 cell 时 `fillArray` 填满，之后按 `(inCellX, inCellY, inCellZ)` 读 | `final_density + beardifier` |

几个细节：

- **`FlatCache` 与 `Interpolated` 对象是互补的**：前者只在水平方向上预算，所以 y 无关的部分（样条）整个区块只算 25 次，而不是在 1225 个角点上各算一次（再少 49 倍）。这是为什么样条这种“重量级”函数几乎不占时间。
- **`CacheOnce` 来自“同一个节点被引用多次”的场景**。例如 `DensityFunctions.lerp(f, a, b)` 要算 `a·(1−f) + b·f`，`f` 出现两次，所以内部先把 `f` 包进 `cacheOnce`：
  ```java
  DensityFunction f2 = cacheOnce(f);
  return add(mul(a, add(mul(f2, constant(-1)), constant(1))), mul(b, f2));
  ```
- **缓存对象是区块私有的**。`wrapped` 这个 `HashMap<DensityFunction, DensityFunction>` 保证同一个节点在同一个区块里只包装一次，因此多处引用同一子树时共享同一个缓存。
- 每种标记都有自己的“范围边界”，**越界就退回直接求值**，不会出错，只是慢。例如 `CacheAllInCell` 在 `functionContext != NoiseChunk.this`（有人拿了一个外部坐标来问）时，直接调用 `noiseFiller.compute`。

## O7：区间短路与闸门

第 3 页讲过 `Ap2.compute` 的短路，第 6 页讲过 `range_choice` 的闸门，这里汇总它们的效果：

| 位置 | 机制 | 节省了什么 |
| --- | --- | --- |
| `min(地形, noodle)` | 左边的值已经小于 `noodle.minValue()` 就不算右边 | 4 个 `noodle` 噪声 |
| `max(洞穴, pillars)` | 左边已经大于 `pillars.maxValue()` 就不算右边 | 柱子噪声 |
| `mul(0, x)` | 左边为 0 就不算 `x` | 整棵 `x` |
| `range_choice(sloped_cheese, …, 1.5625)` | 只走一个分支 | 浅层和空中完全不算 cheese / spaghetti / pillars |
| `yLimitedInterpolatable` | 包一层 `range_choice(y, 范围, 噪声, 0)` | 矿脉噪声只在 y -60 ~ 50（两种矿脉范围的并集）求值，`noodle` 只在 y -60 以上 |

共同的想法：**用一个廉价量（区间上下界、深度计、y 坐标）决定要不要执行昂贵的分支。**

## O8：噪声层面的提前退出

- `BlendedNoise`：`q ≤ 0` 或 `q ≥ 1` 时只算 `min` 或 `max` 其中一组 16 层。实测约 86% 的点命中，40 层平均省三分之一（第 7 页）。
- `PerlinNoise`：`amplitudes[i] == 0` 的层根本不创建、不求值。
- `wrap`：不是性能优化，是精度保护（大坐标下避免 `double` 丢精度）。

## O9：共享不可变函数图，区块私有缓存

这是整套架构里最有价值的设计之一（第 3 页讲过编译阶段）。把“逻辑”和“状态”分开后：

| | 全局共享（只读） | 区块私有（可写） |
| --- | --- | --- |
| 内容 | 函数图结构、噪声实例（`NormalNoise`）、样条 | `NoiseInterpolator` 的 slice、`FlatCache` 的 5×5 表、`Cache*` 的计数器、含水层缓存 |
| 创建时机 | 世界加载时一次 | 每个区块的 `NoiseChunk` 构造时 |
| 线程安全 | 只读，无需加锁 | 只属于一个任务，无需加锁 |

多线程生成因此不需要互斥：每个线程拿着只读的图，加上自己的缓存，互不干扰。

## O10：依赖金字塔与后台线程池

`fillFromNoise` 把 `doFill` 放进 `CompletableFuture.supplyAsync(..., Util.backgroundExecutor())`。能这么做的原因是 `NOISE` 阶段不读邻居的方块（第 2 页）。后面需要邻居的阶段（`CARVERS`、`FEATURES`）则由 `ChunkStatus` 的 `STATUS_BY_RANGE` 保证“邻居先到哪个状态”。

任务排队用 `ChunkTaskPriorityQueueSorter`，按区块的加载等级（离玩家越近等级越高）排优先级。

## O11：群系的粗网格与搜索起点

- 群系只算、只存 4×4×4 一个（比方块少 64 倍），查询时再用抖动放大（第 8 页）。
- 群系查找用 R-Tree，并以**上一次的结果作为起点**做分支限界，相邻位置几乎立刻命中。
- 气候场里的 `continents / erosion / ridges`（以及 `temperature / vegetation` 内部的 `shift_x / shift_z`）与地形共用 `FlatCache`，不重复采样。

## O12：地表规则

- 条件对象带时间戳缓存，XZ 条件一列算一次（第 9 页）。
- `abovePreliminarySurface` 用初步地表跳过深处的整套群系规则。
- 每一段连续石头只向下扫描一次（`stoneDepthBelow`），而不是每个方块都扫。

## O13：含水层

- 只对密度 ≤ 0 的方块起作用，实心方块完全不进入。
- 候选中心按网格索引缓存（`aquiferLocationCache`），同一个中心不重复生成随机数。
- `barrier` 噪声用 `MutableDouble` 懒计算，只在需要判断压力时才求值。
- 全局默认流体（`globalFluidPicker`）直接用海平面和 -54 判断，没有噪声。

## O14：存储

- `PalettedContainer`：全是石头的段只存一个值；种类少用线性调色板，多了才升级为哈希调色板，最后才是全局表（第 2 页）。
- 高度图：`doFill` 每写一个方块就顺手 `heightmap.update`，后面的 SURFACE 不用再找最高点。
- 写入的最小单位是 16³ 的段（`LevelChunkSection`），段级别可以加锁、检测并发。

## 一套通用的“找优化点”方法

把这些手段抽象一下，你可以对自己函数图里的**每一个子树**问五个问题：

| 问题 | 如果答案是“是” | 对应手段 |
| --- | --- | --- |
| 它只依赖 (x,z) 吗？ | 不要在 y 方向重复算 | `FlatCache`（25 个点），样条、气候场都属于此类 |
| 它在 4~8 格内变化平缓吗？ | 只在稀疏网格上算，其余插值 | `Interpolated`（角点） |
| 它会被多个父节点用到吗？ | 同一个点只算一次 | `CacheOnce`、共享缓存对象 |
| 它的结果经常用不上吗？ | 用廉价量把它关在门后 | `range_choice` 闸门、区间短路、`yLimitedInterpolatable` |
| 它的内部是否有“已经足够”的信号？ | 提前退出 | `BlendedNoise` 的 `q`、零振幅跳过 |

以及两个架构层面的问题：

1. 哪些数据是**只读共享**的，哪些是**必须私有**的？分开以后并行就没有锁。
2. 每个阶段**需要邻居的什么**？依赖越清楚，能并行的东西越多。

## 映射到 Unity：Job + Burst 的做法

下面是把这些手段落到 Job System 的一个草图。具体 API 细节见知识库的“Unity-Job与Burst”系列，尤其是“03-项目实践/03-Cell插值与同号填充Job”。

| 步骤 | 数据结构 | Job |
| --- | --- | --- |
| ① 2D 低频场 | `NativeArray<float>`，每个区块 5×5（或再大一圈） | `IJobParallelFor`，25 个任务；在这里求 `continents/erosion/ridges` 和三棵样条 |
| ② 角点密度 | `NativeArray<float>`，5×5×49 = 1225 | `IJobParallelFor`，一个任务一个角点；读 ① 的结果 + 3D 噪声 + `depth` |
| ③ cell 插值与填充 | `NativeArray<byte>`（16×16×384） | `IJobParallelFor` 按 cell 并行；读 ② 的角点；做“同号快速填充”或 `lerp3` |
| ④ 地表规则 | 同上 | `IJobParallelFor` 按列并行；读高度图 |
| ⑤ 网格构建 | `NativeList<float3>` 等 | 按区块并行，主线程最后提交 `Mesh` |

几个要点：

- **函数图不要放进 Job**。托管对象、虚调用、`Dictionary` 都不适合 Burst。更实际的做法是把“图”展开成写死的 Burst 函数（用 `mathematics`），用 `struct` 保存参数；`Marker` 的作用由你手动安排的“阶段”（①②③）代替。
- 缓存层变成**数组的生命周期**：25 个点的数组、1225 个角点的数组，每个区块一份，用完回收，对应“区块私有缓存”。
- 噪声参数、样条控制点放进 `NativeArray`/`BlobAssetReference`，对应“共享只读”。

## 小结

- 核心：98 304 次 → 1 225 次，其余所有手段围绕它展开，或者让每次求值更便宜。
- 五类缓存分别对应五种“复用范围”：角点、列、点、cell、网格。
- 短路和闸门用廉价量关住昂贵分支；`BlendedNoise` 用 `q` 提前退出。
- 共享只读图 + 区块私有缓存，让并行不需要锁。
- 你的优化清单与 MC 高度吻合；其中“同号 cell 快速填充”是 MC 没做、但完全成立的额外优化。

## 自测

1. 98 304 与 1 225 是怎么得到的？
2. `FlatCache` 为什么能比在角点上直接求样条再省 49 倍？
3. `CacheOnce` 和 `Cache2D` 的区别是什么？
4. 为什么并行不需要给函数图加锁？
5. “同号快速填充”为什么不会改变结果？

参考答案：① 16×16×384；(4+1)×(48+1)×(4+1)。② 样条与 y 无关，一个区块只需 5×5 = 25 个点，而角点有 1225 个，1225 / 25 = 49。③ `Cache2D` 以“同一列”为范围；`CacheOnce` 以“同一个点”为范围（被多个父节点引用时才有用）。④ 图是只读的，所有可写状态都在区块私有的缓存对象里。⑤ 三线性插值是 8 个角点值的加权平均，权重非负且和为 1；若 8 个值全为正（或全不为正），结果必然同号，所以整个 cell 的实/空判定不变（若还要保存密度值本身则不能省）。
