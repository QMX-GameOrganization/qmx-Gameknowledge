## 要点

- 样条解决的问题是：**让一个输出量按照“我指定的形状”随输入变化**，同时保持平滑。比如“大陆性越低越像海底、中间是海岸、越高越内陆”，这不可能靠一个线性公式表达。
- Minecraft 用的是**带导数的三次 Hermite 样条**：每个控制点是 `(位置, 值, 斜率)`，段内用三次曲线连接。
- 样条可以**嵌套**：一个控制点的“值”本身可以是另一条样条，于是 2 个、3 个、4 个输入的函数都能用同一套结构搭出来。
- `TerrainProvider` 用三棵这样的嵌套样条，把三个低频场（`continents / erosion / ridges`）变成三个地形参数：`offset`（地表高度）、`factor`（陡峭度）、`jaggedness`（山顶锯齿）。
- 样条求值比较贵（嵌套 3 层、要二分查找），所以它的输出总是被 `flat_cache` 缓存，**每 4×4 格才算一次**。

## 样条的公式

![样条基础：折线、斜率的影响、嵌套](/qmx-Gameknowledge/assets/mc-source/04-spline-basics.png)

左图：同样的三个点，折线（灰）和三次样条（蓝、红）。折线在控制点处有折角；蓝线把每点斜率取 0，所以每个控制点都是“平台”；红线给了斜率，曲线更自然。

### 一段的求值

设相邻两个控制点是 `(x₀, a, d₀)` 和 `(x₁, b, d₁)`，`a, b` 是值，`d₀, d₁` 是斜率。令：

```text
Δx = x₁ − x₀
t  = (x − x₀) / Δx        // 归一化到 [0,1]，样条不直接用 x
p  = d₀·Δx − (b − a)
q  = −d₁·Δx + (b − a)
f(x) = lerp(t, a, b) + t·(1 − t)·lerp(t, p, q)
```

这就是源码 `Multipoint.apply` 里的那一行 `Mth.lerp(k, n, o) + k * (1.0F - k) * Mth.lerp(k, p, q)`。

它和标准的三次 Hermite 多项式完全等价。你笔记里推出来的

```text
f(t) = [m₀ + m₁ − 2Δ]t³ + [3Δ − 2m₀ − m₁]t² + m₀t + y₀      // m₀ = d₀·Δx, m₁ = d₁·Δx, Δ = b − a
```

展开后和上式一致。源码采用“线性插值 + 修正项”的写法（源码没有说明选择它的理由），它只需要几次 `lerp` 和一次乘法。

### 段之外：线性外推

```java
// Multipoint.apply（简化）
i = findIntervalStart(locations, x);        // 二分查找：最后一个 location <= x
if (i < 0)           return linearExtend(x, locations, value[0], derivative, 0);
if (i == last)       return linearExtend(x, locations, value[last], derivative, last);
// 否则走上面的 Hermite 公式

linearExtend: derivative == 0 ? value : value + derivative * (x - location)
```

最左点之前和最右点之后，沿**端点的斜率**直线延伸；斜率为 0 就是常数。所以在 `continents < -1.1` 时，`offset` 样条的第一段（斜率 0）会保持常数 0.044，而不是无限增长。

### 斜率是怎么起作用的

看上面那张图的中间一幅：同样两个点 `(0,0)`、`(1,1)`，换不同的斜率就是不同的曲线。常用的几种意图：

| 想要的形状 | 斜率设置 |
| --- | --- |
| 平台（一段高度基本不变） | 两端斜率 0 |
| 平滑地穿过某点 | 取前后点的割线斜率 |
| 悬崖（短距离内突变） | 把两个控制点的 location 靠得很近、值差很大（如 `offset` 样条在 `-0.18` 与 `-0.16` 之间） |
| 山脊（先快后慢再快） | 端点给较大的正斜率，中间点斜率较小 |

`TerrainProvider.ridgeSpline` 里就是按这个套路写的：`l = max(0.5·(g−f), k)`、`m = 5·(h−g)` 这样的斜率，本质是“从相邻值估一个合理的坡度，再给一个下限避免过平”。

## 嵌套样条：值本身也是样条

上图右幅：外层样条以 `continents` 为坐标，有三个控制点（0.0、0.5、1.0），**每个控制点的值是一条以 `erosion` 为坐标的内层样条**。求值分两步：

1. 先确定 `continents` 落在外层哪一段，比如 0.25 在 `[0.0, 0.5]`；
2. 求出这一段两端的内层样条在**当前 erosion** 上的值 `a`、`b`，再用上面的 Hermite 公式把它们混合。

所以 `continents = 0.25` 的那条曲线（绿色虚线）不是两条内层曲线的简单平均，而是按外层斜率做的平滑混合。这一点在源码里只是一行：

```java
float n = value(i).apply(ctx);        // 内层样条（或常数）在当前点的值
float o = value(i + 1).apply(ctx);
// 再套 lerp(t, n, o) + t(1-t)·lerp(t, p, q)
```

`DensityFunctions.Spline` 把样条的“坐标”换成了**密度函数**（`Spline.Coordinate` 持有一个函数引用），于是外层坐标可以是 `continents` 这样的低频场，内层可以是 `erosion`、`ridges`……层数不限。

## TerrainProvider：三棵样条的结构

输入有四个量（都是 2D 的低频场，只依赖 x、z）：

| 名字 | 来源 | 含义 | 大致取值 |
| --- | --- | --- | --- |
| `continents` | 噪声 `continentalness` | 海 ↔ 陆 | -1.2 ~ 1.0，越小越像深海 |
| `erosion` | 噪声 `erosion` | 侵蚀度：-1 山地 ↔ +1 平坦 | -1 ~ 1 |
| `ridges`（weirdness） | 噪声 `ridge` | 原始“怪异度” | -1 ~ 1 |
| `ridges_folded` | `-3·(\| \|ridges\|−2/3 \| − 1/3)` | 山谷 ↔ 山峰 | -1（山谷）~ 1（山峰） |

![ridges 折叠成山谷—山峰](/qmx-Gameknowledge/assets/mc-source/02-ridges-folded.png)

折叠只有一个目的：**让“山谷”和“山峰”在噪声空间里成为两个对称的、连续的区域**。原始噪声 `ridges` 在 0 附近折叠值为 -1（山谷），在 ±2/3 附近为 +1（山峰），到 ±1 变成 0（坡面）；折叠后一个数就能直接表示“有多像山峰”。

三棵样条的输入各不相同：

| 样条 | 坐标（外层 → 内层） | 输出的含义 |
| --- | --- | --- |
| `offset` | `continents` → `erosion` → `ridges_folded` | 基础地表高度偏移 |
| `factor` | `continents` → `erosion` → 内层按分支用 `ridges` 或 `ridges_folded` | 垂直方向的“硬度”：越大地形越平 |
| `jaggedness` | `continents` → `erosion` → `ridges_folded` → `ridges` | 山顶锯齿的强度 |

注意 `offset` 用的是**折叠后的** `ridges_folded`，不是原始 `ridges`。（你之前笔记里写的 `Spline(Continents, Erosion, Ridges)` 里，`Ridges` 实际指折叠后的版本。）

### offset：外层 continents 的结构

`overworldOffset` 的外层按 `continents` 排了 10 个控制点：

```java
.addPoint(-1.1F,  0.044F)    // 比最深的海还深：常数
.addPoint(-1.02F, -0.2222F)  // ┐ 海底：平坦，-0.2222
.addPoint(-0.51F, -0.2222F)  // ┘
.addPoint(-0.44F, -0.12F)    // ┐ 近海：-0.12
.addPoint(-0.18F, -0.12F)    // ┘
.addPoint(-0.16F, spline1)   // ┐ 海岸线：值变成内层样条（陡升）
.addPoint(-0.15F, spline1)   // ┘
.addPoint(-0.1F,  spline2)   // 沿海平原
.addPoint(0.25F,  spline3)   // 内陆（含山地）
.addPoint(1.0F,   spline4)   // 最内陆
```

样条输出到真实高度的换算很直接：**基础地表 y ≈ 63.5 + 128 × offset**（推导见下一页）。于是：

| continents 区间 | 样条值 | 基础地表高度 | 含义 |
| --- | --- | --- | --- |
| -1.02 ~ -0.51 | -0.2222 | y ≈ 35 | 深海海底（再往左 `< -1.1` 是常数 0.044，约 y ≈ 69，对应蘑菇岛一带） |
| -0.44 ~ -0.18 | -0.12 | y ≈ 48 | 浅海 |
| ≈ -0.16 | 内层样条 | 随 erosion、ridges 变化 | 海岸线，在这里“海底”过渡到“陆地” |
| > 0 | 内层样条，叶子值最高 1.5 | 最高约 y ≈ 255 | 平原到高山 |

## 用图读懂 offset

![offset 随 continents 的变化](/qmx-Gameknowledge/assets/mc-source/05-offset-by-continents.png)

三幅图分别固定 `weirdness` 为山谷（0）、坡面（0.33）、山峰（0.667），每条线对应一个 `erosion`。右轴把 offset 换算成基础地表高度。可以读出几件事：

1. **海域（continents < -0.18）三条线完全重合**：海底是 -0.2222 → -0.12 的两级台阶，不受 erosion 和 ridges 影响。海洋的地形是“平”的，起伏只来自 3D 噪声。
2. **在 continents ≈ -0.16 处出现近乎垂直的跳变**（山峰图里从 -0.12 一下跳到 0.5~0.7）。因为 `-0.18` 与 `-0.16` 两个控制点只差 0.02，值却差很大，这就是“海岸悬崖”的来源。
3. **erosion 高（蓝、紫线）时曲线几乎是平的**，基本停在 0 附近，即基础地表接近海平面（y ≈ 63）。erosion 低（红、橙线）时，内陆会爬升到 0.2~1.4。
4. **山谷 → 山峰，同一个 erosion 的曲线整体抬升**。比较三幅图里的深红线：山谷最高约 0.35，坡面约 0.9，山峰超过 1.2。

## 用热力图读懂三个输出

![offset / factor / jaggedness 在 (continents, erosion) 平面上的分布](/qmx-Gameknowledge/assets/mc-source/06-terrain-params-heatmaps.png)

上排是山谷，下排是山峰，三列是三个输出（颜色标尺在两排之间统一）。

| 输出 | 图里能读到的规律 | 对地形的影响 |
| --- | --- | --- |
| `offset` | 海区一块块的平台；内陆在低 erosion、山峰处最高 | 决定“这一带基础地表在哪”。山谷与山峰的差距在低 erosion 区最大 |
| `factor` | 海区约 3.95；海岸附近升到约 6.3；内陆多数为 4~5.5；山峰且 erosion 在 0.05~0.55 的一块降到 1~2，最低 0.625 | 值越大，密度随高度变化越陡，3D 噪声越难改变地表（**越平**）；值越小，噪声话语权越大（**越崎岖、越容易出悬崖拱门**） |
| `jaggedness` | 只在“内陆 + 低 erosion + 山峰”出现。最内层样条以原始 weirdness 为坐标：`-0.01` 处取 0.63，`0.01` 处取 0.3，所以负 weirdness 的山峰锯齿更强（图里取的是正的 +2/3，故最大 0.3） | 给山顶叠加细碎的锯齿；其它地方为 0 |

两个值得记住的对比：

- **海岸线附近的 `factor` 最大**，所以海滩与海岸非常平整，不容易被 3D 噪声搞乱。
- **`jaggedness` 在山谷整行都是 0**：锯齿只给山峰，所以平原和河谷不会有尖刺。

## 不用背的东西

读 `TerrainProvider` 时最容易陷进去的是那一堆常数：`0.6F`、`0.46082947F`、`1.17F`、`0.7F`……它们是调参的结果，源码里没有注释说明含义（`buildMountainRidgeSplineWithPoints` 里有几条线性关系，看上去是在约束“山地曲线要穿过哪几个点”）。读代码的正确姿势是只回答三个问题：

1. 这棵样条的坐标是谁？（外层 continents，里层 erosion，最里 ridges）
2. 控制点大致落在哪几个区间？每个区间代表什么地貌？（海底、浅海、海岸、平原、内陆、山地）
3. 输出的单位是什么？（offset：128 格 = 1.0；factor：陡峭度；jaggedness：锯齿幅度）

数值要核对时，直接看数据包里烘焙好的 `offset.json / factor.json / jaggedness.json` 即可。

## 在你的项目里怎么用

1. **从单层开始。** 先做 `offset = spline(continents)`，几个控制点：海底、浅海、海岸、陆地。画出 y 方向的剖面，确认“海—岸—陆”的形状对。
2. **再加第二层 erosion，用热力图验证。** 像上面的图 06 那样，固定 ridges，在 (continents, erosion) 平面上画 offset，看有没有突兀的接缝。
3. **最后加 ridges_folded。** 先做折叠函数，再把它作为第三层坐标。
4. **控制点放进数据。** 用 `ScriptableObject` 或 JSON 存 `(location, value, derivative)`，运行时构建。源码要求控制点 location 必须严格升序（`Builder.addPoint` 会抛异常），你也应该在加载时检查。
5. **缓存。** 嵌套样条每次求值要走几层二分查找，开销可观。样条只依赖 (x,z)，所以应该像 `flat_cache` 一样，每 4×4 格算一次存起来（第 10 页）。

## 小结

- 样条 = 一串 `(位置, 值, 斜率)` 控制点，段内是三次 Hermite 曲线，段外沿端点斜率直线外推。
- 嵌套样条让多个输入共同决定一个输出，同时保持每一维都平滑。
- `offset / factor / jaggedness` 三棵样条把 `continents / erosion / ridges` 翻译成“地表在哪、有多平、有多尖”。
- 读源码只需要抓住结构和单位，常数用数据文件核对。

## 自测

1. 一条样条在最右控制点之后会怎么变化？
2. 为什么 `offset` 外层从 `continents = -0.16` 往右的控制点，“值”是另一条样条？
3. 海岸线附近为什么会出现近乎垂直的跳变？它是 bug 吗？
4. `factor` 越大，3D 噪声对地表的影响越大还是越小？

参考答案：① 沿最右点的斜率直线延伸，斜率为 0 就保持常数。② 因为那一段 continents 区间里，地表高度还要由 erosion 和 ridges 决定，所以值是内层样条。③ 两个控制点 location 差很小、值差很大；是刻意设计，用来做“海岸悬崖”。④ 越小，因为 `factor` 乘在 `depth` 上，越大则密度随高度变化越陡，噪声更难改变地表。
