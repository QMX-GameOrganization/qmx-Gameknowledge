> 对应源码：`levelgen/structure/*`（`Structure`、`StructureStart`、`StructurePiece`、`pools/JigsawPlacement`、`placement/*`、`structures/*`）、`StructureTemplate`、`Beardifier`、`ChunkGenerator.createStructures / createReferences / applyBiomeDecoration`、`ChunkGeneratorStructureState`。数据：`worldgen/structure`、`structure_set`、`template_pool`，以及 `structures/*.nbt` 模板。

## 要点

- “结构”不是一个整体，而是三层东西：**放置规则**（`structure_set`：在哪些区块有起点）、**生成规则**（`Structure`：起点确定后怎么摆出一组 `StructurePiece`）、**落地**（把每个 piece 画进它覆盖的各个区块）。
- 起点在 `STRUCTURE_STARTS` 就决定了，**只确定位置和包围盒**；方块要等到 `FEATURES` 阶段才逐区块画出来。
- 村庄这类大型建筑用 **Jigsaw（拼图）**：一块块模板通过“连接点”拼接，广度优先生长，碰撞用体素形状差集检测。
- 非 jigsaw 的结构（沙漠神殿、要塞、矿井、海底神殿）是各写各的程序化生成，思路大多是“单块固定尺寸”或“递归随机生长”。
- 结构会反过来**修改地形密度**（`Beardifier`），让村庄下面是平地、古城周围被挖空。

## 术语

| 名字 | 是什么 | 例子 |
| --- | --- | --- |
| `Structure` | 一类结构的生成规则 | `village_plains`、`stronghold`、`desert_pyramid` |
| `StructureSet` | 一组候选结构 + 一个放置规则 | `villages`（五种群系村庄，各占权重 1） |
| `StructurePlacement` | 放置规则：`random_spread` 或 `concentric_rings` | spacing 34、separation 8 |
| `StructureStart` | 某个区块上一次具体生成的结果：一组 piece + 总包围盒 | 一座已决定位置的村庄 |
| `StructurePiece` | 结构里的一块（带包围盒，会被画进世界） | 一栋房子 |
| `StructureReference` | “这个区块被哪些结构覆盖”的登记 | 村庄的边缘区块 |
| 模板（template） | 一个 `.nbt` 文件，里面是方块、实体、大小 | `plains_small_house_1` |
| 拼图方块（jigsaw） | 模板里的连接点方块 | 房子门口的接口 |

## 完整链条：一座村庄是怎么出现的

以村庄为例，按 `ChunkStatus` 的顺序：

```text
STRUCTURE_STARTS  对每个区块：
  ① 遍历所有 StructureSet；用放置规则判断“本区块是不是候选起点”
  ② 同一个 set 里有多种结构（五种村庄）：按权重抽一种，失败就移除再抽
  ③ Structure.generate：findGenerationPoint 摆出一组 piece（jigsaw 在这里生长）
  ④ 在起点采样群系，不在该结构允许的群系里就丢弃；piece 为空也丢弃
  ⑤ 合法的 StructureStart 存进区块

STRUCTURE_REFERENCES  以本区块为中心 ±8（17×17）个区块里，
  所有包围盒与本区块相交的 start 登记一条引用

NOISE             Beardifier 读取“覆盖本区块的结构”，把贴合地形的密度加进 final_density

FEATURES          applyBiomeDecoration 里，对每个装饰阶段先放这个阶段的结构：
                  StructureStart.placeInChunk → 只对与本区块可写区域相交的 piece 调 postProcess
```

这里的“±8”正是第 2 页金字塔里 `STRUCTURE_REFERENCES` 邻居半径 8 的来源：**结构的包围盒可以很大，一个区块要知道所有可能覆盖它的结构，必须往外看 8 个区块**。源码里没有解释 8 的具体缘由，但与 `max_distance_from_center` 的上限 128 格（= 8 个区块）吻合。

## 放置规则：结构在哪里有起点

### random_spread

```text
villages:  spacing = 34, separation = 8, salt = 10387312
```

算法（`RandomSpreadStructurePlacement.getPotentialStructureChunk`）：

```java
region = (floorDiv(chunkX, spacing), floorDiv(chunkZ, spacing));     // 世界切成 34×34 区块的格子
random.setLargeFeatureWithSalt(worldSeed, region.x, region.z, salt);
n = spacing - separation;                                            // 26
offset = (nextInt(n), nextInt(n));                                   // 各取一次（linear）；海底神殿等用 triangular：两次 nextInt 取平均
candidate = (region.x * spacing + offset.x, region.z * spacing + offset.z);
isStructureChunk = (candidate == 当前区块);
```

- **每个格子恰有一个候选起点**，所以结构数量与世界大小成正比、永远不会扎堆；
- `separation` 保证相邻格子的候选点至少隔开一定距离；
- `salt` 让不同结构类型的随机序列互不相关；
- 整个判定只依赖 (世界种子, 格子坐标, salt)，**不需要任何邻居信息**，所以每个区块独立判断，结果一致。

### frequency_reduction_method

有的结构还要再“掷一次骰子”降低出现率（`frequency < 1`）。有四种写法：`default`、`legacy_type_1`（掠夺者前哨站）、`legacy_type_2`（埋藏的宝藏，用固定盐 10387320）、`legacy_type_3`（废弃矿井，`frequency = 0.004`）。后三种是为了保持旧世界的结构位置不变。

### concentric_rings（要塞）

要塞不用格子，而是**围绕世界原点的同心环**：`count = 128`、`distance = 32`、`spread = 3`。`ChunkGeneratorStructureState` 在第一次用到时才惰性地一次性算出全部 128 个位置：按环分配数量，每个位置的角度与距离带随机偏移，再用 `findBiomeHorizontal` 在 112 格范围内**吸附到偏好群系**（`preferred_biomes`），找不到就保留原位置。位置只依赖世界种子，所以同样是确定性的。它的特点是“全局规划”：必须先知道全部位置才能知道某个区块是不是起点，所以结果被缓存起来，而不是逐区块独立判断。

### 几个常见结构的参数

| 结构集 | 放置 | 参数 |
| --- | --- | --- |
| `villages` | `random_spread` | spacing 34，separation 8，salt 10387312 |
| `desert_pyramids` | `random_spread` | spacing 32，separation 8，salt 14357617 |
| `ocean_monuments` | `random_spread` | spacing 32，separation 5，salt 10387313 |
| `mineshafts` | `random_spread` | spacing 1，separation 0，frequency 0.004（`legacy_type_3`） |
| `strongholds` | `concentric_rings` | count 128，distance 32，spread 3 |

`mineshafts` 的 spacing 为 1 意味着“每个区块都是候选”，再用 0.4% 的概率筛选。

## Jigsaw：用拼图生成村庄

村庄、前哨站、古城、堡垒遗迹都是 jigsaw 结构。数据由三类 JSON/NBT 组成：

| 数据 | 内容 | 例子 |
| --- | --- | --- |
| `structure/village_plains.json` | 起始池、深度、范围、地形适配 | `start_pool = village/plains/town_centers`，`size = 6`，`max_distance_from_center = 80`，`terrain_adaptation = beard_thin` |
| `template_pool/*.json` | 一个池 = 带权重的元素列表 + `fallback` 池 | `houses.json`：小屋权重 2，`small_house_6` 权重 1 |
| `structures/*.nbt` | 模板：方块调色板、方块列表、实体、大小；含 jigsaw 方块 | `plains_small_house_1` |

每个模板里有若干 **jigsaw 方块**（连接点），带这些属性：`name`（我是谁）、`target`（我想接谁）、`pool`（接上去的候选池）、`joint`（`rollable` 可绕轴旋转，`aligned` 要求上方朝向一致）、`final_state`（拼好后这个方块变成什么，默认空气）。

### 匹配规则

两个连接点能接上，当且仅当：**朝向相反**，并且**源端的 `target` 等于对端的 `name`**；`aligned` 的还要求顶部朝向一致（`JigsawBlock.canAttach`）。

### 生长算法

![Jigsaw 的 2D 玩具模拟](/qmx-Gameknowledge/assets/mc-source/21-jigsaw-toy.png)

上图是一个用相同规则写的 2D 玩具：从广场出发，沿连接点广度优先生长，三幅图的最大深度（`size`）分别是 1、3、6，红色虚线是 `max_distance_from_center`。真实算法（`JigsawPlacement.addPieces`）是：

```java
// 起点
start = 起始池里抽一个模板，随机旋转；放在 chunk 西北角，按 heightmap 贴地（project_start_to_heightmap）
free  = Shapes.create(范围盒: 中心 ± max_distance_from_center)
free  = free 减去 start 的包围盒                   // 体素形状差集：剩下的“可用空间”
queue.add(start)                                   // Deque，removeFirst，所以是广度优先

while (queue 非空):
    piece = queue.removeFirst()
    for 每个 jigsaw 连接点:
        目标点 = 连接点位置 + 朝向
        候选 = 目标 pool 的元素乱序 + fallback 池的元素乱序     // 深度到顶（depth == size）时只用 fallback
        for 候选模板 in 候选，对它的每个旋转：
            for 该模板的每个 jigsaw 连接点:
                if (!canAttach(...)) continue
                newBox = 对齐后的包围盒
                if (free 与 newBox(收缩 0.25) 不冲突):      // 差集检测碰撞
                    放置；free = free 减去 newBox；记录 JigsawJunction
                    if (depth + 1 <= size) queue.add(新 piece)
                    进入下一个连接点
```

几个细节：

- **深度 `size` 限制的是“拼接次数”**，范围 0~7（解码时 `intRange(0, 7)`）。`max_distance_from_center` 限制整体范围，范围是 1~128。
- **碰撞检测用的是 `VoxelShape` 差集**（`Shapes.joinIsNotEmpty(..., ONLY_SECOND)`），而不是逐个 AABB 两两比较，可用空间随放置不断缩小。
- 碰撞用的“可用空间”并不总是全局那一个：若连接目标点落在父 piece 自己的包围盒内，就改用只含父包围盒的私有形状。
- 池里遇到 `EmptyPoolElement`（空元素）就在那一端停止——这是“可选的出口”的写法。
- `use_expansion_hack`：村庄为 true。候选盒在 Y 方向较矮时，会把盒子向上撑高再做碰撞检测，避免房子被上方的东西压住。源码只提供了行为，没有注释意图。
- 起点有 `start_jigsaw_name` 时，用该名字的连接点作为锚点对齐，而不是模板原点。

### 池与元素

| 类型 | 说明 |
| --- | --- |
| `single_pool_element` / `legacy_single_pool_element` | 一个 `.nbt` 模板，可带处理器 |
| `list_pool_element` | 一组元素当成一个整体放置（如“房子 + 周围的装饰”） |
| `feature_pool_element` | 放一个 `PlacedFeature`（如一棵树、一盏灯） |
| `empty_pool_element` | 什么都不放，表示“可选的出口” |

`StructureTemplatePool` 的加权是**把元素按权重重复放进一个列表**再均匀抽取（`weight` 取 1~150），不需要累计权重。每个元素还有 `projection`：`rigid` 表示整块不动，`terrain_matching` 表示按地表逐列调整高度（附带一个 `GravityProcessor`）。

## 模板与处理器

模板文件是 NBT：`palette(s)`（方块状态表）、`blocks`（每个方块的位置 + 调色板下标 + 可选 NBT）、`entities`、`size`。放置时（`StructureTemplate.placeInWorld`）做这些事：

1. 对每个方块先做旋转 / 镜像变换：先按镜像翻转 x 或 z，再绕轴心旋转，方块状态本身也要 `mirror().rotate()`（楼梯、门的朝向要跟着转）；
2. 逐个交给 `StructureProcessor` 链处理（见下）；
3. **只写入落在当前可写包围盒内的方块**，这是跨区块裁剪的实现处：同一个模板会在它覆盖的每个区块各被调用一次，每次只画属于自己的部分。

处理器是一类“方块替换规则”，示例：

| 处理器 | 作用 |
| --- | --- |
| `BlockIgnoreProcessor(STRUCTURE_BLOCK)` | 不要把模板里的结构方块画出来 |
| `JigsawReplacementProcessor` | 把 jigsaw 方块换成它的 `final_state` |
| `RuleProcessor`（如 `street_plains`） | 条件替换：水上的泥土路换成木板，10% 的泥土路换成草方块 |
| `BlockRotProcessor` | 以 `integrity` 的概率保留方块，其余删除，做出“风化”的废墟 |

这套机制让**同一个模板在不同群系复用**：沙漠村庄和平原村庄的房子模板结构相同，只靠处理器把材质换掉。

## 非 jigsaw 结构

| 结构 | 做法 |
| --- | --- |
| 沙漠神殿、女巫小屋、丛林神殿、冰屋 | `ScatteredFeaturePiece`：一个固定尺寸的单块（沙漠神殿 21×15×21，女巫小屋 7×7×9）。包围盒在 `postProcess` 时才根据实际地表高度下移 |
| 要塞 | 递归随机生长（`StrongholdPieces`，`MAX_DEPTH = 50`）：起始 piece 不断从待处理列表里取一个继续长，直到生成了传送门房间，否则换个种子重来 |
| 废弃矿井 | 递归生长（`MineshaftPieces`）：深度超过 8，或 x / z 任一方向离父 piece 超过 80 格就停；每次 `nextInt(100)`：≥80 十字路口，≥70 楼梯，其余走廊 |
| 海底神殿 | 先检查周围 29 格内的群系都满足标签；只放一个 `MonumentBuilding`，内部房间由它自己生长 |

这些结构的共同点是：**piece 的位置在 `findGenerationPoint` 里一次确定，方块在后面的 `postProcess` 里才按区块画**。

## 结构如何改写地形：Beardifier

村庄建在山坡上会悬空，古城建在地下要把周围挖空，这靠 `terrain_adaptation`。取值（1.20.1）：`none`、`bury`、`beard_thin`、`beard_box`。

| 取值 | 用在 | 效果 |
| --- | --- | --- |
| `beard_thin` | 村庄、掠夺者前哨站、下界化石 | 在 piece 下方“垫实”，上方“削掉”，像给建筑加了一圈薄薄的胡须 |
| `beard_box` | 古城 | 整个包围盒内外都被改写，形成盒状空腔 |
| `bury` | 要塞、古迹废墟 | 把 piece 埋进地里 |
| `none`（默认） | 其它 | 不改地形 |

实现在 `Beardifier`（167 行）：

```java
BEARD_KERNEL_RADIUS = 12;            // 影响范围 ±12 格
BEARD_KERNEL = float[24 * 24 * 24];  // 预先算好的 24³ 衰减核，值 = exp(-(距离²)/16)
```

- `forStructuresInChunk` 只收集“离本区块 12 格以内、且 `terrain_adaptation != none`”的结构 piece。参与方式：jigsaw 的 piece 只有 `rigid` 的才作为刚体参与；非 jigsaw 的 piece（如要塞）无条件参与；jigsaw 的连接点（`JigsawJunction`）对所有拼图 piece 都会收集。`terrain_matching` 的 piece 自己会贴地，所以不作为刚体。
- 对一个方块位置，把附近 piece 的贡献累加（`beard_thin / beard_box` 乘 0.8，jigsaw 连接点乘 0.4）。单个贡献为 `−d · invsqrt(e/2) / 2 · kernel`，其中 `d` 是方块相对 piece 地面高度的偏移（+0.5），`e` 是到 piece 水平范围和这个高度的距离平方。**方块在 piece 地面之下时 `d < 0`，贡献为正（密度增加，被垫实）；在地面之上时贡献为负（密度减少，被削空）**；`bury` 则用 `clampedMap(length(水平距离, 垂直距离/2), 0~6, 1~0)`，在 piece 周围水平约 6 格、垂直约 12 格内增加密度，把它埋进去。
- **接入点是第 5、6 页的 `NoiseChunk`**：最终被缓存的函数是 `cacheAllInCell( final_density + beardifier )`。也就是说结构的修正是**逐方块加在插值后的密度上**，不进入 cell 插值，所以不会被“磨圆”。
- 因为需要提前知道哪些结构会覆盖本区块，`NOISE` 阶段才依赖邻居的 `STRUCTURE_STARTS`（第 2 页）。

结构的 `adjustBoundingBox` 在适配非 `none` 时会把包围盒向外扩 12 格，保证核的影响范围也被计入“结构覆盖了这个区块”的判断。

## 结构如何落地：跨区块写入

落地发生在 `FEATURES` 阶段（`ChunkGenerator.applyBiomeDecoration`）：

```java
for 每个装饰阶段 step:
    for 该阶段的每个结构类型:
        random.setFeatureSeed(decorationSeed, 结构序号, step)
        for 覆盖本区块的每个 StructureStart:
            start.placeInChunk(level, structureManager, generator, random, 可写区域 = 本区块 16×16 全高, chunkPos)
```

`StructureStart.placeInChunk`：

```java
for (piece : pieces)
    if (piece.getBoundingBox().intersects(可写区域))        // 只处理与本区块相交的 piece
        piece.postProcess(level, structureManager, generator, random, 可写区域, chunkPos, 基准点);
```

`postProcess` 收到的 `BoundingBox` 就是本区块的可写区域，piece **必须自己按它裁剪**（模板的 `placeInWorld` 就是这样做的）。同一座村庄跨 4 个区块，就会被 `postProcess` 调用 4 次，每次画一部分。这与传统洞穴的“源区块 ±8、各区块独立裁剪”是同一个设计：**用确定性数据（piece 列表）取代区块间的同步**。

结构所在的装饰阶段由 `Structure.step()` 决定（村庄是 `surface_structures`，矿井是 `underground_structures`，要塞是 `strongholds`）；同一阶段里结构先于特征放置，所以树不会长进房子里。

## 给 Unity 项目的取舍

| 阶段 | 做什么 | 要点 |
| --- | --- | --- |
| 1 | 单个固定建筑（一个小房子） | 用 `random_spread` 决定位置；先只放平坦地面；用“位置 + 旋转”描述，不要直接写方块 |
| 2 | 模板 + 旋转 / 镜像 + 处理器 | 把建筑存成“方块调色板 + 位置列表”。放置时只写落在当前区块内的方块 |
| 3 | 跨区块 + 引用 | 起点阶段只决定包围盒；落地阶段每个区块各画自己的一部分；需要查“哪些结构覆盖我”时遍历周围 N 个区块 |
| 4 | 地形适配 | 先用“把地面拉平”的简单办法；想要自然的再做 Beardifier 式的密度修正 |
| 5 | Jigsaw | 最后做。只需要：连接点（名字 / 目标 / 方向）、带权重的池、广度优先、包围盒碰撞检测、深度与范围限制 |

两条设计原则可以直接照搬：

1. **起点是确定性的纯函数**：`f(种子, 格子坐标, 盐) → 起点`。不需要邻居，也不需要存档就能重算。
2. **“决定”与“绘制”分离**：先产生一份只含 piece 列表与包围盒的轻量数据（`StructureStart`），任意区块需要时再按自己的范围绘制。这份数据很小，可以长期缓存。

## 小结

- 结构 = 放置规则（`structure_set`）+ 生成规则（`Structure`）+ 落地（`placeInChunk`）。
- `random_spread` 把世界切成格子，每格一个起点；`concentric_rings` 全局规划要塞。
- Jigsaw 是广度优先的拼图：匹配连接点、体素差集碰撞、深度和范围限制。
- 模板 + 处理器让一套模型适配多种群系；放置时按可写包围盒裁剪，跨区块不需要同步。
- `Beardifier` 把结构的“垫实 / 削空”加进 `final_density`，逐方块生效。

## 自测

1. 为什么结构起点的判定不需要邻居区块的信息？
2. `STRUCTURE_REFERENCES` 为什么要遍历周围 17×17 个区块？
3. 一座横跨 4 个区块的村庄，`postProcess` 会被调用几次？每次做什么？
4. Jigsaw 里“深度 `size`”与“`max_distance_from_center`”分别限制什么？
5. `beard_thin` 为什么只对 `rigid` 的 piece 起作用？

参考答案：① 只依赖 (种子, 格子坐标, 盐)，用确定性随机数算出该格子的候选区块。② 结构的包围盒可以很大，一个区块要登记“谁覆盖了我”，必须往外看到所有可能覆盖它的起点。③ 4 次（每个相交区块一次），每次只写属于该区块可写区域内的方块。④ 前者限制拼接的层数（连接点的传递深度），后者限制整体范围（包围盒中心 ± 距离）。⑤ `terrain_matching` 的 piece 自己按地表逐列贴合，不需要再改地形，只有刚性的 piece 才需要地形适配。
