> 对应源码：`world/level/levelgen/NoiseRouterData`（`nether`、`end`、`noNewCaves`、`slideNetherLike`、`slideEndLike`）、`DensityFunctions.EndIslandDensityFunction`、`synth/SimplexNoise`、`LegacyRandomSource`、`world/level/biome/TheEndBiomeSource`、`MultiNoiseBiomeSourceParameterList`（下界预设）、`carver/NetherWorldCarver`、`SurfaceRuleData`；数据：`worldgen/noise_settings/{nether,end}.json`、`dimension_type/*.json`。

## 要点

- 三个维度**共用同一套引擎**：`NoiseChunk` 的单元插值、缓存、`ChunkStatus` 流水线都不变，变的只是 `noise_settings` 里的参数和 `NoiseRouter` 里的密度函数图。
- **下界**是“一个 3D 噪声 + 上下两端的 slide”：没有大陆性、侵蚀这些 2D 气候噪声，没有含水层，没有矿脉，群系只由温度和湿度两个噪声决定。
- **末地**的岛屿位置由一个**几何函数** `end_islands` 决定（主岛是一个圆锥，外岛是用单纯形噪声挑出来的若干圆锥的最大值），再叠加一层 `BlendedNoise` 做表面起伏：`sloped_cheese_end = end_islands + base_3d_noise_end`。
- 这一页能让你看清：**“换一个维度”在代码里只是换一份配置和几个密度函数**，这正是配置驱动设计的价值。第 5、6 页讲的主世界是其中最复杂的一份。

## 三份配置并排对比

| 项 | 主世界 | 下界 | 末地 |
| --- | --- | --- | --- |
| `min_y` / `height` | -64 / 384 | 0 / 128 | 0 / 128 |
| `size_horizontal` / `size_vertical` | 1 / 2 | 1 / 2 | 2 / 1 |
| 单元宽 / 高（方块） | 4 / 8 | 4 / 8 | 8 / 4 |
| `sea_level` | 63 | 32 | 0 |
| 默认方块 / 默认流体 | 石头 / 水 | 下界岩 / 岩浆 | 末地石 / 空气 |
| 含水层、矿脉 | 开 | 关 | 关 |
| `legacy_random_source` | false | true | true |
| `disable_mob_generation` | false | false | true |

几点解读：

1. **单元尺寸**：末地的单元是 8×4×8，水平更粗、垂直更细。单元体积 256 格，是主世界 4×8×4（128 格）的两倍，所以同样体积的角点采样数约减半（第 10 页的单元插值收益）。推测这样选是因为岛形主要在水平方向变化、垂直方向很薄，需要更细的垂直分辨率。
2. **`legacy_random_source = true`**：下界和末地用旧的 `LegacyRandomSource`（Java 的 48 位线性同余），主世界用 Xoroshiro（第 7 页）。这是为了保持旧存档的地形不变。
3. **`disable_mob_generation`**：末地在**区块生成时**不放生物（岛上的末影人来自后面的刷怪循环，见第 14 页）。
4. **维度类型**（`dimension_type`）是另一份配置：下界 `has_ceiling = true`、`ultrawarm = true`、`coordinate_scale = 8`、`ambient_light = 0.1`，怪物刷新光照上限 7；维度高度 256，而噪声只覆盖 128。

## 下界：一个噪声 + 两端 slide

### 精简的路由 `noNewCaves`

下界的 `NoiseRouter` 由 `noNewCaves` 搭出来（`caves`、`floating_islands` 预设也用它；末地另有自己的路由，见后文）：15 个字段里**只保留温度、植被（两个 2D 偏移噪声）和 `finalDensity`**，其余 12 个（含水层、矿脉、大陆性、侵蚀、深度、脊线……）全是 `zero()`。这些字段是常数 0，下界不需要含水层、矿脉和大陆性这套 2D 气候，所以**没有任何额外的采样开销**。

```java
// NoiseRouterData.noNewCaves（简化）
temperature = shiftedNoise2d(shift_x, shift_z, 0.25, TEMPERATURE)
vegetation  = shiftedNoise2d(shift_x, shift_z, 0.25, VEGETATION)
finalDensity = postProcess(下界/末地的地形函数)       // postProcess = squeeze(0.64 · interpolated(...))
// 其余 12 个字段 = zero()
```

### slide：把上下两端压成实心

下界地形函数是 `slideNetherLike(0, 128)`，作用在 `nether/base_3d_noise` 上，这个噪声是 `BlendedNoise(0.25, 0.375, 80, 60, 8)`（主世界是 `0.25, 0.125, 80, 160, 8`，垂直方向的缩放更大）：

```java
// NoiseRouterData.slide(df, minY=0, height=128, k=24, l=0, 顶目标=0.9375, m=-8, n=24, 底目标=2.5)
top = yClampedGradient(minY+height-k, minY+height-l, 1, 0)       // y 从 104 到 128，权重 1 → 0
d1  = lerp(top, 0.9375, df)        // = 0.9375 + top·(df − 0.9375)：越靠顶越被拉向 0.9375
bot = yClampedGradient(minY+m, minY+n, 0, 1)                      // y 从 -8 到 24，权重 0 → 1
d   = lerp(bot, 2.5, d1)           // = 2.5 + bot·(d1 − 2.5)：越靠底越被拉向 2.5
```

![下界密度剖面与切片](/qmx-Gameknowledge/assets/mc-source/34-nether-density.png)

左图是 slide 的效果：y 在 24 到 104 之间，权重都是 1，密度就是噪声本身；往上、往下的渐变带里，密度被推到正数，**所以顶部和底部必然是实心（基岩层之上的下界岩顶和地板）**。右图是用移植算法算出的 x–y 切片（种子是示意的）。

- **顶目标 0.9375 与底目标 2.5 都是正数**，所以只要在渐变带的末端，密度一定 > 0，不会出现噪声把天花板挖穿的情况。底部的 2.5 比顶部的 0.9375 大得多，地板更厚。
- 和主世界第 5 页的 `slideOverworld` 是同一个函数，只是参数不同：主世界的目标值是 −0.078125（顶）和 0.1171875（底），目的是**淡出**，让地形平滑地接上空气；下界则是**淡入实心**。
- 经过 `0.64 × interpolated` 与 `squeeze`（第 5 页）后，密度 > 0 为实心。图 34（示意种子）里约 68% 的格子是实心。

### 岩浆海

下界和末地的 `aquifers_enabled = false`，`NoiseChunk` 用的是 `Aquifer.createDisabled(fluidPicker)`：

```java
// Aquifer.createDisabled
computeSubstance(ctx, density) = density > 0 ? null           // 实心：交给后面的方块规则
                                : fluidPicker.computeFluid(x, y, z).at(y)   // 非实心：直接问全局流体
shouldScheduleFluidUpdate() = false                           // 不排流体更新
// NoiseBasedChunkGenerator.createFluidPicker：y < min(-54, 海平面) ? 岩浆 : 默认流体（水位 = 海平面）
```

下界 `sea_level = 32`、默认流体是岩浆，而 `min(-54, 32) = -54` 低于下界底部，所以这一支永远不会触发；结果就是**所有 y < 32 的非实心格子都是岩浆**（`FluidStatus.at(y)` 在 `y` 低于水位时返回流体，否则空气）。没有第 6 页那种“每个区域自己决定水位”的含水层逻辑，也不排流体更新，所以岩浆海是平整的。末地 `sea_level = 0`、默认流体是空气，等于没有海。下界雕刻器 `NetherWorldCarver` 还会把 `y ≤ minGenY + 31` 的空洞填成岩浆。

### 下界雕刻器与群系

- `NetherWorldCarver`（洞穴雕刻器的下界版）：`caveBound = 10`，垂直缩放 `yScale = 5.0`（洞是扁而宽的大厅）；洞的粗细是 `(nextFloat·2 + nextFloat)·2`；主世界的 `CaveWorldCarver` 对应参数是 `caveBound = 15`、`yScale = 1.0`。
- **群系**由 `MultiNoiseBiomeSource` 的“下界预设”选，只有 5 个点，只用温度、湿度和一个“偏移”（偏移越大越难被选中）：

| 群系 | 温度 | 湿度 | 偏移 |
| --- | --- | --- | --- |
| 下界荒地 | 0 | 0 | 0 |
| 灵魂沙峡谷 | 0 | −0.5 | 0 |
| 绯红森林 | 0.4 | 0 | 0 |
| 诡异森林 | 0 | 0.5 | 0.375 |
| 玄武岩三角洲 | −0.5 | 0 | 0.175 |

群系点的选择规则与主世界一样（第 8 页的 `Climate.ParameterList`）：算采样点与每个群系点在各维度上的平方距离，**偏移的平方也加进距离里**，取最小者。偏移越大，这个群系越难被选中，所以诡异森林（0.375² ≈ 0.14）比下界荒地（0）稀少。下界的温度和湿度噪声不走主世界的“按名字哈希取种子”，而是 `RandomState` 里 `legacy_random_source = true` 时的特殊分支：用 `NormalNoise.createLegacyNetherBiome(LegacyRandomSource(种子), NoiseParameters(-7, 1.0, 1.0))`，温度和湿度各用一个固定的偏移（0 和 1）。反编译出来的 `newLegacyInstance(l)` 写成了 `new LegacyRandomSource(l + l)`，形参和捕获的世界种子被反编译器重命名成了同一个名字；同一个类的 `wrapNew` 里 `new EndIslandDensityFunction(l)` 的 `l` 只能是世界种子，所以我按“世界种子 + 偏移”理解（间接证据，没有查字节码，也没在游戏里验证）。同一分支里，`BlendedNoise` 也用 `LegacyRandomSource` 创建，不用 Xoroshiro。

### 地表规则

下界的 `SurfaceRuleData.nether()` 是一棵规则树（第 9 页的 `SurfaceRules`）：

1. 地板和天花板各 5 层的**基岩渐变**（`verticalGradient`）；
2. `basalt_deltas`：天花板下是玄武岩，地板下按噪声在砂砾、玄武岩、黑石间选；
3. `soul_sand_valley`：噪声阈值 0 处在灵魂沙与灵魂土间切换；
4. 绯红 / 诡异森林：噪声 `NETHERRACK` < 0.54 且 y ≥ 31 时，噪声 `NETHER_WART` ≥ 1.17 放下界疣块，否则放下界菌岩；噪声 ≥ 0.54 的位置回落为下界岩；
5. 其余群系的地板层（`ON_FLOOR`）：`y < 32` 且 `hole()`（该列的表层厚度噪声 ≤ 0）时放岩浆。这条排在玄武岩三角洲和灵魂沙峡谷之后，对它们不生效。

## 末地：用几何函数“摆”岛屿

### 路由

末地的 `end()` 路由与下界不同，它不用 `noNewCaves`：

```java
// NoiseRouterData.end（简化）
erosion                       = cache2d(end_islands)                   // 借“侵蚀”字段，给群系源用
initialDensityWithoutJaggedness = slideEnd(end_islands − 0.703125)
finalDensity                  = postProcess(slideEnd(sloped_cheese_end))
// sloped_cheese_end = end_islands + base_3d_noise_end；base_3d_noise_end = BlendedNoise(0.25, 0.25, 80, 160, 4)
// 其余字段 = zero()（温度、植被也是 0，末地没有 2D 气候）
```

注册表里写的是 `endIslands(0L)`，但 `RandomState` 创建时会换成**带世界种子的** `EndIslandDensityFunction(seed)`，所以不同世界的末地外岛不同。

### EndIslandDensityFunction

```java
// 构造：用世界种子建 LegacyRandomSource，空转 17292 次 nextInt()，再用它建一个 2D SimplexNoise
getHeightValue(noise, i, j):          // i、j = 方块坐标 / 8（整数除法，向 0 取整）
    k = i / 2;  l = j / 2;  m = i % 2;  n = j % 2           // 区块级坐标 + 余数
    f = clamp(100 − sqrt(i² + j²)·8, −100, 80)               // 主岛：圆锥
    for o in −12..12, p in −12..12:                          // 周围 25×25 个“候选岛”
        q = k + o;  r = l + p
        if (q² + r² > 4096  &&  noise.getValue(q, r) < −0.9):   // 离原点 > 64 区块，且单纯形噪声很低才“有岛”
            g = (|q|·3439 + |r|·147) % 13 + 9                   // 这个岛的“陡度”：9 ~ 21，由坐标哈希决定
            t = clamp(100 − sqrt((m − 2o)² + (n − 2p)²)·g, −100, 80)   // 以该岛为中心的圆锥
            f = max(f, t)
    return f

compute(x, y, z) = (getHeightValue(noise, x/8, z/8) − 8) / 128            // 值域 [−0.84375, 0.5625]
```

关键点：

1. **岛的位置来自噪声，形状来自公式**：单纯形噪声只回答“这个 16×16 区块格点上有没有岛”（阈值 −0.9，很稀），岛的陡度由坐标的整数哈希得到。每个岛是圆锥，取最大值就成了一片相交的岛群。
2. **2D 函数**：`compute` 只用 x、z，所以 `cache2d` 就够了；垂直方向的形状交给后面的 `slideEnd` 和 `base_3d_noise_end`。
3. **每次求值要遍历 625 个候选格点**（25×25），但只有距原点超过 64 区块的格点才会调用 2D 单纯形噪声（`q² + r² > 4096` 排在噪声调用前面）。路由里给 `erosion` 字段包了 `cache2d`，它只缓存**最近一次**的 (x, z)。移植时可以先把单纯形噪声预算成表（图 35 就是这样算的）。

### 随机数与单纯形噪声

`EndIslandDensityFunction` 用的是旧式 Java 随机数：

```java
LegacyRandomSource: seed' = (seed ^ 0x5DEECE66D) & (2^48 − 1)           // 初始化
next(bits): seed = (seed · 25214903917 + 11) & (2^48 − 1);  return (int)(seed >> (48 − bits))
consumeCount(17292): 调用 nextInt() 17292 次，丢掉         // 为了与旧版本的随机数流对齐
SimplexNoise(rng): xo、yo、zo = nextDouble()·256（2D 版没用到）；p[0..255] = 0..255，
                   然后 for i in 0..255: j = nextInt(256 − i); swap(p[i], p[i + j])    // Fisher–Yates
```

2D 单纯形噪声（`SimplexNoise.getValue(x, y)`）：把坐标斜切到三角形网格，找到所在的三角形，三个角各取一个梯度（`p[]` 查表后对 12 取模），每个角贡献 `(0.5 − d²)⁴ · (梯度·偏移)`，三项相加后乘 70。值域约 [−1, 1]，阈值 −0.9 只有最负的一小部分会触发，所以外岛很稀。

![末地外岛与群系分类](/qmx-Gameknowledge/assets/mc-source/35-end-islands.png)

这张图用上面的算法**逐句移植**（不是示意）：同样的 `LegacyRandomSource`、同样的 17292 次空转、同样的置换表。左图是种子 0 的 `end_islands` 值，右图是按 `TheEndBiomeSource` 的规则分类。可以看到：

- 中心主岛很小，周围一大圈（半径 1024 格）是虚空；
- 外岛成团出现，每团由若干陡度不同的圆锥合成；
- 大部分面积是 `small_end_islands`（值 < −0.21875，基本是虚空），陆地部分只占一小块。

### 群系分类

```java
// TheEndBiomeSource.getNoiseBiome（简化）
section = (blockX >> 4, blockZ >> 4)
if (sx² + sz² ≤ 4096)  return the_end                    // 半径 64 区块内：主岛群系
d = erosion(sx·16 + 8, sz·16 + 8)                        // 采样点取区块中心；erosion 字段正是 end_islands
d > 0.25            → end_highlands
d ≥ −0.0625         → end_midlands
d < −0.21875        → small_end_islands
否则                → end_barrens
```

这里体现了配置驱动的好处：**群系源直接问路由里的“侵蚀”字段**，而末地把它接成了 `end_islands`，所以群系和地形一致，不需要额外的噪声。

### slideEnd：垂直方向的形状

```java
// slideEnd = slide(df, minY=0, height=128, k=72, l=−184, 顶目标=−23.4375, m=4, n=32, 底目标=−0.234375)
top = yClampedGradient(56, 312, 1, 0)        // y 从 56 到 312，权重 1 → 0（越过世界顶部，实际只用到前一段）
bot = yClampedGradient(4, 32, 0, 1)          // y 从 4 到 32，权重 0 → 1
```

![末地主岛轮廓与垂直剖面](/qmx-Gameknowledge/assets/mc-source/36-end-profile.png)

左图是沿 +x 轴的 `end_islands`：主岛是平顶加陡坡（顶 20 格，200 格处触底到 −0.84375）；外岛从 1024 格之后才开始，不少隆起的峰值仍是负数，意味着不会长出陆地。右图是 `slideEnd` 对固定岛值的作用：**y 在 32 到 56 之间权重为 1，密度等于岛值本身，所以岛值为正才有陆地**；上下两端的渐变把密度拉向负数，限制岛的上下边界。按公式，岛值 0.5625 的零交叉在 y≈12 和 y≈62。这张图**没有叠加 `base_3d_noise_end` 和 `squeeze`**，只是 slide 的骨架，真实的岛厚度和底面形状还会被噪声改变。

## 与主世界对照：换维度到底换了什么

| 层面 | 主世界 | 下界 | 末地 |
| --- | --- | --- | --- |
| 地形主体 | 样条出 offset / factor / jaggedness，再叠 `sloped_cheese`（[第 5 页](/qmx-Gameknowledge/knowledge/minecraft源码学习/源码专栏/05-sloped_cheese地形主体/)） | 一个 `BlendedNoise` | `end_islands` + `BlendedNoise` |
| 垂直形状 | `slideOverworld`（淡出） | `slideNetherLike`（淡入实心） | `slideEnd`（淡出到负数） |
| 洞穴 | 噪声洞穴 + 含水层（[第 6 页](/qmx-Gameknowledge/knowledge/minecraft源码学习/源码专栏/06-finaldensity洞穴与含水层/)） | 雕刻器 `NetherWorldCarver` | 没有噪声洞穴和含水层（群系的雕刻器列表未核实） |
| 群系 | 6 维气候噪声（[第 8 页](/qmx-Gameknowledge/knowledge/minecraft源码学习/源码专栏/08-气候与群系/)） | 温度 + 湿度 + 偏移，5 个点 | 直接读 `end_islands` 分类 |
| 随机数 | Xoroshiro | `LegacyRandomSource` | `LegacyRandomSource` |

## 给 Unity 项目的取舍

1. **优先级低**：如果你的项目只做主世界，这一页可以只读“三份配置并排对比”和“主世界对照”两节，理解“换维度 = 换配置”。
2. **下界的做法最容易复用**：单个 3D 噪声加一个 slide，一个噪声加两段线性渐变就能得到封顶封底的洞穴世界。可以拿它当第 5 页的练习：先别接样条，看看单个 `BlendedNoise` 配 slide 能得到什么。
3. **末地的 `end_islands` 是一个很好的“稀疏结构”范例**：用低频噪声当“有无”开关，用整数哈希决定每个岛的参数，用 `max` 合并。这个套路可以用来放“浮空岛”“遗迹”一类稀疏对象，不依赖区块边界（只要取周围 25×25 个格点）。
4. **旧版随机数不必照搬**：Java 的线性同余只是为了兼容旧存档，Unity 里可以用任何确定性哈希，只要保证“同一个格点在任何区块里算出来的结果一致”。

## 小结

- 三个维度共用同一套 `NoiseChunk` 引擎，差别在 `noise_settings` 和密度函数图；下界 / 末地的单元尺寸、海平面、默认方块、含水层与矿脉开关都不同。
- 下界：`noNewCaves` 路由只保留温度、植被和 `finalDensity`；单个 `BlendedNoise` 经 `slideNetherLike` 压成封顶封底；岩浆海来自“关闭含水层 + 全局流体选择器”；群系只有 5 个点。
- 末地：`end_islands` 用主岛圆锥加外岛圆锥的最大值；外岛由 2D 单纯形噪声（阈值 −0.9）挑选；群系直接按 `end_islands` 的值分类；`slideEnd` 决定垂直范围。

## 自测

1. 为什么下界的 `noNewCaves` 路由可以把 12 个字段设成 `zero()`？
2. `slideNetherLike` 的顶目标 0.9375 和底目标 2.5 为什么都是正数？
3. 下界的岩浆海是怎么来的？它和主世界的海有什么不同？
4. `EndIslandDensityFunction` 中，一个外岛的位置、大小、陡度分别由什么决定？
5. 末地群系为什么不需要自己的噪声？

参考答案：① 下界没有大陆性、侵蚀等 2D 气候，没有含水层和矿脉，这些字段不会被读到。② 正的目标值在渐变带末端强制实心，噪声无法把天花板和地板挖穿；底部更大因为地板需要更厚。③ 含水层关闭，`createDisabled` 对所有非实心且 y 低于海平面（32）的位置直接填默认流体（岩浆），没有区域水位，也不排流体更新。④ 位置：由单纯形噪声在区块级格点上的值（< −0.9）决定“有没有岛”，岛的中心就是这个格点；大小和陡度：由 `(|q|·3439 + |r|·147) % 13 + 9` 决定圆锥的斜率，斜率越大岛越小。⑤ 路由把 `end_islands` 接到了“侵蚀”字段，群系源读它并按阈值分类。
