## 要点

- 生物来源有四种：**区块生成时**的初始生物（`ChunkStatus.SPAWN`）、**运行时的自然刷新**（`NaturalSpawner`，每个游戏刻一次）、**特殊刷新器**（幻翼、巡逻队、猫、流浪商人、袭村），以及**结构专属刷新**（下界要塞的烈焰人、沼泽小屋的女巫）。
- 自然刷新是一个**层层过滤的漏斗**：先用便宜的条件（类别开关、数量上限）挡掉绝大多数尝试，最后才做昂贵的检查（碰撞箱、光照）。
- 数量上限不是全局常数，而是 `类别上限 × 可刷新区块数 ÷ 289`，并且按玩家分摊（`LocalMobCapCalculator`）。
- 刷新是**每个区块每个类别每刻只尝试一次**，每次尝试最多 3 组随机游走（每组先随机 1~4 步，抽到种类后改为该种类的群体数量），这是控制成本的核心。
- 刷新表（谁能刷、权重、数量）是**数据**：在群系 JSON 的 `spawners` 里，结构可以用 `spawn_overrides` 覆盖。

## 自然刷新：一次完整的漏斗

![自然刷新的漏斗](/qmx-Gameknowledge/assets/mc-source/23-natural-spawn-funnel.png)

流程发生在 `ServerChunkCache.tickChunks`，每个游戏刻一次：

1. **`createState`**：遍历所有实体，统计每个 `MobCategory` 当前数量（跳过需要持久保存的生物和 `MISC`），同时更新每个玩家的本地计数。结果是一个 `SpawnState`，**这一刻所有区块共用**，每刷出一只用 `afterSpawn` 增量更新，不会重复遍历。
2. 取所有 ticking 区块并 `Collections.shuffle`，让每个区块被处理的先后随机。
3. **区块过滤**：区块允许自然刷新，且 128 格内有玩家（`anyPlayerCloseEnoughForSpawning`，区块中心到玩家水平距离平方 < 16384）。
4. 对每个类别（`SPAWNING_CATEGORIES`，不含 `MISC`）：

```java
// NaturalSpawner.spawnForChunk
for (category : SPAWNING_CATEGORIES)
    if ((spawnFriendlies || !category.isFriendly())
     && (spawnEnemies    ||  category.isFriendly())
     && (每400刻的那一刻 || !category.isPersistent())          // 被动生物（CREATURE）每 400 刻才有一次机会
     && spawnState.canSpawnForCategory(category, chunkPos))   // 数量上限
        spawnCategoryForChunk(...)
```

注意括号里的含义：友好类别由 `spawnFriendlies` 控制，敌对类别由 `spawnEnemies` 控制（对应服务器的 `spawn-animals` / `spawn-monsters` 设置）；只有 `CREATURE` 是 `persistent`，所以普通动物约每 20 秒才有一次刷新机会，而怪物每刻都有。

## 生物上限

```java
// SpawnState.canSpawnForCategory
上限 = category.maxInstancesPerChunk × spawnableChunkCount / 289;     // 289 = 17²
return 当前该类别数量 < 上限 && localMobCapCalculator.canSpawn(category, chunkPos);
```

`spawnableChunkCount` 是“离任一玩家足够近、可以刷新生物的区块数”（`DistanceManager` 用一个以玩家为中心、半径 8 区块的追踪器统计）。单人且周围 17×17 = 289 个区块全部加载时，上限正好等于 `maxInstancesPerChunk`，例如怪物 70。多人时区块并集变大，总上限随之成比例增加。

`LocalMobCapCalculator` 在此基础上**按玩家分摊**：每个玩家有自己的类别计数，只要区块附近有一个玩家的计数未满就允许刷新，避免一个人把整个服务器的上限占满。

| `MobCategory` | 上限（每 289 区块） | 友好 | 持久 | 立即消失距离 |
| --- | --- | --- | --- | --- |
| `MONSTER` | 70 | 否 | 否 | 128 |
| `CREATURE` | 10 | 是 | 是 | 128 |
| `AMBIENT`（蝙蝠） | 15 | 是 | 否 | 128 |
| `AXOLOTLS` | 5 | 是 | 否 | 128 |
| `UNDERGROUND_WATER_CREATURE` | 5 | 是 | 否 | 128 |
| `WATER_CREATURE` | 5 | 是 | 否 | 128 |
| `WATER_AMBIENT` | 20 | 是 | 否 | 64 |
| `MISC` | 不参与自然刷新 | 是 | 是 | 128 |

所有类别的 `noDespawnDistance`（保证不消失的距离）都是 32。

## 在一个区块里“尝试一次”

`spawnCategoryForChunk` 先取一个随机点：x、z 在区块内随机，y 在最低层到该列地表（`WORLD_SURFACE` + 1）之间均匀随机。注意 y 是均匀随机的，所以洞穴里的空间（占的高度范围大）也会被抽到，这就是洞穴里会刷怪的原因。

随后 `spawnCategoryForPosition` 做一次小范围的随机游走：

```java
if (起点方块是红石导体) return;
for (组 = 0; 组 < 3; 组++) {                 // 最多 3 组
    x = 起点.x;  z = 起点.z;
    步数 = ceil(random * 4);                  // 初始 1~4 步；抽到种类后改写为 minCount + nextInt(1 + maxCount - minCount)
    for (步 ...) {
        x += nextInt(6) - nextInt(6);         // 偏移 -5 ~ +5，三角分布
        z += nextInt(6) - nextInt(6);
        if (距玩家平方 <= 24² 或 距世界出生点 < 24 格) continue;      // isRightDistanceToPlayerAndSpawnPoint
        if (本组还没选定种类) 按权重从群系 / 结构刷新表里抽一种 spawnerData; 步数 = minCount + nextInt(1 + max - min);
        if (位置合法 && 谓词通过 && 无碰撞) {
            生成实体; afterSpawn 更新计数;
            if (已生成数 >= 该种类最大群体) return;       // Mob 默认 4
        }
    }
}
```

要点：

- **一个组内只抽一次种类**，所以同一组生成的是一群同类（比如一群羊）。
- 部分生物覆写了 `isMaxGroupSizeReached`，命中时只结束当前组，而不是整次尝试；已生成数是三组累计的。
- 三角分布的偏移让同一群集中在起点附近。
- 距离判断用平方，不开方；起点方块是红石导体就直接返回，免得浪费后面的检查。

## 刷新位置与条件

对每个候选位置依次检查（`isValidSpawnPostitionForType`）：

| 检查 | 内容 |
| --- | --- |
| 距离 | 离玩家 > 24 格；离世界出生点 > 24 格；离玩家不能太远（超过该类别的消失距离就不刷） |
| 放置类型 | `SpawnPlacements` 为每种实体登记：`ON_GROUND`（脚下实心、本格与上格是空的）、`IN_WATER`、`IN_LAVA`…；以及用哪种高度图 |
| 刷新谓词 | 每种实体自己的 `checkSpawnRules`：怪物检查光照与难度，动物检查草方块与光照，水生生物检查水深 |
| 碰撞 | 该实体的碰撞箱放在这里不与任何东西相交（`noCollision`） |

### 怪物的光照判定

```java
// Monster.isDarkEnoughToSpawn（简化）
if (天空光(pos) > random.nextInt(32)) return false;            // 白天几乎一定失败
limit = dimension.monsterSpawnBlockLightLimit;                  // 主世界 0
if (limit < 15 && 方块光(pos) > limit) return false;            // 主世界：有任何方块光就不刷
亮度 = 雷暴 ? getMaxLocalRawBrightness(pos, 10) : getMaxLocalRawBrightness(pos);
return 亮度 <= dimension.monsterSpawnLightTest.sample(random);  // 主世界：0~7 均匀随机
```

这里体现了光照由**维度配置**决定：主世界 `monster_spawn_block_light_limit = 0`、`monster_spawn_light_level` 为 0~7 均匀分布；下界块光限制是 15、光照上限 7；末地与主世界相同。动物（`Animal.checkAnimalSpawnRules`）则需要脚下是 `animals_spawnable_on` 标签里的方块（草方块等），且基础亮度 > 8。

## 刷新表：谁能刷、权重多少

刷新表是群系数据的一部分（`worldgen/biome/*.json`）：

```json
"spawners": {
  "creature": [ { "type": "minecraft:sheep", "minCount": 4, "maxCount": 4, "weight": 12 },
                { "type": "minecraft:horse", "minCount": 2, "maxCount": 6, "weight": 5 }, ... ],
  "monster":  [ ... ]
},
"spawn_costs": {}
```

`SpawnerData` 的字段是 `type / weight / minCount / maxCount`。选择种类用 `WeightedRandomList`：`nextInt(总权重)` 再按累计权重找。`creature_spawn_probability` 没写时默认 0.1（只用于生成时刷新，见下）。

**结构可以覆盖群系的刷新表**（`spawn_overrides`），例如沼泽小屋：

```json
"spawn_overrides": {
  "monster":  { "bounding_box": "piece", "spawns": [ { "type": "minecraft:witch", "minCount": 1, "maxCount": 1, "weight": 1 } ] },
  "creature": { "bounding_box": "piece", "spawns": [ { "type": "minecraft:cat", ... } ] }
}
```

查询入口是 `ChunkGenerator.getMobsAt(biome, structureManager, category, pos)`：遍历覆盖该位置的结构，**第一个定义了该类别覆盖且包围盒命中的结构胜出**，否则回落到群系自己的刷新表。`bounding_box` 为 `piece` 表示只在具体的 piece 内生效（房子内部），为 `structure` 表示整个包围盒。下界要塞更特殊：`NaturalSpawner.mobsAt` 在“怪物类别 + 脚下是下界砖 + 在要塞包围盒内”时直接用 `FORTRESS_ENEMIES`。

## 消失（despawn）

`Mob.checkDespawn` 每刻调用，规则很短：

```java
if (和平模式 && 该生物在和平模式应消失) discard();
else if (!isPersistenceRequired() && !requiresCustomPersistence()) {
    d = 离最近玩家的距离平方;
    if (d > despawnDistance² && removeWhenFarAway(d)) discard();          // > 128 格：立即消失
    int t = noActionTime;
    if (t > 600 && random.nextInt(800) == 0 && d > 32² && removeWhenFarAway(d)) discard();  // 32~128 格：久无动作就随机消失
    else if (d < 32²) noActionTime = 0;                                     // 32 格内永不消失
}
else noActionTime = 0;                                                       // 持久化的永不消失
```

- **持久化**：命名过的、持有装备掉落的、正在骑乘的生物，以及所有 `Animal`（`removeWhenFarAway` 被覆写为 false），都不会自然消失。
- 这套距离规则（32 / 128）与刷新规则（24 / 128）是配套的：**玩家 24 格内不会刷新，32 格内不会消失，128 格外立即消失**，所以怪物不会在你脸上刷出来，也不会在你身边突然消失，更不会在远处无限累积。

## 生成时刷新（区块第一次生成）

`ChunkStatus.SPAWN` 阶段调用 `spawnOriginalMobs`，最终进 `NaturalSpawner.spawnMobsForChunkGeneration`：

```java
// 只用 CREATURE 类别的刷新表
while (random.nextFloat() < biome.getCreatureProbability()) {      // 默认 0.1 → 平均每区块 0.111 组
    抽一种 spawnerData;  数量 = minCount + nextInt(1 + max - min);
    for (每只) 最多尝试 4 次: 在本区块内随机偏移 nextInt(5)-nextInt(5)，找地表位置，合法就生成;
}
```

只刷被动生物，且每个区块约有 10% 的概率至少出现一群（平均 0.111 群），所以刚创建的世界里动物稀疏，之后靠运行时刷新补足。随机种子用 `setDecorationSeed`，生成结果可以复现。

## 特殊刷新器

主世界另有五个“自定义刷新器”，在 `ServerChunkCache.tickChunks` 末尾通过 `tickCustomSpawners` 每刻调用一次（内部自己控制频率）：

| 刷新器 | 触发条件 | 频率 / 概率常量 |
| --- | --- | --- |
| `PhantomSpawner`（幻翼） | 开启 `doInsomnia`，天空较暗，玩家在海平面以上且能看到天空，玩家已很久没睡觉（以 `(j − 72000) / j` 的概率通过，`j` 为未睡觉的刻数 `TIME_SINCE_REST`；另有按难度的随机门槛） | 间隔 `(60 + nextInt(60)) × 20` 刻；出生在玩家上方 20~34 格、水平 ±10 格；数量 `1 + nextInt(难度 + 1)` |
| `PatrolSpawner`（掠夺者巡逻队） | 游戏日数 ≥ 5 且是白天，随机选一名玩家，不在村庄 2 区块内 | 间隔 `12000 + nextInt(1200)` 刻，通过后再掷 1/5；偏移每轴 24~47 格 |
| `CatSpawner`（村庄的猫） | 玩家附近随机选的候选点靠近村庄，48 格内已被占用的“家”（床）> 4 张，附近猫 < 5 只；沼泽小屋另有规则 | 每 1200 刻一次；偏移每轴 8~31 格 |
| `WanderingTraderSpawner`（流浪商人） | 计时到点后按递增概率 | 检查间隔 1200 刻，总延迟 24000 刻；每次到点的成功率依次为 26%、51%、76%（判定为 `nextInt(100) > chance` 则失败，`chance` 从 25 起每次 +25，上限 75）；通过后再有 1/10 的门槛 |
| `VillageSiege`（僵尸围村） | 夜晚，玩家在村庄内 | 仅在午夜那一刻（`getTimeOfDay == 0.5`）掷 1/10 决定“今晚围村”；围村时每 2 刻刷 1 只僵尸，共 20 只，围绕玩家半径 32 格尝试 10 次选位置 |

## 省算力的设计观察

1. **漏斗式过滤**：类别开关、数量上限、距离等廉价条件在前，光照、碰撞箱等昂贵条件在后。多数尝试在前两关就被淘汰。
2. **一次统计，全区块共用**：`createState` 每刻遍历一次实体，所有区块共用同一个 `SpawnState`，刷出一只就增量更新，不用再扫一遍。
3. **降频**：被动生物每 400 刻才有一次机会；每个区块每个类别每刻最多尝试一次，且一次尝试最多 3 组、每组步数不超过该种类的最大群体数。
4. **用平方比较距离**，避免开方。
5. **随机抽样代替全量扫描**：不是遍历区块里所有可刷新的位置再挑，而是随机抽一个点开始游走；成本固定，与区块里有多少合法位置无关。
6. **按玩家分摊上限**（`LocalMobCapCalculator`），多人服务器里上限与玩家数成比例，且一个玩家不会耗尽别人的额度。

## 给 Unity 项目的取舍

| 内容 | 建议 |
| --- | --- |
| 数据驱动的刷新表（类别、权重、数量） | **做**。刷新表放进群系数据，可被结构覆盖 |
| 数量上限按“活跃区块数”缩放 | 做，比固定总数更自然 |
| 漏斗式过滤 + 随机抽样 | 做；先实现“类别上限 + 距玩家 24 格外 + 地面合法 + 光照”四关 |
| 消失规则 | 做；至少保留“远处立即消失、近处不消失”的区间设计 |
| 生成时刷新 | 简单：新区块以小概率生成一群被动生物 |
| 特殊刷新器 | 以后再说；统一的接口 `Tick(level)` 即可 |

建议先把刷新放进**调度器**里（按帧累积、按区块分批），而不是每帧遍历所有区块；这样既能控制每帧耗时，也为多线程留出空间。

## 小结

- 自然刷新是一个由廉价到昂贵的漏斗；每个区块每刻最多一次尝试，每次最多 3 组随机游走。
- 上限 = 类别上限 × 可刷新区块数 ÷ 289，并按玩家分摊。
- 刷新位置要通过放置类型、刷新谓词（怪物看光照、动物看草）和碰撞检查。
- 玩家 24 格内不刷，32 格内不消失，128 格外立即消失。
- 刷新表是数据，结构可覆盖群系；特殊刷新器各自带频率与条件。

## 自测

1. 在 289 个区块全部可刷新时，怪物上限是多少？只有 100 个区块可刷新时呢？
2. 为什么被动生物比怪物刷新得慢？
3. 为什么洞穴里会刷怪？
4. 玩家站在原地不动，为什么 10 格内不会刷出怪物，而 30 格外可以？
5. 结构的 `spawn_overrides` 与群系 `spawners` 冲突时听谁的？

参考答案：① 70；`70 × 100 / 289 ≈ 24`（向下取整）。② `CREATURE` 类别是 `persistent`，只有 `gameTime % 400 == 0` 的那一刻才有机会。③ 随机点的 y 在最低层到地表之间均匀抽取，洞穴空间会被抽到，光照也满足。④ 距玩家 24 格以内一律拒绝；超过 24 格才进入后续检查。（刷出来后，怪物在 32 格内也不会被消失规则清掉。）⑤ 听结构的：`getMobsAt` 先看覆盖该位置并命中包围盒的结构，其次才回落到群系。
