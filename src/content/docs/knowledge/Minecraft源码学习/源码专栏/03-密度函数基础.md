## 要点

- 一个密度函数就是 `f(x, y, z) → double`。**值 > 0 是实心，≤ 0 是空气或流体**。整个地形主体就是一棵由这类函数拼成的树。
- 树上的节点分几个家族：叶子（常数、渐变、噪声）、运算（加乘最小最大）、变形（abs、square、半负、四分之一负、squeeze）、分支（`range_choice`）、样条（`spline`）、缓存标记（`Marker`）。
- 每个节点都实现同一个接口，所以**节点可以任意嵌套**；调参、换地形不用改代码，只改数据。
- 树在使用前要经过两次“编译”：先把噪声绑定到具体实例（`RandomState`），再按区块把缓存标记替换成私有缓存对象（`NoiseChunk.wrap`）。
- 每个节点自己维护输出的 `[minValue, maxValue]`，`min / max / 乘` 在运行时可以据此**提前短路**，不去算另一边。

## 接口只有五件事

```java
public interface DensityFunction {
    double compute(FunctionContext ctx);                       // ① 求一个点的值
    void   fillArray(double[] out, ContextProvider provider);  // ② 一次填一整批点
    DensityFunction mapAll(Visitor visitor);                   // ③ 遍历并改写整棵树
    double minValue();                                         // ④ 输出下界
    double maxValue();                                         // ⑤ 输出上界

    interface FunctionContext { int blockX(); int blockY(); int blockZ(); }
}
```

（第六个成员 `codec()` 是序列化用的，可以忽略。）

**① `compute`**：上下文只有三个整数坐标。所有噪声、渐变都是“以方块坐标为输入”，所以同一棵树既能给单点用（查询群系、查询高度），也能给整个区块用。

**② `fillArray`**：批量求值。上下文提供者 `ContextProvider.forIndex(i)` 会把“当前点”切换到第 *i* 个位置。区块生成时有两种批量：一根竖直的角点柱（49 个点）和一个 cell 内的所有方块（4×8×4 = 128 个点）。批量求值的价值在于让缓存节点能按“这一批”为单位命中，见第 10 页。

**③ `mapAll`**：访问者模式。传入一个 `Visitor`，它会**自底向上**对每个节点调用一次 `apply`，可以返回原节点，也可以返回替换后的新节点。第 3 步“编译”完全靠它。

**④⑤ `minValue/maxValue`**：节点输出值的保守上下界，见下文“区间与短路”。

## 节点家族

| 家族 | 节点 | 求值 | 在地形里的例子 |
| --- | --- | --- | --- |
| 叶子 | `Constant` | 常数 | `-0.50375`（全局偏移）、`0.64` |
| 叶子 | `YClampedGradient` | `clampedMap(y, fromY, toY, fromValue, toValue)` | 从 y=-64 的 1.5 线性降到 y=320 的 -1.5 |
| 叶子 | `Noise` | `noise(x·xzScale, y·yScale, z·xzScale)` | `jagged`、`cave_cheese`、`cave_layer` |
| 叶子 | `ShiftedNoise` | `noise(x·s + shiftX, y·ys + shiftY, z·s + shiftZ)` | `continents / erosion / ridges` |
| 叶子 | `BlendedNoise`（`old_blended_noise`） | 三组 octave 的混合噪声 | `base_3d_noise`，地形里唯一真正的 3D 噪声 |
| 运算 | `add / mul / min / max` | 两个子节点的和、积、最小、最大 | `depth + jaggedness·…`、`min(地形, 洞穴)` |
| 变形 | `abs / square / cube / half_negative / quarter_negative / squeeze` | 单输入的非线性映射 | 见下一节 |
| 限幅 | `clamp` | `clamp(x, min, max)` | 洞穴偏置、噪声限幅 |
| 分支 | `range_choice` | 输入落在 `[min, max)` 就算 A 子树，否则 B | 浅层/深层切换、`noodle` 的 y 范围 |
| 样条 | `spline` | 多维嵌套三次样条 | `offset / factor / jaggedness` |
| 缓存标记 | `interpolated / flat_cache / cache_2d / cache_once / cache_all_in_cell` | 对求值本身是恒等，`compute` 直接转发 | 第 10 页 |
| 引用 | `HolderHolder` | 指向一个已注册的函数 | 把 `overworld/offset` 这样的名字挂进树里 |

注意 **`Marker` 在“编译”之前什么都不做**：它的 `compute` 只是把调用转发给被包住的子节点。它真正的作用是**给后面的编译步骤做记号**。

## 六个变形函数：每一个都在解决具体问题

![Mapped 六个变形函数](/qmx-Gameknowledge/assets/mc-source/01-mapped-functions.png)

虚线是 `y = x`。把曲线和虚线比较，就能看出每个函数“改变了什么”。

| 函数 | 公式（源码 `Mapped.transform`） | 它改变了什么 | 在世界生成里用在哪 |
| --- | --- | --- | --- |
| `abs` | `\|x\|` | 去掉符号，**折叠**。零点变成尖角 | `ridges_folded` 里折两次；洞穴里把噪声变成“细线” |
| `square` | `x²` | 去掉符号，并压平零附近 | `cave_layer` 的平方，使洞穴层只在噪声极值处出现 |
| `cube` | `x³` | 保留符号，小值压得更小、大值放得更大 | 柱子（`pillars`）和 `spaghetti_2d` 的厚度 |
| `half_negative` | `x > 0 ? x : x·0.5` | 负半边减半 | `jaggedness` 乘的 `jagged` 噪声：山顶只向上凸起，凹处只有一半幅度 |
| `quarter_negative` | `x > 0 ? x : x·0.25` | 负半边缩小到四分之一 | **`sloped_cheese` 最外层**：空气一侧的坡度只有实心一侧的 1/4（第 5 页详讲） |
| `squeeze` | `c = clamp(x,-1,1)` 后取 `c/2 - c³/24` | 平滑限幅，输出落在约 ±0.458 | `final_density` 的最后一步 |

两点值得记住：

1. `half_negative` 和 `quarter_negative` 是**不对称**的。它们让“正”和“负”两边的响应不一样。放在 `sloped_cheese` 里，效果是空气一侧的密度坡度更缓，3D 噪声更容易在地表之上“撑出”实心，这是悬崖、悬挑和拱门的来源（第 5 页有对照图）。
2. `squeeze` 的作用是**限制幅度**而不是改变符号：任何大于 ±1 的输入都被夹到同一个数，所以它不会改变“实/空”的判定，只让后面的运算不用面对极端大的数。

## 函数图如何“编译”：三个阶段

```text
① 数据包 JSON                      "minecraft:overworld/offset" 这样的名字互相引用
       │ 加载 (Codec → Holder)
       ▼
② 共享的函数图 (不可变)             节点里的 NoiseHolder 还没绑定具体噪声
       │ RandomState：router.mapAll(NoiseWiringHelper)
       ▼
③ 绑定了噪声实例的函数图 (全局共享，线程安全)
       │ 每个区块：NoiseChunk 构造时 router.mapAll(this::wrap)
       ▼
④ 区块私有的函数图                  Marker 被替换成带缓存的对象，HolderHolder 被展开
```

**② → ③：`RandomState` 里的 `NoiseWiringHelper`。** 它访问每个节点：遇到 `Noise / ShiftedNoise` 就用 `getOrCreateNoise(噪声名)` 换成绑定好 `NormalNoise` 实例的版本；遇到 `BlendedNoise` 就用名字 `"terrain"` 派生的随机源重建。这样“噪声参数”（数据）和“噪声实例”（种子相关）被分开了。同一个种子对应一份绑定结果，可以被所有区块共享。

**③ → ④：`NoiseChunk.wrap`。** 每生成一个区块都会再 `mapAll` 一次：

```java
// NoiseChunk.wrapNew（简化）
if (df instanceof Marker m) switch (m.type()) {
    case Interpolated   -> new NoiseInterpolator(m.wrapped());   // 角点 + 三线性插值
    case FlatCache      -> new FlatCache(m.wrapped(), true);     // 5×5 个 quart 点预先算好
    case Cache2D        -> new Cache2D(m.wrapped());             // 记住上一次的 (x,z)
    case CacheOnce      -> new CacheOnce(m.wrapped());           // 同一点只算一次
    case CacheAllInCell -> new CacheAllInCell(m.wrapped());      // 整个 cell 一次填满
}
if (df instanceof HolderHolder h) return h.function().value();   // 展开引用
```

这个设计的好处是**“逻辑”（共享、不可变）与“状态”（缓存，区块私有）彻底分离**：

- 函数图只建一次，所有线程共用，没有锁；
- 每个区块有自己的缓存对象，生命周期随 `NoiseChunk` 结束；
- `wrapped` 这个 `HashMap` 保证同一个节点在同一个区块里只会被包装一次，所以被多处引用的子树（例如 `continents` 被 3 个样条共用）**共享同一份缓存**。

## 区间推理与运行时短路

每个节点在**创建时**就算好自己的输出区间，并保存在 `minValue/maxValue` 里。以二元运算为例（`TwoArgumentSimpleFunction.create`）：

| 运算 | 输出下界 | 输出上界 |
| --- | --- | --- |
| `add` | `a.min + b.min` | `a.max + b.max` |
| `min` | `min(a.min, b.min)` | `min(a.max, b.max)` |
| `max` | `max(a.min, b.min)` | `max(a.max, b.max)` |
| `mul` | 按两个区间的正负分情况，取端点乘积 | 同左（保守估计，不保证是最紧的界） |

噪声叶子的上界来自噪声本身的 `maxValue()`（所有 octave 的最大可能值之和），下界是它的相反数。样条的区间由各控制点取值推出。

这些区间不只是装饰，`Ap2.compute` 在运行时用它们**短路**：

```java
// DensityFunctions.Ap2.compute（简化）
double a = arg1.compute(ctx);
switch (type) {
    case ADD: return a + arg2.compute(ctx);
    case MAX: return a > arg2.maxValue() ? a : Math.max(a, arg2.compute(ctx)); // a 已经比 arg2 可能的最大值还大
    case MIN: return a < arg2.minValue() ? a : Math.min(a, arg2.compute(ctx)); // a 已经比 arg2 可能的最小值还小
    case MUL: return a == 0.0 ? 0.0 : a * arg2.compute(ctx);                    // 乘 0 不用算另一边
}
```

最典型的受益者是 `final_density = min(地形, noodle)`：只要地形一边的值已经小于 `noodle` 可能取到的最小值，就不必去算 `noodle` 那一整棵（4 个噪声）子树。同样 `max(洞穴…, pillars)` 里，柱子那一边只在需要时才算。

另一个小优化：当 `add / mul` 的一个参数是常数时，`create` 会返回专用的 `MulOrAdd` 节点，省掉“求一个常数节点”的虚调用，也让区间计算更简单。

**批量版本** `fillArray` 对应同样的逻辑：先填好第一个参数的整批结果，再逐点判断是否需要算第二个参数。这就是为什么 `fillArray` 要保留一个 `ContextProvider`——某些点需要切换回“逐点求值”。

## 对照你自己的实现

| 你现在可能的做法 | 源码的做法 | 为什么值得升级 |
| --- | --- | --- |
| 一个 `GetDensity(x,y,z)` 里顺序写公式 | 公式是节点树，数据驱动 | 换地形不改代码；能在编辑器里组合；便于做优化遍历 |
| 每个噪声自己 new 在某个类里 | 噪声由“名字 + 参数”描述，种子统一派生 | 加噪声不会打乱已有噪声的随机序列 |
| 缓存写在业务代码里 | 缓存是**节点**（`Marker`），由编译步骤自动插入 | 业务逻辑与优化分离，改缓存策略不用动公式 |
| 无 | `mapAll` 访问者 | 一个遍历就能做：绑定噪声、插入缓存、统计节点数、导出调试图 |

不需要一开始就写全：最小的版本只要 `Compute(x,y,z)` + `Constant / Add / Mul / Noise / Spline / YGradient`，再加一个 `Visitor`，就已经有函数图的骨架了。

## 小结

- 密度函数 = 节点树；值 > 0 实心。节点家族有限：叶子、运算、变形、分支、样条、缓存标记。
- 编译分两步：先绑定噪声（共享、不可变），再按区块替换缓存标记（私有、有状态）。
- 区间推理让 `min/max/mul` 可以在运行时短路，砍掉不需要的子树。

## 自测

1. 为什么 `Marker` 的 `compute` 只是转发，却又不可省略？
2. `quarter_negative` 与 `half_negative` 在 x 为正时有什么区别？
3. `min(a, b)` 里，什么时候 `b` 不会被求值？

参考答案：① 它是编译步骤用来找缓存位置的记号，`wrap` 会把它替换成带缓存的对象。② 没有区别，两者在正半边都是恒等，只在负半边缩放系数不同（0.5 与 0.25）。③ 当 `a` 小于 `b.minValue()` 时，`b` 不可能更小，结果就是 `a`。
