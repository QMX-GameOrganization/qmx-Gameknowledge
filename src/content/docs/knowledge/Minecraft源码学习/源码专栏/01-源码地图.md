## 先读数据，再读代码

世界生成是**数据驱动**的：大部分“配置”其实是 JSON，放在数据包的 `data/minecraft/worldgen/` 下。读 JSON 往往比读 Java 更快，因为 JSON 就是最终展开的函数图。

| 目录 | 内容 | 什么时候看 |
| --- | --- | --- |
| `noise_settings/overworld.json` | 高度 384、`min_y=-64`、cell 尺寸、海平面 63、`final_density` 整棵树 | 想看 finalDensity 的真实结构时（第 06 页） |
| `density_function/overworld/` | `sloped_cheese`、`depth`、`offset`、`factor`、`jaggedness`、`continents`、`erosion`、`ridges`、洞穴子函数 | 对照第 03、05 页 |
| `noise/` | 每个噪声的 `firstOctave` 与 `amplitudes` | 第 07 页 |
| `biome/`、`multi_noise_biome_source_parameter_list/` | 群系参数与生成设置 | 第 08、09 页 |
| `configured_carver/`、`configured_feature/`、`placed_feature/` | 洞穴、矿石、树的配置 | 第 09 页 |
| `structure/`、`structure_set/`、`template_pool/` | 结构与放置规则 | 第 09 页（只了解） |

`offset.json` 有 6 万多字节，`factor.json` 3 万多字节：它们是 `TerrainProvider` 里那几个嵌套样条**展开后的结果**。不要读它们，读 `TerrainProvider.java`（270 行）的结构就够了；需要核对数值时才回头查 JSON。

### 怎么读 `DensityFunctions.java`（1332 行）

这个文件看着吓人，其实结构非常规整：**每个内部类 = 一种节点**，每个节点都有同样的五个成员：`compute`、`fillArray`、`mapAll`、`minValue/maxValue`、`codec`。其中 `codec` 是序列化样板，直接跳过。需要读的是这些类：

| 类 | 作用 | 一句话 |
| --- | --- | --- |
| `Constant`、`YClampedGradient` | 叶子 | 常数；按 y 夹紧的线性渐变 |
| `Noise`、`ShiftedNoise`、`ShiftA/ShiftB`、`WeirdScaledSampler` | 噪声叶子 | 采样噪声（可带坐标偏移 / 随值缩放） |
| `Ap2`、`MulOrAdd`（`TwoArgumentSimpleFunction`） | 二元运算 | `add / mul / min / max`；与常数运算时退化为更快的 `MulOrAdd` |
| `Mapped` | 一元变形 | `abs/square/cube/half_negative/quarter_negative/squeeze` |
| `Clamp`、`RangeChoice` | 限幅 / 分支 | 按区间选择走哪个子树 |
| `Spline` | 样条 | 把 `CubicSpline` 包成密度函数 |
| `Marker`（五种） | 缓存标记 | `Interpolated / FlatCache / Cache2D / CacheOnce / CacheAllInCell` |
| `HolderHolder` | 引用 | 指向另一个已注册的函数（相当于“函数名”） |
| `BlendAlpha/BlendOffset/BlendDensity` | 与旧版本区块的边界融合 | 纯新世界里相当于恒等，**可以跳过** |
| `BeardifierMarker` | 结构旁的地形贴合 | 村庄等结构周围把地形“垫高/挖空”，了解即可（见 `Beardifier.java`） |
| `EndIslandDensityFunction` | 末地岛屿 | 可以跳过 |

## 读代码时的三条经验

1. **从调用链读，不要从文件开头读。** 例如：`ChunkStatus.NOISE` → `NoiseBasedChunkGenerator.fillFromNoise` → `doFill` → `NoiseChunk.getInterpolatedState`。每一步只回答“输入是什么、输出写到哪、随机数从哪来”。
2. **看到 `Holder`、`Codec`、`Registry` 就当成“按名字取东西”。** 它们是序列化与注册机制，与算法无关。
3. **遇到不懂的数，先去 JSON 里找它的真实值。** 比如 `NoiseSettings` 的 `size_horizontal=1`、`size_vertical=2` 乘 4 就是 cell 的 4×8。
