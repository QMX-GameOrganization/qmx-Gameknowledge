> 对应源码：`biome/Climate`（539 行）、`MultiNoiseBiomeSource`（96）、`BiomeManager`（108）、`OverworldBiomeBuilder`（1069，**只需了解结构**）。

## 要点

- 群系不是“再生成一张图”，而是**用六个气候参数在一张表里找最近的条目**。其中三个（`continentalness`、`erosion`、`weirdness`）和地形样条用的是**同一批低频场**，所以群系与地形天然一致：深海群系出现在深海海底，山峰群系出现在山峰。
- 查表用的是 R-Tree（空间索引）+ “上次结果作为起点”的剪枝，查得快。
- 群系只存 **4×4×4 一个**（比方块粗 4 倍），查询时再用一个抖动函数把边界“放大”成参差的形状。

## 六个气候参数

| 参数 | 来源 | 范围 | 说明 |
| --- | --- | --- | --- |
| `temperature` | 噪声 `temperature`（`ShiftedNoise`，`firstOctave=-10`） | -1 ~ 1 | 冷 ↔ 热 |
| `humidity` | 噪声 `vegetation`（`firstOctave=-8`） | -1 ~ 1 | 干 ↔ 湿 |
| `continentalness` | 与地形共用的 `continents` | 约 -1.2 ~ 1 | 海 ↔ 陆 |
| `erosion` | 与地形共用的 `erosion` | -1 ~ 1 | 山地 ↔ 平坦 |
| `depth` | 密度函数 `depth`（**与 y 有关**，即第 5 页的 `yClampedGradient + offset`） | 约 -2 ~ 2.5 | 相对于地表的深度。地表之上为负，地表处为 0，地下为正 |
| `weirdness` | 与地形共用的 `ridges` | -1 ~ 1 | 折叠后表示山谷/山峰 |

`depth` 是唯一和高度有关的参数，所以**同一个 (x,z) 在不同 y 可以有不同的群系**。`OverworldBiomeBuilder` 里的做法很直观：

| 类别 | `depth` 取值 | 例子 |
| --- | --- | --- |
| 地表群系 | 两个点：`0.0` 与 `1.0`（每个地表群系登记两条） | 平原、森林、沙漠 …… |
| 地下群系 | 区间 `[0.2, 0.9]` | 繁茂洞穴（湿度 ≥ 0.7）、溶洞（大陆性 ≥ 0.8） |
| 最深处 | 点 `1.1` | 深暗之域 |

`Climate.target(...)` 把每个参数 `×10000` 取整为 `long`（`quantizeCoord`），后面全部用整数运算，避免浮点比较问题。

## 群系怎么选：最近的参数点

数据里的每个群系条目是一个 **`ParameterPoint`**：六个参数各是一个区间 `[min, max]`，外加一个 `offset`。

```java
// Climate.ParameterPoint.fitness（数值越小越匹配）
fitness = Σ_{6个参数}  ( 区间距离(目标值, 该区间) )²  +  offset²;
// 区间距离：落在区间内为 0；否则是到最近端点的距离
```

对一个 `TargetPoint`（六个目标值），在全部条目里挑 `fitness` 最小的那个群系。`offset` 是留给数据的“人工偏置”：它越大，这个条目越难被选中。主世界的 `OverworldBiomeBuilder` 里所有条目的 `offset` 都是 0，所以你自己的实现里完全可以不要它。

### 为什么需要 R-Tree

主世界的参数点成百上千，对每个 4×4×4 的位置都线性扫描一遍太慢。`Climate.RTree` 把参数点组织成树：

```text
叶子：一个 ParameterPoint
内部节点：最多 6 个子节点（CHILDREN_PER_NODE = 6），记录“包住所有子节点的 7 维区间盒”
搜索：对每个子节点算“目标点到它区间盒的距离”（一个下界），
      如果下界已经 ≥ 当前最优，就整棵子树跳过
```

这是典型的**分支限界**。还有一个很实用的细节：

```java
// RTree.search
Leaf leaf = root.search(target, lastResult.get() /* 上一次的结果 */, metric);
lastResult.set(leaf);
```

`lastResult` 是 `ThreadLocal`，保存**这个线程上一次查到的叶子**，下次查询以它为初始最优值。相邻的两个 4×4×4 位置气候几乎一样，常常落在同一个群系，起始的“当前最优”就已经很好，大量子树一开始就被剪掉。**利用空间连续性做搜索起点**，几乎不增加代码，却明显加速。

## OverworldBiomeBuilder：一张分层的“参数 → 群系”表

这个文件 1069 行，但结构只有三层，**读结构，不读细节**：

1. 先把每个参数切成几档（见下表）。
2. 用 `continentalness × erosion × weirdness` 决定“地形大类”：海、海岸、平原、高原、山地、碎裂地形……
3. 在每个大类里再用 `temperature × humidity` 的 5×5 矩阵挑具体群系。

| 参数 | 档位（源码里的 `Parameter` 数组） |
| --- | --- |
| `temperature`（5 档） | -1~-0.45 冻、-0.45~-0.15 冷、-0.15~0.2 温、0.2~0.55 暖、0.55~1 热 |
| `humidity`（5 档） | -1~-0.35、-0.35~-0.1、-0.1~0.1、0.1~0.3、0.3~1 |
| `erosion`（7 档） | -1~-0.78、-0.78~-0.375、-0.375~-0.2225、-0.2225~0.05、0.05~0.45、0.45~0.55、0.55~1 |
| `continentalness` | 蘑菇岛 -1.2~-1.05、深海 -1.05~-0.455、海 -0.455~-0.19、海岸 -0.19~-0.11、近内陆 -0.11~0.03、中内陆 0.03~0.3、远内陆 0.3~1 |

最常用的“中间群系”矩阵 `MIDDLE_BIOMES[温度][湿度]`（行：温度由冷到热；列：湿度由干到湿）：

| | 湿度 0 | 湿度 1 | 湿度 2 | 湿度 3 | 湿度 4 |
| --- | --- | --- | --- | --- | --- |
| 温度 0（冻） | 雪原 | 雪原 | 雪原 | 积雪针叶林 | 针叶林 |
| 温度 1（冷） | 平原 | 平原 | 森林 | 针叶林 | 原始云杉针叶林 |
| 温度 2（温） | 繁花森林 | 平原 | 森林 | 桦木森林 | 黑森林 |
| 温度 3（暖） | 热带草原 | 热带草原 | 森林 | 丛林 | 丛林 |
| 温度 4（热） | 沙漠 | 沙漠 | 沙漠 | 沙漠 | 沙漠 |

另有 `MIDDLE_BIOMES_VARIANT`（变体，如冰刺平原、向日葵平原）、`PLATEAU_BIOMES`（高原）、`SHATTERED_BIOMES`（山地/风袭丘陵）等同样形状的表。**这就是“按气候挑群系”的全部逻辑**，剩下的几百行只是“哪一档的 continentalness × erosion × weirdness 用哪张矩阵”的组合枚举。

### 地形与群系用的是同一套阈值

`OverworldBiomeBuilder` 里有这些常量：`PEAK_START = 0.56666666F`、`HIGH_START = 0.4F`、`NEAR_INLAND_START = -0.11F`、`MID_INLAND_START = 0.03F`……

回头看第 4 页的 `TerrainProvider.buildRidgeJaggednessSpline`：锯齿样条的控制点是 `peaksAndValleys(0.4F)`（= 0.2，从这里开始为 0）、它与 `peaksAndValleys(0.56666666F)`（= 0.7）的中点（0.45），以及 1.0。**同一组“高地从 0.4 开始、山峰从 0.5667 开始”的阈值，既划分了群系的高度档，也决定了山顶锯齿从哪里开始出现。**海岸（-0.19 ~ -0.11）与 offset 样条里那段近乎垂直的跳变（-0.18 ~ -0.16）也基本重合。这就是地形与群系看起来天然一致的原因：它们读的是同一份“地貌语言”。

## 存粗查细：4×4×4 的群系网格

**存储**：`ChunkAccess.fillBiomesFromNoise` 对每个 `LevelChunkSection` 做 4×4×4 = 64 次采样（`QuartPos`：一个 quart = 4 格），写进段里的群系容器。整个区块只有 4 × 4 × 96 = 1536 个群系值，比 98304 个方块少 64 倍。

**计算**：`Climate.Sampler.sample(qx, qy, qz)` 把 quart 坐标左移 2 位变回方块坐标，然后求六个密度函数。这六个函数在 `NoiseChunk.cachedClimateSampler` 里被 `wrap` 过，所以带 `flat_cache` 的 `continents / erosion / ridges` **和地形共用同一份缓存**，`temperature / vegetation` 内部用到的 `shift_x / shift_z` 也是缓存过的（这两个噪声本身是每次求值的）；`depth` 因为与 y 有关，不被缓存，但它里面的 `offset` 是缓存过的。

**查询**：任意方块坐标要知道群系时，`BiomeManager.getBiome` 不是直接取格子，而是做一次“模糊放大”：

![BiomeManager 的存粗查细](/qmx-Gameknowledge/assets/mc-source/18-biome-zoom.png)

1. 坐标先减 2，落到 4×4×4 的网格，得到在格内的相对位置 `(d, e, f)`（0~1）。
2. 取周围 **8 个**格子（立方体的 8 个角），对每个格子用 `LinearCongruentialGenerator` 派生出一个 ±0.45 的小抖动，计算“到抖动后角点”的距离平方。
3. 取最近的那个角，返回它的群系。

结果是群系边界不再是笔直的方格，而是带有 1~2 格参差的自然边缘（图右）。种子经 `sha256` 混淆后参与抖动（`obfuscateSeed`），所以抖动图案由世界种子决定，同样是确定性的。

**这个“存得粗、查得细”的结构几乎是个通用套路**：任何变化缓慢、但边界需要显得自然的属性（群系、温度着色、植被密度）都可以这样做。

## 给 Unity 项目的取舍

| 内容 | 建议 |
| --- | --- |
| 复用地形的 `continents / erosion / ridges` 作为群系输入 | **做**。这是最划算的设计：地形与群系天然一致，不需要额外采样 |
| `temperature` / `humidity` 两个独立噪声 | 做，`firstOctave` 取 -8 ~ -10，波长几千格 |
| 参数点 + “最近区间距离” | 做，实现只要几十行 |
| R-Tree | **暂时不做**。条目少于几十个时线性扫描更快更简单。条目上千、且查询很频繁时才需要，并且别忘了“上次结果起点”这个技巧 |
| 4×4×4 群系网格 + 模糊放大 | 做，群系边界一下就自然了，存储也小 |
| `depth` 参数与地下群系 | 等有了洞穴再做 |
| 整张 `OverworldBiomeBuilder` 表 | 不要照搬。自己设计 4~6 个群系即可 |

建议最小可用版本：

1. 噪声：`continents`、`erosion`、`temperature`、`humidity`（后两个新增）。
2. 条目：海洋、海滩、平原、森林、沙漠、雪原、山地，每个写一个 `ParameterPoint`（五个区间）。
3. 查询：对每个 4×4 的 quart 位置求 `fitness` 最小的条目，结果写进群系网格。
4. 用群系决定地表规则和特征（第 9 页）。

## 小结

- 群系 = 用六个气候参数在参数表里找最近条目。
- `continentalness / erosion / weirdness` 与地形共用，所以群系与地形一致；`depth` 让群系可以随高度变化。
- R-Tree + 上次结果起点让查表很快；群系存 4×4×4 一个，查询时模糊放大。
