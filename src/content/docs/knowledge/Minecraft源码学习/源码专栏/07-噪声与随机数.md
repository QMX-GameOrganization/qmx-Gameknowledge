## 要点

- 噪声分四层：**`ImprovedNoise`**（单层 Perlin）→ **`PerlinNoise`**（多 octave 叠加）→ **`NormalNoise`**（两份 `PerlinNoise` 相加 + 归一化）→ 密度函数里的 `Noise / ShiftedNoise`。
- 噪声的“配置”只有两个量：`firstOctave`（最低频是 2^firstOctave）和 `amplitudes`（每个 octave 的权重，0 表示这一层根本不创建）。
- `NormalNoise` 的目的不是“更好看”，而是**让数值范围可预测**，这样密度函数里的阈值（如 `-0.27`）才有统一的含义。
- `BlendedNoise` 是地形里唯一的 3D 噪声，它用一个“选择噪声”在两组噪声之间插值，并且有**提前退出**优化。
- 所有噪声的随机性都来自“种子 + 名字”，与创建顺序无关。

## ImprovedNoise：一层 Perlin

```java
// ImprovedNoise.noise(x, y, z) —— 简化
x += xo; y += yo; z += zo;                 // 每层有自己的随机偏移 (0~256)
xi = floor(x), xf = x - xi;  (y、z 同理)
// 8 个格点各取一个梯度，与“从格点指向采样点的向量”做点积
for corner in 8 corners:
    h = p[(p[(p[xi + cx] + yi + cy)] + zi + cz)];   // 用排列表 p[256] 做哈希
    v[corner] = dot(GRADIENT[h & 15], (xf - cx, yf - cy, zf - cz));
// 三个方向各做一次 smoothstep，再三线性插值
return lerp3(smoothstep(xf), smoothstep(yf), smoothstep(zf), v...);
```

三个设计点：

1. **排列表**：256 个数的随机排列，由 `RandomSource` 洗牌得到。它把整数格点坐标哈希成“梯度编号”，所以每个 `ImprovedNoise` 实例都有自己独立的噪声场。
2. **梯度**：`SimplexNoise.GRADIENT` 里 16 个向量，其中 12 个是立方体 12 条棱的方向（如 `(1,1,0)`、`(0,-1,1)`），再重复 4 个凑够 16 以便 `& 15`。
3. **smoothstep**：`6t⁵ − 15t⁴ + 10t³`，在 0 和 1 处一阶、二阶导数都为 0，保证格点之间过渡平滑、没有明显的网格痕迹。

此外每层有一个随机偏移 `(xo, yo, zo)`：避免不同噪声在原点处总是同相，也避免“以整数坐标为中心”的对称。

## PerlinNoise：octave 叠加

![octave 叠加](/qmx-Gameknowledge/assets/mc-source/20-noise-octaves.png)

左图是 `continentalness`（`firstOctave = -9`，`amplitudes = [1,1,2,2,2,1,1,1,1]`）每一层的贡献和叠加结果。核心循环：

```java
// PerlinNoise.getValue —— 简化
inputFactor = 2^firstOctave;                       // 最低频
valueFactor = 2^(n-1) / (2^n - 1);                 // 保证所有层权重之和归一
for (i, noiseLevel : levels) {                     // 从低频到高频
    if (noiseLevel != null)                        // amplitude == 0 的层根本没有创建
        sum += amplitudes[i] * noiseLevel.noise(wrap(x * inputFactor), wrap(y * ...), wrap(z * ...)) * valueFactor;
    inputFactor *= 2;                              // 频率翻倍
    valueFactor /= 2;                              // 权重减半
}
```

- **频率每层 ×2，权重每层 ÷2**：这是经典的分形噪声（fBm）。`amplitudes[i]` 在这个基础上再调节某一层的强弱。
- `firstOctave = -9` 意味着最低频的波长是 2⁹ = 512 个噪声单位。因为 `continents` 是 `shifted_noise(xz_scale = 0.25)`，噪声坐标 = 方块坐标 × 0.25，所以实际波长是 512 ÷ 0.25 = **2048 格**。这就是“大陆”尺度的来源。
- `amplitudes` 里写 `0.0` 的层（如 `erosion` 的 `[1,1,0,1,1]` 的第 3 项）不会创建 `ImprovedNoise`，求值时直接跳过，既省内存也省时间。
- `wrap(x) = x − floor(x / 2²⁵ + 0.5) · 2²⁵`：把坐标折回 ±2²⁴ 以内。`double` 在坐标极大时（几千万格）精度会损失，噪声会出现台阶，`wrap` 保证远处的精度。
- 每层的随机源来自 `positional.fromHashOf("octave_" + octave编号)`：**每个 octave 有自己固定的名字**，换 `amplitudes` 不会打乱其它 octave 的排列表。

## NormalNoise：两份叠加，并统一尺度

右图是 `NormalNoise` 的结构：两份独立种子的 `PerlinNoise`（蓝、绿），第二份的**输入坐标乘 1.0181268882175227**（频率略高），两份相加再乘 `valueFactor`（图中红线为了与分量同尺度比较，按 `(first + second) / 2` 画）。

```java
// NormalNoise
INPUT_FACTOR = 1.0181268882175227;
valueFactor  = (1/6) / expectedDeviation(最高非零 octave 下标 − 最低非零 octave 下标);
expectedDeviation(k) = 0.1 * (1 + 1/(k + 1));
getValue(x,y,z) = (first.getValue(x,y,z) + second.getValue(x*INPUT_FACTOR, y*INPUT_FACTOR, z*INPUT_FACTOR)) * valueFactor;
maxValue        = (first.maxValue + second.maxValue) * valueFactor;   // 供区间推理使用
```

为什么这样做：

- **打破规整感。** 单份 `ImprovedNoise` 在整数格点上值为 0，叠多层后仍能看出一点格子的痕迹。两份频率比为无理数附近的噪声叠加，格点永远对不齐。
- **统一尺度。** 不同的噪声有不同的 octave 数，如果不归一化，octave 越多的噪声幅度就越大，阈值没法比较。`valueFactor` 按“有效 octave 跨度”估计期望标准差，把不同噪声的幅度拉到同一量级。这样噪声相关的阈值（如 `cave_cheese < -0.27`、矿脉的 `|veininess| ≥ 0.4`）才有统一含义。
- **有明确的 `maxValue`。** 区间推理（第 3 页）需要知道每个噪声的上界。

## BlendedNoise：地形里唯一的 3D 噪声

```java
// BlendedNoise.compute —— 简化（xzMul = 684.412 * xz_scale，yMul = 684.412 * y_scale）
// ① main：8 个 octave，决定“混合系数” q
n = Σ main[p].noise(x·xzMul/80, y·yMul/160, z·xzMul/80, ...) / 2^-p
q = (n/10 + 1) / 2                      // 没有夹紧，实际常常远超出 [0,1]
// ② min / max：各 16 个 octave
l = q < 1 ? Σ minLimit[r].noise(x, y, z, ...) / 2^-r : 0       // q ≥ 1 时不用算 min
m = q > 0 ? Σ maxLimit[r].noise(x, y, z, ...) / 2^-r : 0       // q ≤ 0 时不用算 max
return clampedLerp(l/512, m/512, q) / 128;
```

直观理解：有两种“地形噪声”`min` 和 `max`，再有一个低频的“选择噪声”`main`。在 `q ≈ 0` 的地方地形像 `min`，`q ≈ 1` 的地方像 `max`，中间平滑混合。因为 `min` 和 `max` 的特征不同，大范围上就有了“这里粗糙那里平滑”的区域性差异。

两个值得学的点：

1. **提前退出。** `q ≥ 1` 或 `q ≤ 0` 时，另一组 16 层噪声完全不用算。这是最典型的“用廉价信号决定是否执行昂贵计算”。用移植版实测：`main` 噪声每层除以 `2^-p`（即低频层被放大），所以 `q` 的分布远超 `[0,1]`，约 **86% 的点落在区间之外**（42% 的点 `q ≤ 0`，44% 的点 `q ≥ 1`），只有约 14% 的点需要两组都算。40 层 octave 平均能省掉约三分之一。这也说明 `BlendedNoise` 大多数时候其实是在 `min`、`max` 两种地形里**硬选一个**，只有一条较窄的过渡带才是混合。
2. **y 方向的“涂抹”（smear）。** `ImprovedNoise.noise` 有两个额外参数 `(yScale, yMax)`：把 y 的小数部分按 `yScale` 量化：`r = (yMax ≥ 0 && yMax < 小数y) ? yMax : 小数y`，`s = floor(r / yScale) · yScale`，梯度点积用 `小数y − s`，smoothstep 仍用原来的小数 y。这会让噪声在 y 方向呈现台阶，是早期 Minecraft 地形那种“平台感”的来源。这部分是兼容旧版的历史包袱，了解即可。

`684.412` 这类常数来自旧版地形，**不用深究**；把它当成“这个噪声的基础频率”就好。

## ShiftedNoise：域扭曲

![shift_x / shift_z 的域扭曲](/qmx-Gameknowledge/assets/mc-source/17-shift-domain-warp.png)

`continents / erosion / ridges` 不是直接用 `Noise`，而是 `ShiftedNoise`：

```text
continents(x, z) = noise_continentalness( x·0.25 + shift_x(x,z),  0,  z·0.25 + shift_z(x,z) )
shift_x = 4 · offset_noise( x·0.25, 0, z·0.25 )
shift_z = 4 · offset_noise( z·0.25, x·0.25, 0 )
```

先用一个小尺度的“偏移噪声”（`firstOctave = -3`，波长约 8 个噪声单位）把采样点推一下，再去采样大尺度的噪声。这叫**域扭曲**（domain warping）。中图红线是加了扭曲后的海岸，黑虚线是没有扭曲时的海岸。位移量在 4 个噪声单位以内（右图），换成方块约十几格：海岸线没有被大幅改变，只是多出了自然的细小曲折。

`shift_a / shift_b` 用的是同一个噪声，只是把坐标轴互换（`shift_z` 用 `(z, x, 0)`），所以两个方向的位移互不相同但又来自同一个噪声场。

## 随机数：位置随机与名字哈希

Minecraft 的随机源接口有三种能力：

| 方法 | 含义 | 用在哪 |
| --- | --- | --- |
| `PositionalRandomFactory.fromHashOf(名字)` | 同一个名字永远给出同一个随机源 | 给每个噪声、每个 octave 分配独立的随机源 |
| `PositionalRandomFactory.at(x, y, z)` | 同一个坐标永远给出同一个随机源 | 含水层中心、矿脉的概率判定 |
| `RandomSource.forkPositional()` | 从当前随机源“分叉”出一个位置随机工厂 | 把一个种子扩展成可按名字/坐标取值的一族随机源 |

默认使用 `XoroshiroRandomSource`（Xoroshiro128++）；`LegacyRandomSource`（Java 的线性同余）并非只是历史遗留：下界、末地等维度的 `noise_settings` 里 `legacy_random_source` 仍为 true，`BlendedNoise` 的 octave 也始终用旧式的 `createLegacyForBlendedNoise` 播种；主世界的气候噪声才是 Xoroshiro + 名字哈希。具体的位运算不必读，**记住接口形状**：你的项目只需要一个“种子 + 名字 / 坐标 → 随机数”的纯函数，就能获得同样的确定性。

## 噪声配置速查

下面是 overworld 地形相关噪声（来自 `worldgen/noise/*.json`）。读法：`firstOctave` 越小越“大尺度”；括号里是 `amplitudes`。

| 噪声 | firstOctave | amplitudes | 最大尺度（噪声单位 → 方块，按 xz_scale 0.25） | 用途 |
| --- | --- | --- | --- | --- |
| `continentalness` | -9 | 1,1,2,2,2,1,1,1,1 | 512 → 约 2048 格 | 海陆 |
| `erosion` | -9 | 1,1,0,1,1 | 512 → 约 2048 格 | 侵蚀度 |
| `ridge` | -7 | 1,2,1,0,0,0 | 128 → 约 512 格 | 山脊（weirdness） |
| `temperature` | -10 | 1.5,0,1,0,0,0 | 1024 → 约 4096 格 | 温度 |
| `vegetation` | -8 | 1,1,0,0,0,0 | 256 → 约 1024 格 | 湿度/植被 |
| `jagged` | -16 | 全 1（16 项） | 65536 ÷ 1500（xz_scale） → 约 44 格 | 山顶锯齿 |
| `offset`（shift） | -3 | 1,1,1,0 | 8 → 约 32 格 | 域扭曲 |

规律很清楚：**决定“哪里是海、哪里是山”的是几千格尺度的低频噪声；细节（锯齿、扭曲）靠高频噪声叠加。** 这也是为什么这些场可以每 4 格才算一次而不失真。

## 在 Unity 里复刻

想与游戏结果逐点一致，必须严格复刻 `Xoroshiro`、`fromHashOf` 的哈希算法和排列表洗牌顺序，成本较高。**学习阶段不需要。**只要保持以下几点，你得到的就是“Minecraft 风格”的噪声：

```csharp
// 最小的 PerlinNoise octave 叠加，语义与源码一致
float Sample(float x, float y, float z) {
    float sum = 0, freq = Mathf.Pow(2, firstOctave);
    float weight = Mathf.Pow(2, n - 1) / (Mathf.Pow(2, n) - 1);
    for (int i = 0; i < n; i++) {
        if (amplitudes[i] != 0)
            sum += amplitudes[i] * levels[i].Noise(Wrap(x * freq), Wrap(y * freq), Wrap(z * freq)) * weight;
        freq *= 2; weight *= 0.5f;
    }
    return sum;
}
```

| 要点 | 原因 |
| --- | --- |
| 用 `firstOctave + amplitudes` 描述噪声，不要写死频率 | 以后要调大尺度，只改数据 |
| 每个 octave 有自己的名字 / 随机源 | 改某一层不会打乱其它层 |
| 做 `NormalNoise` 式的两份叠加 + 归一化 | 阈值有统一含义，也更自然 |
| 对 `amplitudes = 0` 的层跳过 | 省时间 |
| 大坐标用 `wrap` | 精度，尤其是 `float` 实现 |
| 低频场做缓存（每 4×4 格一个） | 第 10 页 |

## 小结

- 噪声层级：`ImprovedNoise → PerlinNoise → NormalNoise → 密度函数节点`。
- `firstOctave` 决定尺度，`amplitudes` 决定每层强弱，0 表示不创建。
- `NormalNoise` 用两份噪声相加打破规整，并按 octave 跨度归一化幅度。
- `BlendedNoise` 用 `main` 噪声在 `min / max` 之间选择，并在 `q` 超出 [0,1] 时提前退出。
- 随机性来自“种子 + 名字 / 坐标”，与调用顺序无关。

## 自测

1. `firstOctave = -9`、`xz_scale = 0.25` 的噪声，最大特征尺度大约是多少方块？
2. `amplitudes` 里写 0 会发生什么？
3. 为什么 `NormalNoise` 要乘 `valueFactor`？
4. 在 `BlendedNoise` 里，什么时候不需要计算 `maxLimit` 那 16 层噪声？

参考答案：① 2⁹ ÷ 0.25 = 2048 格。② 对应的 `ImprovedNoise` 不创建，求值时跳过。③ 让不同 octave 配置的噪声幅度落在可比较的量级，阈值才有统一含义。④ 当 `q ≤ 0` 时，结果只取 `minLimit` 一侧。
