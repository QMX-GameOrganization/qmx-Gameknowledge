## 这个专栏是什么

本目录里已有的笔记（密度函数扩展、样条函数、y 轴渐变、优化记录）是**你自己的实践和理解**：你手搓了什么、遇到了什么问题。这个专栏补的是另一半：

| | 已有笔记 | 源码专栏 |
| --- | --- | --- |
| 视角 | 我怎么做 | Mojang 怎么做，为什么这样做 |
| 内容 | 实验、效果图、踩坑 | 设计、原理、优化手段、源码位置 |
| 用途 | 记录进度 | 查缺补漏、对照自己的实现 |

读者设定：用 Unity（或类似引擎）做体素 / 程序化生成，重点关心**生成算法**和**性能**，不打算复刻整个 Minecraft。

## 全景：从种子到方块

下面是一个区块从“空”走到“有地形”的主线（括号里是 `ChunkStatus` 的名字）。**粗体**是本项目的主线。

```text
种子 seed
  └─ RandomState：用“名字哈希”给每个噪声/随机源派生独立的种子（保证确定性）

结构起点 (STRUCTURE_STARTS / REFERENCES)   先决定村庄、要塞等“大东西”落在哪
  │
生物群系 (BIOMES)                           按 4×4×4 的粗网格，用 6 个气候参数查表
  │
**地形主体 (NOISE)**                        finalDensity(x,y,z) > 0 即实心；cell 插值 + 缓存
  │   └─ 含水层 Aquifer：决定“空”的地方是空气、水还是岩浆
  │   └─ 矿脉 OreVeinifier：巨型铜/铁矿脉直接在这一步写入
  │
地表规则 (SURFACE)                          草/沙/雪/泥土/基岩 …… 
  │
洞穴雕刻 (CARVERS)                          传统“随机游走”洞穴与峡谷
  │
特征 (FEATURES)                             矿石、树、花草、湖泊；结构也在这一步落地
  │
光照 / 生成生物 / 变成可玩区块 (LIGHT … FULL)
```

区块变成 `FULL` 之后，世界进入**运行时**：方块更新与计划刻（红石、水流）、光照更新、自然刷新生物、结构的模板放置等机制接手（第 12~15 页，扩散类机制与爆炸见第 20 页；客户端网格与区块调度见第 16、17 页）。它们与生成阶段共享同一套思想：确定性、数据驱动、只做必要的计算。

整套流程有三个反复出现的设计思想，读源码时带着它们会轻松很多：

1. **数据驱动、声明式**：地形不是写死的 `if/else`，而是一张“密度函数图”（JSON），运行时把图编译成对象再求值。
2. **阶段分离、依赖显式**：每个阶段只做一件事，并明确声明需要邻居区块到达哪个阶段。
3. **确定性**：同一个种子在任何线程、任何加载顺序下结果必须一致，所以随机数都从“种子 + 名字/坐标”派生。

## 取舍原则

**1. 学函数的“形状与作用”，不背参数。** 你在阶段小记里已经得出这个结论：不要去猜每个常数的含义。专栏的做法是把每个函数画出来，只回答三个问题：它把输入变成了什么形状？为什么需要这个形状？去掉它会出什么问题？例如 `0.64`、`-0.50375`、`1.5625` 这些数，只需要知道它们**起什么作用**（缩放、对齐海平面、闸门阈值），不需要背。

**2. 区分“算法”与“工程”。** 地形算法（密度函数、样条、噪声）是主线；`Codec`、注册表、`PalettedContainer`、存档属于工程支线。先用最朴素的数据结构把算法跑通，再决定要不要引入工程支线的东西。

**3. 优化是一条独立的线。** 优化的前提只有一个：搞清楚**哪些值只依赖 (x,z)、哪些值变化缓慢可以插值、哪些子树可以按条件跳过**。懂了这三点，Mojang 用的每一种缓存和插值你都能自己推出来。第 10 页把它们集中讲。

## 推荐的三轮阅读

**第一轮：搞懂“地形是怎么长出来的”**（03 → 04 → 05）。读完你应该能不看资料，口头讲清楚 `sloped_cheese` 每一项的含义，并且能解释自己之前笔记里“上空非常乱”的原因。

**第二轮：搞懂“为什么这么快”**（10 → 06 → 02）。读完你应该能回答：为什么 `Interpolated` 里放整棵洞穴子树却不慢？为什么浅处不算洞穴噪声？为什么 NOISE 阶段可以并行？

**第三轮：补齐整条流水线**（07 → 08 → 09）。噪声、群系、地表、洞穴、特征。这一轮可以按项目进度穿插着读，不必一次读完。

**第四轮（可选）：运行时系统**（12 → 13 → 14 → 15）。建筑与结构、方块更新 / 红石 / 水流、实体刷新、光照更新。等地形生成稳定、开始做“活的世界”时再读。

**第五轮（可选）：补充专题**。按需要挑着读：做渲染优化时读 16（客户端网格）；做流式加载时读 17（区块调度）；想让矿、树、晶洞更像原版时读 18（地物造型）；做其它维度时读 19（下界与末地）；做火、爆炸、幽匿、叶子衰减这类扩散机制时读 20。

遇到想看原始代码的地方，先翻 01 的“源码地图”，里面标了每个文件的行数、读哪几个方法、跳过什么。

## 关于专栏里的图

大部分曲线、剖面、热力图都**不是示意**，而是用 Python（`numpy`）把源码里的算法逐段移植后算出来的：

- 样条（`TerrainProvider` → `CubicSpline`）与数据包里烘焙好的 `offset.json / factor.json / jaggedness.json` 逐点对比，最大误差在 1e-6 量级，所以第 04、05 页里的 offset/factor/jaggedness 曲线可以当作真值看。
- 噪声（`ImprovedNoise → PerlinNoise → NormalNoise`、`BlendedNoise`）算法一致，但随机数换成了 `numpy` 的，所以**不会和游戏里某个种子的具体地形逐点一致**，只在频率、幅度、统计特性上一致。
- 末地外岛（第 19 页，图 35、36）连随机数一起移植（`LegacyRandomSource` + 单纯形噪声），在给定世界种子的前提下，结果就是游戏里的外岛分布；但这个移植没有和游戏实际输出逐点对照过。
- 概念图（流水线、树状图、格点示意）是手绘的结构图。

脚本在仓库的 `scripts/mc-source-figures/` 下，可以改参数重新出图。想验证自己的实现，最实用的办法是：把自己的样条/函数输出和这里的曲线叠在一起比。
