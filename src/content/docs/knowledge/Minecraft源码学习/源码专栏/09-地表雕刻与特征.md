## 要点

- **地表规则**是一份“决策列表”：条件 + 方块。它被惰性求值：只依赖 (x,z) 的条件每列只算一次，依赖 y 的条件每个方块才算。
- **传统洞穴（carver）**不是密度函数，而是“从源区块出发的随机游走”。关键思想：洞穴由**源区块**决定，但可以伸进最远 8 个区块外，所以雕刻某个区块时要遍历周围 17×17 个源区块。
- **特征**（矿石、树、花）= 一个“放什么”（`ConfiguredFeature`）加一串“放在哪”（`PlacementModifier`）。位置修饰器把一个起点逐级变成一批候选位置，像一条流管线。
- **结构**用 `random_spread`：把世界切成大格子，每格用“种子 + 格子坐标 + 盐”决定唯一的起点。
- 这四项都是“**确定性随机 + 跨区块**”的典型：随机数一律由种子与坐标派生，写入范围被严格限制在允许的区块内。

## 地表规则：把石头换成草、沙、雪

`NOISE` 阶段结束后，整片地形全是石头（以及水、岩浆、空气）。`SURFACE` 阶段对每一列把顶部几格换成合适的方块。

### 外层：逐列自顶向下扫描

```java
// SurfaceSystem.buildSurface —— 简化
for 每一列 (x, z):
    top = heightmap(WORLD_SURFACE_WG)[x,z] + 1;      // 用 NOISE 阶段留下的高度图直接找到最高点
    ctx.updateXZ(x, z);                              // 本列的 XZ 相关量失效
    stoneDepthAbove = 0;  waterHeight = -∞;
    for y = top .. 最低:
        b = 方块(x,y,z);
        if 空气:          stoneDepthAbove = 0; waterHeight = -∞;
        elif 流体:         记下水面位置 waterHeight（第一次遇到时）
        else:              // 固体
            stoneDepthAbove++;                       // 上方连续固体的数目
            stoneDepthBelow = 到这一段固体底部的距离 // 每段固体只向下扫描一次
            ctx.updateY(stoneDepthAbove, stoneDepthBelow, waterHeight, x, y, z);
            if (b == 默认方块) { r = rule.tryApply(x,y,z); if (r != null) 写入 r; }
```

两点值得注意：

1. **高度图是在 NOISE 阶段顺手维护的**（`heightmap.update` 在 `doFill` 里），SURFACE 才能直接定位顶部，不用从 y=320 开始扫。
2. 传给规则的是“**离空气多远**”（`stoneDepthAbove`/`stoneDepthBelow`），而不是绝对高度。所以“地表下 3 格是泥土”这条规则同时适用于山顶、洞穴顶和洞穴底。

### 内层：条件 + 规则

规则是一棵树，叶子是“方块”，节点是：

| 规则类型 | 含义 |
| --- | --- |
| `block` | 返回一个固定方块 |
| `sequence` | 依次尝试子规则，**第一个返回非空的获胜**（类似 `if / else if`） |
| `condition`（`ifTrue(条件, 规则)`） | 条件成立才执行子规则，否则返回空 |

条件有这些：`stone_depth`（离地面/洞穴顶的距离）、`y_above`（绝对高度）、`water`（水深）、`biome`、`noise_threshold`（噪声落在某区间）、`vertical_gradient`（基岩、深板岩的随机渐变过渡）、`steep`（陡坡）、`hole`、`above_preliminary_surface`、`temperature`。

主世界的规则（`SurfaceRuleData.overworldLike`）就是一长串这样的嵌套：先放基岩，再按群系挑，再按是否有水决定草方块还是泥土……

顶层 `sequence` 的顺序是：**基岩底层 → （地表以上才求值的）群系规则 → 深板岩渐变**：

```java
builder.add( ifTrue(verticalGradient("bedrock_floor", bottom, aboveBottom(5)), BEDROCK) );   // 最底 5 层，概率渐变
builder.add( ifTrue(abovePreliminarySurface(), surfaceRulesByBiome) );                         // 只在“初步地表”之上
builder.add( ifTrue(verticalGradient("deepslate", absolute(0), absolute(8)), DEEPSLATE) );     // y 0~8 之间随机过渡到深板岩
```

`verticalGradient` 的做法很巧：在两个高度之间，用**该方块的位置随机数**与线性概率比较（越深越可能是基岩），所以过渡带参差不齐，而且只依赖坐标，是确定性的。

### 两个值得抄的优化

**1. 惰性条件缓存。** 每个条件对象保存一个“上次求值的时间戳”：

```java
// SurfaceRules.LazyCondition —— 简化
boolean test() {
    long now = context.lastUpdateXZ（或 lastUpdateY，取决于条件类型）;
    if (now == this.lastUpdate) return this.result;     // 上下文没变，直接用缓存
    this.lastUpdate = now;  this.result = compute();  return this.result;
}
```

`Context.updateXZ` 换了列就把 XZ 计数器 +1（同时也让 Y 计数器 +1，并立即算出本列的表层深度），`updateY` 换了方块就把 Y 计数器 +1。于是群系查询、表层深度噪声这类“只依赖 (x,z)”的条件，**一列只算一次**；只有真正依赖 y 的条件才每块重算。规则树被反复用同一批条件查询时，这几乎不增加代码，却省掉大量重复计算。

**2. `abovePreliminarySurface`：先用廉价估计跳过深处。** 地表规则很复杂（群系、噪声、水深），但绝大多数方块深埋在地下，永远不会被改写。`NoiseChunk.preliminarySurfaceLevel` 在 quart 网格的列上，用 `initial_density_without_jaggedness`（不含锯齿的初始密度）从世界顶部起以 cell 高度（8 格）为步长向下扫，找到第一个密度 > 0.390625 的高度，当作“初步地表”并缓存。`SurfaceRules` 取 16×16 范围四个角上的初步地表做双线性插值，再加上表层深度并减 8，得到 `minSurfaceLevel`；`abovePreliminarySurface` 条件只在 `y ≥ minSurfaceLevel` 时成立，深处的方块直接跳过整套群系规则，只走基岩和深板岩渐变。

`getSurfaceDepth` 决定“表层有多厚”：`(int)(noise(x,z)·2.75 + 3 + 随机·0.25)`（强转整数，向 0 截断），也就是大约 3 格上下浮动，由一个 2D 噪声与位置随机共同决定。

## 传统洞穴：源区块 ±8

密度函数里的 cheese、spaghetti 洞穴是“新式洞穴”；`CARVERS` 阶段还有“旧式洞穴”（蠕虫洞）和峡谷，由 `carver/*` 实现。它们的核心问题是：**一条洞穴可能长达几十上百格，会穿过很多区块，怎么保证确定性、又不需要一个区块一个区块地“等”？**

答案是“**源区块**”思想：

```java
// NoiseBasedChunkGenerator.applyCarvers —— 简化
for (dx = -8; dx <= 8; dx++)
  for (dz = -8; dz <= 8; dz++) {                    // 以当前区块为中心的 17×17 个“源区块”
      source = (chunk.x + dx, chunk.z + dz);
      for (carver : 源区块群系的洞穴配置) {
          random.setLargeFeatureSeed(worldSeed + index, source.x, source.z);   // 种子只由源区块决定
          if (carver.isStartChunk(random))                                      // 例如洞穴 15%，峡谷 1%
              carver.carve(ctx, 当前区块, random, aquifer, source, carvingMask);
      }
  }
```

要点：

1. **同一个源区块用同一个种子，不管是“从哪个目标区块的视角”来重算**，洞穴的路径完全一样。所以每个区块独立地重算周围 289 个源区块的洞穴，只把“落在自己范围内”的那一部分写进去，邻居也做同样的事，最终拼起来是连续的。这避免了区块之间的任何同步。
2. 洞穴的最大长度是有限的：`getRange()` 默认为 4，隧道最多走 `(4·2 − 1)·16 = 112` 步，也就是离起点最远约 7 个区块。循环取 ±8 就足以覆盖“所有可能影响我的源区块”，这也是 `ChunkStatus.CARVERS` 要求邻居半径为 8 的原因。
3. 写入前先做包围盒裁剪：`carveEllipsoid` 如果球心离当前区块太远（> 16 + 2·半径）就整个跳过，并把循环范围夹在本区块的 16×16 里。
4. 一个 `CarvingMask`（每个区块一个位图）记录哪些方块已被挖过，避免重复处理。
5. 挖出的空间不是直接填空气，而是问一次**含水层**（`aquifer.computeSubstance(点, 0.0)`），所以海平面以下的洞穴会自动灌水或岩浆。

洞穴本身是“一串随机球体”：`CaveWorldCarver.carve` 先取 `nextInt(nextInt(nextInt(15)+1)+1)` 个起点（取三次嵌套的随机，使数量偏向小值），每个起点有 1/4 概率先挖一个房间，然后沿着随机方向（偏航角、俯仰角）一步步前进，每步在当前位置挖一个椭球，半径由 `thickness` 和 `sin` 曲线决定。

## 特征：矿石、树、花草

特征由两部分组成，一个“放什么”，一个“放在哪”：

| 部分 | 类 | 职责 |
| --- | --- | --- |
| 放什么 | `ConfiguredFeature` | 一个特征类型（`ore`、`tree`、`random_patch`……）加上它的配置（矿石种类、大小、树的参数） |
| 放在哪 | `PlacedFeature` | 一个 `ConfiguredFeature` 加上一串 `PlacementModifier` |

### 位置管线

```java
// PlacedFeature.placeWithContext —— 简化
Stream<BlockPos> stream = Stream.of(起点);                  // 起点是区块最小角
for (PlacementModifier m : placement)
    stream = stream.flatMap(pos -> m.getPositions(ctx, random, pos));   // 每个修饰器：一个位置 → 0 个、1 个或多个位置
stream.forEach(pos -> configuredFeature.place(level, generator, random, pos));
```

每个修饰器只做“位置变换”，可以**放大**（`count`：变成 N 个）、**移动**（`in_square`：随机偏移 0~15；`height_range`：随机选一个 y）、**过滤**（`biome`、`rarity_filter`、`block_predicate_filter`）。组合起来就像一条可复用的管线。

例子 1：煤矿（`placed_feature/ore_coal_upper.json`）：

```json
"placement": [ {"type":"count","count":30},
               {"type":"in_square"},
               {"type":"height_range","height":{"type":"uniform","min_inclusive":{"absolute":136},"max_inclusive":{"below_top":0}}},
               {"type":"biome"} ]
```

读法：每个区块 30 次尝试 → 每次在区块范围内随机 (x,z) → y 在 136 到世界顶之间均匀随机 → 只保留当前群系允许的位置。

例子 2：平原的树（`trees_plains`）：数量用加权列表（19 份概率 0 棵、1 份概率 1 棵，约每 20 个区块 1 棵）→ 随机 (x,z) → 水深过滤（水里不种）→ 用高度图 `OCEAN_FLOOR` 把 y 贴到地面 → 检查“这里能不能活一棵橡树苗”。

这个设计的价值是：**新增一种矿石或树不需要写代码，只要写一份 JSON，把现成的修饰器拼起来。**

### 11 个装饰阶段与种子

`GenerationStep.Decoration` 有固定的 11 个阶段：`raw_generation → lakes → local_modifications → underground_structures → surface_structures → strongholds → underground_ores → underground_decoration → fluid_springs → vegetal_decoration → top_layer_modification`。`applyBiomeDecoration` 的主循环就是“对每个阶段：先放这个阶段的结构，再放这个阶段的特征”。

```java
decorationSeed = random.setDecorationSeed(worldSeed, 区块最小角x, z);
for 阶段 k:
    for 结构 in 该阶段: random.setFeatureSeed(decorationSeed, 结构序号, k); 结构.放入区块
    for 特征索引 p in 3×3 区块里出现的所有群系的特征并集（升序）:
        random.setFeatureSeed(decorationSeed, p, k);       // 每个特征有自己独立的随机序列
        placedFeature.placeWithBiomeCheck(...)
```

要点：

- **按“全局特征序号”排序**（`FeatureSorter`）：不同群系的特征列表合并后顺序一致，邻居区块对同一个特征的相对顺序永远相同，保证确定性。
- **每个特征一个种子**：`setFeatureSeed` 把“区块基础种子 + 特征序号 + 阶段”揉成新种子，所以改动一个特征不会影响别的特征的随机序列。
- **写入范围**：`FEATURES` 用的是 `WorldGenRegion`，写半径为 1，意味着一个特征最多溢出到相邻一圈区块。矿脉、树冠超出 16 格的话也只能落在这一圈里。所以邻居区块必须先把地形和洞穴做完，这就是第 2 页金字塔里“第 2 圈到 CARVERS”的来由。

## 结构（了解即可）

村庄、要塞、废墟等大型结构由 `structure_set` 定义放置规则。最常用的是 `random_spread`：

```text
villages: spacing=34, separation=8, salt=10387312
```

```java
// RandomSpreadStructurePlacement.getPotentialStructureChunk —— 简化
region = (floorDiv(chunkX, spacing), floorDiv(chunkZ, spacing));          // 把世界切成 34×34 区块的大格子
random.setLargeFeatureWithSalt(seed, region.x, region.z, salt);
offset = (nextInt(spacing - separation), nextInt(spacing - separation));  // 0~25（linear 分布；部分结构用 triangular，取两次 nextInt 的平均）
return (region.x * spacing + offset.x, region.z * spacing + offset.z);    // 每个大格子恰有一个候选起点
```

含义：每个 34×34 区块的大格子里最多一个村庄起点，且至少与相邻格子的起点隔着 8 个区块；`salt` 让不同结构互不相关。要塞则用 `concentric_rings`（128 个要塞分布在围绕原点的同心环上）。

结构起点在 `STRUCTURE_STARTS` 阶段决定，包围盒覆盖到的区块在 `STRUCTURE_REFERENCES` 阶段登记，最终在 `FEATURES` 阶段由 `StructureStart.placeInChunk` 把每个区块与包围盒相交的那部分画进去。结构周围的地形贴合（`Beardifier`）则在 `NOISE` 阶段通过 `terrain_adaptation` 修改密度，所以 `NOISE` 需要邻居的“结构起点”但不需要邻居的方块。

## 给 Unity 项目的取舍

| 内容 | 建议 |
| --- | --- |
| 地表规则的 `sequence + condition` 结构 | **做**。把“草/泥土/沙/雪”写成数据，比散在代码里的 `if` 容易维护 |
| `stone_depth`（离地面多远）而不是绝对高度 | 做，它让规则对任何地形形状都适用 |
| 条件的惰性缓存 + `abovePreliminarySurface` | 做，实现简单、收益大 |
| 传统洞穴蠕虫 | 先跳过，用 cheese 洞穴（第 6 页）。需要时再做，并牢记“源区块 ±N” |
| `PlacedFeature` 修饰器管线 | 做。矿石、树、花草统一用它，先实现 `count / in_square / height_range / heightmap / biome` 五个 |
| 装饰阶段与特征种子 | 做。先分 3~4 个阶段（矿石 → 树 → 花草），每个特征独立种子 |
| 结构 | 最后做。先做一个“随机间隔放一个小房子” |

## 小结

- 地表规则是“决策列表 + 惰性条件”，用初步地表跳过深处。
- 传统洞穴由源区块决定，目标区块只重算周围 17×17 个源区块的洞穴并裁剪到自己范围，不需要区块间同步。
- 特征 = 放什么 + 一串位置修饰器；每个特征有独立种子，写入范围限制在邻居一圈。
- 结构用 `random_spread` 在大格子里选唯一起点。

## 自测

1. 为什么地表规则里用 `stone_depth` 而不是 `y` 来决定“表层三格泥土”？
2. 传统洞穴为什么每个区块要遍历 17×17 个源区块？
3. `count: 30`、`in_square`、`height_range` 这三个修饰器的顺序能调换吗？
4. `random_spread` 里 `separation` 的作用是什么？

参考答案：① `stone_depth` 是“离空气的距离”，山顶、洞穴顶、洞穴底都能用同一条规则。② 因为洞穴最远能从 7 个区块之外延伸过来，必须重算所有可能影响我的源区块的洞穴，再各自裁剪。③ 不能随意调换：`count` 先放大数量，`in_square` 再给每个位置分配随机 (x,z)，`height_range` 再随机 y。如果先 `in_square` 再 `count`，同一个随机 (x,z) 会被复制 30 份。④ 保证相邻格子的起点至少隔开 `separation` 个区块，避免两个结构贴在一起。
