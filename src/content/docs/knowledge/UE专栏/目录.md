这里从能在项目中找到的对象出发研究 Unreal Engine：先解释职责和数据流，再追源码，最后回到蓝图验证。首个专题是 [运动系统：CMC、Mover 与 GASP](/qmx-Gameknowledge/knowledge/ue专栏/运动系统/目录/)。

## 当前研究版本

本系列基于本机引擎 `5.8.4-58902052+++UE5+Release-5.8`，以及本地“游戏动画示例”工程中的 Game Animation Sample（下文简称 GASP）。这是本地样本的研究记录，不代表所有 GASP 版本的实现。Mover 在这套引擎中仍位于 `Plugins/Experimental`；升级时优先核对接口和蓝图默认值。

## 阅读方式

- **引擎机制**：给出源码相对路径、具体类型和函数，便于在自己安装的同版本引擎中查找。
- **样例实现**：使用 `/Game/...` 资源路径定位蓝图，区分组件默认配置、图节点连接与运行表现。
- **练习**：说明如何在复制的工程中验证；未执行的 PIE、联网和性能实验不会写成已验证结论。

从 Unity 转来，可以先阅读专题中的对象与职责，再研究 CMC。`Pawn` 不是 Unity `GameObject` 的严格等价物，AnimBP 也不只是 Animator Controller；这里采用职责对照，不把两套引擎逐项硬映射。
