> 适用版本：C# 9.0。

## 要点

- **运算符重载**让自己写的类型能用 `a + b`、`a == b`。必须写成 `public static`，且成对出现（`==` 和 `!=`）。
- **内部类（嵌套类）**把只给外层类用的辅助类型藏进外层类里，避免污染全局命名。
- **分部类（`partial`）**把同一个类拆成多个文件，Unity 的代码生成和编辑器扩展里常见。
- 三者都不难，重点是认出来、知道用在哪。

## 运算符重载

用一个简单的二维向量举例（Unity 的 `Vector2` 就是这样做的）：

```csharp
struct Vec2
{
    public float x, y;
    public Vec2(float x, float y) { this.x = x; this.y = y; }

    public static Vec2 operator +(Vec2 a, Vec2 b) => new Vec2(a.x + b.x, a.y + b.y);
    public static Vec2 operator -(Vec2 a, Vec2 b) => new Vec2(a.x - b.x, a.y - b.y);
    public static Vec2 operator *(Vec2 a, float k) => new Vec2(a.x * k, a.y * k);

    public static bool operator ==(Vec2 a, Vec2 b) => a.x == b.x && a.y == b.y;
    public static bool operator !=(Vec2 a, Vec2 b) => !(a == b);

    public override bool Equals(object obj) => obj is Vec2 v && this == v;
    public override int GetHashCode() => HashCode.Combine(x, y);
}

Vec2 pos = new Vec2(1, 2);
Vec2 velocity = new Vec2(3, 0);
Vec2 next = pos + velocity * 0.5f;             // 读起来就是数学公式
```

写 `==` 时编译器会提醒你同时重写 `Equals` 和 `GetHashCode`，保持三者一致，否则放进 `Dictionary` 或 `HashSet` 会出错。

可以重载的有 `+ - * / %`、比较运算符、一元运算符，以及 `implicit` / `explicit` 的类型转换。不能重载的有 `=`、`&&`、`||`、`.`。

**节制使用**：只有语义确实像"数学运算"时才重载。比如角色 `a + b` 是什么意思没人知道，写成方法 `Merge(a, b)` 更清楚。

## 内部类

```csharp
class Inventory
{
    private class Slot                         // 只有 Inventory 内部能使用 Slot
    {
        public string itemName;
        public int count;
    }

    private Slot[] slots = new Slot[20];

    public void Add(string name)
    {
        for (int i = 0; i < slots.Length; i++)
        {
            if (slots[i] == null)
            {
                slots[i] = new Slot { itemName = name, count = 1 };
                return;
            }
        }
    }
}
```

如果内部类是 `public`，外部要写 `Inventory.Slot` 才能访问。适合的场景：状态机里的状态类、某个管理器内部用的节点结构、一个类专属的数据结构。

## 分部类

```csharp
// Player.Stats.cs
partial class Player
{
    public int hp = 100;
    public int atk = 10;
}

// Player.Movement.cs
partial class Player
{
    public float speed = 3f;
    public void Move() { /* ... */ }
}
```

编译时两部分合并成一个 `Player`，字段和方法互相可见。使用场景：

1. 一个类太大，按职责拆成几个文件。
2. 工具生成了一部分代码（序列化、网络协议、UI 绑定），你另写一份手写部分，互不覆盖。
3. Unity 的 Source Generator 和一些插件要求类声明为 `partial`。

每一部分都要写 `partial`，且类名、访问级别要一致。

## 常见坑

- 只重载 `==` 没重载 `!=`，或者不重写 `Equals` / `GetHashCode`。
- 结构体里重载 `==` 后又拿 `object` 做比较，发生装箱。
- 把可变的内部类当作公开 API 返回出去，外部拿到后直接改内部状态。
- 分部类散落在好几个文件里，读代码时找不到某个成员在哪。
