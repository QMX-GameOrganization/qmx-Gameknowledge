> 适用版本：C# 9.0。

## 要点

- **属性**（property）看起来像字段，实际是一对 `get` / `set` 方法，可以在读写时加校验或触发逻辑。
- 对外暴露数据时，用属性而不是 `public` 字段：以后想加规则，调用方的代码不用改。
- `{ get; private set; }` 是最常用的写法：外部可读，只有自己能改。
- **索引器**让对象支持 `obj[i]`，常用于背包、棋盘这类"像容器"的类。

## 为什么需要属性

只要字段是 `public`，谁都能写 `player.hp = -999`。如果规则（不能为负、不能超过上限）要在每个调用点都检查，迟早漏掉一处。属性把规则收进一个地方：

```csharp
class Player
{
    private int hp;                    // 真正存数据的私有字段（后备字段）
    public int MaxHp { get; } = 100;   // 只读自动属性

    public int Hp
    {
        get { return hp; }
        set { hp = Math.Clamp(value, 0, MaxHp); }   // value 是赋值时右边的值
    }

    public bool IsDead => hp <= 0;     // 只读属性，每次访问时计算
}

Player p = new Player();
p.Hp = 500;                            // 看起来像赋值，实际调用 set
Console.WriteLine(p.Hp);               // 100，被限制在上限
p.Hp = -20;
Console.WriteLine(p.IsDead);           // True
```

调用方的写法和字段完全一样，所以后来才发现需要加规则时，不用改动任何调用代码。

## 自动属性

不需要额外逻辑时，让编译器代写后备字段：

```csharp
class Item
{
    public string Name { get; set; }               // 读写
    public int Id { get; private set; }            // 外部只读，类内部可写
    public int Price { get; init; }                // C# 9：只能在对象初始化时赋值
}
```

`init` 是 C# 9 的语法，但它依赖运行时里的 `IsExternalInit` 类型，Unity 没有自带，直接写会报编译错误，需要自己补一个同名的空类型才能用（待核实各 Unity 版本现状），入门阶段先不用它。命名惯例上，**属性用大写开头**（`Hp`），私有字段用小写（`hp` 或 `_hp`），这也是微软与 Unity 社区通用的风格。

## 表达式体与计算属性

```csharp
class Rect2
{
    public float Width { get; set; }
    public float Height { get; set; }
    public float Area => Width * Height;           // 没有后备字段，只是个计算结果
}
```

属性里**不要写耗时操作**。调用方会把它当字段看待，比如在循环里反复读取，不会预料到背后有复杂计算。

## 属性与 Unity

Unity 里 `transform.position` 就是属性，所以：

```csharp
// 以下为 Unity 代码示意
transform.position.y = 5;                 // 编译错误：属性返回的是 Vector3 的副本
var p = transform.position; p.y = 5; transform.position = p;   // 正确写法
```

Inspector 默认**不显示属性**，只显示字段。如果想显示自动属性的后备字段，需要写 `[field: SerializeField]`。

## 索引器

```csharp
class Inventory
{
    private string[] slots = new string[20];

    public string this[int index]                // 索引器：用 this[...] 定义
    {
        get
        {
            if (index < 0 || index >= slots.Length) return null;
            return slots[index];
        }
        set
        {
            if (index >= 0 && index < slots.Length) slots[index] = value;
        }
    }

    public string this[string itemName]          // 索引器也可以重载
    {
        get
        {
            for (int i = 0; i < slots.Length; i++)
                if (slots[i] == itemName) return slots[i];
            return null;
        }
    }
}

Inventory bag = new Inventory();
bag[0] = "长剑";                                // 调用 set
Console.WriteLine(bag[0]);                      // 调用 get
Console.WriteLine(bag["长剑"]);                  // 另一个索引器
```

`List<T>` 和 `Dictionary<K,V>` 的 `list[i]`、`dict[key]` 就是用索引器实现的。

## 动手试试

用属性守住血量范围，并用 `[ContextMenu]` 在不写输入代码的情况下触发：

```csharp
using UnityEngine;

public class Health : MonoBehaviour
{
    [SerializeField] private int maxHp = 100;
    private int hp;

    public int Hp
    {
        get => hp;
        private set => hp = Mathf.Clamp(value, 0, maxHp);     // 永远落在 0 到 maxHp 之间
    }
    public bool IsDead => hp <= 0;

    void Awake() { Hp = maxHp; }

    [ContextMenu("受伤 30")]
    void Hurt30()
    {
        Hp -= 30;
        Debug.Log($"Hp={Hp} 死亡={IsDead}");
    }
}
```

运行后，右键点击 Inspector 里这个组件的标题栏（或右上角三个点），选择"受伤 30"，连续点几次，看血量停在 0 而不会变成负数。再试把 `Hp` 的 `private set` 删掉，在另一个脚本里直接赋 `-999`，观察属性是否仍然拦住。

## 常见坑

- 属性的 `set` 里再给自己赋值（`Hp = value;`），造成无限递归。要给后备字段赋值。
- 把属性写得很重，调用方在 `Update` 里每帧读多次。
- 公开字段改成属性后，如果已经有序列化的存档或 Inspector 数据，需要留意序列化名称的变化。
- 索引器的 `get` 不做越界检查，调用方出错时难以定位。
