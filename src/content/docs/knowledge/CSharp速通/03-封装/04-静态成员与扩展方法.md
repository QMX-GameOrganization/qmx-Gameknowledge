> 适用版本：C# 9.0。

> **本篇主线标记**：本篇的 `GameMath` 是 `【主线必做】`，单例示例是 `【可选扩展】`；不要用单例替代无状态规则库。

## 要点

- 普通成员属于**对象**，每个对象一份；`static` 成员属于**类本身**，全体共享一份，通过类名访问。
- **静态类**只能包含静态成员，不能 `new`，用来放工具函数，如 `Math`、Unity 的 `Mathf`、`Debug`。
- **静态构造函数**在类第一次被使用前自动运行一次，没有参数、没有访问修饰符。
- **扩展方法**让你给已有类型"加"方法，不改它的源码，调用时像成员方法一样。

## 静态成员

```csharp
class Enemy
{
    public static int aliveCount = 0;          // 全体共享
    public string name;

    public Enemy(string name)
    {
        this.name = name;
        aliveCount++;                          // 每创建一个，共享计数加 1
    }

    public static void PrintAlive()            // 静态方法：不依赖某个具体对象
    {
        Console.WriteLine($"存活敌人：{aliveCount}");
        // Console.WriteLine(name);            // 编译错误：静态方法里没有"当前对象"
    }
}

new Enemy("史莱姆");
new Enemy("哥布林");
Enemy.PrintAlive();                            // 存活敌人：2，用类名调用
```

规则很简单：**静态方法里不能直接访问实例成员**，因为不知道是哪个对象。反过来，实例方法可以随便访问静态成员。

## 主线项目：封装一个可复用的数学规则库

现在项目里会同时出现玩家、敌人、陷阱和掉落物。它们都可能需要“限制数值”和“计算伤害”，但这些规则不属于某个具体对象，也不应该复制四份。这里把它们放进一个静态工具类：调用方只依赖输入和输出，不需要先实例化工具对象。

```csharp
using UnityEngine;

namespace CSharpSpeedrun.Gameplay
{
    /// <summary>集中存放无状态、可重复验证的游戏数学规则。</summary>
    public static class GameMath
    {
        public static int ClampInt(int value, int min, int max)
        {
            if (min > max) (min, max) = (max, min);
            return Mathf.Clamp(value, min, max);
        }

        public static int DamageAfterDefense(int rawDamage, int defense)
        {
            int safeDamage = Mathf.Max(rawDamage, 0);
            int safeDefense = Mathf.Max(defense, 0);
            return Mathf.Max(safeDamage - safeDefense, 1);
        }

        public static float DistanceSquaredXZ(Vector3 a, Vector3 b)
        {
            float dx = a.x - b.x;
            float dz = a.z - b.z;
            return dx * dx + dz * dz;
        }
    }
}
```

玩家和敌人的战斗脚本都可以直接调用：

```csharp
int damage = GameMath.DamageAfterDefense(attackPower, targetDefense);
hp = GameMath.ClampInt(hp - damage, 0, maxHp);
```

这里的工程意义很具体：规则只维护一份，所有系统得到相同结果；工具类没有对象状态，不需要 `new GameMath()`；测试时可以直接给定输入检查输出。`static` 适合这种“输入 → 输出”的无状态能力，不等于所有系统都应该做成全局单例。

## 静态类与常量

```csharp
static class GameConfig
{
    public const int MaxLevel = 99;                   // const：编译期常量，隐式 static
    public static readonly string Version = "1.0.2";  // 运行时确定的只读

    public static int Exp(int level) => level * level * 10;
}

Console.WriteLine(GameConfig.Exp(5));                  // 250
```

静态类适合放无状态的工具函数。如果里面保存了可变的静态字段，它就是个"全局变量"，要慎重：谁都能改，测试和排错都变难。

## 静态构造函数

```csharp
class Database
{
    public static readonly Dictionary<int, string> items;

    static Database()                           // 第一次使用 Database 前自动执行，只执行一次
    {
        items = new Dictionary<int, string> { { 1, "铁剑" }, { 2, "木盾" } };
    }
}
```

## 单例：有生命周期对象的谨慎选择

```csharp
class AudioManager
{
    public static AudioManager Instance { get; private set; }

    public AudioManager() { Instance = this; }
    public void Play(string clip) { Console.WriteLine($"播放 {clip}"); }
}

new AudioManager();
AudioManager.Instance.Play("爆炸");              // 任何地方都能访问
```

Unity 里常见的写法是在 `Awake` 里 `Instance = this;`，这样别的脚本可以直接 `AudioManager.Instance.Play(...)`。它适合确实只有一个、并且有生命周期的对象，例如场景级音频或存档服务；它不适合替代 `GameMath` 这类无状态工具。主线项目先用 Inspector 引用和事件传递依赖，只有明确需要跨场景唯一对象时再引入单例。

## 扩展方法

给一个你改不了的类型（比如 Unity 的 `Vector3`、系统的 `string`）加方法：

```csharp
// 以下为 Unity 代码示意（Vector3 来自 UnityEngine）
static class Extensions                          // 必须在静态类里
{
    public static float DistanceXZ(this Vector3 a, Vector3 b)    // 第一个参数前加 this
    {
        float dx = a.x - b.x;
        float dz = a.z - b.z;
        return (float)Math.Sqrt(dx * dx + dz * dz);
    }

    public static bool IsNullOrEmpty(this string s) => string.IsNullOrEmpty(s);
}

// 使用：像成员方法一样
// float d = player.position.DistanceXZ(enemy.position);
// bool empty = "".IsNullOrEmpty();
```

扩展方法的本质是静态方法的语法糖，**不能访问被扩展类型的私有成员**，也不能真的修改类型。LINQ 的 `Where`、`Select` 就是给 `IEnumerable` 加的扩展方法。

## 与 C++ 的差别

- C++ 的类静态成员需要在类外再定义一次；C# 声明时直接初始化即可。
- C++ 可以有全局函数；C# 用静态类里的静态方法承担这个角色。
- C++ 没有扩展方法，类似的效果通常靠自由函数完成。

## 在 Unity 里用到它

主线项目会先复用 `GameMath.ClampInt`、`GameMath.DamageAfterDefense` 和 `GameMath.DistanceSquaredXZ`，之后玩家攻击、敌人受伤、陷阱伤害和掉落判定都调用同一套规则。你每天都在用静态成员：`Time.deltaTime`、`Mathf.Clamp`、`Debug.Log`、`Input.GetKeyDown`、`Physics.Raycast`，它们都是 Unity 提供的静态类或类上的静态成员，不需要先 `new`。游戏里的"全局管理器"（音频、存档、分数）常用单例，也就是一个静态的 `Instance` 属性。

## 动手试试：让玩家和陷阱复用同一条规则

> **代码归属**：`【实验代码】`。本段只放进 `Assets/Speedrun/Labs/` 临时验证；要进入小游戏主线，请跟随后文或目录中的 `【主线实践】` 文章，在 `Assets/Speedrun/Game/` 重新接入并完成验收。

1. 在 `Assets/Speedrun/Game/Gameplay/GameMath.cs` 创建上面的静态类。
2. 给玩家和陷阱各写一个调用点：输入相同的原始伤害与防御，Console 应得到相同结果。
3. 把 `ClampInt` 的 `min` 与 `max` 传反，确认方法仍能得到稳定结果；再把 `DamageAfterDefense` 的原始伤害改成负数，确认最低伤害规则没有被绕过。
4. 尝试写 `new GameMath()`，记录编译器为什么拒绝它，并说明这正是静态工具类想表达的约束。

```csharp
using UnityEngine;

public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }
    public int Score { get; private set; }

    void Awake()
    {
        if (Instance != null && Instance != this) { Destroy(gameObject); return; }
        Instance = this;                                  // 登记唯一实例
    }

    public void AddScore(int value)
    {
        Score += value;
        Debug.Log($"分数：{Score}");
    }
}

public class Coin : MonoBehaviour
{
    void Start()
    {
        GameManager.Instance.AddScore(10);                // 直接通过类名访问，不用拖引用
    }
}
```

场景里一个空物体挂 `GameManager`，再放 3 个物体挂 `Coin`，运行后分数应是 10、20、30。这个单例练习只用于理解生命周期；主线战斗计算应调用 `GameMath`，不要为了调用一个数学函数创建或寻找 `GameManager`。想一想：为什么 `Coin` 在 `Start` 里用 `Instance` 是安全的，而在 `Awake` 里用可能是空？（回看 0.3 篇的“Awake 管自己，Start 管别人”。）

## 项目应用决策：静态工具、实例对象和单例分工

无状态的数值规则调用 `GameMath`；需要读取某个玩家或敌人的状态时用实例对象；需要跨场景唯一且有生命周期的服务才考虑单例。三者都能“被很多地方调用”，但所有权和测试方式不同，不能只因为调用方便就全部做成 `static`。

验收时让玩家和敌人用同一个伤害函数得到一致结果，再让两个独立的 `Health` 对象保持各自血量。这样能证明静态方法共享的是规则，而不是错误地共享运行时状态。

## 常见坑

- 在静态方法里想用实例字段，编译器报错"需要对象引用"。
- 用静态字段保存关卡状态，切换场景后旧数据还在。**Unity 开启 Domain Reload 禁用时，静态字段在重新进入 Play 模式时也不会重置**。
- 静态事件或静态集合保存了对象引用，对象就永远不会被 GC 回收，形成内存泄漏。
- 扩展方法与类型已有的成员同名：类型自己的成员优先，扩展方法永远不会被调用。
