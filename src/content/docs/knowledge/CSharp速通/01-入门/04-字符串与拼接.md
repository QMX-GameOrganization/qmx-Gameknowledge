> 适用版本：C# 9.0。`StringBuilder` 的细节放在 4.4 篇，这里只讲入门要用的部分。

## 要点

- `string` 是**引用类型但表现得像值**：不可变，`==` 比较内容。每次"修改"都会生成新字符串。
- 拼接首选**字符串插值** `$"..."`，格式化数字用 `{x:F2}` 这类格式串。
- 比较大小写不敏感的字符串，用 `StringComparison.OrdinalIgnoreCase`，不要先 `ToLower()` 再比。
- 在 `Update` 这类每帧调用的地方做大量拼接，会持续产生垃圾，触发 GC 卡顿。

## 拼接与格式化

```csharp
string name = "Hero";
int hp = 85;
float ratio = 0.8523f;

string a = "名字：" + name + "，血量：" + hp;          // 加号拼接，可行但难读
string b = $"名字：{name}，血量：{hp}";                // 插值，推荐
string c = $"命中率 {ratio:P1}，血量 {hp:D4}";          // P1 百分数一位小数 -> 85.2%，D4 补零 -> 0085
string d = string.Format("{0}: {1}", name, hp);         // 旧写法，了解即可
string e = string.Join(", ", new[] { "剑", "盾", "药水" }); // 剑, 盾, 药水
string path = @"C:\Saves\slot1.json";                   // @ 逐字字符串，反斜杠不用转义
```

常用格式串：`F2` 保留两位小数，`D3` 整数补零到三位，`P0` 百分数，`N0` 带千分位（`1,234`）。

## 常用方法

```csharp
string s = "  Fire Ball ,Ice Bolt, Heal ";
Console.WriteLine(s.Length);                        // 长度
string trimmed = s.Trim();                          // 去首尾空白
string[] skills = s.Split(',');                     // 按分隔符切分
Console.WriteLine(trimmed.Contains("Ice"));         // True
Console.WriteLine(trimmed.IndexOf("Ice"));          // 找不到返回 -1
Console.WriteLine(trimmed.Substring(0, 4));         // "Fire"
Console.WriteLine(trimmed.Replace("Fire", "Flame"));
Console.WriteLine(trimmed.ToUpper());
Console.WriteLine(trimmed.StartsWith("Fire"));
```

这些方法**都不会修改原字符串**，而是返回新的。下面这个写法没有任何效果：

```csharp
trimmed.ToUpper();          // 结果被丢弃了，trimmed 仍是原样
trimmed = trimmed.ToUpper(); // 要接收返回值
```

字符串可以用下标读取字符 `s[0]`（得到 `char`），但**不能赋值** `s[0] = 'x'`，因为它不可变。

## 比较

```csharp
string x = "Hero";
string y = "hero";
Console.WriteLine(x == y);                                         // False，比较内容
Console.WriteLine(string.Equals(x, y, StringComparison.OrdinalIgnoreCase)); // True
Console.WriteLine(string.Compare("a", "b"));                       // 负数，排序用
Console.WriteLine(string.IsNullOrEmpty(null));                     // True，判空首选
```

C++ 里比较两个 `const char*` 是比地址；C# 的 `string` 重载了 `==`，直接比内容，所以不必担心这个坑。

## 为什么游戏代码要在意拼接

```csharp
void Update()
{
    scoreText.text = "Score: " + score;     // 每帧生成新字符串，旧的变垃圾
}
```

每次拼接都在堆上新建一个字符串。每帧一次看起来很小，但长时间累积后，垃圾回收器（GC）会选一个时刻统一清理，那一帧会明显卡一下。常见的处理方式：

1. **只在数值变化时才更新文本**，不要每帧都写。
2. 需要大量拼接时用 `StringBuilder` 复用缓冲区。
3. 预先缓存常用字符串（例如把 0 到 99 的字符串做成数组）。

GC 的具体机制在「C# 底层专栏」里展开，这里只需要记住一条：**循环和每帧逻辑里，少造字符串**。

## 常见坑

- 在 `for` 循环里用 `+=` 拼上千次字符串，性能和内存都很差。
- 用 `==` 比较时没注意大小写。
- 对 `null` 字符串调用 `.Length`：抛 `NullReferenceException`，先用 `IsNullOrEmpty`。
- 用字符串当物品或事件的标识符，拼写错了编译器不报错。后面学了枚举（2.1）就该换掉。
