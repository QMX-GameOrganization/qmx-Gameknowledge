## 为什么单独放主线实践文章

`Update`、`Time.deltaTime` 和 `Transform` 属于 C#/Unity 基础文章；把输入映射、移动脚本挂载、镜头偏移和运行验收全部写在语法文章里，会让语言主线变得臃肿。因此这里集中完成“能操作”的工程支撑。

## 玩家移动

```csharp
using UnityEngine;

/// <summary>【主线实践】只把输入转换为平面位移，血量和攻击由其他组件负责。</summary>
public sealed class PlayerMover : MonoBehaviour
{
    [SerializeField] private float speed = 5f;

    private void Update()
    {
        Vector3 input = new Vector3(
            Input.GetAxisRaw("Horizontal"),
            0f,
            Input.GetAxisRaw("Vertical"));

        if (input.sqrMagnitude > 1f)
            input.Normalize();

        transform.position += input * speed * Time.deltaTime;
    }
}
```

这里的边界很明确：输入和位移属于移动组件，`Health` 不应该读取键盘，`GameSession` 不应该直接修改 Transform。以后换成 Rigidbody 移动时，只替换移动组件，不改血量、库存或胜负系统。

## 摄像机跟随

```csharp
using UnityEngine;

/// <summary>【主线实践】摄像机只跟随目标，不参与玩家状态判断。</summary>
public sealed class CameraFollow : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField] private Vector3 offset = new Vector3(0f, 8f, -6f);

    private void LateUpdate()
    {
        if (target == null) return;
        transform.position = target.position + offset;
        transform.LookAt(target);
    }
}
```

## 验收

- [ ] WASD 能移动 `Player`；
- [ ] 对角线移动速度不会超过单轴速度；
- [ ] 限制帧率后移动距离基本一致；
- [ ] `CameraFollow.target` 拖入 `Player` 后镜头跟随；
- [ ] 移除 `CameraFollow`，玩家仍能移动，说明职责没有耦合；
- [ ] 运行结果能作为后续血量、攻击和拾取文章的起点。
