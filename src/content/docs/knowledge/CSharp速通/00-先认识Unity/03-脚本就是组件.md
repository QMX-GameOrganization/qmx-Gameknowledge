## 要点

- **脚本就是一个 C# 类，继承自 `MonoBehaviour`，挂到物体上后变成该物体的一个组件。**
- 继承 `MonoBehaviour` 给了这个类四种能力：能挂到物体上、能被引擎在特定时机调用（`Start`、`Update`……）、字段能显示在 Inspector、能直接使用 `transform`、`gameObject` 等成员。
- `Start`、`Update` 这些函数不是你调用的，而是**引擎按名字找到并调用的**。名字写错，函数就不会被执行，而且不报错。
- 脚本**文件名必须与类名一致**，否则无法挂载。

## 为什么要继承 MonoBehaviour

回到 0.1 的游戏循环：循环在 Unity 里，你的代码在另一边。Unity 要调用你的代码，就需要一个约定：**凡是继承 `MonoBehaviour` 的类，我就认识它，会在合适的时机调用它里面名叫 `Update` 等的函数**。继承它，就是向引擎"注册"自己。

![引擎调用你的脚本函数，你的脚本调用引擎提供的 API](/qmx-Gameknowledge/assets/csharp/script-engine.svg)

这正是 4.1 篇讲的继承：`MonoBehaviour` 是父类，你的脚本是子类，自动拥有父类的成员。

## 创建第一个脚本

1. 在 Project 面板空白处右键 → Create → C# Script（Unity 6 中菜单可能叫 MonoBehaviour Script），命名为 `Spinner`。
2. 双击打开，会看到类似这样的模板：

```csharp
using UnityEngine;                    // 引入 Unity 的命名空间，MonoBehaviour 就在里面

public class Spinner : MonoBehaviour  // 类名 Spinner 必须和文件名 Spinner.cs 一致
{
    void Start()                      // 第一次 Update 之前调用一次
    {
    }

    void Update()                     // 每一帧调用一次
    {
    }
}
```

3. 把脚本拖到场景里某个物体上（或选中物体，Add Component 搜 Spinner）。

注意 `Start` 和 `Update` 前面没有 `public`，也没有人写代码调用它们。它们是引擎用名字查找的"消息函数"，用 `private`（默认）完全可以。

## 让立方体转起来

```csharp
using UnityEngine;

public class Spinner : MonoBehaviour
{
    [SerializeField] private float degreesPerSecond = 90f;   // 每秒转多少度，可在 Inspector 调

    void Update()
    {
        // transform 是继承来的成员，指向这个物体自己的 Transform 组件
        transform.Rotate(0f, degreesPerSecond * Time.deltaTime, 0f);
    }
}
```

逐行对应前面学到的概念：

| 代码 | 含义 |
| --- | --- |
| `[SerializeField] private float` | 私有字段显示在 Inspector，可填数值（5.4 特性） |
| `transform` | `MonoBehaviour` 的成员，指向本物体上的 Transform 组件 |
| `Rotate(x, y, z)` | Transform 的方法，沿三个轴旋转（单位：度） |
| `degreesPerSecond * Time.deltaTime` | 每秒速度 × 本帧耗时 = 本帧应转角度（0.1 篇） |

把同一个 `Spinner` 挂到两个 Cube 上，Inspector 里分别设 `90` 和 `360`，两个立方体就以不同速度旋转。这就是"同一个类，两个对象，各有各的字段值"。

## 生命周期：引擎调用你的函数的顺序

![MonoBehaviour 生命周期：Awake、OnEnable、Start，之后每帧 FixedUpdate、Update、LateUpdate，最后 OnDisable、OnDestroy](/qmx-Gameknowledge/assets/csharp/lifecycle.svg)

| 函数 | 何时调用 | 典型用途 |
| --- | --- | --- |
| `Awake` | 脚本实例刚创建时，一次 | 初始化自身、缓存 `GetComponent` 的结果 |
| `OnEnable` | 每次脚本被启用时 | 订阅事件 |
| `Start` | 第一次 `Update` 之前，一次 | 依赖其他物体的初始化 |
| `Update` | 每帧一次 | 读输入、移动、逻辑 |
| `FixedUpdate` | 固定时间间隔 | 物理：给 Rigidbody 加力 |
| `LateUpdate` | 所有 `Update` 之后 | 相机跟随 |
| `OnDisable` | 每次脚本被禁用时 | 取消订阅事件 |
| `OnDestroy` | 物体销毁时 | 清理 |

记一条规则：**`Awake` 管自己，`Start` 管别人。** 场景里所有物体的 `Awake` 都执行完，才会开始执行 `Start`，所以在 `Start` 里访问别的物体的数据是安全的。

## 脚本怎么拿到别的东西

```csharp
using UnityEngine;

public class Demo : MonoBehaviour
{
    [SerializeField] private Transform target;    // 方式一：在 Inspector 里把别的物体拖进来

    private Rigidbody rb;

    void Awake()
    {
        rb = GetComponent<Rigidbody>();           // 方式二：从同一物体上找组件
    }

    void Update()
    {
        Debug.Log(gameObject.name + " 离目标 " + Vector3.Distance(transform.position, target.position));
    }
}
```

| 想拿到 | 写法 |
| --- | --- |
| 自己的位置、旋转 | `transform` |
| 自己这个物体 | `gameObject` |
| 同一物体上的其他组件 | `GetComponent<T>()` |
| 场景里的其他物体 | Inspector 拖拽 `[SerializeField]` 字段（首选） |
| 动态创建/销毁物体 | `Instantiate(prefab)` / `Destroy(obj)` |
| 打日志 | `Debug.Log("...")` |

`GetComponent<T>()` 的 `<T>` 就是 5.1 篇的泛型。拖拽引用比 `Find` 按名字查找更快，也更不容易出错。

## 几个必须记住的规则

- **不要自己 `new` 一个 `MonoBehaviour`**，也不要给它写构造函数。创建它是引擎的事（挂载或 `AddComponent`）。
- 脚本前面的小复选框是启用开关：**禁用后 `Update` 不再被调用**，但对象依然存在。
- 物体被 `SetActive(false)` 时，上面的所有脚本也不再运行。
- 一个物体上可以挂多个不同脚本，也可以挂同一个脚本的多个副本。

## 项目应用决策：生命周期函数各自负责什么

主线项目固定一套职责，避免初始化和订阅散落在任意函数里：

- `Awake`：准备自己拥有的引用和默认状态，例如缓存 `Health`；
- `OnEnable`：订阅事件，脚本重新启用时也能恢复；
- `Start`：读取其他对象或开始依赖场景的流程；
- `Update`：读取输入和推进非物理状态；
- `OnDisable`：解除事件订阅，避免对象销毁后仍收到回调。

`MonoBehaviour` 由 Unity 创建和驱动，所以 `new PlayerController()` 不能替代把脚本挂到 `GameObject`。普通的 `WeaponConfig`、`DamageRule` 等纯数据类才由代码 `new`。验收时禁用再启用 HUD，血量事件仍能正确更新；销毁目标后 Console 不应出现来自旧订阅者的回调。
