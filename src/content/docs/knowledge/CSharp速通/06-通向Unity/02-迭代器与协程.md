> 适用版本：C# 9.0，Unity 2021 LTS 到 6000.x。迭代器和 async 的隐藏分配，见「C# 底层专栏」第 6 章。

## 要点

- 带 `yield return` 的方法是**迭代器**：它不会一口气执行完，每次 `yield return` 就暂停，下次再从暂停处继续。
- Unity 的**协程**就是返回 `IEnumerator` 的迭代器，引擎每一帧（或等够指定时间后）推进它一步。
- 协程**不是多线程**，仍然在主线程里分段执行。
- 它的价值是把"需要持续几帧或几秒的流程"写成顺序代码，不必手写状态变量。

## 迭代器

```csharp
static IEnumerable<int> Countdown(int n)
{
    while (n > 0)
    {
        yield return n;          // 交出一个值，然后暂停在这里
        n--;
    }
}

foreach (int i in Countdown(3))
    Console.WriteLine(i);        // 3 2 1
```

`foreach` 能遍历任何实现了 `IEnumerable` 的东西，你自己写的迭代器也可以。编译器会把这个方法改写成一个状态机类，记录"执行到了哪一步、局部变量是什么"。

## 手动推进：协程的核心原理

```csharp
static IEnumerator Routine()
{
    Console.WriteLine("A");
    yield return null;           // 暂停，等待下一次被推进
    Console.WriteLine("B");
    yield return null;
    Console.WriteLine("C");
}

IEnumerator r = Routine();
while (r.MoveNext())             // 每调用一次 MoveNext，执行到下一个 yield
    Console.WriteLine("--下一帧--");
```

输出依次为 `A`、`--下一帧--`、`B`、`--下一帧--`、`C`。Unity 做的事就是这个 `while`：每帧对所有活跃协程调一次 `MoveNext`，并根据 `yield return` 后面的值决定"下一次什么时候继续"。

## Unity 里的协程

```csharp
// 以下为 Unity 代码示意
public class Skill : MonoBehaviour
{
    private bool onCooldown;

    public void Cast()
    {
        if (onCooldown) return;
        StartCoroutine(CooldownRoutine(2f));       // 启动协程
    }

    private IEnumerator CooldownRoutine(float seconds)
    {
        onCooldown = true;
        Debug.Log("技能释放");
        yield return new WaitForSeconds(seconds);  // 等 2 秒，期间游戏继续运行
        onCooldown = false;
        Debug.Log("冷却完毕");
    }
}
```

没有协程的话，要自己写计时变量，在 `Update` 里每帧累加并判断，状态一多就乱。

常见的 `yield return` 形式：

| 写法 | 含义 |
| --- | --- |
| `yield return null` | 等下一帧 |
| `yield return new WaitForSeconds(t)` | 等 t 秒（受 `Time.timeScale` 影响） |
| `yield return new WaitForSecondsRealtime(t)` | 等 t 秒真实时间（暂停游戏时仍然计时） |
| `yield return new WaitForFixedUpdate()` | 等下一次物理更新 |
| `yield return new WaitUntil(() => cond)` | 等到条件成立 |
| `yield return StartCoroutine(other)` | 等另一个协程结束 |
| `yield break` | 提前结束协程 |

## 渐隐效果：持续多帧的典型例子

```csharp
private IEnumerator FadeOut(CanvasGroup group, float duration)
{
    float t = 0f;
    while (t < duration)
    {
        t += Time.deltaTime;
        group.alpha = 1f - t / duration;          // 每一帧调整透明度
        yield return null;                        // 交还控制权，下一帧继续
    }
    group.alpha = 0f;
}
```

没有 `yield return null` 的 `while` 会在同一帧里跑完，或者变成死循环让整个编辑器卡死。

## 停止协程

```csharp
Coroutine c = StartCoroutine(FadeOut(group, 1f));
StopCoroutine(c);                // 停掉指定协程
StopAllCoroutines();             // 停掉本脚本启动的全部协程
```

协程绑定在启动它的 `MonoBehaviour` 上，以下情况会**自动停止**：脚本所在物体被销毁、物体被 `SetActive(false)`、脚本被禁用后物体不再激活时。协程里抛出异常，该协程也会静默终止。

## 动手试试

```csharp
using System.Collections;
using UnityEngine;

public class CooldownDemo : MonoBehaviour
{
    private bool onCooldown;

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space) && !onCooldown)
            StartCoroutine(CooldownRoutine(2f));
    }

    IEnumerator CooldownRoutine(float seconds)
    {
        onCooldown = true;
        Debug.Log("技能释放");
        yield return new WaitForSeconds(seconds);
        onCooldown = false;
        Debug.Log("冷却完毕");
    }
}
```

1. 运行后连按空格，只有冷却结束后才能再次释放，Console 里 `技能释放` 和 `冷却完毕` 间隔约 2 秒。
2. 把 `yield return new WaitForSeconds(seconds);` 换成 `yield return null;`，现在冷却只有一帧，对比观察。
3. 在协程中途禁用物体（Inspector 里取消勾选），再启用，确认协程已经被终止、`onCooldown` 一直为 `true`，这就是协程"绑定在物体上"的含义。

## 常见坑

- 每次循环都 `new WaitForSeconds(...)`，产生垃圾。固定时长的写成字段缓存复用。
- 以为协程是并行的：两个协程之间不会同时运行，每个都在主线程轮流执行。
- 物体被停用后协程消失，但你的逻辑还在等它完成。
- 在应该用 `Update` 的地方滥用协程，状态逻辑反而更难读。持续每帧运行的逻辑用 `Update`，"等一会再做"的逻辑用协程。
- 启动同一个协程多次，没有保护，造成效果叠加。用布尔变量或保存 `Coroutine` 引用判断。
