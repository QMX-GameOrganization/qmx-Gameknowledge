> 适用版本：C# 9.0 与 Unity 2021 LTS 到 6000.x。

## 要点

- 语言只需要快速过一遍，**真正熟悉靠在 Unity 里写**。这页是回头查的，不用背。
- 最容易出错的五件事：值类型与引用类型、`null`、`Update` 里的垃圾分配、事件不取消订阅、子线程调 Unity API。

## C++ 到 C# 对照总表

| 主题 | C++ | C# | 篇目 |
| --- | --- | --- | --- |
| 程序结构 | 头文件 + 源文件 | 没有头文件，所有函数在类里 | 1.1 |
| 内存 | `new`/`delete`、智能指针 | `new` + GC，不手动释放 | 3.1 |
| 基本类型 | 大小随平台 | `int` 恒为 32 位，`float` 要加 `f` | 1.1 |
| 局部变量未初始化 | 随机值 | 编译错误 | 1.1 |
| 类型转换 | `static_cast` 等 | `(T)x`、`as`、`is`、`TryParse` | 1.2 |
| 异常 | `try/catch`，可抛任意类型 | 必须是 `Exception` 子类，有 `finally` | 1.3 |
| 字符串 | `std::string` 可变 | `string` 不可变，引用类型 | 1.4 |
| 枚举 | `enum class` | `enum`，可强转任意整数 | 2.1 |
| 容器 | `vector` / `unordered_map` | `List<T>` / `Dictionary<K,V>` | 2.2 |
| 对象赋值 | 默认拷贝 | `class` 复制引用，`struct` 复制内容 | 2.3 |
| 引用传参 | `T&` | `ref` / `out`，调用处也要写 | 2.4 |
| `struct` | 同 `class`，只差默认权限 | 值类型，不能继承类 | 2.5 |
| 访问控制 | `public/private/protected` | 同，另有 `internal`；成员默认 `private` | 3.1 |
| getter/setter | 手写函数 | 属性 `{ get; set; }` | 3.3 |
| 全局函数 | 允许 | 不允许，用静态类 | 3.4 |
| 运算符重载 | 成员或友元 | `public static operator` | 3.5 |
| 继承 | 多重继承 | 单继承 + 多接口 | 4.1 |
| 多态 | `virtual`，`override` 可省 | `virtual` + `override` 必须写 | 4.3 |
| 纯虚函数 | `= 0` | `abstract` | 4.3 |
| 模板 | 编译期展开，可特化 | 泛型 + `where` 约束 | 5.1 |
| 函数指针 / `std::function` | | `delegate` / `Action` / `Func` | 5.2 |
| lambda | `[&](int x){}` | `x => ...`，自动捕获变量 | 5.2 |
| 观察者 | 手写回调列表 | `event` | 5.2 |
| 反射 | 无 | `System.Reflection` | 5.4 |
| 条件编译 | `#ifdef` | `#if`，不能定义带值的宏 | 5.4 |
| 多线程 | `std::thread`、`std::mutex` | `Thread`/`Task`、`lock` | 5.5 |
| 协程 | C++20 `co_await` | 迭代器 + `yield return` | 6.2 |

## 进入 Unity 前的自测清单

用自己的话回答，答得出就可以开始写 Unity 脚本，答不出就回到对应篇目：

1. `int[] b = a;` 之后改 `b[0]`，`a` 会变吗？`Vector3 p = transform.position; p.y = 5;` 物体会动吗？（2.2、2.3）
2. `class Player` 和 `struct Player` 在赋值时有什么区别？（2.5）
3. 为什么字段要用 `private` 加属性？写出一个带范围限制的属性。（3.3）
4. `virtual`、`override`、`abstract`、`interface` 分别用在什么场合？（4.3）
5. 为什么游戏里推荐用对象池？`List<int>` 和 `ArrayList` 谁会装箱？（4.2、5.1）
6. 事件订阅后为什么要取消订阅？（5.2）
7. `Start` 和 `Awake` 谁先执行？协程是不是多线程？（0.3、6.2）

## 写 Unity 时的五个习惯

1. **缓存引用**：`GetComponent`、`Find` 在 `Awake` 或 `Start` 做一次，别放进 `Update`。
2. **少造垃圾**：`Update` 里不 `new`、不拼字符串、不创建 lambda、不用 `foreach` 遍历会装箱的旧集合。
3. **对 Unity 对象判空用 `!= null`**，不要依赖 `?.` 和 `??`。
4. **订阅与取消订阅成对**，放在 `OnEnable` / `OnDisable`。
5. **子线程只算数据**，不碰 Unity 对象。

## 之后读什么

按需要选，不必按顺序：

| 你想做什么 | 本知识库里的专栏 |
| --- | --- |
| 先熟悉编辑器界面 | 「认识 Unity」 |
| 想从 C++ 角度补面向对象 | 「面向对象串讲」 |
| 想知道值类型、GC、内存怎么回事 | 「C# 与 Unity 内存基础」 |
| 想理解 Mono、IL2CPP、装箱的底层 | 「C# 底层专栏」 |
| 想做高性能的数据并行 | 「Unity Job 与 Burst」、「ECS 学习」 |
| 准备面试 | 「基础知识速查」 |

最有效的下一步：**做一个很小的东西**，比如会移动、能开火、有血条、能死亡的方块人。这个小项目会把本栏位里的枚举、属性、事件、接口、协程全部用一遍，遇到不会的再回来查。
## 项目应用决策：从知识点到项目决策

学完本专栏时，不应只会回答“语法怎么写”，还要能在方块地牢中说明：

| 问题 | 应该能做出的选择 |
| --- | --- |
| 这个数据是否有身份和生命周期？ | `class`、`struct` 或配置资产 |
| 这个功能是否依赖对象状态？ | 实例方法、静态工具或组件 |
| 多个对象是否只共享一种能力？ | 接口；若共享实现再考虑抽象类 |
| 这是输入、物理还是等待流程？ | `Update`、`FixedUpdate` 或协程 |
| 结果需要通知多少个系统？ | 事件；若只是一次调用就用普通方法 |
| 访问是否高频、是否会分配？ | 先测量，再决定集合、池化或 Job/Burst |

最后的验收不是背完 API，而是从空场景搭出组件关系，解释每个脚本的所有者和生命周期，并完成“启动 → 操作 → 状态变化 → 胜负 → 重开”的闭环。
