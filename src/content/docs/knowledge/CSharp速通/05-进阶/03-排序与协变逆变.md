> 适用版本：C# 9.0。

## 要点

- `List<T>.Sort` 有三种用法：默认比较（元素实现 `IComparable<T>`）、传一个 lambda、传一个比较器对象。**lambda 最常用**。
- 比较函数返回负数表示"前者排前面"，0 表示相等，正数表示"前者排后面"。
- `List.Sort` 是**不稳定排序**：相等元素的相对顺序可能改变。
- **协变**（out）和**逆变**（in）解决"`IEnumerable<Player>` 能不能当 `IEnumerable<Entity>` 用"这类问题。看懂规则、会读报错即可，日常很少自己写。

## 排序

```csharp
class Hero
{
    public string name;
    public int level;
    public int score;
}

List<Hero> heroes = new List<Hero>
{
    new Hero { name = "战士", level = 10, score = 300 },
    new Hero { name = "法师", level = 12, score = 500 },
    new Hero { name = "射手", level = 10, score = 400 },
};

// 1. lambda：按分数从高到低（把 b 放左边就是降序）
heroes.Sort((a, b) => b.score.CompareTo(a.score));

// 2. 多条件：先按等级降序，等级相同按分数降序
heroes.Sort((a, b) =>
{
    int c = b.level.CompareTo(a.level);
    return c != 0 ? c : b.score.CompareTo(a.score);
});
```

`CompareTo` 是基本类型自带的比较方法，直接用就好。别写成 `a.score - b.score`，数值很大时相减会溢出，结果出错。

## 让类自己知道怎么比

```csharp
class Item : IComparable<Item>
{
    public string name;
    public int price;

    public int CompareTo(Item other) => price.CompareTo(other.price);   // 默认按价格升序
}

List<Item> shop = new List<Item> { new Item { name = "剑", price = 50 }, new Item { name = "药", price = 10 } };
shop.Sort();                                    // 不用传参数，用 CompareTo
Array.Sort(new[] { 3, 1, 2 });                  // 数组同理
```

只有"这种类型天然只有一种比较方式"时才实现 `IComparable`；排行榜、背包整理这种按场景变化的排序，用 lambda 更灵活。

## 稳定排序与 LINQ

```csharp
using System.Linq;

var sorted = heroes.OrderByDescending(h => h.score).ThenBy(h => h.name).ToList();
```

`OrderBy` 是稳定排序，写起来也直观，但会分配新的集合和迭代器对象，不要放进每帧调用的地方。游戏里的排行榜、背包整理这类低频操作，用哪个都行。

## 协变与逆变

先看一个直觉上应该成立的写法：

```csharp
// 沿用 Entity、Player 的继承关系（4.1 篇）
IEnumerable<Player> players = new List<Player>();
IEnumerable<Entity> entities = players;          // 可以：协变

List<Player> pList = new List<Player>();
// List<Entity> eList = pList;                   // 编译错误：List<T> 不协变
```

为什么 `List` 不行？因为如果允许，就能通过 `eList.Add(new Enemy(...))` 把敌人塞进一个实际是 `Player` 的列表，类型安全被破坏。而 `IEnumerable<T>` 只能**读出**元素，不能写入，所以安全。

![IEnumerable 协变允许，List 不变不允许，Action 逆变允许](/qmx-Gameknowledge/assets/csharp/variance.svg)

| 概念 | 关键字 | 方向 | 典型例子 |
| --- | --- | --- | --- |
| 协变 | `out T` | 子类的泛型可以当父类的泛型用 | `IEnumerable<out T>`、`Func<out TResult>` |
| 逆变 | `in T` | 父类的泛型可以当子类的泛型用 | `Action<in T>`、`IComparer<in T>` |
| 不变 | 无 | 不能互换 | `List<T>` |

记忆法：`out` 表示 T 只用作**输出**（返回值），`in` 表示 T 只用作**输入**（参数）。

```csharp
Action<Entity> healAny = e => Console.WriteLine("治疗 " + e.name);
Action<Player> healPlayer = healAny;             // 逆变：能处理任何实体的，当然能处理玩家
```

自己声明接口时标注：

```csharp
interface IRepository<out T>                      // T 只出现在返回位置
{
    T Get(int id);
}
```

只有**接口和委托**能声明变体，`class` 不行。这个知识点主要用来理解为什么有些赋值编译器不让过，不用刻意用。

## 在 Unity 里用到它

- 排行榜、背包整理、按距离找最近的敌人，都是排序的典型场景。
- 比较距离时用 `sqrMagnitude`（距离的平方）代替 `magnitude`，省掉开方运算，结果的大小顺序不变。
- `List.Sort` 带 lambda 且 lambda 捕获了外部变量时，每次调用会产生一次小的堆分配，低频调用没关系，每帧调用就要避免。

## 动手试试

> **代码归属**：`【实验代码】`。本段只放进 `Assets/Speedrun/Labs/` 临时验证；要进入小游戏主线，请跟随后文或目录中的 `【主线实践】` 文章，在 `Assets/Speedrun/Game/` 重新接入并完成验收。

```csharp
using System.Collections.Generic;
using UnityEngine;

public class SortDemo : MonoBehaviour
{
    [SerializeField] private List<Transform> targets;

    [ContextMenu("按距离排序")]
    void SortByDistance()
    {
        Vector3 origin = transform.position;
        targets.Sort((a, b) =>
            (a.position - origin).sqrMagnitude.CompareTo((b.position - origin).sqrMagnitude));

        foreach (Transform t in targets)
            Debug.Log($"{t.name} 距离 {Vector3.Distance(origin, t.position):F1}");
    }
}
```

场景里放 4 个 Cube，故意摆在不同远近，拖进 `Targets`，右键组件选"按距离排序"，确认输出由近到远。再把比较里的两个 `sqrMagnitude` 前后对调，看顺序反过来。

## 项目应用决策：排序是为了哪个游戏决策

玩家锁定目标、敌人选择最近玩家、掉落列表按稀有度展示，都是“先定义决策，再选择比较器”。距离比较使用 `sqrMagnitude` 足够，因为只比较大小，不需要开平方；真正需要显示距离时再使用 `magnitude`。

`List.Sort` 会改变原集合，适合明确允许重排的临时列表；如果 UI 仍需要原始顺序，应复制或使用投影结果。排序不应放在每帧无条件执行，应该在目标集合变化、玩家请求或固定刷新间隔时触发。验收是同一组目标在锁定、UI 展示和敌人 AI 三处得到一致的排序规则。

## 常见坑

- 比较函数写成 `a.x - b.x`，溢出时顺序混乱。
- 比较函数前后不一致（`a<b` 且 `b<a`），`Sort` 可能抛 `InvalidOperationException` 或排序结果错乱。
- 以为 `Sort` 稳定，实际相等元素顺序会变。需要稳定就用 `OrderBy` 或加入第二排序键。
- 每帧对大列表排序。能增量维护就不要重新排。
