> 适用版本：C# 9.0。委托与闭包带来的隐藏堆分配，见「C# 底层专栏」第 6 章。

## 要点

- **委托**是"指向函数的类型"，可以把函数存进变量、当参数传、放进列表。相当于 C++ 的函数指针加 `std::function`，但类型安全。
- 日常不用自己声明委托：`Action`（无返回值）和 `Func`（有返回值）覆盖绝大多数需求。
- **lambda** `(a, b) => a + b` 是写匿名函数的简短语法，能**捕获**外面的局部变量（闭包）。
- **事件**（`event`）是委托的受限版本：外部只能订阅和取消订阅，不能自己触发。游戏里的"血量变化通知 UI"就靠它。

## 委托基础

```csharp
delegate int DamageCalc(int atk, int def);            // 声明一个委托类型：签名要匹配

static int Normal(int atk, int def)  => Math.Max(atk - def, 0);
static int Pierce(int atk, int def)  => atk;           // 无视防御

DamageCalc calc = Normal;                              // 把函数赋给变量
Console.WriteLine(calc(20, 8));                        // 12
calc = Pierce;
Console.WriteLine(calc(20, 8));                        // 20
```

调用方只关心"算伤害"，具体算法由传入的函数决定。这是策略模式最短的写法。

## Action 和 Func

```csharp
Action<string> log = msg => Console.WriteLine(msg);          // 参数 string，无返回值
Func<int, int, int> add = (a, b) => a + b;                   // 前面是参数，最后一个是返回类型
Predicate<int> isEven = n => n % 2 == 0;                     // 返回 bool 的专用形式

log("开始");
Console.WriteLine(add(2, 3));
Console.WriteLine(isEven(4));

List<int> nums = new List<int> { 1, 2, 3, 4, 5, 6 };
List<int> evens = nums.FindAll(isEven);                      // 集合方法接受委托
nums.ForEach(n => Console.Write(n + " "));
```

## 多播委托

一个委托变量可以挂多个函数，调用时依次执行：

```csharp
Action onLevelUp = null;
onLevelUp += () => Console.WriteLine("播放特效");
onLevelUp += () => Console.WriteLine("加属性点");
onLevelUp?.Invoke();                                          // 为 null 时不调用，安全
```

## 匿名函数与 lambda

```csharp
Func<int, int> old = delegate (int x) { return x * 2; };     // 匿名方法，旧写法
Func<int, int> neo = x => x * 2;                             // lambda，现在的主流
Func<int, int, int> max = (a, b) => { return a > b ? a : b; };  // 多行体用花括号

int bonus = 5;
Func<int, int> addBonus = x => x + bonus;                    // 捕获了局部变量 bonus
bonus = 10;
Console.WriteLine(addBonus(1));                              // 11，捕获的是变量本身，不是当时的值
```

**捕获的是变量，不是值**，这是闭包最容易出错的地方：

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.WriteLine(i));                 // 三个 lambda 共享同一个 i

foreach (var a in actions) a();                              // 输出 3 3 3，而不是 0 1 2

// 修正：循环内复制一份
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.WriteLine(copy));              // 每次迭代一个新的 copy
}
```

![共享同一个循环变量 i 的三个 lambda 都输出 3；每轮复制一份后分别输出 0、1、2](/qmx-Gameknowledge/assets/csharp/closure.svg)

另外，捕获了变量的 lambda 每次创建都会在堆上分配一个对象，在 `Update` 里反复创建会产生垃圾。

## 事件：受限的委托

```csharp
class Player
{
    public event Action<int, int> OnHpChanged;           // 参数：旧值，新值
    private int hp = 100;

    public void TakeDamage(int amount)
    {
        int old = hp;
        hp = Math.Max(hp - amount, 0);
        OnHpChanged?.Invoke(old, hp);                    // 只有 Player 自己能触发
    }
}

class HpBar
{
    public void Bind(Player p) { p.OnHpChanged += Refresh; }
    public void Unbind(Player p) { p.OnHpChanged -= Refresh; }     // 不用时取消订阅
    private void Refresh(int old, int now) => Console.WriteLine($"血条：{old} -> {now}");
}

Player player = new Player();
HpBar bar = new HpBar();
bar.Bind(player);
player.TakeDamage(30);                                   // 血条：100 -> 70
// player.OnHpChanged = null;                            // 编译错误：事件外部不能直接赋值
// player.OnHpChanged(1, 2);                             // 编译错误：外部不能触发
```

好处是 **Player 完全不知道有血条存在**：以后加音效、成就、镜头抖动，只需要再订阅，不用改 Player 的代码。这是最常用的解耦手段。

![Player 触发事件，血条、音效、成就各自订阅；Player 不认识它们](/qmx-Gameknowledge/assets/csharp/event-flow.svg)

Unity 里相关的写法：

```csharp
// 以下为 Unity 代码示意
button.onClick.AddListener(() => Debug.Log("按下"));    // UI 按钮就是事件
```

## 在 Unity 里用到它

Unity 里有两套"事件"：

| 方式 | 在哪配置 | 适合 |
| --- | --- | --- |
| C# `event` / `Action` | 代码里 `+=` 订阅 | 脚本之间的逻辑通知，性能好，类型安全 |
| `UnityEvent` | Inspector 里拖拽 | 策划/美术配置回调，如按钮点击 |

`Button.onClick` 就是 `UnityEvent`。订阅和取消订阅要成对，Unity 里固定写在 `OnEnable` / `OnDisable`。

## 动手试试

```csharp
using System;
using UnityEngine;

public class Hero : MonoBehaviour
{
    public event Action<int, int> OnHpChanged;
    private int hp = 100;

    [ContextMenu("受伤 30")]
    void Hurt()
    {
        int old = hp;
        hp = Mathf.Max(hp - 30, 0);
        OnHpChanged?.Invoke(old, hp);
    }
}

public class HpLogger : MonoBehaviour
{
    [SerializeField] private Hero target;

    void OnEnable()  { target.OnHpChanged += Log; }
    void OnDisable() { target.OnHpChanged -= Log; }
    void Log(int oldHp, int newHp) { Debug.Log($"血量 {oldHp} → {newHp}"); }
}
```

给 `Hero` 和 `HpLogger` 各建一个物体，把 `Hero` 拖进 `Target`。运行后右键 `Hero` 组件选"受伤 30"，看 Console。然后**停用 `HpLogger` 所在的物体**再受伤，确认不再输出；这就是 `OnDisable` 里 `-=` 的作用。最后把 `OnDisable` 里的 `-=` 注释掉，销毁 `HpLogger` 物体后再受伤，观察会发生什么。

## 常见坑

- 订阅后忘记取消订阅：发布者持有订阅者的引用，订阅者被销毁（或场景切换）后仍被调用，抛 `MissingReferenceException` 或造成内存泄漏。在 Unity 里通常配对写在 `OnEnable` / `OnDisable`。
- 触发前不判空：没人订阅时 `OnHpChanged()` 抛 `NullReferenceException`，用 `?.Invoke()`。
- 在 `for` 循环里直接捕获循环变量，结果全是最后一个值。
- 一个事件里某个订阅者抛异常，后面的订阅者就不会被执行。
