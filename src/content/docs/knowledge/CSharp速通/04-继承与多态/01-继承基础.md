> 适用版本：C# 9.0。

## 要点

- 继承表达"是一种"：玩家**是一种**实体，敌人**是一种**实体。子类自动拥有父类的成员，再追加自己的。
- C# **只允许单继承**（一个类只有一个父类），但可以实现多个接口（4.3 篇）。
- 子类对象可以当成父类使用（**里氏替换原则**）：凡是需要 `Entity` 的地方，传 `Player` 或 `Enemy` 都合法。
- 构造时**父类先于子类**；子类用 `: base(...)` 指定调用父类的哪个构造函数。

## 基本写法

```csharp
class Entity
{
    public string name;
    protected int hp;                    // protected：本类和子类可访问，外部不行

    public Entity(string name, int hp)
    {
        this.name = name;
        this.hp = hp;
        Console.WriteLine($"Entity 构造：{name}");
    }

    public void Describe() => Console.WriteLine($"{name} hp={hp}");
}

class Player : Entity                    // 冒号表示继承
{
    public int gold;

    public Player(string name) : base(name, 100)      // 先调用父类构造函数
    {
        Console.WriteLine("Player 构造完成");
    }

    public void Hurt(int damage) { hp -= damage; }          // 子类可以直接访问 protected 的 hp
}

class Enemy : Entity
{
    public Enemy(string name, int hp) : base(name, hp) { }
    public void Roar() => Console.WriteLine($"{name} 咆哮！");
}
```

`new Player("勇者")` 的输出顺序是 `Entity 构造：勇者`，然后是 `Player 构造完成`。如果父类没有无参构造函数，子类的每个构造函数都**必须**显式写 `: base(...)`，否则编译不过。

## 里氏替换：父类变量接子类对象

```csharp
Entity e1 = new Player("勇者");          // 子类对象赋给父类变量：隐式，自动
Entity e2 = new Enemy("哥布林", 30);

List<Entity> scene = new List<Entity> { e1, e2 };
foreach (Entity e in scene)
    e.Describe();                        // 这里只当它们是 Entity

// e2.Roar();                            // 编译错误：Entity 类型的变量看不到 Roar
```

这个特性让你能把不同类型的东西放进同一个容器统一管理，是多态（下一章）的基础。变量的**声明类型**决定你能调用什么，对象的**真实类型**决定实际运行谁的版本。

## 向下转换：is 与 as

要使用子类独有的成员，需要把父类变量转回子类，但先得确认它真的是：

```csharp
Entity e = scene[1];

if (e is Enemy enemy)                    // 判断并转换，推荐
    enemy.Roar();

Enemy en = e as Enemy;                   // 失败得到 null，不抛异常
if (en != null) en.Roar();

Enemy forced = (Enemy)e;                 // 强转：类型不对会抛 InvalidCastException
```

首选 `is` 模式匹配。Unity 里最典型的用法是处理碰撞：

```csharp
// 以下为 Unity 代码示意
void OnTriggerEnter(Collider other)
{
    Enemy hit = other.GetComponent<Enemy>();
    if (hit != null) hit.TakeDamage(10);     // 对 Unity 对象判空用 != null，原因见 2.3 篇
}
```

## 继承里的几条规则

| 规则 | 说明 |
| --- | --- |
| 单继承 | `class A : B, C` 只有一个能是类，其余必须是接口 |
| `private` 成员不能访问 | 子类拥有它，但读写不了，要通过父类提供的 `protected` / `public` 接口 |
| 构造函数不被继承 | 每个类自己写，用 `base(...)` 衔接 |
| 所有类最终继承 `object` | 见 4.2 |
| 没有 `private` / `protected` 继承 | 不像 C++ 的 `class A : private B`，C# 的继承一律是公开的 |

## 继承该不该用

继承是最强的耦合。玩家、敌人、NPC 都从 `Entity` 继承听起来合理，但需求增加后（会飞的敌人、可骑乘的玩家、能被摧毁的箱子），继承树会越来越深，难以调整。Unity 提倡的做法是**组合**：用 `GameObject` 挂载多个小组件（`Health`、`Mover`、`Attacker`）。

经验法则：**真正的"是一种"关系才用继承，只是"有某种能力"就用接口或组合**。

## 在 Unity 里用到它

你写的每个脚本都已经在用继承了：`class Player : MonoBehaviour`。你还可以自己再加一层，让一类物体共用代码：

```csharp
using UnityEngine;

public class Enemy : MonoBehaviour
{
    [SerializeField] protected int hp = 50;               // protected：子类能访问，外部不能
    public void ShowHp() => Debug.Log($"{name} hp={hp}");
}

public class Goblin : Enemy
{
    void Start()
    {
        ShowHp();
        hp -= 10;                                         // 直接使用父类的 protected 字段
        ShowHp();
    }
}
```

有一个 Unity 特有的陷阱：如果父类和子类都定义了 `Awake`，Unity 只会调用子类那个，父类的被"遮住"，初始化就丢了。正确做法是父类写 `protected virtual void Awake()`，子类 `override` 后调用 `base.Awake()`（学完 4.3 篇再回来看这一句）。

## 常见坑

- 子类构造函数忘了 `: base(...)`，而父类没有无参构造，编译失败。
- 以为 `private` 字段子类也能直接访问。
- 对父类变量调用子类的方法没转换就写，编译失败。
- 继承层级过深（四五层），修改父类影响一大片。
