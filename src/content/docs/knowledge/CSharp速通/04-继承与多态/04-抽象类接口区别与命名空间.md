> 适用版本：C# 9.0。

## 要点

- 抽象类表达"**是什么**"，可以带字段和部分实现；接口表达"**能做什么**"，只有契约。
- 命名空间用来避免重名，Unity 里 `System.Random` 和 `UnityEngine.Random` 冲突是经典坑。
- 大量拼接字符串用 `StringBuilder`，它是可变的缓冲区。
- `struct` 与 `class` 的区别是整套语言里最常被问到的一题，本篇给出完整对照表。

## 抽象类 vs 接口

| 比较项 | 抽象类 | 接口 |
| --- | --- | --- |
| 能否实例化 | 否 | 否 |
| 能否含字段 | 能 | 不能 |
| 能否含已实现的方法 | 能 | 一般不含（C# 8 默认实现除外） |
| 能否有构造函数 | 能 | 不能 |
| 一个类能继承/实现几个 | 一个 | 多个 |
| 表达的关系 | "是一种" | "具备某种能力" |
| 典型例子 | `Weapon`、`Enemy` | `IDamageable`、`IComparable` |

选择思路：先问"这几个类**共享状态和实现**吗"，是就用抽象类；如果只是**约定一组能力**，而且这些类彼此毫无继承关系（木桶、宝箱、敌人都能受伤），就用接口。两者可以同时用：抽象类 `Enemy` 实现接口 `IDamageable`。

## 命名空间

命名空间给类型加"姓"，避免两个人写了同名类互相冲突：

```csharp
namespace MyGame.Combat                 // 可以用点号表示层级
{
    class Skill { }
}

namespace MyGame.UI
{
    class Skill { }                     // 同名，但不冲突
}

// 使用
var a = new MyGame.Combat.Skill();      // 全名
```

在文件开头用 `using` 引入后可省略前缀：

```csharp
using MyGame.Combat;
using SysRandom = System.Random;         // 起别名，解决冲突

var s = new Skill();
var r = new SysRandom();
```

Unity 常见冲突：同时 `using System;` 和 `using UnityEngine;` 后，直接写 `Random` 会报"不明确的引用"。解决办法：用全名 `UnityEngine.Random.Range(0, 10)`，或者用 `using Random = UnityEngine.Random;` 起别名。

C++ 的 `namespace` 概念相同，只是 C# 的 `using` 不会把代码拷进来，也没有 `using namespace` 污染全局的头文件问题。

## StringBuilder

```csharp
using System.Text;

var sb = new StringBuilder();
for (int i = 0; i < 100; i++)
{
    sb.Append("第").Append(i).Append("关 ");     // 链式调用，直接在缓冲区追加
}
sb.AppendLine();                                 // 追加换行
sb.Insert(0, "[开始] ");
string result = sb.ToString();                   // 最后一次性生成字符串
sb.Clear();                                      // 清空后可以复用同一个 StringBuilder
```

与 `string` 对比：

| 比较项 | `string` | `StringBuilder` |
| --- | --- | --- |
| 可变性 | 不可变，每次修改生成新对象 | 可变，原地修改 |
| 适合 | 少量拼接、存储结果 | 循环中大量拼接 |
| 内存 | 每次拼接分配新字符串 | 缓冲区按需扩容，可复用 |

注意：两三个字符串拼一下用 `+` 或 `$""` 完全没问题，别为了这个而滥用 `StringBuilder`。在 Unity 里**缓存并复用**一个 `StringBuilder`（用 `Clear()` 而不是每次 `new`），才能真正避免 GC。

## struct 与 class 总对照

| 比较项 | `struct` | `class` |
| --- | --- | --- |
| 类别 | 值类型 | 引用类型 |
| 赋值 | 复制全部内容 | 复制引用 |
| 能否为 `null` | 不能（除 `T?`） | 能 |
| 继承 | 不能继承类，可实现接口 | 可以 |
| 默认构造函数（C# 9） | 不能自定义无参构造 | 可以 |
| 内存分配 | 随包含它的位置，不单独分配 | 堆上分配，由 GC 回收 |
| 作为 `object`/接口使用 | 装箱 | 无额外开销 |
| 适合 | 小而不可变的数据 | 有身份、有行为、需要共享的对象 |
| Unity 例子 | `Vector3`、`Color` | `GameObject`、`MonoBehaviour` |

## 面向对象章节小结

| 概念 | 一句话 |
| --- | --- |
| 类与对象 | 图纸与实物，引用类型 |
| 封装 | private 字段 + public 属性与方法 |
| 继承 | 单继承，子类复用父类 |
| 多态 | virtual + override，同一调用不同实现 |
| 接口 | 能力契约，可多实现 |
| 抽象类 | 带共享实现的半成品 |

## 动手试试

> **代码归属**：`【实验代码】`。本段只放进 `Assets/Speedrun/Labs/` 临时验证；要进入小游戏主线，请跟随后文或目录中的 `【主线实践】` 文章，在 `Assets/Speedrun/Game/` 重新接入并完成验收。

亲自制造一次命名空间冲突，再修好它：

```csharp
using System;
using UnityEngine;

public class RandomDemo : MonoBehaviour
{
    void Start()
    {
        Debug.Log(Random.Range(0, 10));      // 编译错误 CS0104：Random 不明确
    }
}
```

三种修法任选一种试一遍：

1. 写全名 `UnityEngine.Random.Range(0, 10)`。
2. 在 `using` 区加别名 `using Random = UnityEngine.Random;`。
3. 删掉 `using System;`（如果用不到 `System` 里的类型）。

再把这个类包进 `namespace MyGame.Combat { ... }`，确认仍然能挂到物体上。

## 项目应用决策：接口、抽象类和命名空间如何落到项目

方块地牢的攻击者只需要知道目标能否受伤，因此依赖 `IDamageable`；敌人之间共享移动和受击骨架时，才考虑抽象基类 `EnemyBase`。接口表达“我能做什么”，抽象类表达“我属于哪一类并共享哪些实现”。

命名空间按游戏职责隔离 `Gameplay`、`UI`、`Config`，避免 `Random`、`Object` 等名称冲突。`StringBuilder` 只在需要反复追加战斗日志时使用，单次插值字符串不需要为了“看起来高级”改写。

## 常见坑

- 一个 `.cs` 文件里的 `namespace` 与文件夹结构不对应，之后找类很难。
- Unity 的 `Random`、`Object` 与 `System` 同名冲突。
- 在循环里每次 `new StringBuilder()`，等于没用。
- 抽象类里放太多"以防万一"的成员，子类被迫继承用不到的东西。
