## 生产器不是特殊的传送带

`ItemProcessorComponent` 记录的是加工语义：

```text
processorType
inputsPerCharge
inputSlots
inputCount
ongoingCharges
queuedEjects
nextOutputSlot
bonusTime
```

它通过 `ItemAcceptor` 收输入，通过 `ItemEjector` 发输出；生产逻辑只处理中间状态。

## 一次加工的状态流

```text
接收输入
→ 按源槽位放入 inputSlots
→ 达到 inputsPerCharge
→ 创建 ongoingCharge
→ 累积 processingTime
→ 把结果放入 queuedEjects
→ 等输出槽和下游可用
→ Ejector 交付结果
```

输出被阻塞时，处理器不会丢弃成品；成品停留在 `queuedEjects` 或输出槽中，最终让输入和生产继续受到背压。

## 为什么输入槽按槽位记录

某些处理器需要多个输入同时满足，且每个输入来自指定方向或对应位置。`inputSlots` 能保证同一个源槽不会重复占用：

```text
sourceSlot 已有物品 → 本次不能再次接收
```

对于 Unity ECS，可以把固定数量的配方输入放到 BlobAsset，把动态当前输入放到 `DynamicBuffer<InputStack>`。

## Unity ECS 组件建议

```csharp
public struct RecipeRef : IComponentData { public int Id; }
public struct ProcessingState : IComponentData
{
    public float RemainingTime;
    public int InputCount;
}
public struct InputStack : IBufferElementData
{
    public int Slot;
    public int ItemType;
    public int Count;
}
public struct PendingOutput : IBufferElementData
{
    public int ItemType;
    public int Count;
}
```

第一版不要为每个生产结果创建一个独立 Entity；用批量堆叠可以更直接地练习数据布局和吞吐量。
