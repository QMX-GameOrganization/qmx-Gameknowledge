## 速度不是“每帧传一个”

`BeltPath.update()` 每 tick 计算可前进的距离：

```text
beltSpeed × deltaSeconds × itemSpacingOnBelts
```

路径中的物品按间距排序，靠后的物品先处理；每个物品最多前进到“前方物品减去最小间距”的位置。这样速度、物品间距和吞吐量自然关联：

```text
吞吐量 ≈ MovementSpeed / ItemSpacing
```

对于 Unity ECS，建议使用固定时间步，避免渲染帧率改变生产结果。

## 入口阻塞

`BeltPath.tryAcceptItem()` 只检查起点到第一个物品的距离是否达到最小间距：

```text
空间足够 → 插入路径起点，返回 true
空间不足 → 返回 false
```

输出器件只有在得到 `true` 后才清空自己的输出槽。失败时物品不丢失，也不回滚到某个全局库存。

## 末端阻塞

路径末端物品到达出口后，会调用缓存的 `boundAcceptor`：

```text
接收成功 → 移除路径头部物品
接收失败 → 物品停在末端，不再越过它
```

后续物品由于最小间距约束无法超过头部物品，于是阻塞从出口向入口传播。

```text
接收器满
→ 路径末端卡住
→ 路径内部填满
→ 新物品无法进入
→ 输出槽占满
→ 生产器停止输出
```

这就是 shapez.io 的背压，不需要额外的“全局阻塞传播消息”。

## 传送带需要两个状态维度

不要把以下概念合成一个 `Speed` 字段：

```text
MovementSpeed   物品沿路径的空间速度
ItemSpacing     物品不能重叠的最小距离
Capacity        由总长度和间距隐含出的最大数量
InputRate       入口每秒允许接收量（可选）
OutputRate      出口每秒允许交付量（可选）
```

shapez.io 主要用前两个量产生吞吐；你的工厂若要让机器端口有独立速率，再在端口上加预算累积器。

## 端点交付的伪代码

```text
if head.Distance >= path.TotalLength:
    if TryAccept(target, head.ItemType):
        remove head
    else:
        head.Distance = path.TotalLength
        path.Blocked = true
```

`Blocked` 可以作为调试和 UI 状态，但不要让它成为唯一的逻辑依据；真正决定是否阻塞的是下一次 `TryAccept` 是否成功。
