通用底座是所有客户端方向的共同部分。这里的目标不是把每个计算机专业课程都学完，而是能读懂运行时行为、定位问题、设计边界并交付一个可维护的功能。

## 学习顺序

```text
语言与内存
→ Unity 运行时
→ 算法与数学
→ 性能与并发
→ 工程交付
```

| 模块 | 学到什么程度算够用 | 最小实践 |
| --- | --- | --- |
| C# / C++ 运行时 | 能解释生命周期、所有权、分配和并发边界 | 写对象池、事件系统和一个 C++ RAII 小实验 |
| Unity 运行时 | 能解释对象、资源和 PlayerLoop 的关系 | 完成可重开的小型场景 |
| 算法与数学 | 能为玩法问题选择合适的数据结构和查询策略 | 范围查询、寻路、视野和调度 |
| 性能与并发 | 能用工具定位瓶颈并做前后测量 | 完成一份 CPU/GPU/GC 优化报告 |
| 工程交付 | 能让功能可测试、可配置、可构建和可回滚 | 加入日志、配置、检查器和自动构建 |

## 四个学习入口

### 01. [C#、C++ 与运行时基础](./01-CSharp与CPlusPlus运行时/)

先补齐语言和运行时边界，再进入更复杂的 Unity 系统。重点是值类型与引用类型、对象生命周期、托管分配、事件和异步、C++ RAII、移动语义、所有权、并发和原生插件边界。

完成标准是能解释一段代码为什么产生分配、为什么出现对象泄漏或回调残留，并能写出对象池、资源句柄和可取消的异步流程。

### 02. [Unity 运行时与资源](./02-Unity运行时与资源/)

从 `GameObject`、`Component`、Prefab 和 `ScriptableObject` 开始，理解 PlayerLoop、生命周期、序列化、场景切换、Addressables 和异步加载之间的关系。

完成标准是能做出一个可重开的战斗场景，明确每个对象的创建者、拥有者、可用时机、释放时机和失败恢复路径。

### 03. [算法、数学与性能基础](./03-算法数学与性能基础/)

把数据结构、空间查询、寻路、状态机、游戏数学和性能分析连接到真实的 Unity 问题。这里不追求泛泛刷题，而是要求算法能落到范围查询、视野判断、目标选择、调度和批处理上。

完成标准是能对同一问题实现朴素版本、空间优化版本和 Job/Burst 版本，并用固定输入、固定设备和明确指标比较结果。

### 04. [工程交付与工具](./04-工程交付与工具/)

把功能开发推进到可协作、可测试、可构建和可回滚。重点包括 Git、日志、断言、配置、数据迁移、Unity Editor 工具、资源检查、构建、崩溃分析和发布回滚。

完成标准是能做出一个资源检查与构建前置工具，能够定位错误、批量修复安全问题、阻止严重错误，并输出可追踪的检查报告。

## 建议的学习节奏

第一轮按 `01 → 02 → 03 → 04` 完成四个最小实践。第二轮把它们合并到一个小型 Gameplay 项目中，要求项目同时具备对象生命周期管理、异步加载、空间查询、性能报告和构建检查。之后进入岗位主线，根据目标选择 Gameplay、客户端框架、性能、网络、渲染、工具管线或 TA 分支，不再把所有分支按同样深度学习。

## 学习原则

- 先用项目暴露问题，再回到专栏补概念。
- 每个底层知识都要连接到一个 Unity 运行时现象。
- 每个性能结论都要记录输入、设备、指标和前后结果。
- 每个架构选择都要写清楚所有者、生命周期和失败路径。
- 底座达到够用后就进入岗位主线，不需要无限期横向扩展。
