## 必学范围

- Git 分支、提交、冲突处理和代码审查。
- 日志等级、错误码、断言、调试面板和问题复现。
- 配置与代码分离，版本兼容和数据迁移。
- 单元测试、PlayMode 测试、回归测试和测试数据。
- Unity Editor 工具、资源检查、批量处理和导入规则。
- 构建配置、平台差异、符号文件、崩溃分析和发布回滚。
- 热更新、资源版本、下载升级和失败恢复。

## 工具的验收标准

一个工具至少要能说明：

- 它减少了哪一步人工操作。
- 输入错误时如何提示。
- 重复执行是否安全。
- 中途失败后能否继续或回滚。
- 是否有日志和统计数据。
- 是否可以被其他项目复用。

## 最小实践

做一个 Unity 资源检查和构建工具，支持：

- 目录和命名检查。
- 纹理、模型、材质和动画规则检查。
- 错误列表定位到资源。
- 批量修复可修复的问题。
- 构建前自动阻止严重错误。
- 输出一份机器可读的检查报告。

## 结果要求

工程能力不是工具数量，而是能把需求拆成边界、接口、生命周期、失败路径和验证步骤。后续用主项目验证这些能力是否真的减少了返工和定位时间。
