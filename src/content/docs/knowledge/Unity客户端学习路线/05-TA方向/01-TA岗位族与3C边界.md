## TA 不是一个单一岗位

技术美术（Technical Artist）通常处在程序、美术、设计和引擎之间。不同公司会把职责拆成不同岗位，也会把多个方向合并成一个“技术美术”岗位。腾讯近期公开的技术美术岗位直接列出渲染、动画、工具与管线、PCG、性能五条赛道。网易的岗位样本还出现角色技术、Shader、材质、灯光、骨骼动画、LOD、动态布料和 AI 美术管线等组合。

因此，看到“TA”时，先看它解决的生产问题和技术对象，再看职位名称。

## TA 的主要分流

| 方向 | 主要对象 | 常见技术 | 典型作品 |
| --- | --- | --- | --- |
| 渲染 TA | 画面、材质、光照、后处理 | HLSL/GLSL、PBR、RenderDoc、Shader Graph、渲染管线 | 角色皮肤、毛发、卡通渲染、环境光、后处理 |
| 角色 / 动画 TA | 骨骼、绑定、蒙皮、动画资产和运行时表现 | Maya/Blender、Rigging、IK、Animation Blueprint/Animator、Python | 自动绑定、脚部 IK、重定向、动作融合、布料和面部动画 |
| 特效 TA | 粒子、技能表现、材质特效和特效管线 | VFX Graph、Shuriken、Shader、Niagara、Houdini | 技能特效、破碎、流体感、轨迹、受击和环境特效 |
| 工具与管线 TA | DCC、资源、导入导出和美术生产流程 | Python、MEL、MaxScript、C# Editor、AssetPostprocessor | 一键导出、资源检查、批量修复、材质转换、动画处理 |
| PCG / 程序化 TA | 地形、植被、道路、建筑和关卡内容 | Houdini/HDA、UE PCG、Geometry Nodes、随机采样、几何和图算法 | 程序化地形、道路生成、植被散布、建筑组合、UGC 编辑器 |
| 性能 TA | 多平台画面预算和资源预算 | Profiler、RenderDoc、Memory Profiler、LOD、DrawCall、带宽 | 移动端降级、角色预算、纹理压缩、阴影和粒子优化 |
| AI / AIGC TA | AI 生成和美术生产管线 | Python、模型调用、数据处理、DCC、引擎接入、工具评估 | AI 资产生成、自动标注、材质生成、批量变体和生产工具 |
| 场景 / 环境 TA | 环境资产、灯光、材质、地形和场景组织 | Shader、Lighting、Houdini、DCC、资源规范、性能预算 | 大世界地形、植被、风格化材质、烘焙和场景检查 |

## 3C 和动画 TA 为什么容易混在一起

3C 通常指 Character、Camera、Control，实际项目里还会延伸到移动、瞄准、交互、战斗反馈和网络表现。它的核心问题是：

```text
玩家输入 → 角色状态 → 移动 / 相机 / 战斗 → 动画与特效表现 → 网络或物理约束
```

动画 TA 的核心问题是：

```text
美术资产 / 骨骼 / 动作数据 → 绑定与处理 → 导入导出 / 动画图 / IK → 运行时表现与生产效率
```

二者在以下区域共享大量技术：

- 动画状态机和动画图。
- 根运动、速度匹配和方向匹配。
- IK、脚部贴地、瞄准偏移和身体朝向。
- 受击、击退、布娃娃和物理动画。
- 动画事件、攻击窗口、移动和相机协同。
- 动画资产导入、重定向、压缩和性能预算。

所以，展示角色移动、脚部 IK、瞄准、动作融合或程序化动画的作品，常常会被放到动画 TA 作品集里。它们也可能属于 3C 客户端，关键要看作品的技术核心是什么。

## 用四个问题判断作品归属

### 问题一是主要服务谁

- 主要服务玩家输入、角色控制和战斗体验，偏 **Gameplay / 3C**。
- 主要服务动画师、绑定师和资产制作流程，偏 **动画 TA**。

### 问题二是主要修改什么

- 修改运行时角色状态、移动规则、相机和战斗逻辑，偏 **3C**。
- 修改骨骼、绑定、动画资产、导入导出和动画图模板，偏 **动画 TA**。

### 问题三是结果在哪里体现

- 玩家操作时的行为、手感、镜头和网络表现，偏 **3C**。
- DCC 工具、引擎工具、资产批处理和动画生产效率，偏 **动画 TA**。

### 问题四是验收指标是什么

- 输入延迟、移动手感、转向、命中反馈、网络误差和帧率，偏 **3C**。
- 绑定时间、资产错误率、导出成功率、动画质量、重定向成本和生产效率，偏 **动画 TA**。

## 三类常见交叉作品

### 角色运动 + 脚部 IK

如果重点是移动控制、斜坡、速度和网络状态，作品可以定位为 3C。若重点是自动脚部绑定、骨骼处理、批量配置和动画师使用的工具，作品更接近动画 TA。

### 瞄准系统 + Aim Offset

如果重点是输入、相机、武器状态、射击和网络预测，属于 3C / 战斗客户端。若重点是骨骼层级、瞄准偏移资产、动画图模板和批量制作流程，则属于动画 TA。

### 受击与布娃娃

如果重点是战斗状态、伤害、击退、倒地和网络同步，属于 Gameplay / 3C。若重点是物理骨骼配置、约束生成、布娃娃资产工具和多角色复用，属于动画 TA 或角色技术。

## 作品集应该怎么命名

不要只写“3C Demo”或“动画 TA Demo”。应写清楚主问题、技术边界和指标，例如：

- **网络 FPS 角色控制**：输入缓冲、预测移动、动画状态和延迟注入。
- **角色动画工具链**：批量生成骨骼配置、导出检查、动画重定向和错误报告。
- **程序化脚部 IK**：运行时贴地、动画融合、斜坡处理和移动性能。
- **角色动作生产管线**：Maya 导出、Unity 导入、骨骼校验和动画压缩。

同一个作品可以同时投递两个方向，但说明重点必须不同。投 3C 时突出运行时行为、输入和战斗。投动画 TA 时突出资产、工具、管线和生产效率。

## 你该怎么选 TA 子方向

结合你已经会 Unity、C#、C++、ShaderGraph 和部分图形学的情况，优先级可以这样排：

1. **性能 / 工程型 TA**：最容易和你的客户端主线衔接，学习 Profiler、RenderDoc、资源预算、工具和平台优化。
2. **渲染 TA**：已有 ShaderGraph 基础，可以继续补 HLSL、渲染管线、光照、材质和 GPU 分析。
3. **动画 / 角色 TA**：如果你喜欢角色手感、IK、动作融合和角色表现，可以从 3C 作品自然切入。
4. **工具与管线 TA**：适合喜欢编辑器、自动化和工程约束的人，可以用 C# Editor 加 Python DCC 工具建立作品。
5. **PCG TA**：适合对场景生成、Houdini、几何和程序化内容有兴趣的人，学习曲线与美术工具较长。
6. **特效 TA**：适合以视觉表现为主的路线，需要补粒子系统、Shader、VFX Graph 和美术表达。
7. **AI / AIGC TA**：适合在已有 DCC、引擎和管线基础上扩展，不能只停留在调用模型接口。

## 推荐的主副组合

| 主线 | 副线 | 适合的作品 |
| --- | --- | --- |
| Gameplay / 3C | 动画 / 角色 TA | 网络角色控制、IK、动作融合、受击和回放 |
| Gameplay / 3C | 性能 TA | 角色和战斗场景的 CPU/GPU/内存预算与优化 |
| 渲染 TA | 性能 TA | Shader、材质、RenderDoc、移动端降级 |
| 工具与管线 TA | PCG TA | Houdini 生成、Unity 导入、资源检查和批处理 |
| 特效 TA | 渲染 TA | VFX Graph、Shader、技能表现和性能预算 |
| 动画 TA | 工具与管线 TA | Rigging、重定向、动画检查和导出工具 |

对你当前的推荐组合是：

```text
主线：Unity Gameplay / 3C
副线：性能与工程，逐步加入动画运行时
```

这样可以解释你看到的许多“动画 TA 作品”，也能避免把所有角色表现作品都误判成需要转行动画 TA。
