> 适用版本：CoreCLR 部分以 .NET 8/9 为准；Unity 部分以 Unity 6000.x（C# 9.0，Mono/IL2CPP，Boehm GC）为主线，并说明 Unity 6.8 起 CoreCLR 取代 Mono 的计划。各篇里无法核实的细节标"待核实"。

## 这套资料是什么

这是为扩充八股知识库、并配合 ECS 学习而写的 C# 运行时专栏，共 26 篇，分 7 章。读者默认已有 Unity/C# 开发经验，不讲语法基础，直接讲对象在内存里怎么放、IL 和 JIT 做了什么、GC 怎么扫、哪些写法会分配，并在合适的地方与 C++ 对照。

## 与 ECS 学习的对应关系

| ECS / DOTS 里的做法 | 对应的 C# 底层知识 |
|---|---|
| 组件是 blittable 的 struct，按 Chunk 连续存放 | 1.1、1.4（布局与 padding），2.2（blittable） |
| 组件里不能放托管引用 | 3.1（GC 要扫引用），2.3（NativeArray 不归 GC 管） |
| `NativeArray`、`UnsafeList` 手动释放 | 2.3、2.5、3.5 |
| Job 与 Burst 里不能 new 托管对象 | 3.4、6.1、6.2（隐藏分配） |
| `in`/`ref` 传参，避免 struct 拷贝 | 1.3、2.4 |
| Burst 限制 C# 子集、禁用异常与托管类型 | 2.1（IL 与 JIT）、4.1（IL2CPP） |
| 对 Chunk 布局和缓存行的讨论 | 1.4（false sharing），5.3（内存模型） |

与 Job 和 Burst 专栏的内存分配器、安全系统两篇互补：那边讲 Native 内存怎么管，这里讲托管世界为什么要躲开。

## 版本与核实说明

- Unity 6.8 起 CoreCLR 取代 Mono，IL2CPP 保留，且其 Boehm GC 行为不变，依据 Unity 官方论坛《Path to CoreCLR, 2026: Upgrade Guide》。
- 各页末尾的"参考资料"链接多数在写作时没有逐条打开验证，引用前请抽查。
- 标"待核实"的条目是写作时没能确证的版本差异、数值或实现细节，不要直接当作面试标准答案背。
