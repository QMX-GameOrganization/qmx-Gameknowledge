> 适用版本：Unity 2021 LTS 到 Unity 6000.x。答案为面试速答，细节见对应章节。标"待核实"的条目不要直接当作标准答案背。

## AssetBundle

**1. AssetBundle 是什么？**
Unity 的资源归档格式，包含序列化对象和依赖信息，运行时通过 `AssetBundle` 类加载，是资源热更的基础。（2.1）

**2. 显式依赖与隐式依赖的区别？**
显式资源是被分配到某个 AB 的资源；隐式依赖是被引用但未分配的资源，会被复制进每个引用它的 AB，产生冗余。（2.1）

**3. 怎么解决 AB 冗余？**
把共享资源放入公共包，其他包依赖它；构建后用报告或脚本检查被多个包重复包含的资源。（2.1）

**4. LZMA、LZ4、不压缩怎么选？**
LZMA 包最小但需整体解压，适合传输；LZ4 分块压缩、随机访问，运行时首选；不压缩加载最快、包最大。（2.1）

**5. TypeTree 是什么，禁用有什么影响？**
TypeTree 保存序列化类型结构，用于跨 Unity 版本容错。禁用后包更小、加载更快，但要求构建与运行的 Unity 版本一致。（2.1）

**6. `LoadFromFile` 与 `LoadFromMemory` 的区别？**
前者从路径读取，LZ4/未压缩时按需读取，内存省；后者要求整包字节已在内存，多一份拷贝，常用于解密后加载。（2.2）

**7. `Unload(true)` 与 `Unload(false)`？**
`true` 连同已加载的资源一并销毁，仍被引用的对象丢失；`false` 只卸载容器，已加载资源留在内存，之后重复加载可能产生多份。（2.2）

**8. 加载一个 AB 需要注意什么？**
先加载依赖，同一 AB 不能重复加载，异步并发请求要去重，用引用计数管理卸载。（2.2）

**9. 为什么编辑器里正常真机资源丢失？**
编辑器常通过 `AssetDatabase` 加载，不经过 AB，缺依赖被掩盖。真机走 AB，依赖未加载或未打包就丢失。（2.2）

**10. `Resources.UnloadUnusedAssets` 的作用与代价？**
卸载没有被引用的资源，需要扫描全部对象，开销随对象数增长，会引起卡顿，应放在加载界面。（2.3）

**11. 销毁实例等于释放资源吗？**
不等于。`Destroy` 只销毁实例，共享的 Mesh、Material、Texture 仍占内存，需要卸载 AB 或 `UnloadUnusedAssets`。（2.3）

**12. 怎么排查 AB 的内存泄漏？**
Memory Profiler 做快照对比，找出应释放而仍存在的对象，沿引用路径找到持有者；同时在自己的管理器里统计引用计数。（2.3）

## Addressables

**13. Addressables 相比直接用 AB 的好处？**
自动依赖加载、引用计数、统一寻址、目录更新与下载、有分析工具，减少自建管理器的出错面。（3.1）

**14. Address、Label、Group、Catalog 分别是什么？**
Address 是资源的逻辑名；Label 是分类标签；Group 是带打包规则的资源集合；Catalog 是运行时的寻址目录。（3.1）

**15. Bundle Mode 的三种模式？**
Pack Together（整组一包）、Pack Separately（拆分为多个包）、Pack Together By Label（按标签合并）。（3.1）

**16. 静态组（Cannot Change Post Release）的意义？**
发版后包内容保持不变，更新时只把变化的资源移入新的远程组，旧缓存继续有效，减少重复下载。（3.1、3.2）

**17. Addressables 的热更流程？**
`InitializeAsync` → `CheckForCatalogUpdates` → `UpdateCatalogs` → `GetDownloadSizeAsync` → `DownloadDependenciesAsync`，之后加载从缓存读取。（3.2）

**18. `addressables_content_state.bin` 有什么用？**
记录静态组的发版状态，用于 Update a Previous Build 判断哪些内容发生变化，必须归档保存。（3.2）

**19. 为什么热更不能再用 New Build？**
New Build 会重新计算所有包，哈希变化导致旧缓存全部失效，用户需全量重下。（3.2）

**20. Addressables 的引用计数怎么运作？**
Load/Instantiate 加一，Release/ReleaseInstance 减一；资源计数为 0 才可卸载，bundle 内所有资源为 0 且无依赖者时才卸载 bundle。（3.3）

**21. 为什么对 Addressables 实例 `Destroy` 会泄漏？**
`Destroy` 不会减引用计数，应使用 `ReleaseInstance`。（3.3）

**22. 如何降低漏释放的概率？**
封装加载作用域，让句柄与拥有者生命周期绑定，统一入口并统计未配对的加载。（3.3）

## 流程与版本

**23. 资源热更的完整链路？**
构建产物、生成清单、上传 CDN、客户端拉清单、比对、下载差异、校验、落盘、加载。（1.1、1.3）

**24. 如何判断哪些文件要下载？**
对比远端清单与本地记录的内容哈希；版本号只用于兼容性判断。（1.3）

**25. 下载中途被杀进程怎么保证安全？**
先写临时文件，校验大小与哈希通过后再重命名；本地状态在写入完成后才更新。（1.3）

**26. CDN 缓存导致更新不生效怎么处理？**
入口文件禁缓存，清单与大文件使用带版本或哈希的文件名，旧文件保留不覆盖。（1.3）

**27. 热更后如何回滚？**
保留上一个稳定版本，启动成功后才提升为稳定；失败自动切回；服务端旧文件保留，入口可指回旧清单。（7.1）

**28. 哈希与签名的区别？**
哈希防损坏，攻击者可同时替换文件与哈希；签名用私钥签清单，客户端用公钥验证，防篡改。（7.2）
