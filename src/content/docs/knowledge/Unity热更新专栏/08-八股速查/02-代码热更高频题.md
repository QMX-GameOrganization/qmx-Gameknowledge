> 适用版本：Unity 2021 LTS 到 Unity 6000.x。各方案的版本与功能细节随项目更新，标"待核实"的条目以官方文档为准，不要直接当作标准答案背。

## 平台与基础

**1. 为什么 IL2CPP/iOS 上不能直接 `Assembly.Load` 新 dll？**
IL2CPP 把 IL 提前编译成原生代码，运行时没有 JIT，也没有 IL 执行引擎；iOS 还禁止运行时生成可执行内存。新 dll 的 IL 无法被执行。（1.2）

**2. 代码热更有哪几类思路？**
换语言（Lua）、自带解释器执行 IL（ILRuntime）、扩展 IL2CPP 运行时使其解释 IL（HybridCLR）。（1.2）

**3. 能数据驱动解决的需求为什么不推荐代码热更？**
数据变更风险小、测试面小、审核压力小；代码热更要承担解释性能、AOT 兼容和调试成本。（1.1）

**4. 热更新与应用商店政策的关系？**
Apple 审核指南 2.5.2 等条款限制下载并执行改变应用功能的代码，Google Play 对下载可执行代码也有限制。应把热更限定在修复与内容更新，并以官方条款为准。（1.2，待核实）

## HybridCLR

**5. HybridCLR 的原理？**
扩展 IL2CPP 运行时，加入元数据解析和 IL 解释器，使动态加载的程序集能被解释执行，AOT 代码与解释代码经桥接函数互相调用。（4.1）

**6. 热更程序集为什么不能被主包引用？**
被引用会被 IL2CPP 提前编译进原生代码，失去热更意义，主包发布后也无法替换。（4.2）

**7. 启动与下载逻辑放在哪里？**
放在 AOT 程序集里，因为这时热更代码还没加载。（4.2）

**8. `LoadMetadataForAOTAssembly` 解决什么问题？**
热更代码出现了主包没有原生实现的 AOT 泛型实例，补充 AOT 程序集的元数据后，解释器可以为它们提供解释执行的实现。（4.2、4.3）

**9. 什么是 AOT 泛型实例缺失？**
值类型作实参的泛型（如 `List<MyStruct>`）在构建期没被收集到，就没有对应原生代码，运行时调用会报 "no ahead of time (AOT) code was generated"。（4.3，C# 底层专栏 4.2）

**10. 热更代码性能不够怎么办？**
热点逻辑下沉到 AOT，减少跨界调用，固化关键泛型实例，缓存反射；必要时评估进阶的混合执行方案。（4.3）

**11. 编辑器里正常，真机崩溃的原因？**
编辑器用 Mono JIT，没有 AOT 限制，也不走解释器；缺 AOT 泛型、缺桥接、裁剪问题只在真机暴露。（4.2、4.3）

**12. 热更脚本挂在预制体上出现 Missing Script 怎么办？**
确认热更程序集已在预制体加载前加载，或改为运行时 `AddComponent`。（4.2）

## Lua

**13. Lua 热更的原理？**
Lua VM（C 实现，随包编译）解释执行脚本，脚本文件可下载更新；C# 与 Lua 通过 Lua C API 的栈交互。（5.1）

**14. Lua 调用 C# 的两种方式？**
静态 Wrap（预生成绑定，无反射）和反射（兜底，慢且有 GC）。（5.1）

**15. 为什么需要生成 Wrap？**
避免反射的开销与分配；IL2CPP 不能运行时生成代码，需要预先生成。（5.1、5.2）

**16. xLua Hotfix 的实现？**
构建时对标记类做 IL 注入，在方法入口插入补丁检查；运行时 Lua 注册补丁，命中则执行 Lua 实现。（5.1）

**17. iOS 上 LuaJIT 为什么没有优势？**
iOS 禁止 JIT，LuaJIT 只能以解释模式运行，速度优势大幅减少。（5.1，待核实）

**18. Lua 项目 GC 压力大，如何排查？**
分清 Lua 堆和 C# 堆。C# 侧查反射、装箱、字符串转换；Lua 侧查每帧创建的 table、字符串、闭包。（5.2）

**19. 跨 GC 的泄漏怎么产生？**
Lua 持有 C# 对象或 C# 持有 Lua 函数，一端不释放就使对方无法回收；`LuaFunction` 需要手动 `Dispose`。（5.2）

**20. 如何降低 Lua 与 C# 边界开销？**
减少跨界次数，缓存引用，提供批量接口，热点逻辑留在 C#，避免热路径传递值类型和创建临时对象。（5.2）

## ILRuntime

**21. ILRuntime 的原理？**
纯 C# 实现的 IL 解释器，在自己的域内解释执行热更 dll，调用主域方法靠反射或 CLR 绑定。（6.1）

**22. 为什么需要跨域适配器？**
热更类型不是真实 CLR 类型，主域代码无法直接继承或使用它，适配器在主域里转发到热更域的实现。（6.1）

**23. CLR 绑定的作用？**
为热更代码实际调用的主域方法生成直接调用的代码，避免反射开销。（6.1）

**24. 委托为什么要注册转换？**
热更方法要传给主域的委托类型，需要生成对应的委托适配，否则运行时报错。（6.1）

## 选型与工程

**25. HybridCLR 与 ILRuntime 的本质区别？**
HybridCLR 把解释器集成进 IL2CPP 运行时，热更类型是原生运行时类型，互操作几乎无需适配；ILRuntime 是独立解释器，类型隔离，需适配器与转换。（4.1、6.2）

**26. 三类方案怎么选？**
以团队技能和代码资产为起点：C# 为主选 HybridCLR，已有 Lua 框架保持 Lua，存量 ILRuntime 项目评估迁移收益；性能敏感部分放 AOT。（6.2）

**27. 热更层与 AOT 层的边界怎么划？**
稳定的、性能敏感的、与平台强相关的放 AOT，易变的玩法与 UI 放热更层，中间用稳定接口。（6.2）

**28. 什么情况下必须发整包？**
AOT 代码、原生插件、权限或 Player 设置变化，以及热更代码依赖的 AOT 接口变化。（7.1）

**29. 灰度发布怎么做？**
服务端按稳定用户标识哈希分桶返回不同清单，分阶段放量，观察崩溃率等指标，异常时停止。（7.1）

**30. 客户端加密能不能防外挂？**
不能，只能提高成本。关键数据和行为要在服务端校验。（7.2）
