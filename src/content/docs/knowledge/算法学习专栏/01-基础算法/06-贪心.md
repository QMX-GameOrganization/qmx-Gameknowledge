> 适用版本：C++17。前置：`sort` 的自定义比较、`priority_queue` 的小根堆写法。

## 要点

- 贪心算法（greedy）：每一步都做当前看起来最好的选择，不回头。写起来短，难点在于**证明它对**。
- 一道题能用贪心，需要有“贪心选择性质”：存在一个最优解，包含当前的贪心选择；以及“最优子结构”：做完这一步后，剩下的是同类子问题。
- 常见的证明方式是**交换论证**（exchange argument）：任取一个最优解，若它与贪心解不同，把它的第一处不同换成贪心选择，结果不会变差。
- 套路一：排序后贪心，关键是选对排序的依据。套路二：用堆动态地取当前最小或最大。
- 贪心最容易错：没有证明就提交，靠样例通过。遇到拿不准的题，先写暴力对拍（0.3）。

## 例 1：区间调度（无重叠区间的最大数量）

有若干个活动，每个活动有开始和结束时间，同一时刻只能参加一个，问最多能参加多少个活动（端点相接不算冲突）。这也是 LeetCode 435 无重叠区间（用总数减去最大不重叠数就是最少移除数）。

可能的贪心策略有：选最早开始的、选最短的、选冲突最少的、选**最早结束的**。前三种都有反例。比如最早开始的可能是一个横跨整个时间轴的大活动。

正确策略：按**结束时间**从小到大排序，依次检查，若当前区间起点不早于上一个已选区间的终点，就选它。

![按右端点排序后，依次选择不与已选冲突的区间：[1,4]、[5,7]、[8,11]](/qmx-Gameknowledge/assets/algo/c1-greedy-interval.svg)

**为什么对（交换论证）：** 设贪心选择的第一个区间是结束最早的 `g`。任取一个最优解 `O`，设其中结束最早的区间为 `o`。由于 `g` 结束得不晚于 `o`，把 `O` 里的 `o` 换成 `g`，不会与 `O` 中其他区间冲突（它们都在 `o` 结束之后才开始，而 `g` 结束得更早）。所以存在一个包含 `g` 的最优解。去掉 `g` 以及所有与 `g` 冲突的区间，剩下的是同类子问题，重复这个论证即可。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<pair<int, int>> iv = {{1, 4}, {3, 5}, {0, 6}, {5, 7}, {3, 9},
                                 {5, 9}, {6, 10}, {8, 11}, {8, 12}, {2, 14}};
    sort(iv.begin(), iv.end(), [](auto& a, auto& b) { return a.second < b.second; });
    int cnt = 0, end = INT_MIN;
    for (auto& [s, e] : iv) {
        if (s >= end) {          // 与已选区间不冲突（端点相接允许）
            cnt++;
            end = e;
        }
    }
    printf("%d\n", cnt);   // 3
}
```

复杂度 O(n log n)，主要是排序。

## 例 2：排队接水（洛谷 P1223）

`n` 个人排队用同一个水龙头，第 `i` 个人接水需要 `t[i]` 时间。每个人的等待时间是他前面所有人的接水时间之和，问怎样排队使平均等待时间最小。

策略：接水时间短的排在前面。

**交换论证：** 任取一个排队方案，若存在相邻的两人 `x, y`，`x` 在前且 `t[x] > t[y]`，把二者交换。其他人的等待时间不变（前面的总时间不变）。交换前 `y` 等待多了 `t[x]`，交换后 `x` 等待多了 `t[y]`，总和减少了 `t[x] - t[y] > 0`。所以最优方案里不会有这样的相邻逆序，也就是按接水时间升序排列。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> t = {56, 12, 1, 99, 1000, 234, 33, 55, 99, 812};
    int n = t.size();
    vector<int> id(n);
    iota(id.begin(), id.end(), 1);                       // 编号 1..n
    stable_sort(id.begin(), id.end(), [&](int a, int b) { return t[a - 1] < t[b - 1]; });
    long long wait = 0, total = 0;
    for (int i = 0; i < n; i++) {
        printf("%d ", id[i]);
        total += wait;                                   // 第 i 个人的等待时间
        wait += t[id[i] - 1];
    }
    printf("\n%.2f\n", (double)total / n);               // 291.90
}
```

等值时用 `stable_sort` 保持编号小的在前，这是该题要求输出字典序最小方案时的写法。

## 例 3：合并果子（洛谷 P1090）

`n` 堆果子，每次合并两堆，代价是两堆重量之和，合并 `n - 1` 次后变成一堆，求最小总代价。

策略：每次合并**当前最轻的两堆**。这就是哈夫曼编码的构造过程。直觉：先合并的堆在之后的每次合并中都会被重复计入，应该让轻的堆被重复计入。用小根堆动态取最小的两个：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> w = {1, 2, 9};
    priority_queue<long long, vector<long long>, greater<long long>> pq(w.begin(), w.end());
    long long cost = 0;
    while (pq.size() > 1) {
        long long a = pq.top(); pq.pop();
        long long b = pq.top(); pq.pop();
        cost += a + b;
        pq.push(a + b);          // 合并后的新堆放回去，下一轮还要参与比较
    }
    printf("%lld\n", cost);   // 15：先合并 1+2=3（代价 3），再 3+9=12（代价 12）
}
```

复杂度 O(n log n)。此处不能只排序一次再依次合并，因为合并出的新堆可能比未合并的堆还轻，需要堆来维护顺序。

## 贪心是否成立：自检清单

1. 能否举出反例？先拿几个小数据手动试各种贪心策略。
2. 能否写出交换论证？说不清楚“为什么换了之后不会更差”，多半是错的。
3. 能否写出暴力解，在随机小数据上对拍？这是最可靠的办法。
4. 贪心失败时的典型信号：硬币面值 `{1, 5, 11}` 凑 15，贪心取 `11 + 1 + 1 + 1 + 1`（5 枚），最优是 `5 + 5 + 5`（3 枚）。这类题应转向动态规划。

## 常见坑

- 排序依据选错。区间调度按结束时间排序，不是开始时间，也不是长度。
- 比较函数不满足严格弱序（用了 `<=`），运行时会崩溃或结果随机。
- 只在样例上通过就认为贪心正确。样例往往恰好是贪心成立的情形。
- 合并果子类题用 `int` 存和，总代价可能溢出，用 `long long`。
- 等价元素的处理（相同结束时间、相同时间）会影响题目要求的输出顺序，注意用 `stable_sort` 或增加第二关键字。
