> 适用版本：C++17。前置：0.1 篇的复杂度概念。

## 要点

- 写递归只需想清三件事：函数的含义、终止条件、如何把问题缩小。
- 递归树的每个节点是一次函数调用。节点总数乘以单个节点的额外代价，就是时间复杂度。
- 递归的空间开销是调用栈，大小等于树的深度，而不是节点总数。
- 同一个子问题被重复调用时，用记忆化可以把指数级降到多项式级。
- 递归深度太大会栈溢出，需要改写成迭代或手动用栈。

## 递归的三个要素

以“求 n 的阶乘”和“汉诺塔”为例，写递归前先回答：

1. **函数的含义**：`f(n)` 返回什么，要把它当作已经正确实现的黑盒。
2. **终止条件**：最小的问题直接给出答案，如 `n == 0`。
3. **缩小问题**：怎样用更小的 `f` 的结果拼出当前答案。

写的时候不要去想内部怎样展开，只检查这三条是否成立。展开过程留给画递归树时再看。

## 斐波那契：递归树里的重复

```cpp
long long fibSlow(int n) {
    if (n < 2) return n;
    return fibSlow(n - 1) + fibSlow(n - 2);
}
```

![fib(5) 的递归树，fib(3) 出现 2 次，fib(2) 出现 3 次](/qmx-Gameknowledge/assets/algo/c0-fib-tree.svg)

fib(5) 共产生 15 次调用，其中 fib(3) 算了 2 次、fib(2) 算了 3 次。每多一层，节点数大约乘以 1.6（黄金分割比），所以朴素递归的时间是指数级，约 O(1.618ⁿ)，常简写为 O(2ⁿ) 的上界。实测 fib(30) 要调用 2 692 537 次。

给每个 n 只算一次，就是记忆化：

```cpp
long long memo[100];                     // 初始化为 -1
long long fibMemo(int n) {
    if (n < 2) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
}
```

此时 fib(30) 只调用 59 次，也就是 2n−1 次，时间降为 O(n)。完整的程序和输出如下，第 3.4 节“记忆化搜索”和第 6 章会反复用到这个思路。

```cpp
#include <bits/stdc++.h>
using namespace std;
long long calls = 0, callsMemo = 0, memo[100];
long long fibSlow(int n) { calls++; if (n < 2) return n; return fibSlow(n - 1) + fibSlow(n - 2); }
long long fibMemo(int n) {
    callsMemo++;
    if (n < 2) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
}
int main() {
    long long r1 = fibSlow(30);                  // 先调用，再读计数器
    printf("fib(30) = %lld，朴素调用 %lld 次\n", r1, calls);
    memset(memo, -1, sizeof memo);
    long long r2 = fibMemo(30);
    printf("fib(30) = %lld，记忆化调用 %lld 次\n", r2, callsMemo);
}
```

输出：`fib(30) = 832040，朴素调用 2692537 次` 和 `fib(30) = 832040，记忆化调用 59 次`。

## 用递归树求复杂度

递归树法分三步：画出每一层有多少个节点、每个节点本身做多少工作，把每层加起来，再把层数相加。

![归并排序的递归树：每层规模合计 n，共 log n 层](/qmx-Gameknowledge/assets/algo/c0-merge-levels.svg)

**归并排序** T(n) = 2T(n/2) + n：第 k 层有 2^k 个节点，每个规模 n/2^k，合并代价合计 n；规模减到 1 需要 log₂n 层，所以 T(n) = n · log n。

常见递推式可以直接套用：

| 递推式 | 递归树的特点 | 结果 | 例子 |
| --- | --- | --- | --- |
| T(n) = T(n/2) + 1 | 一条链，每层折半 | O(log n) | 二分查找 |
| T(n) = T(n−1) + 1 | 一条链，每层减 1 | O(n) | 阶乘、链表遍历 |
| T(n) = T(n−1) + n | 一条链，每层代价逐渐减小 | O(n²) | 选择排序的递归写法 |
| T(n) = 2T(n/2) + n | 每层合计 n，共 log n 层 | O(n log n) | 归并排序 |
| T(n) = 2T(n/2) + 1 | 叶子主导，节点约 2n 个 | O(n) | 线段树建树 |
| T(n) = 2T(n−1) + 1 | 节点数翻倍 | O(2ⁿ) | 汉诺塔 |

这些结果还可以用 0.4 篇的主定理直接套。

## 栈深度与栈溢出

调用 `f` 会在调用栈里压入一帧，返回时弹出。同一时刻栈里只有从根到当前节点的这条路径，所以栈空间是树的**深度**：

- `fibSlow(n)` 的深度是 n，空间 O(n)，而不是 2ⁿ。
- 归并排序的深度是 log n。
- 对链式的输入（如长度 10^6 的链）做 DFS，深度也是 10^6，在默认栈只有 1 到 8 MB 的环境里会崩溃。

遇到深度可能达到 10^5 以上的递归，有两种办法：

```cpp
// 递归版：深度 n
long long sumRec(int n) { return n == 0 ? 0 : n + sumRec(n - 1); }
// 迭代版：显式用循环（或 stack）代替调用栈
long long sumIter(int n) { long long s = 0; for (int i = 1; i <= n; i++) s += i; return s; }
```

树和图上的 DFS 改成迭代，要自己用 `stack` 保存“下一步要处理的节点”，在 4.1 篇会写。

## 例题

### 例 1：汉诺塔

把 n 个盘从 A 移到 C，每次移一个，大盘不能压小盘。把 n−1 个盘先移到 B，移最大的盘，再把 n−1 个盘从 B 移到 C。

```cpp
#include <bits/stdc++.h>
using namespace std;
long long moves = 0;
void hanoi(int n, char from, char to, char via) {
    if (n == 0) return;
    hanoi(n - 1, from, via, to);
    moves++;                                // 移动第 n 个盘
    hanoi(n - 1, via, to, from);
}
int main() {
    hanoi(10, 'A', 'C', 'B');
    printf("%lld\n", moves);
}
```

输出 `1023`。T(n) = 2T(n−1) + 1，解得 2ⁿ − 1。

### 例 2：快速幂（递归写法）

a^b = (a^(b/2))²，b 为奇数时再乘一个 a。每次 b 减半，所以 O(log b)。

```cpp
#include <bits/stdc++.h>
using namespace std;
long long power(long long a, long long b, long long mod) {
    if (b == 0) return 1 % mod;
    long long half = power(a, b / 2, mod);
    long long res = half * half % mod;
    return (b & 1) ? res * a % mod : res;
}
int main() {
    printf("%lld\n", power(2, 30, 1000000007));
    printf("%lld\n", power(3, 200, 1000000007));
}
```

输出 `73741817` 和 `136318165`，与 Python `pow` 的结果一致。

## 常见坑

- 忘记终止条件或没有真正缩小问题，导致无限递归，直接栈溢出。
- 在递归里按值传大数组或 `vector`，每次调用都复制，复杂度翻倍。
- 记忆化数组的初值与合法答案冲突（如用 0 表示“未算过”，而 0 本身是答案）。
- 只看节点数不看栈深度，或者反过来，估错时间或空间。
