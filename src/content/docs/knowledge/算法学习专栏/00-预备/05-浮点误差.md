> 适用版本：C++17，`double` 为 IEEE 754 双精度。前置：会用 `printf`。什么时候需要学：题目出现小数、几何、实数二分、概率期望时，建议在做第 1 章的二分和第 8 章的数学之前读完。

## 要点

- `double` 有约 15 到 16 位十进制有效数字，0.1 这类数在二进制里是无限循环小数，存储时已有误差。
- 不要用 `==` 比较两个计算出来的浮点数，改用 `fabs(a - b) < eps`。
- 取整前先考虑误差：`floor(0.29 * 100)` 得到 28，不是 29。
- 能用整数解决就不要用浮点，如几何里判断共线、比较分数大小。
- 实数二分用固定迭代次数，比 `while (r - l > eps)` 更稳。

## 为什么会有误差

`double` 用 52 位尾数表示小数部分。0.1 的二进制是 0.0001100110011…（无限循环），只能截断到 52 位，所以 `0.1 + 0.2` 的结果是 0.30000000000000004，不等于同样被截断的 0.3。

![0.1 + 0.2 与 0.3 相差约 5.5×10^-17，落在容差区间内就视为相等](/qmx-Gameknowledge/assets/algo/c0-float-eps.svg)

误差只有 10^-17 量级，平时可以忽略。问题出在**比较、取整、累积和极端大小混用**这四种场景。

## 带容差的比较

```cpp
const double EPS = 1e-9;
bool eq(double a, double b) { return fabs(a - b) < EPS; }
bool lt(double a, double b) { return a < b - EPS; }     // a 严格小于 b
bool le(double a, double b) { return a < b + EPS; }     // a 小于等于 b
```

EPS 取多大要看数据：值在 1 左右、只做几次运算时，1e-9 常见；值本身很大（如 10^6）时，绝对误差也会放大，改用相对误差 `fabs(a - b) <= EPS * max(1.0, fabs(a))`。EPS 过大会把本不相等的数判成相等，过小则起不到作用。

## 其他常见陷阱

下面一个程序把几种情况放在一起：

```cpp
#include <bits/stdc++.h>
using namespace std;
const double EPS = 1e-9;
bool eq(double a, double b) { return fabs(a - b) < EPS; }
int main() {
    double a = 0.1 + 0.2;
    printf("a == 0.3 ? %d\n", a == 0.3);
    printf("eq(a, 0.3) ? %d\n", eq(a, 0.3));
    printf("a = %.17g\n", a);

    double x = 0.29 * 100;                                  // 取整陷阱
    printf("0.29 * 100 = %.17g\n", x);
    printf("floor = %d, llround = %lld\n", (int)floor(x), llround(x));

    double neg = -0.001;                                    // 输出 -0.00
    printf("%.2f\n", neg);
    if (fabs(neg) < 0.005) neg = 0;
    printf("%.2f\n", neg);

    double lo = 0, hi = 2;                                  // 实数二分：固定迭代次数
    for (int it = 0; it < 100; it++) {
        double mid = (lo + hi) / 2;
        if (mid * mid * mid < 2) lo = mid; else hi = mid;
    }
    printf("cbrt(2) = %.10f, 库函数 %.10f\n", lo, cbrt(2.0));

    double big = 1e16;                                      // 大数吃掉小数
    printf("1e16 + 1 == 1e16 ? %d\n", big + 1 == big);

    double c = 1.0000000000000002;                          // 越出定义域
    printf("acos(%.17g) = %f\n", c, acos(c));
    printf("acos(clamp) = %f\n", acos(min(1.0, max(-1.0, c))));
}
```

输出：

```text
a == 0.3 ? 0
eq(a, 0.3) ? 1
a = 0.30000000000000004
0.29 * 100 = 28.999999999999996
floor = 28, llround = 29
-0.00
0.00
cbrt(2) = 1.2599210499, 库函数 1.2599210499
1e16 + 1 == 1e16 ? 1
acos(1.0000000000000002) = nan
acos(clamp) = 0.000000
```

逐条说明：

- **取整**：0.29 × 100 实际是 28.999999999999996，`floor` 得到 28。需要四舍五入时用 `llround`，需要向下取整且怕误差时用 `floor(x + EPS)`。
- **输出 −0.00**：很小的负数按两位小数输出会得到 `-0.00`，评测系统可能判错。输出前把绝对值小于 0.5 × 10^-k 的数置为 0。
- **实数二分**：循环 100 次足够把区间缩小到机器精度；`while (r - l > eps)` 在 l 和 r 很大时可能因精度不够而不收敛，死循环。
- **大数吃小数**：1e16 + 1 == 1e16。累加很多小数时，从小到大加，或用 `long double`，或用 Kahan 求和。
- **越出定义域**：`acos`、`asin` 的参数略大于 1 会返回 `nan`，先用 `min`、`max` 夹到 [−1, 1]。`sqrt` 参数略小于 0 同理。

## 能用整数就用整数

几何里的判断可以全部做成整数运算：

- 三点 A、B、C 是否共线：`(B.x - A.x) * (C.y - A.y) == (B.y - A.y) * (C.x - A.x)`，坐标是整数时用 `long long`，没有误差。
- 比较分数 a/b 与 c/d：比较 `a * d` 与 `c * b`（b、d 为正），不要先除。
- 概率和期望要对大质数取模时，用模逆元（8.1 篇）而不是浮点。

## 常见坑

- 用浮点数做循环计数器，如 `for (double x = 0; x != 1; x += 0.1)`，永远等不到 1。
- 输出的小数位数不够：`cout << x` 默认只输出 6 位有效数字，需要时用 `printf("%.10f", x)` 或 `cout << fixed << setprecision(10)`。
- 把 EPS 当成万能药：误差来源不同，该用整数的地方就不要靠 EPS。
- 对 `long double` 以为一定更精确：它在部分平台（如 MSVC）上与 `double` 相同。
