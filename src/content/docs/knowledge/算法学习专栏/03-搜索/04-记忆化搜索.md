> 适用版本：C++17。前置知识：3.1 DFS 与回溯、0.2 递归树。本篇是第 6 章动态规划的预备，请带着它去读 6.1。

## 要点

- 记忆化搜索（memoization）= 递归 + 备忘表：每个状态第一次计算时把结果存起来，之后再遇到直接取。
- 能用的条件：有**重叠子问题**（同一个状态会被多次问到），并且一个状态的结果**只由它的参数决定**，和怎么走到这里无关。
- 复杂度 = 状态个数 × 每个状态内部的转移开销。
- 它和动态规划是同一个模型的两种写法：记忆化是自顶向下（从目标开始往下问），DP 是自底向上（从边界开始往上填）。

## 重复计算有多可怕

求斐波那契数 `fib(n) = fib(n-1) + fib(n-2)`。朴素递归把 `fib(3)` 算了 2 次，`fib(2)` 算了 3 次，n 越大重复越夸张。

![fib(5) 的递归树里有大量重复，记忆化后每个状态只算一次](/qmx-Gameknowledge/assets/algo/c3-memo-fib.svg)

做法：多开一个数组 `memo`，初始为 -1（表示"还没算"）。进入函数先查表，算完先存表再返回。

```cpp
#include <bits/stdc++.h>
using namespace std;

long long calls;
long long fib_plain(int n) {
    calls++;
    return n <= 1 ? n : fib_plain(n - 1) + fib_plain(n - 2);
}

vector<long long> memo;                  // memo[n] = -1 表示还没算过
long long fib_memo(int n) {
    calls++;
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];   // 算过就直接返回
    return memo[n] = fib_memo(n - 1) + fib_memo(n - 2);     // 算完先存起来再返回
}

int main() {
    int n = 40;
    calls = 0;
    long long a = fib_plain(n);
    cout << "朴素递归: fib(" << n << ") = " << a << "，调用 " << calls << " 次\n";
    memo.assign(n + 1, -1);
    calls = 0;
    long long b = fib_memo(n);
    cout << "记忆化:   fib(" << n << ") = " << b << "，调用 " << calls << " 次\n";
}
```

```text
朴素递归: fib(40) = 102334155，调用 331160281 次
记忆化:   fib(40) = 102334155，调用 79 次
```

调用次数从 3.3 亿降到 79 次。朴素递归的复杂度是 O(φ^n)，φ ≈ 1.618；记忆化后状态只有 n 个，每个只算一次，O(n)。

## 三步写出记忆化搜索

1. **定义状态**：`dfs(参数)` 表示什么？参数要能完整描述"接下来还要做什么"，一个都不能少，也不要多。
2. **写出递归关系和边界**：先不考虑记忆化，写一个正确的递归。
3. **加备忘表**：表的维度等于参数个数，用不可能出现的值（如 -1）表示"没算过"。

## 例题 1：0-1 背包

n 件物品，容量为 `cap`，每件物品选或不选，求最大价值。

状态：`dfs(i, c)` = 只考虑第 i 件及之后的物品、剩余容量为 c 时的最大价值。这两个参数就足够了：前面选了什么不重要，只有"还剩多少容量"会影响后面。

```cpp
#include <bits/stdc++.h>
using namespace std;

int n = 4, cap = 8;
int w[] = {2, 3, 4, 5}, v[] = {3, 4, 5, 8};
int memo[5][9];                          // memo[i][c]：从第 i 件起、剩余容量 c 时的最大价值，-1 表示未算

int dfs(int i, int c) {                  // 状态 (i, c) 完整描述了"还能做什么选择"
    if (i == n) return 0;
    int& res = memo[i][c];
    if (res != -1) return res;
    res = dfs(i + 1, c);                 // 不拿第 i 件
    if (c >= w[i]) res = max(res, dfs(i + 1, c - w[i]) + v[i]);   // 拿第 i 件
    return res;
}

int main() {
    memset(memo, -1, sizeof memo);
    cout << "最大价值: " << dfs(0, cap) << '\n';
}
```

```text
最大价值: 12
```

下图是这次运行结束后的备忘表。i = 0 到 3 共 36 个状态（i = 4 是边界，直接返回 0，不进备忘表），只有 14 个被计算过，其余从未被访问到。记忆化只计算"用得到"的状态，这是它比递推有时更省的地方。

## 例题 2：矩阵中的最长递增路径

给一个整数矩阵，从任意格子出发，每步走到上下左右中**严格更大**的格子，求最长路径的长度（LeetCode 329）。

状态：`dfs(x, y)` = 以 `(x, y)` 为起点的最长递增路径长度。每步只会走向更大的值，所以不会走回头路，也不会出现环，不需要 `visited`。每个格子的结果固定，正好可以记忆化。

```cpp
#include <bits/stdc++.h>
using namespace std;

// LeetCode 329：矩阵中的最长递增路径
vector<vector<int>> a = {
    {9, 9, 4},
    {6, 6, 8},
    {2, 1, 1},
};
int R, C;
vector<vector<int>> memo;
const int dx[] = {1, -1, 0, 0}, dy[] = {0, 0, 1, -1};

int dfs(int x, int y) {                  // 以 (x,y) 为起点的最长递增路径长度
    int& res = memo[x][y];
    if (res) return res;                 // 路径长度至少为 1，所以 0 可以当"未计算"
    res = 1;
    for (int d = 0; d < 4; d++) {
        int nx = x + dx[d], ny = y + dy[d];
        if (nx < 0 || nx >= R || ny < 0 || ny >= C || a[nx][ny] <= a[x][y]) continue;
        res = max(res, dfs(nx, ny) + 1); // 只走到更大的格子，所以不会走回头路，不需要 visited
    }
    return res;
}

int main() {
    R = a.size(); C = a[0].size();
    memo.assign(R, vector<int>(C, 0));
    int ans = 0;
    for (int i = 0; i < R; i++)
        for (int j = 0; j < C; j++) ans = max(ans, dfs(i, j));
    cout << "最长递增路径长度: " << ans << '\n';
}
```

```text
最长递增路径长度: 4
```

示例矩阵里最长的路径是 `1 → 2 → 6 → 9`，长度 4。

**复杂度**：状态 R · C 个，每个看 4 个邻居，O(R · C)。不加记忆化会是指数级。

**能记忆化的前提**：状态之间的依赖不能成环。这题因为"只走更大的值"，依赖关系是有向无环的。如果允许走相等或更小的值，同一个状态会依赖它自己，就不能这样直接记忆化。

## 和动态规划的关系

背包例题用递推写出来是这样的，状态和转移方程与记忆化版本完全相同，只是计算顺序反过来：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n = 4, cap = 8;
    int w[] = {2, 3, 4, 5}, v[] = {3, 4, 5, 8};
    int f[5][9] = {};                            // f[i][c] 与 knap_memo.cpp 里的 dfs(i, c) 含义完全相同
    for (int i = n - 1; i >= 0; i--)             // i 从大到小：先算依赖的状态 (i+1, ·)
        for (int c = 0; c <= cap; c++) {
            f[i][c] = f[i + 1][c];
            if (c >= w[i]) f[i][c] = max(f[i][c], f[i + 1][c - w[i]] + v[i]);
        }
    cout << "最大价值: " << f[0][cap] << '\n';
}
```

```text
最大价值: 12
```

| | 记忆化搜索 | 递推（DP） |
| --- | --- | --- |
| 方向 | 自顶向下：从目标往下问 | 自底向上：从边界往上填 |
| 计算范围 | 只算用得到的状态 | 通常填满整张表 |
| 写法 | 递归，转移直观 | 循环，顺序要自己安排 |
| 常数和栈 | 有递归开销，深度大会栈溢出 | 常数小，无栈风险 |
| 适合 | 状态稀疏、转移顺序不好排 | 状态规整，要滚动数组优化 |

先写记忆化，确认状态和转移正确，再改成递推做优化，是一个稳妥的做法。第 6 章会反复用到。

## 备忘表怎么选

- **数组**：状态是小范围整数，如 `memo[i][c]`。最快，用 `memset(memo, -1, ...)` 或 `assign` 初始化。
- **`map` / `unordered_map`**：状态稀疏或范围大，如把整个棋盘编码成字符串。
- **用 0 当“未算”标记**：只在答案一定大于 0 时可以，如最长路径长度至少是 1。答案可能是 0 时必须用 -1。

## 常见坑

- **状态漏了维度**：函数结果依赖了没放进参数的信息（如全局变量、已走过的路径），备忘表就会返回错误结果。
- **多组数据没清空备忘表**：上一组的结果被下一组读到。
- **备忘表里存了依赖路径的值**：如记录了"已访问集合"作为全局变量。状态里需要的信息要么写进参数，要么保证它由参数唯一确定。
- **有环的依赖**：递归会死循环，或者读到尚未算完的值。要先确认状态图是 DAG（有向无环图）。
- **递归太深**：状态链很长时（如 n = 10^6 的线性递推）可能栈溢出，改成递推。
- **在 `if (memo != -1) return` 之前做了有副作用的操作**：必须先查表再干活。
