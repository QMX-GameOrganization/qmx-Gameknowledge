> 适用版本：C++17。前置：数组、递归。并查集是 5.3 篇 Kruskal 算法的核心组件，建议手写到不看资料也能默写。

## 要点

- 并查集（disjoint set union，DSU）支持两个操作：合并两个集合 `unite`，查询两个元素是否在同一集合 `find`。
- 每个集合是一棵树，用 `parent[x]` 记录父亲，根的 `parent` 是自己，根就是这个集合的代表。
- 路径压缩：`find` 时把路径上的点直接挂到根上，之后再查就是一步。
- 按大小合并：总是把小树挂到大树的根下，防止树变高。
- 两个优化一起用，单次操作均摊 O(α(n))，α 是反阿克曼函数，在实际范围内不超过 4，可以当作常数。

## 基本思想

先看不加任何优化的并查集是什么样子。初始时每个元素自成一个集合，父亲是自己。合并就是让一个集合的根指向另一个集合的根：

![并查集是一片森林：初始每人一棵树，合并让一个根指向另一个根](/qmx-Gameknowledge/assets/algo/c2-dsu-forest.svg)

`find(x)` 沿着 `parent` 一路走到根。两个元素在同一集合，当且仅当它们的根相同。不加优化时，合并的顺序不好会让树退化成一条链，一次 `find` 要走 n 步。

## 路径压缩

`find(5)` 走过 5→4→3→2→1 时，顺手把路径上每个点的父亲改成根 1。压缩只改 `parent`，不改变谁和谁属于同一集合。

![路径压缩前后：长链变成直接挂在根上的菊花](/qmx-Gameknowledge/assets/algo/c2-dsu-compress.svg)

递归写法只要一行：`return p[x] = find(p[x]);`。

## 按大小合并

合并时先找到两个根，让**节点数少**的根挂到节点数多的根下。这样每个节点的深度每增加一次，所在树的大小至少翻倍，深度不超过 log₂n。

![大树挂到小树下会让高度变成 2，小树挂到大树下高度仍是 1](/qmx-Gameknowledge/assets/algo/c2-dsu-rank.svg)

“按秩”指按树的高度（rank）比较，“按大小”指按节点数比较，两者效果接近，按大小更好写，还能顺便得到集合大小。

## 模板

```cpp
#include <bits/stdc++.h>
using namespace std;
struct DSU {
    vector<int> p, sz;                       // p：父亲，sz：以该点为根的集合大小
    int comps;                               // 当前集合个数
    DSU(int n) : p(n), sz(n, 1), comps(n) { iota(p.begin(), p.end(), 0); }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }      // 路径压缩
    bool same(int a, int b) { return find(a) == find(b); }
    bool unite(int a, int b) {               // 已经在同一集合返回 false
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);       // 小的挂到大的下面
        p[b] = a;
        sz[a] += sz[b];
        comps--;
        return true;
    }
    int size(int x) { return sz[find(x)]; }
};
int main() {
    DSU d(6);
    d.unite(0, 1); d.unite(2, 3); d.unite(1, 3);
    printf("集合个数 %d\n", d.comps);
    printf("0 和 2 同集合吗 %d，0 和 4 呢 %d\n", d.same(0, 2), d.same(0, 4));
    printf("0 所在集合大小 %d\n", d.size(0));
}
```

输出：

```text
集合个数 3
0 和 2 同集合吗 1，0 和 4 呢 0
0 所在集合大小 4
```

只用按大小合并时深度是 O(log n)，递归 `find` 不会爆栈；只用路径压缩而不按大小合并时，第一次 `find` 前树可能很深，建议改成迭代的“路径减半”写法：

```cpp
int find(int x) { while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; } return x; }
```

## 例题

### 例 1：连通块个数

n 个点 m 条无向边，求连通块个数。每读一条边就 `unite`，最后输出 `comps`。上面模板已经做到：6 个点，三次合并后剩 3 个集合。你也可以用 DFS 或 BFS 做，并查集的好处是边可以一条一条在线加入。

### 例 2：找出多余的边

一棵树加一条边变成有环图。按顺序读入边，第一条让两个端点已经连通的边，就是形成环的那条。

```cpp
#include <bits/stdc++.h>
using namespace std;
struct DSU {
    vector<int> p;
    DSU(int n) : p(n + 1) { iota(p.begin(), p.end(), 0); }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
    bool unite(int a, int b) { a = find(a); b = find(b); if (a == b) return false; p[b] = a; return true; }
};
int main() {
    vector<pair<int, int>> edges = {{1, 2}, {2, 3}, {3, 4}, {1, 4}, {1, 5}};
    DSU d(5);
    for (auto [u, v] : edges)
        if (!d.unite(u, v)) { printf("多余的边：%d %d\n", u, v); break; }
}
```

输出 `多余的边：1 4`。这就是 [LeetCode 684《冗余连接》](https://leetcode.cn/problems/redundant-connection/)的解法，也是 Kruskal 判环的做法。

## 常见坑

- 忘记先 `find` 再比较，直接拿 `p[a] == p[b]` 判断，路径压缩前的 `p` 不是根。
- 只在 `unite` 里用大小，却把 `sz` 当成任意节点的大小：只有根上的 `sz` 有意义，查大小要先 `find`。
- 下标从 1 开始时数组开 n，访问 n 越界。
- 把并查集用来**拆分**集合：并查集只能合并，删除或撤销要用 2.4 篇的可撤销并查集。
- 在递归 `find` 的深链上栈溢出：参考上面的迭代版。
