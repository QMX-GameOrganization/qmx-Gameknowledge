> 适用版本：C++17。前置：异或运算和递归记忆化。什么时候需要学：题目是两个人轮流操作的"取石子"、"在图上走棋子"类游戏，问先手必胜还是必败。

## 要点

- 本篇讨论**公平组合游戏**（impartial game）：两人轮流行动，双方可选的操作只取决于局面本身；不能操作的一方输，游戏有限步内结束。
- 局面分两种：必败态（P 态，上一步行动的人赢）和必胜态（N 态，下一步行动的人赢）。
- **Nim 游戏**：各堆石子数的异或和不为 0，先手必胜；为 0，先手必败。
- **SG 函数**：`SG(u) = mex{ SG(v) | u → v }`。SG 值为 0 的局面是必败态。
- 由多个互不影响的子游戏组成的游戏，总局面的 SG 值是各子游戏 SG 值的**异或**。

## 必胜态与必败态

按下面规则递归定义：

- 无法操作的局面（终点）是**必败态**。
- 如果存在一个操作使局面变成必败态，当前局面是**必胜态**。
- 如果所有操作都使局面变成必胜态，当前局面是**必败态**。

这等价于在局面图（有向无环图）上从终点往回标记。

## Nim 游戏

n 堆石子，每次从某一堆取走任意正数个。取走最后一颗的人赢（即不能取的人输）。

**结论**：设各堆大小异或和为 X。X ≠ 0 先手必胜，X = 0 先手必败。

证明（只需验证三点）：

1. 终点（全 0）的异或和为 0，是必败态，符合。
2. 从 X = 0 的局面出发，任何一步只改变一堆的大小，使这一堆的某些二进制位变化，所以新的异或和一定不为 0。
3. 从 X ≠ 0 的局面出发，一定存在一步使异或和变成 0：设 X 的最高位为第 k 位，必有某一堆 a 的第 k 位是 1（否则异或和的第 k 位不会是 1）。把这堆改成 `a ^ X`，因为 `a ^ X` 的第 k 位是 0 而更高位不变，所以 `a ^ X < a`，可以取走 `a - (a ^ X)` 个石子，使总异或和为 0。

![三堆3、4、5的二进制逐位对齐：011、100、101，每一位异或后得到010，不为0；先手把3那堆减到1，使异或为0](/qmx-Gameknowledge/assets/algo/c8-nim-xor.svg)

示例：堆大小 `(3, 4, 5)`，`3 ^ 4 ^ 5 = 2 ≠ 0`，先手必胜。取走第一堆的 2 个，局面变成 `(1, 4, 5)`，`1 ^ 4 ^ 5 = 0`，对手进入必败态。

## SG 函数

不是所有游戏都是 Nim。比如"每次只能取 1、3 或 4 个"。对每个局面 u，定义

```text
SG(u) = mex{ SG(v) | u 可以一步走到 v }
```

其中 **mex**（minimum excludant）是集合里没有出现的最小非负整数，例如 `mex{0, 1, 3} = 2`，`mex{} = 0`。

性质：

- `SG(u) = 0` 当且仅当 u 是必败态：终点 `SG = 0`；若所有后继的 SG 都不是 0，则 mex 为 0，所以 u 是必败态；若存在后继的 SG 为 0，则 mex 不为 0，u 是必胜态。
- Nim 中一堆大小为 n 的 SG 值就是 n（可以走到 0 到 n-1 的任何一个）。

### 游戏之和

若游戏 G 由若干个互相独立的子游戏 `G1, G2, …` 组成，每次操作选一个子游戏走一步，则

```text
SG(G) = SG(G1) ^ SG(G2) ^ …
```

这是 Sprague-Grundy 定理：每个子游戏都等价于一个相同 SG 值的 Nim 堆，而 Nim 的结论就是异或。因此，只要会算单个子游戏的 SG 值，就能判断组合游戏的胜负。

![有向无环图上的游戏：v3、v4 没有后继，SG 均为 0；v1 只能走到 v3，SG 为1；v2 可以走到 v3 或 v4，SG 为1；v0 的后继 SG 集合是 {1}，mex 为 0，所以 v0 是必败点](/qmx-Gameknowledge/assets/algo/c8-sg-graph.svg)

## 代码

```cpp
#include <bits/stdc++.h>
using namespace std;

// 1) Nim：所有堆大小异或，非零则先手必胜
bool nim_first_wins(const vector<int> &piles) {
    int x = 0;
    for (int p : piles) x ^= p;
    return x != 0;
}

// 2) 一般的"取石子"：每次可取的数量属于集合 S，用 mex 递推出 SG 值
int mex(const vector<int> &v) {
    set<int> s(v.begin(), v.end());
    int m = 0;
    while (s.count(m)) m++;
    return m;
}

vector<int> sg_subtraction(int n, const vector<int> &S) {
    vector<int> sg(n + 1, 0);
    for (int i = 1; i <= n; i++) {
        vector<int> next;
        for (int s : S)
            if (i >= s) next.push_back(sg[i - s]);   // 后继局面的 SG 值
        sg[i] = mex(next);
    }
    return sg;
}

// 3) 有向无环图上的游戏：棋子在点 u，每次沿一条边移到后继，不能移动者输
struct GraphGame {
    vector<vector<int>> g;
    vector<int> memo;
    explicit GraphGame(int n) : g(n), memo(n, -1) {}
    int sg(int u) {
        if (memo[u] != -1) return memo[u];
        vector<int> next;
        for (int v : g[u]) next.push_back(sg(v));
        return memo[u] = mex(next);
    }
};

int main() {
    printf("Nim {3,4,5}: 先手%s\n", nim_first_wins({3, 4, 5}) ? "必胜" : "必败");
    vector<int> sg = sg_subtraction(12, {1, 3, 4});
    printf("S={1,3,4} 的 SG: ");
    for (int i = 0; i <= 12; i++) printf("%d ", sg[i]);
    puts("");
    // 多堆：每堆独立，SG 值异或
    int total = sg[5] ^ sg[7] ^ sg[10];
    printf("三堆(5,7,10)的 SG 异或=%d → 先手%s\n", total, total ? "必胜" : "必败");
    GraphGame gg(5);
    gg.g[0] = {1, 2};
    gg.g[1] = {3};
    gg.g[2] = {3, 4};
    printf("图游戏 SG(0)=%d\n", gg.sg(0));
    return 0;
}
```

运行结果：

```text
Nim {3,4,5}: 先手必胜
S={1,3,4} 的 SG: 0 1 0 1 2 3 2 0 1 0 1 2 3 
三堆(5,7,10)的 SG 异或=2 → 先手必胜
图游戏 SG(0)=0
```

- `Nim {3,4,5}` 先手必胜，与上面一致。
- 取法集合 `{1, 3, 4}` 的 SG 序列 `0 1 0 1 2 3 2 | 0 1 0 1 2 3 …`，周期为 7。
- 三堆 `(5, 7, 10)`：`SG(5) = 3`，`SG(7) = 0`，`SG(10) = 1`，异或为 2，先手必胜。
- 图游戏中起点 v0 的 `SG = 0`，先手必败。

复杂度：`sg_subtraction` 是 O(n · |S|) 再加上 mex 的开销；图游戏的 SG 用记忆化搜索，每个点只计算一次。程序已用暴力搜索验证：对几组不同的取法集合，三堆的胜负结论与 SG 异或完全一致。

## 例题

### 例 1：取石子堆

每次可以取 1、3 或 4 个，现有 3 堆，大小 `(5, 7, 10)`，先手必胜还是必败？

先求出每个大小的 SG 值（见上），异或为 2 ≠ 0，先手必胜。

### 例 2：棋盘上的棋子

在 DAG 上放几枚棋子，每次选一枚沿边移动一步，不能移动的人输。对每枚棋子所在的点求 SG，异或即可。

### 例 3：阶梯 Nim（延伸）

石子放在阶梯上，每次可以把某一级的任意个石子移到下一级（第 0 级是地面）。只需要考虑**奇数级**的石子堆做 Nim，偶数级的石子可以被对手"跟着移回去"所以不起作用。这个转化的证明留作练习。

## 适用与不适用

适用：双方可选操作完全相同的游戏（公平游戏），并且局面数可以枚举或能找到规律。不适用：双方可选操作不同的游戏（如象棋，需要更一般的组合博弈理论）；有平局或循环的游戏。

## 常见坑

- 误把"取走最后一颗者输"（反 Nim）当成普通 Nim，二者的结论在某些情况下相反，需要单独处理。
- `mex` 的定义是"最小**非负**整数"，集合为空时是 0。
- 把多个子游戏的 SG 值相加而不是异或。
- 计算 SG 时遍历的是"可以走到的局面"，不是"取的数量"。写成 `sg[i - s]` 时别忘了判断 `i >= s`。
- 记忆化搜索的 SG 要在有向无环图上使用；有环的游戏需要更复杂的分析。
