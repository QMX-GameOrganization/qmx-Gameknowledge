> 适用版本：C++17。前置：8.1 扩展欧几里得与同余方程。什么时候需要学：题目给出"除以 3 余 2，除以 5 余 3，除以 7 余 2"这类多个同余条件，或者需要把模合数的计算拆成几个小模数分别算再合并时。

## 要点

- **中国剩余定理（CRT）**：若模数 `m1, m2, …, mk` 两两互质，则方程组 `x ≡ ri (mod mi)` 在模 `M = m1·m2·…·mk` 下有唯一解。
- 实际写代码时最好不用 CRT 的公式，而用**逐个合并**：每次把两个方程合并成一个，模数变成 lcm。这个写法对模数不互质同样有效（扩展中国剩余定理，EXCRT）。
- 合并两个方程要用 8.1 的扩展欧几里得，无解时直接发现。
- 合并后的模数是 lcm，容易超过 `long long`。中间乘法要用 `__int128`。

## 互质时：为什么解存在且唯一

以 `x ≡ 2 (mod 3)`、`x ≡ 3 (mod 5)` 为例。模 3 有 3 种余数，模 5 有 5 种余数，组合共 15 种，恰好对应模 15 的 15 个剩余类。下表中每个格子写的就是满足该组余数的 x：

![以x mod 3为行、x mod 5为列的3行5列表格，里面依次填入0到14，每个数字恰好出现一次；x≡2 (mod 3) 且 x≡3 (mod 5) 对应的格子是8](/qmx-Gameknowledge/assets/algo/c8-crt-grid.svg)

每个 x（0 到 14）有唯一一组 `(x mod 3, x mod 5)`，而且两个余数组合没有重复，这就是"唯一"。反过来，为什么 15 个数不会让两个不同的 x 得到同一组余数？若 `x ≡ y` 同时模 3 和模 5，则 `x - y` 同时是 3 和 5 的倍数，从而是 15 的倍数，在 0 到 14 内只能 `x = y`。

## 逐个合并两个方程

设已有 `x ≡ r1 (mod m1)`，要加入 `x ≡ r2 (mod m2)`。把第一个方程的解写成 `x = r1 + m1·k`，代入第二个：

```text
r1 + m1·k ≡ r2 (mod m2)
m1·k ≡ r2 - r1 (mod m2)
```

这是 8.1 的同余方程。令 `g = gcd(m1, m2)`：

- `g` 不整除 `r2 - r1`：无解。
- 否则 `k ≡ ((r2 - r1) / g) · (m1/g)⁻¹ (mod m2/g)`。用扩展欧几里得得到 `m1·p + m2·q = g`，两边除以 g 并模 `m2/g`，得 `(m1/g)·p ≡ 1`，所以 `p` 正是 `m1/g` 模 `m2/g` 的逆元，`k = ((r2-r1)/g · p) mod (m2/g)`。
- 新解 `x ≡ r1 + m1·k (mod lcm(m1, m2))`，其中 `lcm = m1/g·m2`。

重复这个过程，每次把方程数减一。模数互质时 `g = 1`，永不无解，结果与经典 CRT 一致。

```cpp
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
typedef __int128 lll;

ll exgcd(ll a, ll b, ll &x, ll &y) {
    if (b == 0) { x = 1; y = 0; return a; }
    ll g = exgcd(b, a % b, y, x);
    y -= a / b * x;
    return g;
}

// 把 x≡r1 (mod m1) 与 x≡r2 (mod m2) 合并成 x≡r1 (mod m1)，其中 m1 更新为 lcm
// 模数不要求互质；无解返回 false
bool merge(ll &r1, ll &m1, ll r2, ll m2) {
    ll p, q;
    ll g = exgcd(m1, m2, p, q);            // m1*p + m2*q = g
    if ((r2 - r1) % g != 0) return false;
    ll m2g = m2 / g;
    // m1*k ≡ r2-r1 (mod m2) → k ≡ (r2-r1)/g * p (mod m2/g)
    ll k = (ll)((lll)((r2 - r1) / g % m2g) * (p % m2g) % m2g);
    k = (k % m2g + m2g) % m2g;
    ll lcm = m1 / g * m2;
    r1 = (ll)(((lll)m1 * k + r1) % lcm);
    r1 = (r1 % lcm + lcm) % lcm;
    m1 = lcm;
    return true;
}

int main() {
    // 孙子算经：x≡2 (mod 3)，x≡3 (mod 5)，x≡2 (mod 7)
    ll r = 2, m = 3;
    bool ok = merge(r, m, 3, 5) && merge(r, m, 2, 7);
    printf("互质: ok=%d x≡%lld (mod %lld)\n", ok, r, m);
    // 模数不互质：x≡1 (mod 4)，x≡3 (mod 6)
    r = 1; m = 4;
    ok = merge(r, m, 3, 6);
    printf("不互质: ok=%d x≡%lld (mod %lld)\n", ok, r, m);
    // 无解：x≡1 (mod 4)，x≡2 (mod 6)
    r = 1; m = 4;
    printf("无解: ok=%d\n", merge(r, m, 2, 6));
    return 0;
}
```

运行结果：

```text
互质: ok=1 x≡23 (mod 105)
不互质: ok=1 x≡9 (mod 12)
无解: ok=0
```

- 互质：`x ≡ 23 (mod 105)`，经典的"韩信点兵"。验算：23 除 3 余 2，除 5 余 3，除 7 余 2。
- 不互质：`x ≡ 1 (mod 4)` 与 `x ≡ 3 (mod 6)`，`gcd = 2` 整除 `3 - 1`，合并成 `x ≡ 9 (mod 12)`。验算：9 = 4·2+1 = 6·1+3。
- 无解：`x ≡ 1 (mod 4)` 与 `x ≡ 2 (mod 6)`，`gcd = 2` 不整除 `2 - 1 = 1`，直接返回 `false`。

复杂度：每次合并 O(log m)，k 个方程总共 O(k log M)。

## 实现注意

- `k` 和 `m1·k` 的乘积可能超过 `long long`：`m1` 与 `k` 各接近 10¹⁸ 时乘积达 10³⁶。代码里统一用 `__int128` 做乘法和取模。
- `(r2 - r1) % g` 对负数在 C++ 里结果也可能是负的，但只用来判断是否为 0，没有问题；后面参与计算时再做模规范化。
- 最终 lcm 如果超出 `long long`，题目通常会保证不会发生；否则需要换大整数。

## 例题

### 例 1：古代猪文的拆分思路

题目要求 G 的一个巨大指数（若干组合数之和）对质数 999911659 取模。由费马小定理，指数只需要模 999911658，而 999911658 = 2 · 3 · 4679 · 35617，4 个因子都是小质数。思路：对每个小质数 p 用 Lucas 定理（8.3）求出指数模 p 的余数，再用 CRT 合并成模 999911658 下的唯一解。这是 CRT 在竞赛里最常见的用法：把一个合数模数拆成互质的小模数分别计算，再合并。

### 例 2：模数不互质的方程组

给出 n 个方程 `x ≡ ai (mod mi)`，求最小非负整数解，无解输出 -1。直接用 `merge` 逐个合并：

```cpp
// 片段：沿用上面的 merge
ll r = a[0], m = mod[0];
bool ok = true;
for (int i = 1; i < n && ok; i++) ok = merge(r, m, a[i], mod[i]);
// ok 为真时答案是 r（已在 [0, m) 内），否则输出 -1
```

## 适用与不适用

适用：多个同余条件合并；大合数模数拆分计算。不适用：模数很多且非常大导致 lcm 超出范围时，需要大整数或换思路。

## 常见坑

- 忘记在合并前对 `ri` 取模，导致差值过大。
- 把 `merge` 里的 `m1` 更新放在 `r1` 之前，导致用错旧值。
- 直接套用只适合互质情形的"M/mi 乘逆元"公式去处理不互质的数据，会得到错误答案而不报错。
- `lcm` 过大时 `__int128` 也不够用，需要提前判断。
