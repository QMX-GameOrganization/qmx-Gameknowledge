> 适用版本：C++17。前置知识：6.1 记忆化搜索；3.1 DFS。什么时候需要学：题目问「[l, r] 内有多少个数满足某个与各位数字有关的条件」，且 r 高达 10^9 到 10^18，不可能逐个枚举。

## 要点

- 数位 DP 把「数」看成一串数字，从最高位到最低位逐位填，用记忆化搜索统计合法的填法。
- 区间 `[l, r]` 的答案是 `f(r) - f(l-1)`，其中 `f(n)` 统计 `[0, n]` 或 `[1, n]`。
- 基本状态是 `dfs(pos, ..., limit, lead)`：`pos` 是还剩几位，`limit` 表示前面是否一直贴着上界，`lead` 表示是否仍在前导零阶段。
- 记忆化只存 `limit` 为假（以及 `lead` 为假）的状态，因为这类状态与具体的 n 无关，可以反复使用，甚至跨多个 n 复用。

## 为什么能做

数一个范围里满足条件的数，朴素做法是逐个检查，r 到 10^9 就不行了。但数字只有最多 18 位，每位 10 种取值。把数字看成一棵「按位展开」的搜索树，大量分支在「后面还剩几位、上一位是什么」这些信息上完全相同，所以可以记忆化。

先考虑上界 n = 253。从高位往低位填，每位能填的最大值取决于前面是否已经「贴着」n：

- 如果前面所有位都等于 n 对应位，当前位最大只能填 n 的这一位，称为**贴上界（limit）**。
- 一旦某一位填得比 n 的对应位小，后面各位就自由了，可以填 0 到 9。

![n = 253 的搜索树：百位填 0~1 为自由分支，填 2 继续贴上界；十位填 0~4 自由，填 5 继续贴上界；个位填 0~2 自由，填 3 就是 253 本身](/qmx-Gameknowledge/assets/algo/c6-07-tree.svg)

这棵树里，只有「一直贴着上界」的那一条链需要真正展开，一共只有位数那么多层。所有自由的分支，其结果只取决于「还剩几位、上一位是什么」（以及题目额外需要的状态），可以直接查表。这就是数位 DP 复杂度只有 O(位数 × 状态数 × 10) 的原因。

## 状态参数

![n = 253 时几个前缀的 limit 与 lead 取值，包括 2 5 3、2 5 _、2 4 _、1 _ _、0 0 7](/qmx-Gameknowledge/assets/algo/c6-07-state.svg)

- **pos**：还剩几位没填。常把 n 的各位存进数组 `digits[1..len]`，`digits[1]` 是个位，`digits[len]` 是最高位，`pos` 从 `len` 递减到 0。
- **limit**：前面是否一直贴着上界。当前位的上限是 `limit ? digits[pos] : 9`；下一位的 limit 是 `limit && d == up`。
- **lead**（需要时才加）：是否仍然全是前导零。题目的条件如果会被前导零干扰（例如「相邻数字之差」「各位数字都不同」），就必须区分前导零和真正的 0。
- **额外状态**：上一位数字 `pre`、已出现的某数字个数 `cnt`、数位和、余数等，按题目条件决定。

记忆化的下标是 `(pos, 额外状态)`，只有 `!limit`（以及 `!lead`）时才读写缓存。

## 例 1：不含 4 和 62 的数

统计 `[0, n]` 中，十进制表示里不含数字 4、也不含相邻两位 `62` 的数的个数（杭电 HDU 2089「不要 62」就是这类题）。

额外状态只需要上一位数字 `pre`（用来判断「6 后面不能接 2」）。不含 4 是对当前位的限制，不需要记。

```cpp
#include <bits/stdc++.h>
using namespace std;

// 统计 [0, n] 中不含数字 4、也不含相邻 "62" 的数的个数（HDU 2089 "不要62" 的做法）
int digits[12], len;
int memo[12][10];                                      // memo[pos][pre]：还剩 pos 位、上一位是 pre、不受上界限制时的方案数

int dfs(int pos, int pre, bool limit) {
    if (pos == 0) return 1;                            // 所有位填完，得到一个合法数
    if (!limit && memo[pos][pre] != -1) return memo[pos][pre];
    int up = limit ? digits[pos] : 9;                  // 当前位最大能填几
    int res = 0;
    for (int d = 0; d <= up; d++) {
        if (d == 4) continue;
        if (pre == 6 && d == 2) continue;
        res += dfs(pos - 1, d, limit && d == up);
    }
    if (!limit) memo[pos][pre] = res;                  // 只有不受上界限制的状态才可复用
    return res;
}

int count_(int n) {                                    // [0, n] 中合法的数的个数（包含 0）
    len = 0;
    do { digits[++len] = n % 10; n /= 10; } while (n); // digits[1] 是个位，digits[len] 是最高位
    return dfs(len, 0, true);
}

int main() {
    memset(memo, -1, sizeof memo);                     // memo 与 n 无关，只需初始化一次
    cout << count_(100) - count_(0) << "\n";           // [1, 100] 中合法的数的个数：80
}
```

这里没有用 `lead`，因为前导零是 0，既不是 4 也不会和 6 组成 `62`，把数补零写成固定位数不影响判断。`[1,100]` 里含 4 的有 19 个，另外 62 一个，所以答案 100 - 19 - 1 = 80。

为什么 `memo` 可以只初始化一次、跨多个 n 使用：`memo[pos][pre]` 描述的是「后面 pos 位随便填」的合法数量，这与 n 无关。区间题里 `f(r)` 和 `f(l-1)` 共用一个缓存。

## 例 2：统计数字 1 出现的次数

统计 `[1, n]` 中数字 1 总共出现了多少次（LeetCode 233）。例如 n=13 时，1、10、11（含两个 1）、12、13 一共出现 6 次。

这里要的不是「合法数的个数」，而是「出现次数之和」。让 `dfs` 多带一个参数 `cnt`（前面已填的 1 的个数），填完所有位时返回 `cnt`，中间层把各分支的返回值相加。

```cpp
#include <bits/stdc++.h>
using namespace std;

// 统计 [1, n] 中数字 1 出现的总次数（LeetCode 233）
// dfs(pos, cnt, limit) 返回：从当前位往后填完，所有数里 1 出现的次数之和，cnt 是前面已出现的 1 的个数。
// 这里"答案"不是计数而是求和，所以递归到底时返回 cnt。
int digits[12];
long long memo[12][12];

long long dfs(int pos, int cnt, bool limit) {
    if (pos == 0) return cnt;
    if (!limit && memo[pos][cnt] != -1) return memo[pos][cnt];
    int up = limit ? digits[pos] : 9;
    long long res = 0;
    for (int d = 0; d <= up; d++)
        res += dfs(pos - 1, cnt + (d == 1), limit && d == up);
    if (!limit) memo[pos][cnt] = res;
    return res;
}

long long countDigitOne(int n) {
    memset(memo, -1, sizeof memo);
    int len = 0;
    do { digits[++len] = n % 10; n /= 10; } while (n);
    return dfs(len, 0, true);                          // 前导零不是 1，不影响结果，所以不需要 lead
}

int main() {
    cout << countDigitOne(13) << "\n";                 // 6：1, 10, 11（两个）, 12, 13
}
```

这个写法把数 0 也算进去了，但 0 里没有数字 1，不影响结果，所以 `[0, n]` 和 `[1, n]` 的答案相同。

## 例 3：windy 数与前导零

windy 数是不含前导零，且相邻两位数字之差至少为 2 的正整数。洛谷 P2657 求 `[a, b]` 内有多少个。

这里前导零会干扰条件：数 7 如果补零写成 `007`，相邻的 `0` 与 `0` 之差为 0，会被误判为不合法。所以必须区分「前导零」和「真正填的数字」，加上参数 `lead`：

- `lead` 为真时，当前还没有填过非零数字；此时填 0 继续留在前导零阶段，不检查相邻差，`pre` 无意义；填非零数字则结束前导零阶段，该数字成为首位，也不检查（没有上一位）。
- `lead` 为假时，才检查 `abs(d - pre) >= 2`。

另外，全是前导零对应数 0，不是正整数，递归到底时 `lead` 仍为真就返回 0。

```cpp
#include <bits/stdc++.h>
using namespace std;

// windy 数（洛谷 P2657）：不含前导零且相邻两位数字之差至少为 2 的正整数。求 [a, b] 内有多少个。
// 前导零的位不能参与"相邻差"的判断，所以要多记一个 lead（是否还在前导零阶段）。
int digits[12];
int memo[12][10];                                      // memo[pos][pre]：只在 !limit 且 !lead 时使用

int dfs(int pos, int pre, bool lead, bool limit) {
    if (pos == 0) return lead ? 0 : 1;                 // 全是前导零就是数 0，不计入
    if (!limit && !lead && memo[pos][pre] != -1) return memo[pos][pre];
    int up = limit ? digits[pos] : 9;
    int res = 0;
    for (int d = 0; d <= up; d++) {
        if (lead && d == 0) {                          // 继续留在前导零阶段
            res += dfs(pos - 1, 0, true, limit && d == up);
        } else {
            if (!lead && abs(d - pre) < 2) continue;   // 已经有首位了才检查相邻差
            res += dfs(pos - 1, d, false, limit && d == up);
        }
    }
    if (!limit && !lead) memo[pos][pre] = res;
    return res;
}

int solve(int n) {                                     // [1, n] 中 windy 数的个数
    if (n <= 0) return 0;
    int len = 0;
    do { digits[++len] = n % 10; n /= 10; } while (n);
    return dfs(len, 0, true, true);
}

int main() {
    memset(memo, -1, sizeof memo);
    cout << solve(25) << "\n";                         // 19：1~9，13~19，20，24，25
}
```

做区间题时输出 `solve(b) - solve(a - 1)`。

## 模板总结

```
dfs(pos, 额外状态, [lead], limit):
    if pos == 0: 返回此时的结果（计数返回 1，求和返回累计值）
    if !limit [且 !lead] 且 memo 命中: 返回 memo
    up = limit ? digits[pos] : 9
    for d in 0..up:
        检查 d 是否违反条件（结合 pre、lead 等）
        累加 dfs(pos-1, 新的额外状态, 新的 lead, limit && d == up)
    if !limit [且 !lead]: 写 memo
```

套模板时要问自己三件事：除了位置，还需要记哪些信息才能判断后面的合法性？前导零会不会影响条件？结果是计数还是求和？

复杂度：状态数 `位数 × 额外状态数`，每个状态枚举 10 个数字，所以大约 O(位数 × 额外状态数 × 10)。

## 常见坑

- **limit 为真时也读写 memo。** 贴着上界的状态与 n 有关，缓存后换一个 n 会算错。
- **memo 里把 lead 的状态混进去。** `lead` 为真的状态与 `lead` 为假的状态含义不同，不能共用同一个缓存格。
- **memo 没有清零或哨兵值取错。** 答案可能为 0，不能用 0 当「未计算」；用 -1。若 memo 与题目参数（例如模数 k、目标和）有关，换一组参数要重新初始化。
- **前导零处理漏掉。** 条件与相邻数字、数字是否出现过相关时几乎一定要 `lead`。
- **区间端点。** 用 `f(r) - f(l-1)`，`l = 0` 时需单独处理 `f(-1)`。
- **位数组下标。** 统一用 `digits[1..len]`，`pos` 从 `len` 到 0，避免一会儿 0 起一会儿 1 起。
