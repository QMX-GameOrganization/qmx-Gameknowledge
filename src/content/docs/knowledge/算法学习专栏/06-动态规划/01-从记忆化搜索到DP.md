> 适用版本：C++17。前置知识：递归（0.2 篇）。本篇是第 6 章的起点，后面所有 DP 都沿用这里的四步。

## 本章怎么学

DP 没有捷径，要靠题量堆出直觉：6.2 到 6.5 里每一类题型至少做 10 道题再往下走。做题时养成一个顺序：先用一句话写出「状态是什么」，再写转移，最后才写代码。状态定义错了，后面怎么调都不对。

区间 DP 和树形 DP 要用到第 4 章的树遍历，如果树的部分还不熟，先回去补。带 ⭐ 的 6.6 到 6.12 是进阶：6.6 状压 DP 和 6.7 数位 DP 在比赛和面试里都常见，建议基础篇学完后马上补；6.9 到 6.12 是各种 DP 优化与特殊模型，难度陡增，不要太早碰。

## 要点

- 动态规划（Dynamic Programming，DP）处理的问题有两个特征：大问题可以拆成小问题（最优子结构），而且不同的大问题会反复用到同一个小问题（重叠子问题）。
- 把递归过程中算过的子问题结果存起来，就是记忆化搜索；把记忆化搜索改成按依赖顺序的循环，就是自底向上的 DP。两者复杂度相同。
- 设计 DP 要回答四件事：状态是什么、怎么转移、边界是什么、按什么顺序算。
- 当转移只依赖「上一行」或「前几项」时，可以只保留最近几行，这就是滚动数组，能把空间降一个维度。

## 从斐波那契看重复子问题

斐波那契数列 `fib(0)=0, fib(1)=1, fib(n)=fib(n-1)+fib(n-2)`。直接按定义写递归最自然：

```cpp
long long fibNaive(int n) {
    return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2);
}
```

看 `fib(5)` 的递归树：

![朴素递归的 fib(5) 递归树，fib(3) 出现 2 次，fib(2) 出现 3 次](/qmx-Gameknowledge/assets/algo/c6-01-fib-tree.svg)

`fib(2)` 被算了 3 次，`fib(3)` 被算了 2 次，而且每次都会把自己下面的整棵子树重新算一遍。n 每加 1，调用次数大约变成原来的 1.6 倍。实测 `fib(30)` 要调用 2692537 次，n 到 50 左右就跑不动了。

问题出在「算过的东西没有记下来」。解决办法有两种，下面依次讲。

## 记忆化搜索：算过就存起来

加一个数组 `memo[n]`，初始为 -1 表示「还没算过」。进入函数先查表，查到就直接返回；没查到才递归，并在返回前把结果存进去：

```cpp
long long memo[100];                       // -1 表示还没算过
long long fibMemo(int n) {
    if (n < 2) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
}
```

每个 `fib(k)` 现在只会真正展开一次，一共 n 个状态，每个状态 O(1) 转移，总复杂度 O(n)。注意 `memo` 要在使用前用 `memset(memo, -1, sizeof memo)` 初始化。

## 自底向上：把递归改成循环

记忆化搜索是「从大问题往下找小问题」。观察依赖关系：`fib(n)` 只依赖比它小的项，所以可以反过来，从最小的项开始，按从小到大的顺序一个个算出来：

```cpp
long long fibDP(int n) {
    vector<long long> f(n + 2);
    f[0] = 0; f[1] = 1;                    // 边界
    for (int i = 2; i <= n; i++)           // 顺序：从小到大
        f[i] = f[i - 1] + f[i - 2];        // 转移
    return f[n];
}
```

这就是 DP。它和记忆化搜索算的是同一张表，区别只在于顺序由谁决定：记忆化搜索由递归自动决定，DP 由你写的循环决定。

上面几段是函数片段。下面是可以直接编译运行的完整程序，包含统计调用次数的朴素递归、记忆化、DP 和只用两个变量的滚动写法：

```cpp
#include <bits/stdc++.h>
using namespace std;

long long calls = 0;                       // 统计递归调用次数
long long fibNaive(int n) {
    calls++;
    return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2);
}

long long memo[100];                       // -1 表示"还没算过"
long long fibMemo(int n) {
    if (n < 2) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
}

long long fibDP(int n) {                   // 自底向上
    vector<long long> f(n + 2);
    f[0] = 0; f[1] = 1;
    for (int i = 2; i <= n; i++) f[i] = f[i - 1] + f[i - 2];
    return f[n];
}

long long fibRoll(int n) {                 // 滚动变量：只保留前两项
    long long a = 0, b = 1;
    for (int i = 0; i < n; i++) { long long c = a + b; a = b; b = c; }
    return a;
}

int main() {
    int n = 30;
    fibNaive(n);
    cout << "朴素递归调用次数: " << calls << "\n";            // 2692537
    memset(memo, -1, sizeof memo);
    cout << fibMemo(n) << " " << fibDP(n) << " " << fibRoll(n) << "\n";   // 832040 三次
    cout << fibMemo(90) << " " << fibDP(90) << " " << fibRoll(90) << "\n";
}
```

`fib(90)` 约为 2.9×10^18，已经接近 `long long` 的上限（约 9.2×10^18），再往后会溢出。

| | 记忆化搜索 | 自底向上 DP |
| --- | --- | --- |
| 写法 | 递归 + 缓存 | 循环填表 |
| 顺序 | 递归自动保证 | 你必须保证依赖的格子先算 |
| 只算需要的状态 | 是 | 否，整张表都算 |
| 递归深度 | 可能很深 | 没有 |
| 好写程度 | 转移直接照搬递归 | 要多想一步「顺序」 |

做题时可以先写记忆化搜索把转移想清楚，再决定要不要改成循环。状态很多、递归会爆栈、或者需要滚动数组优化时，改成 DP。

## 设计 DP 的四步

![设计 DP 的四步：定义状态、写转移、定边界、定顺序，以网格最小路径和为例](/qmx-Gameknowledge/assets/algo/c6-01-design.svg)

1. **状态**：用几个参数描述一个子问题，并用一句话说明 `dp[...]` 存的是什么。例如 `dp[i][j]` 是「从左上角走到 (i,j) 的最小路径和」。
2. **转移**：考虑这个状态的「最后一步」有哪几种可能，每种可能对应哪个更小的状态，再把它们合并（取最大、最小或求和）。
3. **边界**：最小的、不能再拆的状态直接赋值，同时处理好越界和不可达。
4. **顺序**：保证算 `dp[x]` 时，它依赖的所有状态都已经算好。

## 例：最小路径和

给一个 n×m 的网格，每格有一个非负数，只能向右或向下走，从左上角走到右下角，求路径上数字之和的最小值。

按四步来：

- 状态：`dp[i][j]` 表示走到 (i,j) 的最小路径和。
- 转移：到 (i,j) 的最后一步要么来自上方 (i-1,j)，要么来自左方 (i,j-1)，取较小者再加上本格：`dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + g[i][j]`。
- 边界：`dp[0][0] = g[0][0]`；第一行只能来自左方，第一列只能来自上方，越界的来源当作「无穷大」。
- 顺序：i 从小到大，j 从小到大，这样上方和左方都已经算好。

![左边是网格，右边是 dp 表，绿色格子是最优路径，橙色格子 dp[1][1] 取左方的 2 加上本格的 5 得 7](/qmx-Gameknowledge/assets/algo/c6-01-grid.svg)

下面是三种写法放在同一个程序里，结果应该完全一致：

```cpp
#include <bits/stdc++.h>
using namespace std;

int n = 3, m = 3;
vector<vector<int>> g = {{1, 3, 1}, {1, 5, 1}, {4, 2, 1}};
vector<vector<int>> memo(3, vector<int>(3, -1));

// 写法一：记忆化搜索。f(i, j) = 从 (0,0) 走到 (i,j) 的最小路径和
int f(int i, int j) {
    if (i < 0 || j < 0) return INT_MAX / 2;       // 越界：不可达，给一个很大的数
    if (i == 0 && j == 0) return g[0][0];
    int &res = memo[i][j];
    if (res != -1) return res;
    return res = min(f(i - 1, j), f(i, j - 1)) + g[i][j];
}

// 写法二：自底向上二维表
int dp2d() {
    vector<vector<int>> dp(n, vector<int>(m, INT_MAX / 2));
    dp[0][0] = g[0][0];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++) {
            if (i == 0 && j == 0) continue;
            if (i > 0) dp[i][j] = min(dp[i][j], dp[i - 1][j]);
            if (j > 0) dp[i][j] = min(dp[i][j], dp[i][j - 1]);
            dp[i][j] += g[i][j];
        }
    return dp[n - 1][m - 1];
}

// 写法三：滚动数组。dp[j] 在被覆盖前存的是上一行的值
int dp1d() {
    vector<int> dp(m, INT_MAX / 2);
    dp[0] = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++) {
            if (j > 0) dp[j] = min(dp[j], dp[j - 1]);   // 上方 vs 左方
            dp[j] += g[i][j];
        }
    return dp[m - 1];
}

int main() {
    cout << f(n - 1, m - 1) << " " << dp2d() << " " << dp1d() << "\n";   // 7 7 7
}
```

复杂度：状态 n·m 个，每个 O(1) 转移，时间 O(nm)；二维表空间 O(nm)，滚动数组空间 O(m)。

## 滚动数组：只保留需要的几行

最小路径和里，`dp[i][j]` 只依赖第 i-1 行和第 i 行，更早的行再也用不到，所以不必存整张表。用一维数组 `dp[j]`：处理第 i 行之前，`dp[j]` 存的是上一行的结果；算完 `dp[j]` 之后，它就变成当前行的结果。

![处理第 1 行时一维 dp 数组的变化：从 1 4 5 依次变成 2 4 5、2 7 5、2 7 6](/qmx-Gameknowledge/assets/algo/c6-01-rolling.svg)

看第 1 行的演示：

- 处理 j=0 之前，`dp[0]=1` 是上一行的值，没有左方，只能来自上方，加上本格 1 得 2。
- 处理 j=1 时，`dp[1]=4` 还是上一行的值（上方），`dp[0]=2` 是刚算好的本行结果（左方），取较小的 2，加 5 得 7。
- 处理 j=2 时同理，`min(5, 7) + 1 = 6`。

滚动数组的使用条件是：状态的某一维只依赖「前一层」。用的时候要想清楚读到的是旧值还是新值，6.3 里的背包会遇到同样的问题，只是循环方向会决定它。

滚动之后不能再从 `dp` 表中回溯出具体路径。如果题目要求输出方案，要么保留完整表，要么另外记录每格的来源。

## 例题

**爬楼梯。** 每次爬 1 或 2 级，到第 n 级有多少种走法？最后一步要么从 n-1 级来，要么从 n-2 级来，所以 `dp[i] = dp[i-1] + dp[i-2]`，边界 `dp[0] = dp[1] = 1`。转移只依赖前两项，用两个变量滚动即可：

```cpp
#include <bits/stdc++.h>
using namespace std;

// 爬楼梯：每次爬 1 或 2 级，到第 n 级有多少种走法
// dp[i] = 到第 i 级的走法数。最后一步只可能来自 i-1 或 i-2
int climb(int n) {
    int a = 1, b = 1;                              // a = dp[i-2], b = dp[i-1]，初始为 dp[0] = dp[1] = 1
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}

int main() {
    cout << climb(1) << " " << climb(2) << " " << climb(5) << " " << climb(10) << "\n";   // 1 2 8 89
}
```

**打家劫舍。** 一排房子，相邻两间不能都偷，求最大收益。状态 `dp[i]` 是只考虑前 i 间房的最大收益。第 i 间要么不偷（`dp[i-1]`），要么偷（第 i-1 间不能偷，所以是 `dp[i-2] + a[i-1]`）：

```cpp
#include <bits/stdc++.h>
using namespace std;

// 打家劫舍：相邻的房子不能同时偷，求最大收益
// dp[i] = 只考虑前 i 间房的最大收益
int rob(const vector<int> &a) {
    int n = a.size();
    vector<int> dp(n + 1, 0);                      // dp[0] = 0：没有房子
    if (n >= 1) dp[1] = a[0];
    for (int i = 2; i <= n; i++)
        dp[i] = max(dp[i - 1],                     // 不偷第 i 间
                    dp[i - 2] + a[i - 1]);         // 偷第 i 间，则第 i-1 间不能偷
    return dp[n];
}

int main() {
    cout << rob({2, 7, 9, 3, 1}) << "\n";          // 12 = 2 + 9 + 1
}
```

这两题的状态都是一维、转移只有两个来源，是最小的 DP 练手题。

## 常见坑

- **状态没说清楚就写转移。** 同一道题 `dp[i]` 可以表示「以 i 结尾」也可以表示「前 i 个里」，两种定义的转移和答案位置都不同。写代码前先把定义写成注释。
- **边界漏掉或越界。** `dp[i-1]`、`dp[i-2]` 在 i 很小时会越界，要么单独处理前几项，要么把数组整体后移一位，让 `dp[0]` 表示「空」。
- **「不可达」用 0 表示。** 求最小值时不可达应该是一个很大的数；求最大值时应该是一个很小的负数。用 `INT_MAX` 再做加法会溢出，所以习惯写 `INT_MAX / 2`。
- **记忆化的哨兵值与合法答案冲突。** 如果答案可能是 -1 或 0，就不能拿它们当「没算过」。换成一个取不到的值，或者另开一个 `vis` 数组。
- **循环顺序不满足依赖。** 算 `dp[i][j]` 时它依赖的格子还没算，就会读到初始值，结果错但不报错。写完在小样例上手算几格核对。
- **滚动数组后又想还原路径。** 见上文，需要路径就保留完整表。
