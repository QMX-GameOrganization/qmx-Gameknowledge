> 适用版本：C++17。前置知识：BFS、DFS、5.2 最短路（费用流用到 SPFA 或 Bellman-Ford）。什么时候需要学：题目是"最多能运多少"、"至少断掉哪些边才能隔开两点"、"带花费地分配任务"，或者匹配问题加上了容量和权值，二分图匹配已经不够用。

## 要点

- **网络**：有向图，每条边有容量，指定源点 s 和汇点 t。**流**给每条边分配不超过容量的流量，并且除了 s、t 之外每个点流入等于流出。**最大流**就是从 s 流出的总量最大的流。
- **残量网络**：每条边拆成"还能再推多少"的正向边和"能退回多少"的反向边。反向边让后面的增广路可以撤销之前走歪的决定，这是网络流算法的核心。
- **Dinic**：先 BFS 给残量网络分层，再 DFS 只走"层数加 1"的边，一次推出一批流（阻塞流），重复到 s 到不了 t。一般题目都够快。
- **最大流最小割定理**：最大流的值等于最小割的容量。最大流跑完后，从 s 在残量网络里能到的点构成 S 侧，S 到 T 的原边就是一个最小割。
- **最小费用最大流**：每条边再带一个单位费用，在流量最大的前提下总费用最小。做法是每次沿费用最短的增广路推流，最短路用 SPFA。

## 残量网络与反向边

设边 u→v 容量 5，当前已经流了 3。它在残量网络里变成两条边：u→v 还能推 2，v→u 能退回 3。

![残量网络：上面是一条边拆成的正向边和反向边，下面是反向边如何撤销走歪的第一条增广路](/qmx-Gameknowledge/assets/algo/c5-09-residual.svg)

看图下半部分：所有容量都是 1。第一条增广路 s→a→b→t 走了 a→b，但最优解其实是 s→a→t 和 s→b→t。这时残量网络里有 a→b 的反向边 b→a，于是第二条增广路 s→b→a→t 可以沿着它走：b→a 的"推流"等价于把 a→b 上的那一单位流退回去。两条路加起来，a→b 上的流量抵消为 0，结果就是我们想要的两条路。

没有反向边，贪心地沿任意路径推流可能卡在非最优解上。有了它，"沿残量网络里任意 s 到 t 的路径推流，直到没路"一定得到最大流。这就是 Ford–Fulkerson 方法，Edmonds–Karp（每次用 BFS 找最短路径）和 Dinic 是它的两种实现。

## Dinic

Edmonds–Karp 每次只推一条路。Dinic 的想法是把 BFS 层次相同的最短路一次推完：

1. BFS：从 s 出发，对残量网络里 `cap > 0` 的边分层，`level[v]` 是 s 到 v 的最少边数。t 到不了就结束。
2. DFS：只允许走 `level[v] == level[u] + 1` 的边，这样的子图是 DAG（层次图）。沿它尽量多地推流，直到推不动（阻塞流）。
3. 重复 1、2。每一轮之后 s 到 t 的最短距离严格增大，所以最多 V 轮。

DFS 里有两个剪枝，缺一不可：

- **当前弧优化**：`cur[u]` 记录 u 下一条要尝试的边。走过的边要么已满，要么通向死点，本轮不会再有用。
- **死点剪枝**：如果从 u 推不出任何流（`used == 0`），把 `level[u]` 设为 -1，其他点不会再来。

![Dinic 的两轮：第 1 轮按层推流 4，第 2 轮残量网络重新分层，原来同层的 2→3 边成为主路](/qmx-Gameknowledge/assets/algo/c5-09-dinic-level.svg)

图里的例子：边 1→2 容量 3，1→3 容量 2，2→3 容量 1，2→4 容量 2，3→4 容量 3。第 1 轮层次是 1:0，2:1，3:1，4:2，边 2→3 在同层不走，推流 4。第 2 轮重新分层，1→2→3→4 成为一条路，再推 1，总流量 5。

## 模板：Dinic

边存在一个数组里，**正向边下标是偶数，反向边紧跟其后**。这样 `id ^ 1` 就是配对的反向边，不用额外存。

```cpp
struct Dinic {
    struct Edge { int to; long long cap; };
    int n, s, t;
    vector<Edge> e;               // 边 2k 是正向边，2k+1 是它的反向边
    vector<vector<int>> g;        // g[u] 存边的编号
    vector<int> level, cur;       // 层次、当前弧

    Dinic(int n_, int s_, int t_) : n(n_), s(s_), t(t_), g(n_ + 1), level(n_ + 1), cur(n_ + 1) {}

    void add_edge(int u, int v, long long c) {
        g[u].push_back(e.size()); e.push_back({v, c});
        g[v].push_back(e.size()); e.push_back({u, 0});   // 反向边初始容量 0
    }
    bool bfs() {                  // 在残量网络上分层
        fill(level.begin(), level.end(), -1);
        queue<int> q;
        level[s] = 0; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int id : g[u])
                if (e[id].cap > 0 && level[e[id].to] < 0) {
                    level[e[id].to] = level[u] + 1;
                    q.push(e[id].to);
                }
        }
        return level[t] >= 0;
    }
    long long dfs(int u, long long f) {   // 沿层次图推流，f 是目前路径上的瓶颈
        if (u == t) return f;
        long long used = 0;
        for (int &i = cur[u]; i < (int)g[u].size(); i++) {
            int id = g[u][i], v = e[id].to;
            if (e[id].cap > 0 && level[v] == level[u] + 1) {
                long long d = dfs(v, min(f - used, e[id].cap));
                if (d > 0) {
                    e[id].cap -= d;
                    e[id ^ 1].cap += d;       // 反向边增加同样的容量
                    used += d;
                    if (used == f) break;     // 当前点已推满，保留 cur[u]
                }
            }
        }
        if (used == 0) level[u] = -1;         // 死点，本轮不再访问
        return used;
    }
    long long max_flow() {
        long long flow = 0;
        while (bfs()) {
            fill(cur.begin(), cur.end(), 0);
            flow += dfs(s, LLONG_MAX);
        }
        return flow;
    }
    // 最大流结束后：从 s 沿容量>0 的边能到的点集 S，S 到 V\S 的原边就是最小割
    vector<int> min_cut_edges() {
        vector<bool> in_s(n + 1, false);
        queue<int> q;
        in_s[s] = true; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int id : g[u])
                if (e[id].cap > 0 && !in_s[e[id].to]) { in_s[e[id].to] = true; q.push(e[id].to); }
        }
        vector<int> cut;
        for (int id = 0; id < (int)e.size(); id += 2)
            if (in_s[e[id ^ 1].to] && !in_s[e[id].to]) cut.push_back(id / 2);   // 原边编号
        return cut;
    }
};
```

用法：`Dinic d(n, s, t); d.add_edge(u, v, c); long long f = d.max_flow();`。边按加入顺序编号 0, 1, 2, …，`min_cut_edges()` 返回的是这个编号。容量和流量一律用 `long long`，因为多条边的容量相加很容易超过 `int`。

对分层图里的例子（4 个点、5 条边，s=1，t=4）运行，输入

```text
4 5 1 4
1 2 3
1 3 2
2 3 1
2 4 2
3 4 3
```

输出最大流 5，最小割边为编号 0 和 1（即 1→2 和 1→3），容量和 5，与最大流相等。

## 最小割

**割**是把点分成 S 和 T 两部分（s 在 S，t 在 T），**割的容量**是所有从 S 指向 T 的边的容量之和。**最大流最小割定理**：最大流的值等于最小割的容量。

直观上，任何流都要穿过每个割，所以流量不超过割的容量；最大流结束时残量网络里 s 到不了 t，从 s 能到的点集 S 与剩余点 T 之间的边全部满载，这个割的容量恰好等于流量，所以它最小。

![最小割：绿色是 S 侧，橙色是 T 侧，红色粗线是割边，容量之和等于最大流 4](/qmx-Gameknowledge/assets/algo/c5-09-mincut.svg)

图中边 s→a、a→t、s→b、b→t 的容量是 3、2、2、3，最大流 4。跑完后残量网络里 s→a 还剩 1，所以 a 属于 S；a→t 和 s→b 已满，到不了 t 和 b。S = {s, a}，T = {b, t}，割边是 a→t 和 s→b，容量 2 + 2 = 4。输入 `4 4 1 4`，后接 `1 2 3 / 2 4 2 / 1 3 2 / 3 4 3`（点 1、2、3、4 依次对应 s、a、b、t），实际输出最小割边编号 1 和 2，容量 4。

## 最小费用最大流

给每条边再加一个**单位费用** cost：这条边每流 1 单位要花 cost。要求在流量最大的前提下，总费用最小。

做法是"每次只沿费用最短的增广路推流"（Successive Shortest Path）：

1. 以 cost 为边权，在残量网络上求 s 到 t 的最短路。
2. 沿这条路推流，推的量是路上的最小剩余容量。
3. 重复到 s 到不了 t。

反向边的费用是**正向边费用的相反数**：退回一单位流，等于把之前花的钱收回来。所以残量网络里有负权边，最短路要用 SPFA（或 Bellman-Ford），不能用 Dijkstra（除非加势函数）。原图本身不能有负环，否则"最短路"没有意义。

```cpp
struct MCMF {
    struct Edge { int to; long long cap, cost; };
    int n, s, t;
    vector<Edge> e;
    vector<vector<int>> g;
    vector<long long> dist;
    vector<int> pre_edge;
    vector<bool> inq;

    MCMF(int n_, int s_, int t_) : n(n_), s(s_), t(t_), g(n_ + 1) {}

    void add_edge(int u, int v, long long cap, long long cost) {
        g[u].push_back(e.size()); e.push_back({v, cap, cost});
        g[v].push_back(e.size()); e.push_back({u, 0, -cost});   // 反向边费用取负
    }
    bool spfa() {                 // 以费用为边权求最短路
        dist.assign(n + 1, LLONG_MAX);
        pre_edge.assign(n + 1, -1);
        inq.assign(n + 1, false);
        queue<int> q;
        dist[s] = 0; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            inq[u] = false;
            for (int id : g[u]) {
                int v = e[id].to;
                if (e[id].cap > 0 && dist[u] + e[id].cost < dist[v]) {
                    dist[v] = dist[u] + e[id].cost;
                    pre_edge[v] = id;
                    if (!inq[v]) { inq[v] = true; q.push(v); }
                }
            }
        }
        return dist[t] != LLONG_MAX;
    }
    pair<long long, long long> run() {   // 返回 {最大流, 最小费用}
        long long flow = 0, cost = 0;
        while (spfa()) {
            long long f = LLONG_MAX;     // 最短路上的瓶颈
            for (int v = t; v != s; v = e[pre_edge[v] ^ 1].to) f = min(f, e[pre_edge[v]].cap);
            for (int v = t; v != s; v = e[pre_edge[v] ^ 1].to) {
                e[pre_edge[v]].cap -= f;
                e[pre_edge[v] ^ 1].cap += f;
            }
            flow += f;
            cost += f * dist[t];
        }
        return {flow, cost};
    }
};
```

对 `4 5 1 4`，边 `1 2 2 1`、`1 3 2 3`、`2 3 1 1`、`2 4 2 4`、`3 4 3 1`（每行依次是 u、v、容量、单位费用），输出 `4 16`。手算验证：最大流是 4（s 出边容量共 4）。三种走法的单位费用分别是 1→2→3→4 为 3，1→3→4 为 4，1→2→4 为 5。最优方案是 1→2→3→4 流 1（费用 3），1→2→4 流 1（费用 5），1→3→4 流 2（费用 8），合计 16。

复杂度：每次增广 SPFA 最坏 O(VE)，增广次数不超过最大流量，所以总复杂度 O(流量 × VE)。流量大时，容量为 1 的网络增广次数等于流量，要估一下是否够快。

## 例题：怎么建图

网络流题的难点在建模，算法本身用上面的模板就行。下面三个套路覆盖大部分题目。

### 例 1：二分图匹配转最大流

在左部点前加源点 s，右部点后加汇点 t，建边：

- s → 每个左部点，容量 1
- 左部点 → 右部点（原图的边），容量 1
- 每个右部点 → t，容量 1

最大流就是最大匹配数。容量 1 的网络里 Dinic 的复杂度是 O(E√V)，和 Hopcroft–Karp 同阶。需要输出方案时，看中间那些边里哪些的 `cap` 变成了 0（流量为 1）。这个转化的价值在于：**一旦匹配问题加上了容量（一个人可以接多个任务）、权值（费用流）、或要求某些点必须被匹配，直接改边的容量或费用就能处理**，匈牙利做不到。

### 例 2：最小割处理"拆点"——删最少的点隔开 s 和 t

题目问"至少删掉几个点能让 s 到不了 t"（洛谷 P1345 奶牛的电信）。最小割切的是边，不是点，所以把每个点 x 拆成入点 x_in 和出点 x_out，连一条容量 1 的边 x_in → x_out，表示"删掉这个点的代价是 1"；原图的边 u—v 连成 u_out → v_in 和 v_out → u_in，容量设为无穷大，保证割不会选原边。

```cpp
// 片段：点 x 的入点编号 x，出点编号 x + n
for (int x = 1; x <= n; x++) d.add_edge(x, x + n, 1);
for (auto [u, v] : edges) {
    d.add_edge(u + n, v, INF);       // INF 取一个远大于 n 的数，如 1e9
    d.add_edge(v + n, u, INF);
}
// 源点取 s + n（从 s 的出点出发），汇点取 t（到 t 的入点结束）
```

最大流（也就是最小割）的值就是最少要删除的点数。s 与 t 直接相连时无论删哪些点都隔不开，题目通常会排除这种情况。这个建模用 3 到 7 个点的随机图与枚举所有删点集合的暴力解对拍，结果一致。

### 例 3：带费用的分配（指派问题）

n 个人做 n 件事，第 i 个人做第 j 件事的费用是 `a[i][j]`，每个人做一件、每件事一个人做，总费用最小。

```cpp
// 片段：s=0，t=2n+1；人 1..n，事 n+1..2n
for (int i = 1; i <= n; i++) {
    mf.add_edge(0, i, 1, 0);
    mf.add_edge(n + i, 2 * n + 1, 1, 0);
    for (int j = 1; j <= n; j++)
        mf.add_edge(i, n + j, 1, a[i][j - 1]);
}
auto [flow, cost] = mf.run();        // flow 应等于 n，cost 是最小总费用
```

这个建模用 n 不超过 5、费用为 1 到 20 的随机矩阵，与枚举全部排列的暴力解对拍，结果一致。

## 常见坑

- 反向边必须和正向边成对存放，并且初始容量为 0；`id ^ 1` 取反向边的前提是正向边下标从 0 开始、成对加入。
- 容量、流量、费用都用 `long long`；无穷大不要取 `INT_MAX`，两个无穷相加会溢出。
- Dinic 的 `dfs` 里 `cur[u]` 要用引用 `int &i = cur[u]`，写成普通变量就失去了当前弧优化，会超时。
- 每一轮 BFS 之后都要把 `cur` 清零。
- 求最小割方案时，S 侧是"残量网络里从 s 能到的点"，不是"所有被流经过的点"。
- 费用流的残量网络有负权边，不能直接用 Dijkstra；原图有负环时本模板不适用。
- 建图时点数要算对：拆点后是 2n，加上源汇点还要再加。数组开小是最常见的 Runtime Error。
