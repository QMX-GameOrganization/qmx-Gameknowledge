> 适用版本：以 Unity 6000.x 的 Burst 1.8.x（手册与 API 取自 1.8.31）为主线；本项目的 Unity 7000.0.0a8 中 Burst 2.0.0 是转发（shim）壳包，本页涉及的类型在其 `TypeForwarders.cs` 中均有转发，命名空间仍是 `Unity.Burst` 与 `Unity.Burst.CompilerServices`。Burst 2.0.0 之后是否新增或改动参数，未逐项核对（待核实）。

## 要点

- 别名（aliasing）是指两个指针或引用可能指向重叠的内存。编译器证明不了"不重叠"时，只能保守处理：重复加载、不敢重排、不敢向量化。
- 提示（hint）是你向 Burst 做的承诺，不是请求。承诺为真，代码更快；承诺为假，行为未定义（undefined behavior），不会报错，只会算错或崩溃。
- 绝大多数 Job 不需要手写 `[NoAlias]`：`NativeArray` 这类 `[NativeContainer]` 成员和 Job 结构体本身，Burst 已按规则推断。
- 提示的使用顺序：先写对，先用 Burst Inspector 看汇编和向量化结果，再决定要不要加提示。

## 1 别名是什么，为什么拖慢代码

手册用一个拷贝 Job 说明：输入、输出两个数组如果不重叠，Burst 可以把标量循环改写成一次处理一批元素（向量化）。如果 `Output` 与 `Input` 错开一个元素重叠，按批处理会读到被提前覆盖的数据，结果出错。所以编译器在"可能重叠"的情况下不能向量化。

```
不重叠:  Input  [a0 a1 a2 a3 a4 a5 a6 a7]
         Output [b0 b1 b2 b3 b4 b5 b6 b7]      -> 可以一次拷 4 或 8 个

重叠一格: Input  [a0 a1 a2 a3 a4 ...]
          Output     [b0 b1 b2 b3 ...]         -> Output[0] 就是 Input[1]
                                                  按批读会读到已被覆盖的值
```

手册里该例的 AVX2 汇编一次循环搬 32 个 float，关掉别名分析后变成逐元素标量循环，手册给出的说法是约慢 32 倍。这个倍数来自手册的特定示例，不要当成通用数字。

别名还影响"重复加载"。下面的函数里 Burst 不知道 `a` 与 `b` 是否同址，所以返回前要重新读一次 `b`：

```csharp
int Foo(ref int a, ref int b)
{
    b = 13;
    a = 42;      // 如果 a 与 b 同址，这里会改写 b
    return b;    // Burst 必须重新加载 b
}
```

手册还提到函数克隆（function cloning）：调用点能看清两个实参不别名时，Burst 会为被调函数生成一份"已知不别名"的副本并改调副本，从而省掉那次重复加载。

## 2 Job 里 Burst 已经替你推断了什么

手册 Aliasing and the job system 一页给出的规则：

- Job 结构体中带 `[NativeContainer]` 的成员（如 `NativeArray`、`NativeSlice`）互相不别名。
- 带 `[NativeDisableContainerSafetyRestriction]` 的成员可以与其他成员别名，因为这个特性本身就是在显式允许这种用法。
- 指向 `[NativeContainer]` 结构体的指针不能出现在另一个 `[NativeContainer]` 结构体里（例如不能有 `NativeArray<NativeSlice<T>>`）。
- Job 结构体默认是 `[NoAlias]` 结构体，即结构体自身地址不会出现在它的成员里。
- 不同元素类型也不等于不别名。C# 没有 C/C++ 那种基于类型的别名分析（TBAA），`NativeArray<byte>` 可以与 `NativeArray<float>` 别名（前提是前者带上面那个特性）。
- 手册还提到一个实验特性 `[Alias]`，用于退出这些保证，需要定义 `UNITY_BURST_EXPERIMENTAL_ALIAS_ATTRIBUTE` 才能使用。本页不展开。

## 3 `[NoAlias]`

`Unity.Burst.NoAliasAttribute` 的合法位置（API 页的 `AttributeUsage`）是：`Struct`、`Field`、`Parameter`、`ReturnValue`。四种位置的含义取自手册：

| 位置 | 含义 |
| --- | --- |
| 函数参数 | 该参数与函数的其他参数不别名 |
| 结构体字段 | 该字段与结构体里其他带 `[NoAlias]` 的字段不别名 |
| 结构体 | 结构体自身地址不会出现在它的成员里 |
| 返回值 `[return: NoAlias]` | 返回的指针与同一函数返回的其他指针不别名（如 `malloc`、bump 分配器） |

```csharp
using Unity.Burst;

// 参数：告诉 Burst a 不会和 b 重叠，于是 return b 可以折叠成常量 13
int Foo([NoAlias] ref int a, ref int b)
{
    b = 13;
    a = 42;
    return b;
}

// 字段：自己写的指针容器，Burst 推断不了
unsafe struct TwoBuffers
{
    [NoAlias] public float* Src;
    [NoAlias] public float* Dst;
}

// 返回值：只有保证返回唯一地址的函数才能加
[System.Runtime.CompilerServices.MethodImpl(System.Runtime.CompilerServices.MethodImplOptions.NoInlining)]
[return: NoAlias]
unsafe int* BumpAlloc(int* arena)
{
    int offset = arena[0]++;
    return arena + offset;
}
```

风险：手册明确说，在可能别名的指针上使用 `[NoAlias]` 会导致未定义行为，而且很难追踪。手册对返回值的提醒是，只在确实保证返回唯一指针的函数上使用，并且 Burst 会积极内联小函数，内联后无需该特性也能得到同样结果。

## 4 `Aliasing.ExpectAliased` 与 `ExpectNotAliased`：验证用

这两个是编译期断言，位于 `Unity.Burst.CompilerServices.Aliasing`：

- `ExpectNotAliased(a, b)`：Burst 若不能证明 a 与 b 不别名，就报编译错误。
- `ExpectAliased(a, b)`：Burst 若不能证明 a 与 b 别名，就报编译错误。
- 重载接受 `void*`，也接受 `in A` / `in B`（泛型），所以既能比较指针，也能比较结构体。

```csharp
using Unity.Burst;
using Unity.Burst.CompilerServices;
using Unity.Collections;
using Unity.Collections.LowLevel.Unsafe;
using Unity.Jobs;

[BurstCompile]
struct CopyJob : IJob
{
    [ReadOnly]  public NativeArray<float> Input;
    [WriteOnly] public NativeArray<float> Output;

    public unsafe void Execute()
    {
        // 想确认优化器真的看出这两个数组不重叠，就加断言
        Aliasing.ExpectNotAliased(Input.GetUnsafeReadOnlyPtr(), Output.GetUnsafePtr());

        for (int i = 0; i < Input.Length; i++)
            Output[i] = Input[i];
    }
}
```

1.8.31 手册 "Memory aliasing" 页的示例里取指针写的是小写开头的 `getUnsafePtr()`，这是手册示例的笔误，实际方法名是 `GetUnsafePtr()` / `GetUnsafeReadOnlyPtr()`（`Unity.Collections.LowLevel.Unsafe` 命名空间，本项目其它章节也用同样写法）。手册该页还有 `ExpectNotAliased(in Input, in Output)` 这类直接比较两个容器结构体的写法。

两点行为要记住：

- 手册说明这些检查只在启用优化时运行，因为别名推断依赖优化器通过内联看穿函数。关掉优化（例如勾选 Debug）时它们不起作用。
- 它们是"断言"，不改变生成的代码，适合放在性能关键 Job 里，防止以后重构把向量化悄悄弄丢。失败时是编译错误，比悄悄变慢更容易发现。

## 5 `Hint.Likely` / `Unlikely` / `Assume`

`Unity.Burst.CompilerServices.Hint` 是静态类，三个方法都接收 `bool`：

- `Hint.Likely(cond)`：条件大概率为真。Burst 把更可能走的分支排在跳转之后，利于指令缓存，并在该分支上多花优化时间。
- `Hint.Unlikely(cond)`：与上面相反。手册的典型例子是检查分配是否成功：大多数时候成功，失败分支只是兜底。
- `Hint.Assume(cond)`：Burst 直接当 `cond` 恒为真，不检查。手册给的用法包括：告诉它循环上界是 16 的倍数以获得无尾部标量的完美向量化，或者某个值不是 `NaN`、不是负数。

```csharp
using Unity.Burst.CompilerServices;

// 1) Likely / Unlikely：只影响布局和优化投入，条件判错也不会算错
if (Hint.Unlikely(y < 0 || y >= WorldHeight))
    return BlockId.Air;           // 越界很少发生

// 2) Assume：条件为假时是未定义行为
Hint.Assume(count % 16 == 0);
for (int i = 0; i < count; i++) { /* 现在可以按 16 对齐展开向量化 */ }
```

`Likely` 与 `Unlikely` 判断错了只是慢一点，是安全的。`Assume` 判断错了，Burst 可能把 `else` 分支整段删掉，后果不可预测，这是本页风险最高的一个。

## 6 `Constant.IsConstantExpression`

`Unity.Burst.CompilerServices.Constant.IsConstantExpression<T>(T)`（另有 `void*` 重载）在编译期询问：这个参数此刻是否已被 Burst 视为常量。典型用途是给常量参数走快速路径：

```csharp
using Unity.Mathematics;
using static Unity.Burst.CompilerServices.Constant;

public static float MyPow(float f, int i)
{
    if (IsConstantExpression(i) && i == 2)
        return f * f;                    // 调用点传常量 2 时才会命中
    return math.pow(f, (float)i);
}
```

手册指出两个性质：结果依赖优化的结果，所以会随函数是否被内联而变；关闭优化时一律返回 `false`。因此它只能当优化提示，不能当逻辑条件，两条分支必须算出相同的结果。

## 7 `[AssumeRange]`

`Unity.Burst.CompilerServices.AssumeRangeAttribute` 已在本项目 `TypeForwarders.cs` 中确认转发。API 页：`AttributeUsage` 为 `Parameter | ReturnValue`；构造函数是 `(long min, long max)` 或 `(ulong min, ulong max)`，表示闭区间 `[min..max]`。手册给出的限制：只能用于标量整数类型，且区间参数的类型要与被标注的类型一致。

```csharp
using Unity.Burst.CompilerServices;

[return: AssumeRange(0u, 13u)]
static uint Half([AssumeRange(0, 26)] int x) => (uint)x / 2u;
```

手册说 Burst 已经知道 `NativeArray.Length` 和 `NativeSlice.Length` 非负。自建容器可以在返回 `Length` 的私有函数上写 `[return: AssumeRange(0, int.MaxValue)]` 来传达同样的信息。区间不成立时的后果与 `Hint.Assume` 同类：未定义行为。

## 8 `[SkipLocalsInit]`

`Unity.Burst.CompilerServices.SkipLocalsInitAttribute`，`AttributeUsage` 只有 `Method`。C# 默认把局部变量清零，Burst 对 `stackalloc` 内存会插入一次 `memset`。如果你确定后面会把整块内存写满，就在方法上加它，省掉清零：

```csharp
[SkipLocalsInit]
static unsafe int Fill(int size)
{
    int* data = stackalloc int[size];
    for (int i = 0; i < size; i++) data[i] = i;   // 全部写满，清零是浪费
    return Sum(data, size);
}
```

手册的对比里，加上该特性后汇编中的 `memset` 调用消失。风险是读到未初始化的栈内存，值不确定。注意它是 Burst 自己的特性，不是 `System.Runtime.CompilerServices.SkipLocalsInitAttribute`，两者是不同的类型。

## 9 内联：`MethodImpl`

`System.Runtime.CompilerServices.MethodImplOptions.NoInlining` 在手册的 NoAlias 示例中用来阻止 Burst 内联小函数（手册同时说明 Burst 默认会积极内联小函数）。`AggressiveInlining` 在 Burst 手册里没有专门页面，效果请在 Burst Inspector 里确认。内联不足会挡住常量折叠和别名分析，因为这些分析依赖看穿调用。

## 10 `[IgnoreWarning]`

`Unity.Burst.CompilerServices.IgnoreWarningAttribute`：`AttributeUsage` 为 `Method`，`AllowMultiple = true`，构造函数接收一个 `int`（警告编号）。手册说可以用在：

- 普通方法上，抑制该方法编译时的指定警告。
- `[BurstDiscard]` 方法上，一次性抑制所有调用点的 `BC1371`。

```csharp
[IgnoreWarning(1370)]            // 有意在 Player 里 throw 时，抑制 BC1370
int Checked(int x)
{
    if (x < 0) throw new System.Exception("negative");
    return x * x;
}
```

手册的态度是：Burst 的警告值得认真对待，应少用。`BC1370` 的含义是 `throw` 没有被 `[Conditional("ENABLE_UNITY_COLLECTIONS_CHECKS")]` 保护，在 Player 里 `throw` 会变成中止并让程序崩溃。

## 11 `[BurstCompile(...)]` 的参数逐项说明

`BurstCompileAttribute` 的 `AttributeUsage` 为 `Assembly | Class | Struct | Method`，有两个构造函数：无参，以及 `(FloatPrecision, FloatMode)`。下面的属性来自 1.8.31 的 API 页：

| 参数 | 类型 | 作用 | 备注 |
| --- | --- | --- | --- |
| `FloatPrecision` | `FloatPrecision` | 数学函数（`sin`、`cos`、`exp`、`log`、`pow` 等）的精度 | `Standard`（默认，等于 `Medium`，3.5 ulp）、`High`（1.0 ulp）、`Medium`、`Low`（按函数定义，部分函数 350 ulp） |
| `FloatMode` | `FloatMode` | 浮点运算的重排与特殊值处理 | `Default`（等于 `Strict`）、`Strict`、`Fast`（可重排、可用精度更低的硬件指令）、`Deterministic`（跨平台一致，仅 64 位架构） |
| `CompileSynchronously` | `bool` | 首次使用时立即编译，而不是后台编译 | 只对即时（JIT）编译有意义，影响 Editor/Play 模式；Player 是提前（AOT）编译 |
| `DisableSafetyChecks` | `bool` | 对当前 Job 或函数指针关闭安全检查 | 若全局 Safety Checks 选了 Force On，则仍然开启 |
| `Debug` | `bool` | 以可调试方式编译 | 当前实现会关闭该方法的优化，便于用原生调试器单步 |
| `DisableDirectCall` | `bool` | 关闭"托管代码调用 Burst 静态方法时改成直接调用原生方法"的转换 | 默认会转换；手册说该转换由 IL 后处理完成，设为 `true` 后后处理器不再处理 |
| `OptimizeFor` | `OptimizeFor` | 入口点的优化目标 | 见下 |

`OptimizeFor` 的五个取值（API 页，括号内为枚举数值）：

| 值 | 含义 |
| --- | --- |
| `Default`（0） | 默认，等同于 `Balanced` |
| `Performance`（1） | 追求最优的二进制 |
| `Size`（2） | 追求最小的二进制 |
| `FastCompilation`（3） | 做一些优化，但尽量缩短编译时间 |
| `Balanced`（4） | 兼顾性能与编译时间 |

```csharp
// 世界生成的热路径：要速度，浮点允许重排
[BurstCompile(FloatPrecision.Medium, FloatMode.Fast, OptimizeFor = OptimizeFor.Performance)]
public struct HotJob : IJobParallelFor { /* ... */ }

// 需要跨平台逐位一致（例如依赖种子的世界生成）：用 Deterministic
[BurstCompile(FloatMode = FloatMode.Deterministic)]
public struct SeededJob : IJob { /* ... */ }
```

几条要点：

- `FloatMode.Fast` 能让 Burst 把 `a * b + c` 融合成一条 mad 指令并重排运算，换来速度，代价是精度变化且 NaN 处理不再统一。`FloatMode.Deterministic` 会禁用一些优化，有性能代价，而且手册说明它不保证 NaN 的位模式一致，把非确定输入或非 Deterministic 的函数指针传进来也会破坏确定性。这部分在浮点模式与确定性一章有展开。
- `OptimizeFor` 是否在 Burst 1.8 的所有小版本都存在、各取值在 2.0.0 里是否行为一致，本次只核对了 1.8.31 的 API 页与 2.0.0 的类型转发（`OptimizeFor` 在转发列表里），逐版本差异待核实。
- 以上属性对 `[BurstCompile]` 标在程序集上时也生效，用来给整个程序集设默认值；写法和优先级见本页第 19 节"程序集级 `[assembly: BurstCompile]` 与设置优先级"。
- `Debug = true` 会关掉优化，此时 `Aliasing.Expect*`、`Constant.IsConstantExpression` 的行为也随之变化（见上文）。

## 12 提示总表：用法、效果、风险

| 提示 | 位置 | 效果 | 用错的后果 |
| --- | --- | --- | --- |
| `[NoAlias]` 参数/字段/结构体/返回值 | 标注在声明上 | 解除重复加载，促成向量化 | 指针其实重叠时未定义行为 |
| `Aliasing.ExpectNotAliased` / `ExpectAliased` | 方法体内断言 | 不改代码，只在证明失败时报编译错误 | 无运行时风险；关优化时不起作用 |
| `Hint.Likely` / `Unlikely` | 包在 `if` 条件上 | 调整分支布局与优化投入 | 判断错只会变慢 |
| `Hint.Assume` | 单独一条语句 | 让 Burst 当条件恒为真，可删分支、完美向量化 | 条件为假时未定义行为 |
| `Constant.IsConstantExpression` | `if` 条件 | 常量参数走快速路径 | 两条分支结果不一致会导致内联与否结果不同 |
| `[AssumeRange(min, max)]` | 整数参数/返回值 | 范围信息喂给优化器 | 值越界时未定义行为 |
| `[SkipLocalsInit]` | 方法 | 去掉 `stackalloc` 的清零 | 读到未初始化内存 |
| `MethodImpl(NoInlining)` | 方法 | 阻止内联 | 挡住常量折叠和别名推断 |
| `[IgnoreWarning(n)]` | 方法 | 抑制编号为 n 的警告 | 掩盖真实问题 |
| `BurstCompile(FloatMode.Fast)` | Job/函数 | 允许重排与低精度指令 | 结果与 Strict 不同，NaN 行为不统一 |
| `BurstCompile(DisableSafetyChecks = true)` | Job/函数 | 去掉检查开销 | 越界访问不再被捕获 |

## 13 前后对比示例

### 13.1 别名导致不向量化，加 `[NoAlias]` 后向量化

下面是用原始指针写的缩放拷贝。指针字段不属于 `[NativeContainer]`，Burst 无法保证 `Src` 与 `Dst` 不重叠。

```csharp
[BurstCompile]
public unsafe struct ScaleJob : IJob
{
    public float* Src;
    public float* Dst;
    public int Count;
    public float K;

    public void Execute()
    {
        for (int i = 0; i < Count; i++)
            Dst[i] = Src[i] * K;    // Dst 可能与 Src 重叠，向量化可能被拒绝或需要运行时检查
    }
}
```

前提是调用方确实能保证 `Src[0..Count)` 与 `Dst[0..Count)` 两块内存不重叠。按手册，字段上的 `[NoAlias]` 表示"该字段与结构体里其它带 `[NoAlias]` 的字段不别名"，所以两个字段都要标。满足前提时，在字段上声明：

```csharp
[BurstCompile]
public unsafe struct ScaleJobNoAlias : IJob
{
    [NoAlias] public float* Src;
    [NoAlias] public float* Dst;
    public int Count;
    public float K;

    public void Execute()
    {
        for (int i = 0; i < Count; i++)
            Dst[i] = Src[i] * K;    // 现在可以安全地按批处理
    }
}
```

两份代码生成的汇编是否一个向量化、一个不向量化，取决于具体平台与 Burst 版本。本页没有实际运行验证，请在 Burst Inspector 里对比两个 Job 的汇编（找 `vmovups`、`mulps` 等向量指令），并在 `Execute` 里加 `Aliasing.ExpectNotAliased(Src, Dst)` 做回归保护。更简单的办法是直接改用 `NativeArray<float>`，此时 Burst 已经替你推断不别名，不需要任何特性。

### 13.2 分支提示

体素读取时越界是罕见路径。把它标成 `Unlikely`，热路径就是直线代码：

```csharp
public static byte GetBlock(in NativeArray<byte> blocks, int x, int y, int z, int sx, int sy, int sz)
{
    if (Hint.Unlikely((uint)x >= (uint)sx | (uint)y >= (uint)sy | (uint)z >= (uint)sz))
        return 0;                                   // 越界当作空气
    return blocks[(y * sz + z) * sx + x];
}
```

这里的判断即使被误标也只影响速度，不影响结果。这也是 `Likely` / `Unlikely` 比 `Assume` 安全的原因。本项目当前 `Assets/Scripts/WorldGen/Density` 里的节点是托管类（见上一章），这些提示要等热点逻辑迁到 Burst 后才用得上。

## 14 提示用错会产生未定义行为

未定义行为的意思是：Burst 可以生成任何代码，包括看起来"正常"、只在特定平台或特定优化级别才出错的代码。典型表现是 Editor 里正确、Player 里错；Debug 勾选时正确、优化后错；改一行无关代码后突然错。

下列提示的前提必须由你自己保证：`[NoAlias]`、`Hint.Assume`、`[AssumeRange]`、`[SkipLocalsInit]`，以及 `[return: NoAlias]`。保证不了时宁可不加。

## 15 使用建议：先测量再加提示

1. 先用 Burst Inspector 看汇编，确认热循环是否已经向量化，而不是凭感觉加特性。
2. 先排查更便宜的原因：数据布局、`NativeArray` 代替指针、避免循环里的分支和函数指针。
3. 需要提示时，从最安全的开始：`Aliasing.Expect*` 断言，其次 `Likely`/`Unlikely`，最后才是 `[NoAlias]`、`Assume`、`[AssumeRange]`。
4. 每加一个提示，在注释里写清它所依赖的前提，并尽量加运行时断言（仅 Editor 或开发构建）去验证前提。
5. 用 Profiler 或计时对比前后，没有可见收益就删掉。

## 16 常见坑

- 给 `NativeArray` 字段加 `[NoAlias]`：多余，Burst 已推断；加在带 `[NativeDisableContainerSafetyRestriction]` 的字段上则可能是错的，因为那个特性正是在声明可能别名。
- 以为 `Aliasing.ExpectNotAliased` 会"让"代码不别名：它只是断言，不改变代码。
- 在 Debug 或关闭优化下测试 `Constant.IsConstantExpression`、`Aliasing.Expect*`：结果无参考价值。
- 把 `IsConstantExpression` 当逻辑条件，两条分支返回不同结果。
- `Hint.Assume` 里写了有副作用的表达式，或写了运行时并不总成立的条件。
- 全局打开 `FloatMode.Fast` 后，在依赖 NaN 或逐位一致的逻辑里出现诡异差异。
- 用 `[IgnoreWarning]` 压住警告而不理解原因，尤其是 `BC1370`。

## 17 程序集级 `[assembly: BurstCompile]` 与设置优先级

本节取自 Burst 1.8 手册 Defining Burst options for an assembly。

### 写法

在程序集里的任意一个 C# 文件里写一行程序集级特性（放在命名空间或类型声明之外，`using` 之后），就能给这个程序集里所有的 Burst Job 和函数指针设置选项：

```csharp
using Unity.Burst;

[assembly: BurstCompile(CompileSynchronously = true)]
```

手册的另一个例子：一个程序集只包含需要频繁改动的游戏逻辑，希望迭代快：

```csharp
[assembly: BurstCompile(OptimizeFor = OptimizeFor.FastCompilation)]
```

手册说明，这样 Burst 会尽可能快地编译这个程序集里的代码，让你更快迭代游戏代码；其它程序集不受影响，仍按原来的方式编译，所以你可以逐个程序集控制 Burst 的行为。

浮点选项也可以这样设（例如 `[assembly: BurstCompile(FloatMode = FloatMode.Deterministic)]`，见 2.6 浮点模式与确定性）。`BurstCompileAttribute` 的 API 页确认 `AttributeUsage` 包含 `Assembly`，可以标在程序集上。

### 优先级

手册的原文给出的顺序（这里保持原意翻译）：

1. 编辑器菜单设置优先。例如在 Burst 菜单里启用 `Native Debug Compilation`，Burst 总是把你的代码编译成便于调试的形式。
2. 其次看 Job 或函数指针上的 `BurstCompile` 特性。如果其中写了 `CompileSynchronously = true`，Burst 就同步编译。
3. 其余的设置，才从程序集级特性取。

手册的示例：

```csharp
[assembly: BurstCompile(OptimizeFor = OptimizeFor.FastCompilation)]

// 这个 Job 按快速编译优化，因为程序集级的 BurstCompile 这样要求
[BurstCompile]
struct AJob : IJob
{
    // ...
}

// 这个 Job 按体积优化，因为它自己的 BurstCompile 这样要求
[BurstCompile(OptimizeFor = OptimizeFor.Size)]
struct BJob : IJob
{
    // ...
}
```

小结成一句话：编辑器菜单 > Job（或函数指针）上的属性 > 程序集属性。Burst AOT Settings 里的 `Optimize For` 是全局默认值，会被程序集级与 Job 级的 `OptimizeFor` 覆盖（见 2.11 构建发布与平台差异）。

手册没有说明程序集级属性与 Burst AOT Settings 的 `Floating Point Mode` 冲突时谁优先，只能按"更靠近代码的属性覆盖全局默认"的思路理解，需要时用 Burst Inspector 对比汇编验证（待核实）。

### 使用建议

- 只在确实需要逐程序集差异时才用它。例如把频繁改动、对性能不敏感的玩法程序集设成 `FastCompilation`，把世界生成的热路径程序集保持默认或设成 `Performance`。
- 世界生成程序集如果要求可复现，在程序集级统一设 `FloatMode`，比在每个 Job 上重复写更不容易漏（Job 上写了不同值时，Job 的属性优先）。

## 18 小结

- 别名分析决定 Burst 敢不敢向量化和消除重复加载，`NativeArray` 与 Job 结构体已按规则推断，大多数代码不需要手写。
- `[NoAlias]` 可用在参数、字段、结构体、返回值上；`Aliasing.Expect*` 用来验证，不改代码。
- `Hint.Likely`/`Unlikely` 安全，`Hint.Assume`、`[AssumeRange]`、`[SkipLocalsInit]` 判断错了是未定义行为。
- `[BurstCompile]` 的参数有 `FloatPrecision`、`FloatMode`、`CompileSynchronously`、`DisableSafetyChecks`、`Debug`、`DisableDirectCall`、`OptimizeFor`。
- 设置优先级：编辑器菜单 > Job（或函数指针）上的属性 > 程序集级属性。
- 先在 Burst Inspector 里测量，再加提示。

## 19 自测题

1. 为什么两个可能重叠的指针会阻碍向量化？
   答：按批读取会读到已被前面写入覆盖的数据，结果与逐元素执行不同，所以编译器无法安全地重排。
2. `Hint.Unlikely` 与 `Hint.Assume` 的风险差别是什么？
   答：`Unlikely` 判断错了只影响速度；`Assume` 判断错了是未定义行为，Burst 可能删除分支。
3. `Aliasing.ExpectNotAliased(a, b)` 在什么时候会报错？它会改变生成的代码吗？
   答：优化开启且 Burst 无法证明 a 与 b 不别名时报编译错误；不改变生成的代码，只是断言。
4. `[SkipLocalsInit]` 应该用在什么情况下？
   答：确定 `stackalloc` 的内存会被全部写满再读取时，用它去掉清零；只能标注在方法上。
5. `[BurstCompile]` 中想要开启跨平台确定性浮点，应设置什么？
   答：`FloatMode = FloatMode.Deterministic`（仅 64 位架构），要知道它有性能代价且不保证 NaN 位模式一致。
6. 程序集上写了 `[assembly: BurstCompile(OptimizeFor = OptimizeFor.FastCompilation)]`，其中一个 Job 自己写了 `[BurstCompile(OptimizeFor = OptimizeFor.Size)]`，这个 Job 最终按什么优化？编辑器菜单里勾了 `Native Debug Mode Compilation` 呢？
   答：Job 自己的属性覆盖程序集的，按 `Size`；勾了 `Native Debug Mode Compilation`，编辑器菜单优先，代码总是按便于调试的方式编译。
