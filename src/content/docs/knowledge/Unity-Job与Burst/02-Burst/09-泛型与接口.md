## 要点

- Burst 编译的是已经"填好类型参数"的具体实例。泛型本身不是编译单元，`Job<T>` 里的 `T` 必须在某处被替换成具体类型，Burst 才有东西可编。
- 用泛型约束（`where T : unmanaged, IFoo`）调用接口方法时，编译器知道 `T` 的具体类型，调用是静态绑定，可以内联，没有装箱，没有虚调用。这是 Burst 里"零开销抽象"的主力手段。
- 把接口当字段类型或变量类型（`IFoo foo;`）意味着引用类型或装箱，Burst 不支持。
- 泛型 Job 必须用"完全确定的类型参数"直接使用。通过泛型方法或泛型类的类型参数转手调度，Burst 在 Player 构建时发现不了它（官方手册明确警告）。
- 递归泛型组合（`AddNode<A, B>`）能把整棵表达式树内联成一个函数，代价是代码膨胀、编译时间变长、类型名极长。

## 1 Burst 里的泛型怎么工作

### 1.1 单态化（Monomorphization）

C# 的泛型在 IL 里仍是泛型，运行时才由 JIT 为值类型生成专用代码。Burst 是提前（或编辑器内即时）把 IL 翻成 LLVM IR 的，它对泛型的处理等价于 C++ 模板：对每一个出现过的具体实例各编译一份。手册对类型支持的描述是：Burst 支持与结构体一起使用的泛型类型，并支持带接口约束的泛型调用的完整实例化。

```
MyJob<ClampNode<AddNode<ConstantNode, ConstantNode>>>   ->  编译出一份原生代码
MyJob<ConstantNode>                                      ->  另一份原生代码
MyJob<T>   (T 未知)                                      ->  无法编译
```

### 1.2 Burst 必须"看到"具体实例

编辑器里，泛型 Job 通常能全速运行（手册的说法是"The implicit MyGenericJob<int> will run at Editor time in full Burst speed"）。Player 构建则不同：Burst 要在构建时找出哪些泛型实例会被用到，发现不了的实例就编不进原生库。手册的提醒是：如果 Job 在编辑器里全速、在构建的 Player 里却很慢，问题可能出在泛型 Job 上。

能被发现的写法（类型参数是具体类型）：

```csharp
var job = new MyGenericJob<int>();   // int 是具体类型，Player 构建时能被发现
job.Schedule();
```

发现不了的写法（类型参数来自泛型方法或泛型类的参数）：

```csharp
public static void GenericJobSchedule<TData>() where TData : struct
{
    var job = new MyGenericJob<TData>();   // TData 是泛型参数，构建时看不到具体实例
    job.Schedule();
}

public class SuperJobSystem<TData>
{
    public MyGenericJob<TData> MyJob;      // 同样的限制
}
```

手册的结论：泛型 Job 要用"完全解析的泛型实参"（如 `int`、`MyOtherStruct`）直接使用，不能经由 `MyGenericJob<TContext>` 这种泛型参数间接使用；Burst 不支持通过泛型方法调度泛型 Job。

### 1.3 用 RegisterGenericJobType 显式登记

`Unity.Jobs.RegisterGenericJobTypeAttribute` 是 `Unity.Jobs` 命名空间下的特性（Unity 6.7 Scripting API 页面确认，属引擎 Jobs 模块，不属于 `Unity.Burst`）。API 的描述是：作为程序集级（assembly-level）特性使用时，允许为泛型 Job 的具体实例创建 Job 反射数据（reflection data）；它只有一个属性 `ConcreteType`（"Fully closed generic job type to register with the job system"），构造时传入一个完全封闭的泛型 Job 类型。

```csharp
using Unity.Jobs;

[assembly: RegisterGenericJobType(typeof(MyGenericJob<int>))]
[assembly: RegisterGenericJobType(typeof(MyGenericJob<float>))]
```

要点：
- 它登记的是 Job 系统的反射数据，不是 Burst 的编译清单。Burst 1.8 的 Generic jobs 手册页完全没有提到这个特性。
- 没有登记、且泛型 Job 的反射数据无法自动生成时，运行时可能报"job reflection data has not been automatically computed"一类的错误（该措辞见于论坛帖子，不是官方手册文字，具体触发条件和版本差异待核实）。
- "登记之后 Burst 就一定会在 Player 构建时编译该实例"没有官方出处，不要把它当作解决泛型 Job 在 Player 里变慢的办法。官方给出的办法只有一条：直接用完全确定的类型实参创建和调度泛型 Job（见 1.2 节）。

## 2 接口：作为约束 vs 作为类型

### 2.1 约束：静态分派，可内联

```csharp
public interface IShape { float Area(); }

public struct Circle : IShape { public float R; public float Area() => 3.14159265f * R * R; }
public struct Square : IShape { public float S; public float Area() => S * S; }

[BurstCompile]
public struct SumAreaJob<T> : IJob where T : unmanaged, IShape
{
    public NativeArray<T> Shapes;
    public NativeArray<float> Result;   // 长度 1，用来带回结果

    public void Execute()
    {
        float sum = 0;
        for (int i = 0; i < Shapes.Length; i++)
            sum += Shapes[i].Area();   // T 已知，这是 constrained call，可内联
        Result[0] = sum;
    }
}
```

`SumAreaJob<Circle>` 与 `SumAreaJob<Square>` 各编一份，`Area()` 被直接内联进循环，和手写的非泛型版本几乎没有区别。

### 2.2 类型：引用语义，Burst 不支持

```csharp
public struct BadJob : IJob
{
    public IShape Shape;          // 接口类型的字段：存的是装箱后的引用
    public void Execute() { var a = Shape.Area(); }
}
```

Burst 的类型支持页明确说：Burst 工作在不允许使用任何托管对象或引用类型的 .NET 子集上。接口类型的字段或变量需要装箱成引用，并通过虚调用分派，这两件事 Burst 都做不了。具体报错措辞随版本和位置而异（待核实），遇到时按"把接口换成泛型约束"处理。

### 2.3 NativeContainer 与泛型

容器本身就是泛型结构体，元素要求 `unmanaged`：

```csharp
public struct Chunk<T> where T : unmanaged
{
    public NativeArray<T> Data;    // NativeArray<T> 要求 T : struct，实践中用 unmanaged 更稳
}
```

要点：
- `NativeArray<T>` 里的 `T` 不能含托管引用。接口类型、`string`、数组都不行。
- 泛型方法里写 `NativeArray<T>` 没问题，只要调用点能确定 `T`。
- 手册对非 Job 的 Burst 入口方法另有限制：从托管代码直接调用 Burst 静态方法时，泛型方法或声明类型是泛型的方法不受支持（规则同函数指针）。

## 3 策略模式的 Burst 写法

经典面向对象写法用接口字段持有策略，Burst 里改为"策略作为类型参数"：

```csharp
public interface IFalloff { float Eval(float t); }

public struct Linear : IFalloff { public float Eval(float t) => 1f - t; }
public struct Smooth : IFalloff { public float Eval(float t) => 1f - t * t * (3f - 2f * t); }

[BurstCompile]
public struct FalloffJob<TFalloff> : IJobParallelFor where TFalloff : unmanaged, IFalloff
{
    public TFalloff Falloff;                     // 策略是一个小结构体，按值存放
    [WriteOnly] public NativeArray<float> Output;
    public float InvLength;

    public void Execute(int i) => Output[i] = Falloff.Eval(i * InvLength);
}
```

策略结构体可以带参数（例如 `Smooth` 加一个 `float Power` 字段），因为它是按值嵌入 Job 的普通数据。切换策略等于换一个类型参数，不是换一个运行时分支。

调度写法要避开 1.2 节的陷阱：调度点必须是具体类型。

```csharp
// 正确：调度点的类型参数是具体类型
var job = new FalloffJob<Smooth> { Falloff = default, Output = output, InvLength = 1f / n };
job.Schedule(n, 64).Complete();
```
## 4 泛型方法与扩展方法

- 在 Burst 代码内部，泛型方法和扩展方法都只是普通静态方法，类型参数确定后与手写方法无异，可以被内联。
- 它们作为"入口"（从托管代码被调用）时受限：手册说明，直接调用 Burst 编译的静态方法时，泛型方法与声明类型为泛型的方法不受支持。需要入口的话，用具体类型的包装方法。
- 扩展方法作用在结构体上时，注意 `this` 参数是按值还是 `ref`/`in`。对大结构体可以写成 `this in T x` 或 `this ref T x`（C# 7.2 起支持，且仅限结构体）以避免拷贝。
- 泛型委托无法通过函数指针使用，手册示例 `BurstCompiler.CompileFunctionPointer<MyGenericDelegate<int>>` 会编译失败，原因是 .NET 运行时对这类委托的互操作限制。

## 5 递归泛型组合：表达式树变成类型

把"节点"做成泛型结构体，子节点作为类型参数：

```csharp
public struct AddNode<A, B> : IDensity
    where A : unmanaged, IDensity
    where B : unmanaged, IDensity
{
    public A Left; public B Right;
    public double Sample(in Ctx c) => Left.Sample(c) + Right.Sample(c);
}
```

整棵树的结构编码在类型里，`Sample` 调用链在编译期完全展开，没有虚调用，没有委托调用，常量折叠和向量化也可以跨节点发生。

代价：

| 代价 | 说明 |
| --- | --- |
| 代码膨胀 | 每种树形状各编一份原生代码。树形状在运行时才确定（比如数据驱动的配置）时，实例数不可控 |
| 编译时间 | 每个实例各编译一份。`Show Timings` 手册节指出：前端和优化器的耗时与要编译的操作数线性相关，泛型函数越多前端耗时越高，因为泛型解析有不可忽略的成本。`Jobs > Burst > Show Timings` 可以在 Console 里看到各库的 JIT 编译耗时，具体增幅取决于树形，没有通用数字 |
| 类型名很长 | `ClampNode<AddNode<ConstantNode, MultiplyNode<...>>>` 会出现在 Burst Inspector 与报错信息里，不易阅读 |
| 形状必须编译期已知 | 运行时才读入的任意树形无法直接对应一个具体类型，需要退回到解释器或 switch 方案 |

## 6 与其他方案的对比

| 方案 | 分派时机 | 运行时开销 | 灵活性 | 编译成本 |
| --- | --- | --- | --- | --- |
| 泛型单态化 | 编译期 | 最低，可内联、可跨节点优化 | 树形在编译期固定 | 实例越多越高 |
| 函数指针（`FunctionPointer<T>`） | 运行时 | 每次间接调用，无法内联 | 可运行时切换 | 低，委托签名固定即可 |
| `switch` / 枚举标签 | 运行时 | 分支预测成本，可内联各分支 | 新增类型要改 switch | 低 |
| 解释器（节点数组 + 栈/寄存器） | 运行时 | 每个节点一次分派加数据搬运 | 最高，任意树形 | 低，一份解释器代码 |

经验规则：热路径、形状固定用泛型；形状由数据驱动且种类很多用解释器或节点数组加 `switch`；只有少数几个可选实现、且调用不在最内层循环时，函数指针也够用。

## 7 本项目对照：如果 IDensityFunction 变成 struct 接口加泛型组合

这一节是教学示例，不是对项目代码的修改。

项目里（`Assets/Scripts/WorldGen/Density/`）的现状：

- `IDensityFunction` 声明 `double Sample(in DensityContext context)`，`DensityContext` 是 `readonly struct`，字段 `X`、`Y`、`Z`（`int`）。
- `BinaryFunction` 是 `sealed class`，持有两个 `IDensityFunction` 字段和一个 `Func<double, double, double> operation`，`Sample` 里执行 `operation(left.Sample(context), right.Sample(context))`。
- `DensityFunctions` 的静态工厂（`Constant`、`Add`、`Multiply`、`Clamp` 等）都返回 `IDensityFunction`，其中 `Add` 是 `new BinaryFunction(a, b, (x, y) => x + y)`。

这些写法按 Burst 的标准都不能进 Job：类（引用类型）、接口类型的字段、`Func` 委托。要上 Burst，需要把节点改成结构体，把子节点从"接口字段"改成"泛型类型参数"。下面是一个最小可用的对应物（`Ctx` 对应 `DensityContext`，节点名加 `Node` 后缀以免与项目类型冲突）。

```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;

public readonly struct Ctx
{
    public readonly int X, Y, Z;
    public Ctx(int x, int y, int z) { X = x; Y = y; Z = z; }
}

public interface IDensity { double Sample(in Ctx c); }

public struct ConstantNode : IDensity
{
    public double Value;
    public double Sample(in Ctx c) => Value;
}

public struct AddNode<A, B> : IDensity
    where A : unmanaged, IDensity where B : unmanaged, IDensity
{
    public A Left; public B Right;
    public double Sample(in Ctx c) => Left.Sample(c) + Right.Sample(c);
}

public struct MultiplyNode<A, B> : IDensity
    where A : unmanaged, IDensity where B : unmanaged, IDensity
{
    public A Left; public B Right;
    public double Sample(in Ctx c) => Left.Sample(c) * Right.Sample(c);
}

public struct ClampNode<T> : IDensity where T : unmanaged, IDensity
{
    public T Input; public double Min, Max;
    public double Sample(in Ctx c) => math.clamp(Input.Sample(c), Min, Max);
}
```

对应项目里 `ClampFunction` 的 `Math.Max(min, Math.Min(max, input.Sample(context)))`；这里用 `math.clamp(double, double, double)`（`Unity.Mathematics`，Mathematics 1.3.x 中存在 double 重载）。

下面是泛型 Job、构造辅助方法和调度。注意工厂方法只构造结构体，不调度 Job，调度写在具体类型的调用点。

```csharp
public static class Dens
{
    public static ConstantNode Constant(double v) => new ConstantNode { Value = v };
    public static AddNode<A, B> Add<A, B>(A a, B b)
        where A : unmanaged, IDensity where B : unmanaged, IDensity
        => new AddNode<A, B> { Left = a, Right = b };
    public static MultiplyNode<A, B> Multiply<A, B>(A a, B b)
        where A : unmanaged, IDensity where B : unmanaged, IDensity
        => new MultiplyNode<A, B> { Left = a, Right = b };
    public static ClampNode<T> Clamp<T>(T input, double min, double max)
        where T : unmanaged, IDensity
        => new ClampNode<T> { Input = input, Min = min, Max = max };
}

[BurstCompile]
public struct DensityGridJob<T> : IJobParallelFor where T : unmanaged, IDensity
{
    public T Root;                       // 整棵表达式树，按值嵌入 Job
    public int3 Origin;
    public int Size;                     // 边长，网格为 Size^3
    [WriteOnly] public NativeArray<double> Output;

    public void Execute(int i)
    {
        int x = i % Size, z = (i / Size) % Size, y = i / (Size * Size);
        Output[i] = Root.Sample(new Ctx(Origin.x + x, Origin.y + y, Origin.z + z));
    }
}
```

调用点用 `using` 别名把长类型名收拢成一个具体类型。这样 `new DensityGridJob<DemoRoot>` 的类型实参是完全确定的，符合 1.2 节的规则。

```csharp
// using 别名必须写在文件顶部（其它类型声明之前）；这里只为展示而放在一起
using DemoRoot = ClampNode<AddNode<ConstantNode, MultiplyNode<ConstantNode, ConstantNode>>>;

public static class DensityDemo
{
    public static void Run()
    {
        // clamp(0.5 + 2.0 * 0.25, -1, 1)，结果是 1.0
        DemoRoot root = Dens.Clamp(
            Dens.Add(Dens.Constant(0.5),
                     Dens.Multiply(Dens.Constant(2.0), Dens.Constant(0.25))),
            -1.0, 1.0);

        const int size = 16;
        var output = new NativeArray<double>(size * size * size, Allocator.TempJob);
        var job = new DensityGridJob<DemoRoot>
        {
            Root = root, Origin = new int3(0, 0, 0), Size = size, Output = output
        };
        job.Schedule(output.Length, 64).Complete();   // 具体类型，Player 构建也能发现
        output.Dispose();
    }
}
```

要点：
- `Dens.Add`、`Dens.Clamp` 是泛型方法，但它们只构造结构体，在 Burst 之外运行，不涉及 Burst 编译问题。受限的是"通过泛型方法调度泛型 Job"，这里没有这样做。
- 不要在泛型辅助方法里调度（`static void Run<T>(T root)` 里 `new DensityGridJob<T>()`）：手册明确说 Burst 不支持通过泛型方法调度泛型 Job，Editor 里能全速，Player 构建里 Burst 可能发现不了该实例。`RegisterGenericJobType` 不是官方给出的补救办法，见 1.3 节。
- 这只是教学示例，不是对项目代码的修改。项目的 `IDensityFunction` 仍是类加接口加 `Func` 委托，这套写法要用在项目里，需要重写节点层。

### 7.1 与项目现状的差别

| 项目现状 | 泛型版教学示例 |
| --- | --- |
| 节点是 `sealed class`，在堆上 | 节点是 `struct`，内嵌在 Job 数据里 |
| 子节点是 `IDensityFunction` 字段，调用是接口虚调用 | 子节点是类型参数，调用静态绑定 |
| `Add` 靠 `Func<double,double,double>`，委托调用 | `Sample` 里直接写 `+`，可内联 |
| 树形在运行时随意拼，一个类型 | 树形编码在类型里，每种形状一份原生代码 |
| `Cache2D` 等节点持有可变状态，不是线程安全 | 值类型节点按 Job 拷贝，可变缓存需要另行设计 |

项目的 `DensityFunctions` 能在运行时拼出任意形状，这对数据驱动的世界预设很方便。泛型版换来速度，代价是形状必须在编译期写死。折中办法是把少数热点子树（例如固定的地形主干）做成泛型，其余走解释器或 `switch`。

## 8 常见坑

- 泛型 Job 在 Editor 快、Player 慢：多半是类型实参来自泛型参数，Burst 没发现实例。改成用具体类型直接调度（`RegisterGenericJobType` 登记的是 Job 反射数据，不能当作 Burst 发现实例的保证，见 1.3 节）。
- 把接口当字段：`public IDensity Root;` 不能进 Job。改成 `public T Root` 加泛型约束。
- 约束写成 `where T : IDensity` 而漏了 `unmanaged`：`T` 可能是类，装箱或引用语义会让 Burst 拒绝，也让 `NativeArray<T>` 编不过。
- 泛型方法或泛型类型里的 `[BurstCompile]` 静态方法不能直接从托管代码调用，需要具体类型的包装方法。
- 实例爆炸：每个不同的树形各一份原生代码，Editor 里首次使用还会触发即时编译。形状多时用 Burst Inspector 看实例数量，必要时改用解释器。
- 泛型委托不能做函数指针，`CompileFunctionPointer<MyGenericDelegate<int>>` 会失败。
- 报错措辞：Burst 对托管类型、接口类型、虚调用的拒绝信息格式随版本而异，本文没有逐条核对，遇到时以 Burst Inspector 与 Console 里的实际错误编号为准（待核实）。

## 9 小结

- 泛型加接口约束是 Burst 的静态多态：类型在编译期确定，调用可内联，没有装箱。
- 接口当字段或变量类型走的是引用与虚调用，Burst 不支持。
- 泛型 Job 要用完全确定的类型实参调度，不要经由泛型方法或泛型类的类型参数转手。
- 递归泛型组合能把表达式树编成一个函数，代价是代码膨胀、编译时间和长类型名。
- 形状在运行时才确定时，选解释器、`switch` 或函数指针。

## 10 自测题

1. 为什么 `where T : unmanaged, IFoo` 的调用能内联，而 `IFoo foo` 字段不行？
   答：前者 `T` 在单态化后是具体结构体，调用静态绑定；后者是引用类型，需要装箱和虚调用，Burst 不支持。
2. 下面哪种调度在 Player 构建中可能被 Burst 漏掉？`new MyJob<int>().Schedule()` 还是 `Run<T>() { new MyJob<T>().Schedule(); }`？
   答：后者，类型实参 `T` 是泛型参数，构建时看不到具体实例。
3. `AddNode<A, B>` 把子节点做成类型参数有什么好处和代价？
   答：好处是整棵树内联成一个函数，没有虚调用和委托；代价是每种树形一份代码、编译时间增加、类型名很长。
4. 项目里的 `BinaryFunction` 为什么不能直接放进 Burst Job？
   答：它是类，持有 `IDensityFunction` 接口字段和 `Func` 委托，都是托管引用。
5. 树形由玩家配置文件在运行时决定，应该选哪种方案？
   答：解释器（节点数组加栈或寄存器）或 `switch`，泛型单态化需要编译期已知形状。
