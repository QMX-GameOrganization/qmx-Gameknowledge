> 适用版本：以 Unity 6000.x 的 Burst 1.8.x / Collections 2.x / Mathematics 1.3.x 为主线；Unity 6.4 起 Collections 作为核心包随编辑器分发；本项目的 Unity 7000.0.0a8 中 Burst 2.0.0 与 Collections 6.7.0 是转发（shim）到引擎内置模块的壳包，API 仍在 `Unity.Burst` / `Unity.Collections` 命名空间，文档迁到了 Unity Manual。涉及版本差异处要写明，核实不了的标"待核实"。

## 要点

- Job System（作业系统）负责把工作分给多个核心，Burst 把 C# 编译成优化的本机代码，Collections 提供能在 Job 里用的容器，Mathematics 提供 Burst 友好的数学类型。四者配合使用，缺一不可，但可以不依赖 ECS。
- 新版本 Unity 里这四者在逐步“并入引擎”。Mathematics 从 Unity 6.5 起是内置模块；Collections 从 6.4 起是核心包，本地文档称 6.7 起是内置模块；本项目里的 Burst 2.0.0 与 Collections 6.7.0 都只是转发壳包。
- 写代码时仍然用 `Unity.Jobs`、`Unity.Burst`、`Unity.Collections`、`Unity.Mathematics` 这些命名空间，不受包形态变化影响。差别主要在查哪份文档。
- 本项目没有 `asmdef`，脚本都在默认程序集，上述命名空间可以直接 `using`。

## 版本演进

下表把已核实的事实与未核实的部分分开写。

| 时间或版本 | 事实 | 来源与状态 |
| --- | --- | --- |
| Unity 2018 | C# Job System 随 2018 系列引入，Burst 与 Mathematics 以预览包形式出现 | 常识性说法，具体小版本（待核实） |
| Unity 6000.x（Unity 6） | Burst 1.8.x 为主线，手册当前显示 1.8.31；Collections 2.x；Mathematics 1.3.x，手册显示 1.3.2 | Burst 与 Mathematics 手册页（已读） |
| Collections 2.6.2（2025-09） | 将 Burst 依赖更新到 1.8.23 | Collections 本地 CHANGELOG（已读） |
| Unity 6.4 | Collections 6.4.0（2025-10-16）条目为“Package is now a core package embedded in Unity.”，之后版本写明“从 6.4 起作为核心包随编辑器分发，更新日志不再维护” | Collections 本地 CHANGELOG（已读） |
| Unity 6.5 | Mathematics 成为内置模块，`Unity.Mathematics` 命名空间默认可用，API 文档并入核心 Scripting API | Mathematics 手册页的 Important 提示（已读） |
| Unity 6.7（Collections 6.7.0） | 本地 `Documentation~/index.md` 称：从 6.7 起 Collections 是编辑器与引擎的内置模块，无需单独添加包，文档迁到 Unity Manual | 本地文件（已读）。与 CHANGELOG 的“6.4 起为核心包”说法并存，两者关系（待核实） |
| Unity 7000.0.0a8（本项目） | `com.unity.burst` 版本 2.0.0，`package.json` 中 `"type": "shim"`；`com.unity.collections` 版本 6.7.0，描述为“已移入引擎模块，仅作转发” | 本地 `package.json`（已读） |

关于 Collections 的 6.4 与 6.7 两种说法，一种合理的读法是：6.4 起它以核心包形式随编辑器分发，之后再被进一步并入引擎模块。这只是推断，官方原文没有这样解释，因此标为（待核实）。对写代码的人来说结论一致：API 在 `Unity.Collections` 里。

## Burst 2.0.0 壳包到底转发了什么

本项目 `Library/PackageCache` 里的 `com.unity.burst` 只有 `package.json`、`Runtime/Unity.Burst.asmdef` 和 `Runtime/TypeForwarders.cs`。`TypeForwarders.cs` 用 `[assembly: TypeForwardedTo(...)]` 把类型转发到引擎内置实现，已确认的类型包括：

| 命名空间 | 转发的类型 |
| --- | --- |
| `Unity.Burst` | `BurstCompileAttribute`、`BurstCompiler`、`BurstCompilerOptions`、`BurstRuntime`、`FloatMode`、`FloatPrecision`、`OptimizeFor`、`NoAliasAttribute`、`SharedStatic<>`、`FunctionPointer<>`、`IFunctionPointer`、`BurstExecutionEnvironment` |
| `Unity.Burst.CompilerServices` | `Aliasing`、`AssumeRangeAttribute`、`Constant`、`Hint`、`IgnoreWarningAttribute`、`SkipLocalsInitAttribute` |
| `Unity.Burst.Intrinsics` | `v64`、`v128`、`v256`、`X86`、`Arm`、`Common` 以及 `v64x2` 等多值向量类型 |

这说明旧代码里用的 `[BurstCompile]`、`FloatMode`、`SharedStatic<T>` 等写法在 2.0.0 里依然成立。要判断某个 Burst API 是否存在，可以先对照这份列表。

注意：这里能确认的是“类型名存在并被转发”，不能据此判断行为与 Burst 1.8.x 完全相同。行为差异需要查 Unity Manual 的 Burst 页面。

## 四个组件是什么，如何依赖

| 组件 | 命名空间 | 作用 | 依赖 |
| --- | --- | --- | --- |
| Job System | `Unity.Jobs` | 定义 Job 接口（`IJob`、`IJobParallelFor` 等），调度到工作线程，用 `JobHandle` 表达依赖 | 引擎核心，不需要额外包 |
| Burst | `Unity.Burst` | 把标了 `[BurstCompile]` 的 Job 或静态方法从 IL 编译为本机代码（基于 LLVM） | 单独能用于静态方法；与 Job 搭配最常见 |
| Collections | `Unity.Collections` | `NativeArray<T>`、`NativeList<T>`、`NativeParallelHashMap` 等容器，分配器，`[ReadOnly]` 等属性 | `NativeArray<T>` 本身属于引擎核心，其余容器来自 Collections |
| Mathematics | `Unity.Mathematics` | `float3`、`int3`、`math` 静态函数，`Random`，为 Burst 向量化设计 | 无；6.5 起内置 |

依赖方向大致是：Job 里放 Native 容器和数学类型，Burst 编译这个 Job。去掉 Burst，Job 仍然能跑，只是在 Mono 或 IL2CPP 下按普通 C# 执行，速度差距往往很大；去掉 Job，Burst 也能编译静态方法，但失去多线程。

Burst 官方手册把 Burst 描述为：对 C# 子集（High-Performance C#，HPC#）使用 LLVM 将 IL 翻译成面向目标 CPU 优化的本机代码，最初为 Job System 设计，也能编译静态方法。

## 只用 Job + Burst，不用 ECS/DOTS 的含义

- Job System、Burst、Collections、Mathematics 都是独立库，不要求使用 Entities。ECS 是建立在它们之上的另一层，负责实体、组件、系统的组织方式。
- 本项目不使用 Entities，所以数据仍然放在自己定义的类和 `NativeArray` 里，调度由自己的管线（目前是 `ChunkGenerationPipeline`）管理。
- 不用 ECS 意味着：没有自动的系统依赖管理，`JobHandle` 依赖链要自己维护；没有 `EntityCommandBuffer`，主线程与 Job 之间的数据交接要自己设计。
- 好处是概念更少，现有 `MonoBehaviour` 代码可以逐步迁移。

## 如何确认项目里这些 API 可用

1. 命名空间检查：脚本顶部能写出下列 `using` 且无编译错误。

   ```csharp
   using Unity.Jobs;          // IJob, IJobParallelFor, JobHandle
   using Unity.Burst;         // BurstCompile, FloatMode
   using Unity.Collections;   // NativeArray<T>, Allocator, ReadOnly
   using Unity.Mathematics;   // float3, math
   ```

2. 本项目现状：`Assets` 下没有 `asmdef` 文件，所有脚本编译进默认程序集，因此上述命名空间不需要手动引用。已有的 `VoxelFaceVisibilityJob.cs` 使用了 `Unity.Burst`、`Unity.Collections`、`Unity.Jobs`。
3. 若以后拆分 `asmdef`：需要在 `References` 里添加相应程序集。`Unity.Burst` 的壳包自带 `Unity.Burst.asmdef`（已确认存在，且 `allowUnsafeCode` 为 true）。`Unity.Collections`、`Unity.Mathematics` 在 7000 alpha 中的程序集名称与是否仍需显式引用（待核实），遇到找不到类型时先在 Inspector 里查看 asmdef 引用列表。
4. Mathematics 在 7000.0.0a8 中是否内置：官方手册说明 6.5 起内置，7000 系列沿用这一方向，但 `Packages/manifest.json` 与 `PackageCache` 中本项目没有 `com.unity.mathematics` 包目录，可见项目并未单独安装它。实际能否编译需在 Editor 中验证（待核实）。
5. 若使用 `unsafe` 代码，需在 Player Settings 打开 Allow unsafe code，或在 `asmdef` 里设 `allowUnsafeCode`。

本项目 `Packages/manifest.json` 里没有直接列出 `com.unity.burst` 与 `com.unity.collections`，它们在 `PackageCache` 中出现，应当是其它包（例如渲染管线）依赖带入的。依赖来源（待核实）。

## 如何查文档

- Job System：Unity Manual 的 “Write multithreaded code with the job system” 及子页面（Job system overview、Create a job、Job dependencies、Parallel jobs、Thread safe types）。
- Collections：Unity Manual 的 Collections 章节。本地 Collections 壳包的 `Documentation~/index.md` 指向 `Manual/collections/collections.html`，但该地址在线上公开手册中目前返回 404（审稿时测试），多半只在 6.7 及以后的手册中存在；较低版本请用 Collections 包手册，如 `Packages/com.unity.collections@2.5/manual/index.html`。
- Burst：1.8 的包手册 `Packages/com.unity.burst@1.8/manual/index.html` 内容最全；新版本的 Burst 文档在 Unity Manual 的 `burst/` 路径下（Mathematics 页面中有指向 `burst/script-compilation-burst.html` 的链接）。
- Mathematics：6.5 之前看包手册 1.3；6.5 起看 Scripting API 中的 `Unity.Mathematics.math` 与 Manual 的 “Unity Mathematics APIs”。
- 版本匹配：先确认当前项目的 Unity 版本，再在文档页右上角切换到对应版本；找不到页面时，说明该页面在那个版本不存在。

## 常见坑

- 按旧教程在 Package Manager 里找 Collections 或 Mathematics 并尝试安装，在新版本中可能已不需要或不可见。
- 查到 1.8 文档里的 API，就以为在 Burst 2.0.0 壳包里一定有同样行为。类型名可以对照 `TypeForwarders.cs`，行为以新版文档为准。
- 把“不用 ECS”理解成“不能用 Job”。两者没有必然关系。

## 小结

- 四个组件分工：Job 调度，Burst 编译，Collections 提供容器，Mathematics 提供数学类型。
- 版本线：Job System 自 2018 起；Burst 1.8.x 与 Collections 2.x 是 Unity 6 主线；Collections 6.4 起为核心包；Mathematics 6.5 起内置；本项目 7000.0.0a8 的 Burst 2.0.0 与 Collections 6.7.0 是壳包。
- 本项目无 `asmdef`，命名空间直接可用。

## 自测题

1. Burst 2.0.0 壳包里，如何确认某个类型（例如 `SharedStatic<>`）仍然存在？
   答：读 `TypeForwarders.cs`，其中有对应的 `TypeForwardedTo` 条目。
2. 只用 Job + Burst 而不用 ECS，需要自己负责什么？
   答：自己管理数据布局、`JobHandle` 依赖链、主线程与 Job 之间的数据交接。
3. 本项目为什么不需要在 `asmdef` 里引用 `Unity.Collections`？
   答：`Assets` 下没有 `asmdef`，脚本编译进默认程序集，自动引用可用的引擎与包程序集。
4. Mathematics 与 Collections 的“内置”分别从哪个版本起？
   答：Mathematics 官方手册说明 6.5 起内置；Collections 的 CHANGELOG 称 6.4 起为核心包，本地文档称 6.7 起为内置模块，二者关系（待核实）。
