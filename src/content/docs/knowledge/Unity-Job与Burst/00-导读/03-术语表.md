> 适用版本：以 Unity 6000.x 的 Burst 1.8.x / Collections 2.x / Mathematics 1.3.x 为主线；Unity 6.4 起 Collections 作为核心包随编辑器分发；本项目的 Unity 7000.0.0a8 中 Burst 2.0.0 与 Collections 6.7.0 是转发（shim）到引擎内置模块的壳包，API 仍在 `Unity.Burst` / `Unity.Collections` 命名空间，文档迁到了 Unity Manual。

## 要点

- 本页按主题分为五组：内存与类型、Job、Burst、ECS 与 DOTS、其它。遇到不熟的词来这里查，再回到对应章节深入。
- 每条只给一句话定义，细节、代码与坑见各章。
- 带“（待核实）”的条目表示具体行为或默认值在写作时未能从官方来源确认。

## 内存与类型

| 术语 | 定义 |
| --- | --- |
| 托管（managed） | 由 .NET/Mono 运行时管理内存、由 GC 回收的对象与类型，例如 class、`List<T>`、string。 |
| 非托管（unmanaged） | 不含托管引用、不受 GC 管理的类型，C# 中 `unmanaged` 约束即指这类类型。 |
| blittable | 托管与本机内存中布局相同、可直接按字节拷贝的类型，如 `int`、`float`、只含它们的 struct。 |
| HPC# | High-Performance C#，Burst 可编译的 C# 子集，不允许托管对象、异常处理等。 |
| NativeContainer | 在托管堆之外分配内存、可在 Job 中使用的容器，如 `NativeArray<T>`、`NativeList<T>`。 |
| `NativeArray<T>` | 固定长度的原生数组，是最基础的 NativeContainer。 |
| `NativeList<T>` | 可增长的原生列表，来自 Collections。 |
| `NativeParallelHashMap` | 可在 Job 中使用的原生哈希表，提供 `ParallelWriter` 并行写入（具体 API 见 Native 容器一章）。 |
| Allocator | 决定原生内存生命周期与分配方式的枚举，如 `Allocator.Temp`、`Allocator.TempJob`、`Allocator.Persistent`。 |
| `Allocator.Temp` | 最快的短期分配，只在分配它的线程与作用域内安全，帧末（或 Job 结束时）整体丢弃；主线程上分配的 Temp 内存不能传给 Job。 |
| `Allocator.TempJob` | 可传给 Job 的短期分配，必须在创建后 4 帧内释放；Native 容器超期会抛异常。 |
| `Allocator.Persistent` | 生命周期不限、必须手动 `Dispose` 的分配，分配开销相对更高。 |
| 自定义 NativeContainer | 自己写的、标 `[NativeContainer]` 且含名为 `m_Safety` 的 `AtomicSafetyHandle` 字段的容器结构，要做使用跟踪与泄漏跟踪两件事，详见 1.11。 |
| `MallocTracked` / `FreeTracked` | `UnsafeUtility` 的带泄漏跟踪的分配与释放；自定义容器用它们分配数据内存，泄漏跟踪自动生效（较早版本用 `DisposeSentinel`）。 |
| 别名集合（alias） | 不自己分配、而是整体或部分共享另一个集合分配的集合；对别名 `Dispose` 无效果，原件释放后别名不能再用；与 Burst 的指针别名（aliasing）不是同一个概念，见 1.5。 |
| `Reinterpret<T, U>()` | 把 `NativeArray<T>` 按另一种元素类型 `U` 重新解释的别名（如 `int` 重解释为 `short`，长度翻倍），两个类型都要 `unmanaged`，见 1.5。 |
| `RewindableAllocator` | 类似线性分配器的自定义分配器，快且线程安全；单个 `Free` 默认是空操作（开启 enable block free 后按块回收），整体用 `Rewind()` 一次性释放，见 1.5。 |
| 视图（view） | 不拷贝也不持有数据、直接别名容器数据的访问对象，如枚举器和 `NativeList<T>.AsArray()`；容器 `Dispose` 或大小变化后失效，见 1.4、1.6。 |
| `Dispose` | 释放原生容器内存的方法；NativeContainer 不会被 GC 自动回收。 |
| Leak Detection | 泄漏检测，Editor 中追踪未 `Dispose` 的 NativeContainer 并报告警告。 |
| 值类型（value type） | struct 等按值拷贝的类型，Job 的数据必须放在值类型里。 |
| unsafe 代码 | 使用指针的 C# 代码，需要开启 allow unsafe code 才能编译。 |

## Job

| 术语 | 定义 |
| --- | --- |
| Job | 实现 `IJob` 等接口的 struct，包含数据与 `Execute` 方法，是调度的最小单元。 |
| `IJob` | 单个任务，`Execute()` 只执行一次。 |
| `IJobParallelFor` | 把 N 个索引的工作拆成多批并行执行，`Execute(int index)` 对每个索引调用一次。 |
| `JobHandle` | 调度一个 Job 后返回的句柄，用来等待完成或作为其它 Job 的依赖。 |
| 依赖（dependency） | 一个 Job 必须在另一个 Job 完成后才能开始的约束，通过 `Schedule(dependsOn)` 表达。 |
| `Schedule` | 把 Job 放入队列，由工作线程异步执行。 |
| `Run` | 在调用线程上立即同步执行 Job（可配合 Burst）。 |
| `Complete` | 阻塞当前线程直到对应的 Job 完成，并使安全系统释放该 Job 对容器的占用。 |
| `CombineDependencies` | 把多个 `JobHandle` 合并为一个，等所有都完成才算完成。 |
| 工作线程（worker thread） | Unity 的 Job 线程池中的线程，负责执行已调度的 Job。 |
| work stealing | 空闲线程从其它线程的队列里“偷”任务以保持负载均衡的机制。 |
| batch（批） | `IJobParallelFor` 中一组连续索引，是分给一个线程一次处理的最小单位。 |
| `innerloopBatchCount` | 调度并行 Job 时指定的批大小，影响调度开销与负载均衡。 |
| Safety System（安全系统） | 在 Editor 中检测 Job 对 NativeContainer 的非法并发访问并抛出异常的机制。 |
| `AtomicSafetyHandle` | 安全系统使用的句柄，每个 NativeContainer 持有一个，用于检查读写权限；拷贝容器时每份句柄指向同一条中心记录，各带自己的标志。 |
| 版本号（`AtomicSafetyHandle` 版本号机制） | 中心记录上的主版本号在容器 `Release()` 时加一，使所有拷贝同时失效；另有可独立递增的次级版本号，用来让视图在扩容或调度写 Job 后失效，见 1.6。 |
| `ParallelWriter` / `ParallelReader` | 容器的嵌套类型，用于在并行 Job 里写或读；并发安全，但读写顺序不确定，确定性手段见 1.7（`ParallelReader` 的具体类型待核实）。 |
| `JobProducerTypeAttribute` | 标在 Job 接口上，指明包含静态 `Execute` 方法的 producer 类型，Burst 靠它编译 `Execute`，自定义 Job 类型才用得到，见 1.11。 |
| NativeContainer 自定义特性 | 自定义容器声明能力的属性：`[NativeContainer]`、`[NativeContainerSupportsMinMaxWriteRestriction]`、`[NativeContainerIsReadOnly]`、`[NativeContainerIsAtomicWriteOnly]`、`[NativeContainerSupportsDeferredConvertListToArray]`、`[NativeContainerSupportsDeallocateOnJobCompletion]`、`[NativeSetClassTypeToNullOnSchedule]`，各自要求见 1.11。 |
| 竞争条件（race condition） | 多线程无同步地读写同一数据，结果依赖执行顺序的错误。 |
| `[ReadOnly]` / `[WriteOnly]` | 声明 Job 字段只读或只写，让安全系统允许多个 Job 并发读取。 |
| `[NativeDisableParallelForRestriction]` | 关闭并行 Job 对容器索引范围的限制，需要自己保证不同索引不冲突。 |

## Burst

| 术语 | 定义 |
| --- | --- |
| Burst | Unity 的编译器，把 HPC# 的 IL 通过 LLVM 编译为针对目标 CPU 优化的本机代码。 |
| LLVM | Burst 使用的编译器基础设施，负责优化与生成机器码。 |
| IL | Intermediate Language，C# 编译后的中间语言，是 Burst 的输入。 |
| JIT | Just-In-Time，运行时编译；Editor 中 Burst 在需要时即时编译 Job。 |
| AOT | Ahead-Of-Time，构建时预先编译；发布构建中 Burst 以此方式生成本机库。 |
| `[BurstCompile]` | 标记 Job 或静态方法（及其所在类型）交给 Burst 编译的属性。 |
| 向量化（vectorization） | 把对多个数据的标量操作合并为一条 SIMD 指令的优化。 |
| SIMD | Single Instruction Multiple Data，一条指令同时处理多个数据元素。 |
| SSE / AVX / NEON | 具体的 SIMD 指令集：SSE 与 AVX 属于 x86，NEON 属于 ARM。 |
| 别名（aliasing） | 两个指针或引用指向同一块内存；编译器无法排除别名时会限制向量化与重排。 |
| `[NoAlias]` | 向 Burst 保证某个参数或字段不与其它指针重叠，帮助优化。 |
| `FloatMode` | `Unity.Burst.FloatMode`，控制 Burst 浮点优化的宽松程度，如 `Default`、`Strict`、`Deterministic`、`Fast`。 |
| `FloatPrecision` | `Unity.Burst.FloatPrecision`，控制数学函数的精度级别，如 `Standard`、`High`、`Medium`、`Low`。 |
| intrinsics | 直接映射到某个 CPU 指令的函数，Burst 通过 `Unity.Burst.Intrinsics` 提供（如 `X86`、`Arm`）。 |
| `Unity.Burst.Intrinsics.Common` | 各个硬件目标共享的内部函数，不需要 `IsXXXSupported` 保护：`Pause()`、`umul128` 为正式，`Prefetch`、`InterlockedAnd` / `InterlockedOr` 为实验性，见 2.4。 |
| Burst Inspector | Editor 窗口，用来查看 Burst 编译结果的汇编、IR 与优化信息。 |
| 程序集级 `BurstCompile` | `[assembly: BurstCompile(...)]`，为整个程序集的 Job 与函数指针设默认选项；优先级低于编辑器菜单设置与 Job 上的特性，见 2.10。 |
| `BurstRuntime.LoadAdditionalLibrary` | 运行时加载额外 Burst 编译库的方法（Modding 支持），见 2.11。 |
| `RigidTransform` | `Unity.Mathematics` 中只含旋转（`rot`）与平移（`pos`）的刚体变换结构体，不含缩放，见 2.3。 |
| `MinMaxAABB` | `Unity.Mathematics.Geometry` 中以最小点和最大点存储的轴对齐包围盒，见 2.3。 |
| 函数指针（function pointer） | `FunctionPointer<T>`，让 Burst 编译的函数可被间接调用，有调用开销且不能内联。 |
| `SharedStatic<T>` | 在 Burst 与托管代码之间共享的静态数据容器，用于绕开 Burst 对普通 static 字段的限制。 |
| `SkipLocalsInit` | 属性，让编译器不对局部变量自动清零，减少开销，但读取未赋值内容是危险的。 |
| `Hint` | `Unity.Burst.CompilerServices.Hint`，提供 `Likely`、`Unlikely`、`Assume` 等给编译器的提示。 |
| 单态化（monomorphization） | 泛型在编译期为每个具体类型生成专用代码，使调用可内联。 |
| `Unity.Mathematics` | Burst 友好的数学库，类型如 `float3`、`int3`，函数集中在 `math` 静态类。 |
| `math.hash` / 哈希噪声 | 用整数哈希把格点坐标映射到伪随机值的噪声实现方式；`Unity.Mathematics` 的 `math` 静态类里确有 `math.hash`，用法与签名见 2.3 Unity.Mathematics。 |

## ECS 与 DOTS

定义依据 Entities 1.4 官方手册，详见 0.4 ECS 与 DOTS 概览。本项目未引用 Entities，这些词条仅供阅读时对照。

| 术语 | 定义 |
| --- | --- |
| DOTS | Data-Oriented Technology Stack，Unity 的数据导向技术栈。手册称使用它需要 Entities、Job system、Burst、Collections、Mathematics 五个主要部分。 |
| ECS | Entity Component System，实体组件系统架构；Entities 包是它的实现。 |
| Entities | `com.unity.entities` 包，ECS 模式的实现；手册说通常不单独使用，一般配合 Entities Graphics、Unity Physics 和/或 Netcode for Entities。 |
| Entity（实体） | 唯一标识，类似轻量的非托管 GameObject，本身不含代码，也不是组件的容器。 |
| Component（组件） | 存放实体数据的类型，非托管组件用 `IComponentData` 标记；另有托管、共享、清理、标签、缓冲、chunk、可启用、单例等种类。 |
| System（系统） | 读写组件数据的逻辑，在主线程每帧执行 `OnUpdate`，可调度 Job。 |
| `ISystem` / `SystemBase` | 两种系统写法：`ISystem` 是 struct、非托管，可对生命周期方法做 Burst 编译；`SystemBase` 是 class、托管，可存托管数据。手册建议一般优先用 `ISystem`。 |
| World（世界） | 实体的集合，带 `EntityManager` 和一组系统；实体 ID 只在所属世界内唯一。 |
| Archetype（原型） | 同一世界里组件类型组合完全相同的实体的标识，决定组件在内存中的组织方式。 |
| chunk（ECS 内存块） | 存放同一原型实体的 16 KiB 内存块，每种组件类型一个数组，另有实体 ID 数组；与本项目的 `VoxelChunk` 区块无关。 |
| Structural change（结构性变更） | 重组 chunk 的操作：创建或销毁实体、增删组件、设置共享组件值；只能在主线程做，是同步点的主要来源。 |
| sync point（同步点） | 主线程等待此前所有已调度 Job 完成的位置，会让工作线程闲置。 |
| `EntityQuery` | 找出含指定组件类型集合的原型，并收集其 chunk 供系统处理。 |
| `EntityCommandBuffer` | 线程安全的命令队列，可在 Job 里记录结构性变更，之后在主线程回放。 |
| `IJobEntity` / `IJobChunk` | Entities 里调度 Job 的两种方式：前者便于按实体写 `Execute`，后者手动按 chunk 处理。 |
| Baking（烘焙） | 在 Editor 里把 GameObject 编辑数据转换成实体场景中的实体与组件，不会在游戏运行时发生。 |
| Subscene（子场景） | 对作者场景或实体场景的引用，是方便加载实体场景的挂接点。 |
| Entities Graphics | 用可编程渲染管线（SRP）渲染实体的 ECS 包。 |

## 其它

| 术语 | 定义 |
| --- | --- |
| Domain Reload | Editor 中脚本重新编译或进入 Play 模式时重载程序域，会重置静态变量。 |
| Profiler | Unity 的性能分析工具，Timeline 视图可以看每个线程上的 Job 执行与等待。 |
| 主线程（main thread） | 运行 Unity 脚本与大多数 Unity API 的线程；多数 `UnityEngine.Object` API 只能在这里调用。 |
| 缓存行（cache line） | CPU 缓存与内存之间传输的最小单位，常见为 64 字节。 |
| false sharing（伪共享） | 不同线程写同一缓存行中的不同变量，导致缓存行在核心间反复失效，拖慢速度。 |
| AoS / SoA | 结构体数组与数组的结构，两种数据布局，SoA 更适合向量化。 |
| GC | Garbage Collection，垃圾回收；托管分配过多会造成卡顿。 |
| `Task.Run` | .NET 的线程池任务调用；本项目 `ChunkGenerationPipeline` 当前使用，可用 Job 替代。 |
| `MeshData` | `Mesh.MeshData`，通过 `Mesh.AllocateWritableMeshData` 取得，让 Job 直接写入网格数据。 |
| Amdahl 定律 | 并行加速比受串行部分占比限制的规律。 |
| 背压（backpressure） | 下游处理跟不上时限制上游继续产生数据的机制，如 `ChunkGenerationPipeline` 的 `maxLoadedChunks`。 |
| shim（壳包） | 只保留包名与版本、把类型转发到引擎内置实现的包，如本项目的 `com.unity.burst` 2.0.0。 |
| 类型转发（type forwarding） | 通过 `TypeForwardedTo` 让旧程序集中的类型指向新程序集中的实现。 |

## 小结

- 内存类术语决定“什么能放进 Job”：非托管、blittable 的值类型与 NativeContainer。
- Job 类术语决定“怎么调度”：`Schedule`、`JobHandle`、依赖、批大小。
- Burst 类术语决定“怎么编译得快”：HPC#、向量化、别名、浮点模式。

## 自测题

1. `Schedule`、`Run`、`Complete` 的区别是什么？
   答：`Schedule` 异步入队；`Run` 在当前线程同步执行；`Complete` 阻塞等待已调度的 Job 完成。
2. 为什么 NativeContainer 必须手动 `Dispose`？
   答：它的内存在托管堆之外，GC 不会回收。
3. `[NoAlias]` 解决什么问题？
   答：告诉编译器指针不重叠，使其可以安全地向量化与重排访存。
4. SSE、AVX、NEON 分别属于哪类 CPU？
   答：SSE 与 AVX 属于 x86，NEON 属于 ARM。
5. 什么是壳包（shim）？
   答：只做转发的包，类型实现在引擎内部，包里只留类型转发声明。
