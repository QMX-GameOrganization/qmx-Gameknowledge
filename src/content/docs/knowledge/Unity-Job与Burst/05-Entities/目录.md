> 适用版本：本项目 `Packages/manifest.json` 声明 `com.unity.entities` 与 `com.unity.entities.graphics` 为 `1.5.0`；Unity `7000.0.0a8` 的本地 PackageCache 显示 Entities `6.7.0` 内置实现。本文优先使用 Entities 1.x 的稳定概念，版本差异会单独标注。

## 这部分解决什么问题

Job/Burst 解决“如何高效执行一段数据处理”；Entities 解决“游戏里的大量数据如何组织、查询、转换和调度”。两者结合后，系统可以直接遍历 ECS chunk 中的组件数据，再把遍历交给 Job 和 Burst。

```text
00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08
```

先理解数据如何进入 Entity World，再学习系统如何查询和修改，最后才把工厂逻辑迁移进 ECS。不要从 `IJobEntity` 代码倒推整个 ECS。

## 先把各部分串起来

第一次学习时，读完 00.1 后先读 [00.2 完整链路与最小示例](/qmx-Gameknowledge/knowledge/unity-job与burst/05-entities/00-导读/02-从场景到运行时ecs的完整链路/)，再按章节展开。

```text
默认启动流程 → World → 系统组 → 系统生命周期
                               ↓ 查询和处理
Authoring → Baker → 加载实体场景 → Entity + 组件 → 可选 Job → 后续系统 / 表现
运行时初始化 / 输入 → EntityManager 或 ECB ────↑
```

GameObject 上挂 Authoring 和表现脚本；World 中保存 Entity、ECS 组件和系统。系统不需要挂到场景对象上，组件类型定义也不会自动创建数据实例。

各章短代码可能省略业务类型和上下文，用于说明机制；00.2 提供同一套完整类型、两个可选入口和观察步骤，避免靠拼接不同章节的片段运行。
