## Entities 与 Job/Burst 的关系

```text
Entities：组织实体、组件、系统和世界
Job：把批量工作分发到线程
Burst：把受限 C# 编译成本机代码
Collections：提供 Job 可用的非托管容器
Mathematics：提供 Burst 友好的数学类型
```

Entities 不等于“自动多线程”。一个 `SystemAPI.Query` 的 `foreach` 可以在主线程执行；只有显式调度 `IJobEntity`、`IJobChunk` 或其它 Job，才会离开主线程。

## 本项目的版本记录

```text
Unity Editor：7000.0.0a8
manifest：com.unity.entities 1.5.0
manifest：com.unity.entities.graphics 1.5.0
本地 PackageCache：com.unity.entities 6.7.0（Unity 7 内置实现）
```

包版本字段和本地内置实现不同，是 Unity 7 alpha 的版本形态。学习时以当前 Editor 能编译的 API 为准；不要只看网上针对 Entities 0.x 或旧 DOTS Preview 的代码。

## 先掌握的 Job/Burst 内容

- `NativeArray`、`DynamicBuffer` 和生命周期。
- `JobHandle` 依赖与 `Complete`。
- `[ReadOnly]`、并行写入和竞争条件。
- Burst 支持的 HPC# 子集。

Entities 会自动推导部分组件依赖，但不会替你管理通过普通 `NativeArray` 传递的数据，也不会解决错误的并行写入。

## 这一部分的学习产物

读完后应该能回答：

1. Entity 为什么没有自己的行为代码？
2. 相同组件组合为什么会进入同一个 Archetype？
3. 为什么增删组件会产生结构性变更？
4. Baker 生成的运行时数据为什么不等于 Authoring MonoBehaviour？
5. 什么时候用 `SystemAPI.Query`，什么时候用 `IJobEntity`？

## 带着一条运行链学习

接着读 [00.2 完整链路与最小示例](/qmx-Gameknowledge/knowledge/unity-job与burst/05-entities/00-导读/02-从场景到运行时ecs的完整链路/)。每章都围绕同一组问题定位：

1. 数据入口：谁创建 Entity 和组件，是 Baking 后加载，还是运行时创建？
2. 运行环境：数据和系统是不是同一 World？
3. 执行入口：谁把系统放入组，组是否被 PlayerLoop 调度？
4. 更新条件：系统被禁用了吗，RequireForUpdate 满足了吗，查询匹配了吗？
5. 结果可见性：字段已写入还是仅记录了 ECB，Job 是否完成，表现层是否读取了结果？

理解 Job/Burst 有助于后续优化，但不必先并行化才能练习 ECS。第一轮先跑通主线程数据链和调试观察，再补依赖和 Burst。
