## 先按四条线复述专题

**规则线：** 数据结构能存数据，但不会自动保证业务合法。公开操作维护不变量，调用方因此少承担细节。

**变化线：** 行为差异明显时可建立稳定接口；参数差异用配置；特性组合优先分析组合关系，不把每个维度扩成继承树。

**寿命线：** 所有者、借用者、对象存储、引用有效期必须分清。C++ 的值复制与 C# 的类引用赋值不可混用。

**取舍线：** 虚调用、对象分散、配置复杂度和测试成本都是真实代价；不凭架构名字宣布更快或更高级。

## 常见坑速查表

| 现象 | 核心原因 | 检查与修复方向 |
| --- | --- | --- |
| 生命值有时变成负数 | 写入点绕过统一规则，或算术先溢出 | 收拢修改入口，先比较再做有界运算 |
| 以为重写，实际没调用 | 签名不匹配，尤其漏 const | 使用 override，区分静态与动态类型 |
| 派生对象放进容器后“变回基类” | 按值发生对象切片 | 多态借用或明确的多态所有权 |
| 析构不符合预期 | 基类删除缺少正确虚析构等 | 按删除方式设计析构契约，不运行 UB 猜结果 |
| 添加析构后不能移动 | 特殊成员生成规则改变 | 审视 Rule of Zero/Five，显式声明需要的语义 |
| 扩容后旧指针失效 | vector 元素存储变化 | 不跨失效点保存地址，或采用适合的拥有布局 |
| shared_ptr 全放手却仍泄漏 | 环形共享所有权 | 唯一所有者或 weak_ptr 观察边 |
| 移动后继续使用原资源 | 误解源对象状态或转移责任 | 遵守该类型的移动后契约 |
| new 子类被强转后崩溃 | 实际类型不匹配 | 契约设计优先，必要时检查 dynamic_cast |
| C# 复制后两个角色一起变 | 类赋值只复制引用 | 明确定义独立复制，或承认别名共享 |
| using 退出仍有对象引用 | 误把 Dispose 当 GC | 分开资源释放与托管内存可达性 |
| Unity 对象池复用出现旧状态 | 生命周期不等于一次业务使用 | 明确重置、解绑、目标有效性检查 |

## 先作答，再展开答案

<details>
<summary>1. 只要把字段设为 private，再补全部 getter/setter，就一定封装良好吗？</summary>

不一定。如果 setter 允许任何值或 getter 返回内部可写引用，外部仍可破坏规则。封装的判断依据是不变量是否由稳定边界维护。
</details>

<details>
<summary>2. 为什么治疗和攻击可以实现同一接口，但护甲不该继承角色？</summary>

治疗和攻击都能遵守“对目标施放”的契约；护甲与角色是组成关系，不能作为一个完整角色替换进去。继承需要可替换性，不能只为了拿到字段。
</details>

<details>
<summary>3. const Skill& 调用了派生实现，说明引用复制了派生对象吗？</summary>

没有。引用借用原对象，虚调用按动态类型选择行为。它不拥有对象，也不延长任意被引用对象的寿命。
</details>

<details>
<summary>4. C++ 类里有一个 vector，就必须手写析构吗？</summary>

通常不需要。vector 自己管理资源，生成的析构会销毁成员；优先遵守 Rule of Zero。手写析构反而可能改变隐式移动操作生成。
</details>

<details>
<summary>5. 添加治疗技能只改注册代码，算不算违反开闭原则？</summary>

不算。组装处的职责就是选择具体实现。目标是让稳定战斗流程不依赖每种具体技能，而不是新增功能完全不改任何代码。
</details>

<details>
<summary>6. C# 的 struct 含 List，复制后列表一定独立吗？</summary>

不一定。复制结构体字段，其中 List 字段是引用，两个副本共享同一个列表对象；替换一个副本中的引用则只改变该字段。
</details>

## 一次语法预备课 + 六次串讲建议

| 次数 | 讲授主线 | 课堂动手 | 完成标志 |
| --- | --- | --- | --- |
| 预备课 | 第 0 章：namespace、struct、class、enum | 创建两个计数器，用作用域限定名字 | 能区分类型、对象和命名空间 |
| 1 | 第 1～2 章：为什么需要对象边界 | 给受伤和治疗加入合法范围 | 能解释为什么不是机械 setter |
| 2 | 第 3～4 章：生命周期与所有权 | 预测析构日志、转移 unique_ptr | 能画拥有与借用图 |
| 3 | 第 5～6 章：组合与多态 | 替换技能实现，保持流程不变 | 能区分组合关系和可替换关系 |
| 4 | 第 7 章：逐个排坑 | 解释切片与默认参数输出 | 能区分编译错误与未定义行为 |
| 5 | 第 8～9 章：用变更验证设计 | 完成重击与完整治疗任务 | 能指出合理修改范围和成本 |
| 6 | 第 10～11 章：C# 对照与复盘 | 运行同规则例子，比较赋值 | 能解释 GC、Dispose 与 RAII 的边界 |

每次可按“10 分钟回顾 → 25 分钟图解 → 20 分钟预测并编码 → 15 分钟讨论需求变更”安排；根据学员指针与异常基础调整，不强行在一次课中堆完所有概念。

## 综合作业：带护盾的目标

要求增加护盾：先扣护盾，再按现有护甲规则处理剩余伤害；治疗只恢复生命值。先写清楚这个顺序，不能把“护甲优先”当成默认。决定护盾属于角色内部状态还是独立组件，并解释原因。

交付：一张对象关系图、公开接口说明、所有权表、可运行代码和边界结果。至少验证无护盾、护盾恰好抵消、部分穿透、零伤害、极大输入、生命值归零与满血治疗。若更改返回值来同时报告护盾吸收和生命损失，应说明日志与调用方如何迁移。

评价时看规则是否集中、状态是否合法、寿命是否清楚、新功能是否迫使无关模块改变，不按类数量或设计模式名称评分。
