## 把学习结果分成四项

**能写：** 从空文件定义类、成员、构造、static、派生类和虚接口，不依赖照抄完整例子。

**能解释：** 说清 public/private/protected、实例/static、初始化/赋值、复制/借用、重载/重写/隐藏的区别。

**能排错：** 区分编译错误、链接错误、未定义行为、业务规则错误；修复原因而不是碰运气改到能运行。

**能选择：** 新需求只改参数还是需要新行为？应组合还是继承？一个字段为何私有？一个接口为何接收引用？用实际影响范围说明理由。

## 分阶段作业与验收

| 学习阶段 | 动手任务 | 观察结果与验收 |
| --- | --- | --- |
| 第 0～2 章 | 用命名空间组织角色，创建两个独立对象 | 修改一个对象不会改变另一个；能区分类型与对象 |
| 第 3～5 章 | 生命值私有，提供查询、受伤、治疗 | 外部直接写入报编译错；边界输入结果符合规则 |
| 第 6～7 章 | 创建不同初始生命值，观察资源日志 | 无效初值失败，正常/异常退出按规则清理 |
| 第 8 章 | 实现累计创建数，再实现存活数 | 离开内层作用域后两种统计不同；解释 static 的位置 |
| 第 9～10 章 | 复制背包值、转移独占对象、输出坐标 | 解释谁拥有资源；移动后按类型契约使用源对象 |
| 第 11～12 章 | 扩展精英角色，改变继承方式并预测诊断 | 对照访问表，观察完整构造析构顺序 |
| 第 13～15 章 | 不同技能统一调用，故意制造签名错误与切片 | override 能诊断错误；引用保留多态，值切片不保留 |
| 第 16～18 章 | 新增技能和护盾需求 | 修改范围合理，生命周期清楚，边界有实际验证 |

不要把阶段强行压成“一次课讲所有关键字”。每次按需求、图解、编码、预测输出和变更讨论安排，根据学员实际掌握情况决定是否进入下一阶段。

## 排坑速查

| 现象 | 重点检查 | 修复方向 |
| --- | --- | --- |
| 成员明明写了，外部却不能用 | class 默认 private；继承方式是否漏写 | 明确成员访问和继承访问两个位置 |
| setter 运行后值没变 | 参数遮蔽，出现 value=value | 用 this 或清楚的成员命名 |
| 只读对象调用查询失败 | 后置 const 是否缺失 | 保持声明和定义一致 |
| 构造时读出奇怪值 | 成员声明顺序与依赖关系 | 先初始化被依赖成员 |
| 静态成员链接失败 | 只有声明，无所需定义 | 单一定义或 C++17 inline static |
| 每个源文件有一份计数 | 头文件命名空间 static 的内部链接 | 区分类静态成员与文件作用域 static |
| 存活计数不准确 | 复制/移动、构造失败、析构未处理 | 先明确统计契约，再设计特殊成员 |
| 以为重写却没生效 | 签名、const、静态/动态类型 | 写 override，分开名字查找与分派 |
| 派生对象进容器后像基类 | 按值切片 | 借用或明确的多态所有权 |
| 通过基类删除不可靠 | 虚析构契约 | 对本专题删除方式提供公开虚析构 |
| 扩容后旧引用崩溃 | vector 元素搬移 | 遵守失效规则，重新设计长期引用 |
| shared_ptr 不释放 | 环形共享所有权 | 唯一所有者或 weak_ptr 观察边 |
| 移动后继续访问原资源 | 误解移动后状态 | 查看具体类型的契约 |
| clamp 仍没防住溢出 | 危险算术先执行 | 先比较，再做有界运算 |

## 先答，再展开

<details><summary>1. private 字段配任意 setter，是否一定封装良好？</summary>

不是。setter 仍可能允许非法值，返回内部可写引用也可绕过检查。要看不变量是否被维护。
</details>

<details><summary>2. static 成员函数能读取普通成员吗？</summary>

没有隐含 this，不能直接读取“当前对象”的字段；明确传入对象后，可以在权限允许时读取那个对象的成员。它不是绝对不能碰普通成员。
</details>

<details><summary>3. public 继承会使基类 private 成员公开吗？</summary>

不会。基类 private 仍由基类管理；派生对象包含对应基类状态，但派生代码不能直接访问它。
</details>

<details><summary>4. 基类有 virtual 函数，析构是否自动变成 virtual？</summary>

不是。析构需要独立设计；通过基类普通删除派生对象时，本专题使用公开虚析构。
</details>

<details><summary>5. const Skill& 引用派生对象，是否复制了它？</summary>

没有。它借用原对象，通过虚函数选择实际实现；不拥有对象，也不自动延长任意对象寿命。
</details>

<details><summary>6. 添加技能要改组装处，是否违反开闭原则？</summary>

不是。组装处的职责就是选择具体实现。目标是保护稳定流程，不是声称任何新功能都不改代码。
</details>

## 综合作业：带护盾的目标

新增规则：先扣护盾，再按已有护甲规则处理剩余伤害；治疗只恢复生命值。明确此顺序，不把护甲优先当默认。决定护盾是角色状态还是独立组件，解释拥有关系和公开操作。

交付对象关系图、接口说明、所有权表、可运行代码和边界结果。至少验证无护盾、恰好抵消、部分穿透、零伤害、极大输入、生命值归零与满血治疗。若返回值需要同时报告护盾吸收与生命损失，说明日志及调用方如何迁移。

评价规则是否集中、状态是否合法、语法是否正确、寿命是否清楚、修改范围是否合理，不按类数量或设计模式名字评分。
