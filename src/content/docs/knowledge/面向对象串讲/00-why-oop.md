## 从你已经能做的事开始

你已经会保存一组敌人、按编号查找物品、用队列管理任务。容器和算法帮助你组织、处理数据。现在想写一个小型战斗程序：角色有名字、生命值和护甲，技能能伤害或治疗角色。

最初几个变量、几个函数就可以工作，不需要为了“高级”先画一大张类图。随着需求增长，新的问题会自然出现。

## 一：相关数据怎样放在一起

分别用名字数组、生命值数组、护甲数组保存角色，就必须保证索引对应；删除其中一组的数据时漏删其他组，角色信息就会错位。

我们会学习**自定义类型和对象**：用一种类型描述角色，用一个对象表示具体角色。现在知道这个目的即可；后面会从 class 的第一行开始讲。

## 二：谁来保证生命值合法

攻击要算护甲，治疗不能超上限。若各处代码都直接写生命值，每个调用方都要记住全部规则，多一个入口就多一个漏检查的机会。

我们会学习**访问控制和封装**，明确外部能使用哪些操作，内部怎样保持合法状态。public/private 是语法工具；藏起字段还不够，公开操作也必须维护规则。

## 三：哪些数据每个角色独有，哪些需要共享

每个角色有独立的生命值，但“程序累计创建了多少个角色”是全体共享的统计。等到需要这个功能时，我们会学习 static，区分实例成员与共享成员，也区分它在其他位置的含义。

## 四：不同技能怎样交给同一个流程使用

如果战斗流程总是判断“斩击这样做，火球那样做”，每加一个行为就要改流程。我们希望流程只表达“依次施放”，具体效果由技能提供。

我们会先学继承怎么写、有什么边界，再学**多态**如何让同一调用点选择不同实现。不是所有差异都需要继承：仅数值变化可能只要配置，能力组合可能更适合成员协作。

## 五：对象不再使用时，谁清理

复制角色是否也复制内部资源？容器扩容会不会让旧指针失效？函数返回后，返回的引用还能不能用？我们会逐步学习构造、析构、复制、移动、拥有和借用，把对象代码写正确。

## 不要求现在背完答案

| 先遇到的问题 | 以后使用的工具 | 最后能做什么 |
| --- | --- | --- |
| 角色属性关联 | class、成员、对象 | 创建两个独立角色 |
| 生命值修改守规则 | public/private、封装 | 外部不能随意破坏状态 |
| 创建、退出和失败 | 构造/析构、RAII | 解释对象寿命和资源清理 |
| 全体共享统计 | static | 分清共享数据与实例数据 |
| 多种技能统一调度 | 继承、virtual、接口 | 让流程依赖清楚的契约 |
| 特性与需求不断增加 | 组合与设计取舍 | 说明为什么采用某种结构 |

面向对象不会自动让程序更快，也不替代容器和算法。封装、继承、多态不是互相独立的口诀，而是后面在应用中逐步学会使用的工具。

**本章练习不写新语法：** 列出角色的三项数据、外部希望角色执行的三个动作、不允许出现的三种状态。后面把清单一步步落成 C++ 程序。现在只需知道为什么学、将要学什么。
