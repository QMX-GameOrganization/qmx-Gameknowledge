## 先知道为什么学，再随着应用学会怎么写

你已经学过 C++ 基础、STL 和基础数据结构，能存储和处理数据。接下来会遇到新问题：角色有很多关联属性，怎样放在一起？生命值允许谁改？多个角色哪些数据独立、哪些共享？有攻击和治疗时，怎样让流程统一使用？

面向对象为这些问题提供一组组织代码的工具。**开篇只建立学习动机和地图，之后按应用逐层推进：遇到问题，再学需要的语法和设计。** 本次专注 C++，不展开 C#。

![从已有的容器经验，到管理规则、对象寿命和可替换行为](/qmx-Gameknowledge/assets/oop/roadmap.svg)

## 前提与学习方法

不假设你学过 class、namespace、enum、构造函数、异常或智能指针。“会用 STL”不等于“已经懂类”。指针、引用、const 在使用处会提醒，新语法会解释写法与作用。

采用 **C++17**，不依赖游戏引擎。带头文件和 main 的程序可独立运行；局部片段需要对应上下文；错误代码用于解释诊断，不能混入正常程序。涉及未定义行为的反例不要求运行。图是语义示意，不保证特定 ABI 的精确布局。

每一阶段按“**应用需求 → 最小程序 → 逐项语法 → 相近写法对比 → 常见坑 → 修改需求的练习**”推进。先学会写清一个类，再进入对象协作，不提前堆整套设计原则。

## 学完应该做到什么

能从空文件写出一个类，说明每个访问级别与 static 的理由；正确初始化、复制、借用和销毁对象；写出可替换的技能接口；解释重载、重写、隐藏的区别；新增需求时知道哪里应该改、哪里不必改。设计有效与否由这些结果判断，不以类数量或术语数量判断。
