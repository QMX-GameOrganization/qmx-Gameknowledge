## 这个专题解决什么问题

看到 `NativeArray<float>`、`Allocator.Persistent` 和 `JobHandle` 时，先不用钻进指针或汇编。先能回答：数据在哪里，赋值复制了什么，谁能读写，什么时候失效，谁负责释放。

这里从基础概念串起完整过程。已有 [C# 底层专栏](/qmx-Gameknowledge/knowledge/csharp底层专栏/目录/) 深入运行时实现；[Unity Job 与 Burst](/qmx-Gameknowledge/knowledge/unity-job与burst/目录/) 深入 API、调度与优化。本专题承担它们的入门前置，章节末尾给出深入链接。

## 先区分四个维度

| 维度 | 分类例子 | 它回答什么 |
| --- | --- | --- |
| 类型与复制语义 | 值类型 / 引用类型 | 赋值和传参复制什么 |
| 类型内部是否含托管引用 | 非托管类型 / 含托管引用的类型 | 能否满足 unmanaged 约束 |
| 存储与分配 | 栈、托管堆、原生分配 | 数据实际存放在哪里 |
| 生命周期与访问权 | GC、所有者释放、借用、Job 依赖 | 谁能用、何时可回收 |

这些维度不能混为一谈：`NativeArray<T>` 是值类型句柄，却共享原生数据；`struct` 可以包含 `string`；`int` 字段也可以位于托管对象内部。

## 学习验收

每章都有自测。完成最后一章后，你应能独立解释三种行为：普通数组赋值共享对象、NativeArray 赋值共享底层分配、Job 完成后由唯一所有者释放资源。再用 Profiler 验证真实项目中的分配和等待，避免把“感觉更底层”当作优化证据。
