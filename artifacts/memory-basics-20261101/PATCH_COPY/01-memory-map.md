## 要点

变量是程序中保存值的位置；对象是运行时创建的数据实体；引用是访问对象的方式。容器负责组织元素，内存是这些内容占用的存储空间。

```csharp
float[] density = new float[4];
float[] other = density;
other[0] = 0.75f;
// density[0] 也是 0.75f：两个变量引用同一个数组。
```

这里有两个引用变量、一个数组对象、四个浮点元素。变量名不同不代表数据有两份。

## 常见存储区域

| 名称 | 入门理解 | 不能据此推断的事 |
| --- | --- | --- |
| 线程栈 | 保存调用过程中的部分局部状态；有些值可能被优化到寄存器 | 不能说所有 struct 都在栈上 |
| 托管堆 | 运行时管理的对象存储，GC 跟踪其可达性 | 不能说变量离开作用域就立即回收 |
| 原生内存 | 通过原生分配机制获得的空间，通常由明确所有者管理 | 不能说 C# 代码无法访问 |
| GPU 资源 | 图形系统维护的缓冲、纹理等 | 不能用 GC.Alloc 代表其占用 |

这是帮助读代码的模型，不是每个后端的精确物理布局。编译器可能省略某些分配，地址和布局也不属于普通 C# 代码应依赖的契约。

## 类型与位置分开看

```csharp
class ChunkInfo
{
    public int Seed;
}

var info = new ChunkInfo();
var samples = new float[256];
```

`Seed` 是值类型字段，内联在 `ChunkInfo` 对象中；`samples` 是数组引用，256 个 float 存在数组对象内部。不要给每个 float 想象一个独立堆对象。

局部变量也不意味着始终在栈上：被闭包捕获、进入异步状态机，或被编译器优化，都会改变实际存储方式。

## 分配、使用、回收是不同事件

1. 分配：为数组取得存储。
2. 使用：通过引用读取或写入。
3. 不再需要：业务结束。
4. 回收：运行时或所有者真正归还存储。

第 3 步不会自动等于第 4 步。后面讨论的 GC、Dispose、Job 依赖，主要是在解释这两个时刻如何衔接。

## 自测

**问：两个引用变量各有一个名字，是否存在两个数组？** 答：不一定，上例只有一个。

**问：函数返回时，其中创建的数组一定销毁吗？** 答：不会；若返回值或其他对象仍引用它，数组仍可达。
