> 适用版本：C# 9.0。

## 要点

- C# 没有"全局函数"，所有函数都必须放在类里。目前先写成 `static` 方法，第 3 章再学实例方法。
- `ref` 和 `out` 对应 C++ 的引用传参，但**调用时也必须写出关键字**，一眼就能看出这个参数会被改。
- 默认参数的值必须是编译期常量，且必须放在参数列表最后。
- 重载只看参数列表，**返回值不同不算重载**。

## 基本写法

```csharp
static int Damage(int attack, int defense)
{
    int d = attack - defense;
    return d > 0 ? d : 0;
}

static bool IsDead(int hp) => hp <= 0;            // 单表达式可以写成 =>

static void Log(string msg)                       // 没有返回值用 void
{
    Console.WriteLine(msg);
}
```

函数体里还可以再定义"局部函数"，只在这个函数内可见，适合给一段逻辑起个名字：

```csharp
static int Total(int[] arr)
{
    int sum = 0;
    foreach (int x in arr) sum += Square(x);
    return sum;

    int Square(int n) => n * n;                   // 局部函数
}
```

## 默认参数与命名参数

```csharp
static void Spawn(string name, int hp = 100, float speed = 1.5f)
{
    Console.WriteLine($"{name} hp={hp} speed={speed}");
}

Spawn("史莱姆");                        // hp 和 speed 用默认值
Spawn("骑士", 300);                     // 只改 hp
Spawn("射手", speed: 3f);               // 命名参数：跳过中间的 hp
```

默认值只能是常量（数字、字符串、`null`、`default`），不能写 `new List<int>()`。需要默认对象时，参数写成 `null`，在函数里再判断。

## params：变长参数

```csharp
static int Sum(params int[] values)
{
    int total = 0;
    foreach (int v in values) total += v;
    return total;
}

Console.WriteLine(Sum());               // 0
Console.WriteLine(Sum(1, 2, 3));        // 6
Console.WriteLine(Sum(new[] { 4, 5 })); // 也可以直接传数组
```

`params` 必须是最后一个参数，且一个函数只能有一个。注意每次调用都会隐式创建一个数组，在每帧调用的热点里要避免。

## ref、out、in

```csharp
static void AddHp(ref int hp, int amount)         // ref：调用方必须先赋值
{
    hp += amount;
}

static bool TryFindEnemy(string name, out int id) // out：函数内必须给它赋值
{
    if (name == "史莱姆") { id = 1001; return true; }
    id = -1;                                      // 即使失败也必须赋值
    return false;
}

int myHp = 50;
AddHp(ref myHp, 20);                              // 调用处也要写 ref
Console.WriteLine(myHp);                          // 70

if (TryFindEnemy("史莱姆", out int enemyId))      // out 变量可以直接在调用处声明
    Console.WriteLine(enemyId);

TryFindEnemy("x", out _);                         // 不关心的 out 用 _ 丢弃
```

| 关键字 | 调用前需要赋值 | 函数里可以读 | 函数里必须写 | 典型用途 |
| --- | --- | --- | --- | --- |
| `ref` | 是 | 是 | 否 | 修改调用方变量 |
| `out` | 否 | 赋值前不可读 | 是 | 返回多个结果 |
| `in` | 是 | 是 | 不能写 | 只读地传大 `struct`，避免拷贝 |

Unity 的 `Physics.Raycast(ray, out RaycastHit hit)` 就是 `out` 的标准用例：函数返回"是否命中"，命中信息通过 `out` 带出。

## 重载

```csharp
static void Attack(int target)           { Console.WriteLine("按编号攻击"); }
static void Attack(string target)        { Console.WriteLine("按名字攻击"); }
static void Attack(int target, int times){ Console.WriteLine("连续攻击"); }
// static int Attack(int target) { ... }  // 编译错误：只有返回类型不同，不算重载
```

## 递归

```csharp
static int Factorial(int n) => n <= 1 ? 1 : n * Factorial(n - 1);

// 游戏例子：技能树里，一个技能的总前置数量
static int CountPrerequisites(int skillId, int[] parent)   // parent[i] 是 i 的前置，-1 表示没有
{
    if (parent[skillId] == -1) return 0;
    return 1 + CountPrerequisites(parent[skillId], parent);
}
```

递归需要终止条件。C# 栈溢出**无法用 `try/catch` 捕获**，进程会直接崩溃，在 Unity 里就是编辑器卡死或闪退，所以递归深度要可控。

## 在 Unity 里用到它

- `out` 参数是 Unity 里的常客：`Physics.Raycast(..., out RaycastHit hit)`、`TryGetComponent<T>(out var c)`、`Dictionary.TryGetValue`。
- 默认参数和命名参数让 API 调用更短：`Instantiate(prefab)` 有多个重载，`Debug.DrawLine(a, b, Color.red, 1f)` 的后几个参数都可省略。
- 递归在游戏里用于遍历父子物体树、技能树、寻路；深度要可控。

## 动手试试

把这个脚本挂到一个悬空的 Cube 上，场景里放一个 Plane 当地面：

```csharp
using UnityEngine;

public class RayDemo : MonoBehaviour
{
    void Update()
    {
        if (Physics.Raycast(transform.position, Vector3.down, out RaycastHit hit, 10f))
            Debug.Log($"脚下是 {hit.collider.name}，距离 {hit.distance:F2}");
        else
            Debug.Log("脚下什么都没有");
    }
}
```

运行时在 Scene 视图里把 Cube 往上或往旁边拖，观察输出变化。注意 `out RaycastHit hit` 在调用处就声明了变量。

## 项目应用决策：函数签名暴露协作边界

普通返回值适合查询或计算，`out` 适合“尝试查找并返回结果”，例如 `TryGetComponent`；`ref/in` 只在确实需要避免结构体复制或原地修改时使用。参数过多通常说明职责没有拆开，而不是继续堆默认参数。

主线项目把 `TakeDamage(amount)`、`TryCollect(itemId, out reward)` 和 `CanOpen(exit)` 作为清晰的动作/查询边界。验收时调用方不需要知道血量字段、库存数组或内部搜索过程，只根据函数结果推进游戏状态。

## 常见坑

- 调用 `ref`/`out` 参数时漏写关键字，编译器会报错。这是好事，别想着去掉。
- 给带默认值的参数后面又放了没有默认值的参数。
- `params` 在每帧调用里创建数组，产生垃圾。
- 想用 `out` 返回大量数据：超过两三个就该考虑返回一个 `struct` 或元组。
