> 适用版本：语法以 C# 9.0 为准，Unity 示例覆盖 Unity 2021 LTS 到 Unity 6。主线项目使用传统 Input Manager，若项目启用新 Input System，请在 Player 设置中选择 Both。

## 这套专栏最后要做出什么

这不是把若干语法示例拼在一起，而是边学边完成一个**可从开始玩到胜利或失败的方块地牢**：

- WASD 移动玩家，摄像机跟随；
- 敌人、陷阱和出口都放在场景中，并通过组件各自负责行为；
- 玩家可以攻击、受伤、收集钥匙或水晶；
- 收集目标后到达出口胜利，血量归零失败；
- 胜利、失败和重新开始都有清晰的 UI 状态；
- 最后能从 Unity Build Settings 构建出可运行版本。

每一章都修改同一个项目。文章里的示例代码不是一次性演示：本篇新增的类型、字段或事件，会在后续章节被继续调用、替换或扩展。

## 先建立 Unity 的运行模型

在进入 C# 语法前，先完成 [主线项目与 Unity 运行逻辑](./00-先认识Unity/00-主线项目与Unity运行逻辑/)。需要掌握的不是编辑器菜单背诵，而是下面这条因果链：

```text
场景中的 GameObject
  → 挂载 Component（Transform、Collider、脚本）
  → Unity 在每帧调用脚本生命周期
  → 脚本读取输入、修改状态、调用组件 API
  → 场景和 UI 反映新的状态
```

`Awake` 负责准备自己，`OnEnable` 负责订阅，`Start` 适合读取其他对象，`Update` 处理逐帧输入，`FixedUpdate` 处理需要物理步的逻辑，`OnDisable` 负责解除订阅。后面每次使用这些函数，都要能说明“谁调用、何时调用、修改了哪个状态”。

## 主线项目的阶段契约

| 阶段 | C# 主线 | 项目新增能力 | 进入下一阶段的验收 |
| --- | --- | --- | --- |
| 0. Unity 启动 | 场景、GameObject、Component、生命周期、输入 | 玩家能移动，摄像机能跟随，能在 Console 观察生命周期 | 能解释一帧发生了什么，并能定位一个组件引用 |
| 1. 数据与状态 | 类型、转换、字符串、异常、枚举、数组、结构体、函数 | `PlayerState`、血量、分数、物品数据和基础 HUD | 状态只通过明确的数据和函数改变，非法输入有反馈 |
| 2. 封装与复用 | 类、属性、构造函数、`static`、扩展方法、运算符 | `PlayerStats`、`Inventory`、`GameMath`、`DamageFormula` | 至少两个游戏系统调用同一个静态工具方法，不创建工具类实例 |
| 3. 组合与多态 | 继承、抽象类、接口、命名空间、object | 敌人、陷阱、可攻击目标和可交互物统一接入 | 新增一种目标时，不修改攻击者的核心调用代码 |
| 4. 集合与事件 | 泛型、集合、委托、事件、排序、对象池 | 敌人列表、掉落物、事件驱动 HUD、敌人生成 | 血量、得分和胜负状态能被多个观察者同步收到 |
| 5. Unity 工程能力 | 协程、特性、序列化、预制体、场景状态 | 攻击冷却、波次、拾取、出口、胜负和重开 | 可以完整玩通一局，失败后能重新开始 |
| 6. 发布验收 | 综合调试、构建、回归检查 | 独立可运行的小游戏构建 | 通过 [完整小游戏验收](./06-通向Unity/04-完整小游戏验收/) |

## Unity 基础放在哪里

Unity 使用不会被当作附录。第 0 阶段专门建立：

- `GameObject` 是场景中的实体，`Component` 是附加能力，`Transform` 是所有对象都有的空间组件；
- `MonoBehaviour` 脚本如何挂到对象上，Unity 如何按生命周期调用它；
- `SerializeField`、Inspector 引用、Prefab 和碰撞/触发器如何把代码连接到场景；
- `Update`、`FixedUpdate`、物理事件和协程分别适合什么时机；
- 运行时状态与编辑器配置的边界，以及如何从 Console、Hierarchy、Inspector 反查问题。

## 每篇文章必须回答的五个问题

从这一轮起，每个知识点都要回到主线项目回答五件事：

1. **它解决什么真实问题？** 先看到需求，再引出语法。
2. **为什么选它？** 说明它依赖的状态、生命周期、性能或维护条件。
3. **和相近方案有什么区别？** 至少给出一个容易混用的替代方案。
4. **什么时候不要用？** 明确边界，避免把规则背成万能模板。
5. **项目如何验收？** 给出能在 Unity 场景、Inspector、Console 或 Build 中观察的结果。

只有列出语法、再贴一段孤立代码而没有这五项，不能算主线完成。每篇的“动手试试”也要修改已有项目对象，后续文章继续复用结果。

## 与其他专栏的边界

本专栏负责“能写出并完成一个 Unity 小游戏”的应用层 C#。C# 底层专栏负责对象布局、GC、IL、Mono/IL2CPP 和隐藏分配；C# 与 Unity 内存基础负责托管/Native 生命周期；Unity Job 与 Burst 负责并行和高性能。完成主线项目后再进入这些专题，学习顺序不会被底层细节打断。
