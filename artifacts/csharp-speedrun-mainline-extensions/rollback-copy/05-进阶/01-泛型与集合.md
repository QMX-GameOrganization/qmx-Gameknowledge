## 要点

- **泛型**让一份代码适用于多种类型：`List<int>`、`List<string>` 是同一个模板的不同实例。
- C# 泛型和 C++ 模板写法相近，但不会在编译期展开成无限制的代码：用 `where` **约束**说明类型需要具备的能力。
- `Stack<T>`（后进先出）、`Queue<T>`（先进先出）、`LinkedList<T>`（双向链表）都是现成的泛型集合，在 `System.Collections.Generic` 中。
- 值类型放进泛型集合**不会装箱**，这是泛型相对老式 `object` 容器的主要优势。

## 泛型类

做一个游戏里最常见的东西，对象池：

```csharp
class Pool<T> where T : class, new()           // T 必须是引用类型，并且有无参构造函数
{
    private readonly Stack<T> free = new Stack<T>();

    public T Get()
    {
        return free.Count > 0 ? free.Pop() : new T();     // 池里有就复用，没有才新建
    }

    public void Release(T item)
    {
        free.Push(item);
    }
}

class Bullet { public float x, y; }

Pool<Bullet> pool = new Pool<Bullet>();
Bullet b = pool.Get();
pool.Release(b);                                // 用完放回去，下次再用，不产生新垃圾
```

对象池是减少 GC 的主力手段：子弹、特效、伤害数字每秒创建销毁成百上千次，复用比反复 `new` 好得多。

## 泛型方法与约束

```csharp
static T Max<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) >= 0 ? a : b;
}

Console.WriteLine(Max(3, 7));              // 7，T 自动推断为 int
Console.WriteLine(Max("apple", "pear"));   // pear
```

不加约束的话，编译器不知道 `T` 有没有 `CompareTo` 方法，所以不让调用。这与 C++ 模板"用到才检查"不同，C# 是**在声明处就检查**，报错更早、更清楚。

| 约束 | 含义 |
| --- | --- |
| `where T : class` | 引用类型 |
| `where T : struct` | 值类型 |
| `where T : new()` | 有公开无参构造函数 |
| `where T : Entity` | 是 `Entity` 或其子类 |
| `where T : IDamageable` | 实现了该接口 |

多个约束用逗号隔开，`new()` 必须放最后。

## Stack、Queue、LinkedList

```csharp
using System.Collections.Generic;

// 栈：后进先出，如界面返回栈、撤销操作
Stack<string> pages = new Stack<string>();
pages.Push("主菜单");
pages.Push("设置");
Console.WriteLine(pages.Pop());            // 设置
Console.WriteLine(pages.Peek());           // 主菜单，只看不取

// 队列：先进先出，如行动顺序、消息、伤害结算
Queue<string> actions = new Queue<string>();
actions.Enqueue("战士攻击");
actions.Enqueue("法师施法");
Console.WriteLine(actions.Dequeue());      // 战士攻击

// 链表：在已知节点处插入删除是 O(1)
LinkedList<int> list = new LinkedList<int>();
LinkedListNode<int> n2 = list.AddLast(2);
list.AddFirst(1);
list.AddAfter(n2, 3);                      // 1, 2, 3
list.Remove(n2);                           // 1, 3
foreach (int v in list) Console.WriteLine(v);
```

对空栈 `Pop` 或空队列 `Dequeue` 会抛 `InvalidOperationException`。不确定时用 `TryPop` / `TryDequeue`（.NET Core 及 Unity 较新版本提供，旧版本先判断 `Count`）。

`LinkedList` 在游戏里**很少用**：节点分散在堆上，缓存不友好，遍历比数组慢得多。只有当你持有节点引用并且频繁在中间增删时才有意义。绝大多数时候 `List<T>` 就够了。

## 容器选择速查

| 需求 | 选 |
| --- | --- |
| 按顺序存，按下标访问 | `List<T>` |
| 按键查找 | `Dictionary<K,V>` |
| 去重、判断是否存在 | `HashSet<T>` |
| 先进先出 | `Queue<T>` |
| 后进先出 | `Stack<T>` |
| 频繁在已知节点处增删 | `LinkedList<T>` |

## 与 C++ 模板对照

| 方面 | C++ 模板 | C# 泛型 |
| --- | --- | --- |
| 类型检查 | 实例化时 | 声明时，靠 `where` 约束 |
| 非类型参数 | 支持（`template<int N>`） | 不支持 |
| 特化 | 支持 | 不支持 |
| 运算符 | 直接用 `a + b` | 泛型里不能直接用，需要约束或接口 |
| 值类型实例化 | 每个类型一份代码 | 同样每个值类型一份，引用类型共享一份 |

## 在 Unity 里用到它

- 你已经在用泛型了：`GetComponent<Rigidbody>()`、`List<GameObject>`、`Dictionary<string, Sprite>`、`TryGetComponent<T>(out ...)`。尖括号里的就是类型参数。
- Unity 2021 起自带 `UnityEngine.Pool.ObjectPool<T>`，功能和上面手写的对象池相同，正式项目可以直接用；手写一遍是为了理解原理。
- 对象池里存的通常是 `GameObject`：取出时 `SetActive(true)`，放回时 `SetActive(false)`，避免反复 `Instantiate` 和 `Destroy`。

## 动手试试

```csharp
using System.Collections.Generic;
using UnityEngine;

public class BulletPool : MonoBehaviour
{
    [SerializeField] private GameObject bulletPrefab;                 // 拖一个预制体（或场景里的 Cube）
    private readonly Stack<GameObject> free = new Stack<GameObject>();
    private readonly Stack<GameObject> active = new Stack<GameObject>();

    GameObject Get(Vector3 pos)
    {
        GameObject b = free.Count > 0 ? free.Pop() : Instantiate(bulletPrefab);
        b.transform.position = pos;
        b.SetActive(true);
        return b;
    }

    void Release(GameObject b)
    {
        b.SetActive(false);
        free.Push(b);
    }

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
            active.Push(Get(transform.position + Vector3.up * active.Count));
        if (Input.GetKeyDown(KeyCode.R) && active.Count > 0)
            Release(active.Pop());
    }
}
```

运行后按空格三次，Hierarchy 里出现三个 `Clone`；按 R 三次，它们变灰（被停用）；再按空格三次，**Hierarchy 里仍然只有三个**，说明是复用而不是新建。

## 项目应用决策：泛型保持类型安全，对象池管理生命周期

`List<Enemy>`、`Dictionary<ItemId, int>` 和 `ObjectPool<Bullet>` 分别表达集合、映射和可复用对象。泛型让编译器检查类型，避免 `ArrayList` 的装箱和运行时强转；对象池解决的是反复 `Instantiate/Destroy` 的生命周期成本，不是所有集合都要池化。

主线验收时统计一轮敌人生成和子弹回收：集合负责记录当前对象，池负责借出和归还；两种职责混在一个类里会导致对象既丢失又重复释放。

## 常见坑

- 在泛型里写 `a + b`、`a > b`，编译器不认，要加 `IComparable<T>` 等约束。
- 想用 `new T(args)`：C# 只支持无参 `new()` 约束。
- 对象池取出的对象忘记重置状态，复用时带着上一次的数据。
- 一个循环里反复 `new List<T>()`，应该复用并 `Clear()`。
