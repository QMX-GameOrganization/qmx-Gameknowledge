> 适用版本：C# 9.0。

> **本篇主线标记**：本篇的 `PlayerState`/`GamePhase` 是 `【主线必做】`；状态值最终由[玩家状态与游戏数据](../扩展-主线支撑/01-玩家状态与游戏数据/)承接。

## 要点

- 枚举把"一组有限的选择"变成有名字的类型：`PlayerState.Run` 比魔法数字 `1` 好读，写错时编译器还会报错。
- 成员必须带类型名访问（`PlayerState.Run`），这点像 C++ 的 `enum class`；**但 C# 枚举可以被强转成任何整数**，并不保证值合法。
- 打印枚举会得到成员名，不是数字。
- 加上 `[Flags]` 并取 2 的幂做值，就能用 1.5 的位运算组合多个状态。

## 声明与使用

```csharp
enum PlayerState
{
    Idle,       // 默认从 0 开始递增
    Run,        // 1
    Jump,       // 2
    Attack = 10,// 可以手动指定
    Dead        // 11，接着上一个继续
}

class Demo
{
    static void Main()
    {
        PlayerState s = PlayerState.Run;

        switch (s)
        {
            case PlayerState.Idle:   Console.WriteLine("待机"); break;
            case PlayerState.Run:    Console.WriteLine("奔跑"); break;
            default:                 Console.WriteLine("其他"); break;
        }

        Console.WriteLine(s);             // Run，输出的是名字
        Console.WriteLine((int)s);        // 1
        PlayerState t = (PlayerState)10;  // Attack
    }
}
```

枚举可以定义在类的内部或外部。放在类外时就是一个独立类型，整个项目都能使用；Unity 中通常单独放进一个文件，或放进用到它的类里。

## 和整数、字符串互转

```csharp
int code = (int)PlayerState.Jump;                      // 枚举 -> 整数：显式强转
PlayerState a = (PlayerState)2;                        // 整数 -> 枚举：也要强转

string name = PlayerState.Jump.ToString();             // "Jump"
if (Enum.TryParse("Attack", out PlayerState b))        // 字符串 -> 枚举，失败返回 false
    Console.WriteLine(b);

foreach (PlayerState st in Enum.GetValues(typeof(PlayerState)))
    Console.WriteLine(st);                             // 遍历所有成员
```

强转不会检查合法性：`(PlayerState)99` 能编译也能运行，得到一个"不存在"的状态。读存档或网络数据时，用 `Enum.IsDefined(typeof(PlayerState), value)` 先验证。

## [Flags]：多个状态同时成立

```csharp
[Flags]
enum Buff
{
    None   = 0,
    Poison = 1 << 0,
    Burn   = 1 << 1,
    Freeze = 1 << 2,
    Rage   = 1 << 3
}

Buff b = Buff.Poison | Buff.Rage;           // 同时中毒和狂暴
b |= Buff.Burn;                             // 添加
b &= ~Buff.Poison;                          // 移除
bool burning = (b & Buff.Burn) != 0;        // 判断，也可以写 b.HasFlag(Buff.Burn)
Console.WriteLine(b);                       // Burn, Rage
```

没有 `[Flags]` 时打印组合值只会显示数字；加上之后会显示成 `Burn, Rage`，方便调试。`HasFlag` 更好读，但早期 .NET 版本里有装箱开销，在每帧调用的热点里仍建议写位运算。

## 与 C++ 的差别

| 方面 | C++ `enum class` | C# `enum` |
| --- | --- | --- |
| 访问成员 | `State::Run` | `State.Run` |
| 隐式转整数 | 不允许 | 不允许，必须强转 |
| 值合法性 | 同样不检查 | 同样不检查 |
| 打印成员名 | 需要自己写映射 | `ToString()` 自带 |
| 底层类型 | `: uint8_t` | `: byte`，默认 `int` |

## 在 Unity 里用到它

- `[SerializeField]` 或 `public` 的枚举字段，在 Inspector 里会变成**下拉菜单**，策划不用记数字。
- 角色状态机、AI 状态、物品类型、伤害类型，都是枚举的典型用法。
- 带 `[Flags]` 的枚举在 Inspector 里是多选（Unity 会显示 Everything / Nothing 等选项）。
- 枚举值会被序列化成数字存进场景，**调整成员顺序会让已保存的值指向别的成员**，所以显式写数值、只往后加。

## 动手试试

```csharp
using UnityEngine;

public enum PlayerState { Idle = 0, Run = 1, Jump = 2 }

public class StateDemo : MonoBehaviour
{
    [SerializeField] private PlayerState state;
    private PlayerState last;

    void Update()
    {
        if (state != last)                              // 只在变化时输出，避免刷屏
        {
            Debug.Log($"状态 {last} → {state}");
            last = state;
        }
    }
}
```

Play 之后在 Inspector 里切换下拉菜单，观察 Console。再试着在枚举中间插入一个成员但不写显式数值，想想已经保存的物体会发生什么。

## 项目应用决策：枚举表达有限且有名字的状态

`PlayerState`、`GamePhase`、`EnemyState` 适合普通枚举，因为同一时刻只应处于一个主状态；同时存在的中毒、减速、护盾才适合 `[Flags]`。不要用多个 bool 代替互斥状态，否则会出现 `IsDead` 和 `IsRunning` 同时为真的组合。

枚举值一旦写入存档或配置，就要显式固定数值，新增状态放在末尾并处理旧值。验收时分别切换移动、攻击、死亡状态，确认非法转换被拒绝，UI 和输入系统都读取同一个枚举而不是各自维护字符串。

## 常见坑

- 用 `Enum.Parse` 解析玩家输入，写错一个字母就抛异常。改用 `TryParse`。
- 在序列化（存档、Inspector）中改变枚举成员顺序：数字变了，旧存档里的值会指向错误成员。要保证兼容，**显式写出每个值**，新成员只追加在后面。
- `[Flags]` 枚举忘记写 `None = 0`，或者成员值不是 2 的幂，位运算结果出错。
- Unity 的 Inspector 会把枚举显示成下拉菜单，改名会让场景里已保存的值丢失。
