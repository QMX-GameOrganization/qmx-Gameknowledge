> 适用版本：C# 9.0（Unity 2021 LTS 到 6000.x）。这一语言版本下 struct 不能自定义无参构造函数。

## 要点

- C# 的 `struct` 是**值类型**，赋值、传参都会复制整个内容；而 `class` 是引用类型。这和 C++ 里 `struct` 与 `class` 几乎只差默认访问权限不同。
- `struct` 适合"小而轻、没有身份的数据"：坐标、颜色、伤害数值包。
- `struct` 不能继承别的类，但可以实现接口。
- 数组里的 `struct` 元素是连续存放的，遍历快，也不给垃圾回收器增加负担。

## 声明与使用

```csharp
struct Point2
{
    public int x;
    public int y;

    public Point2(int x, int y)           // 构造函数必须给所有字段赋值
    {
        this.x = x;                       // this 表示"当前这个实例"，用来区分同名的参数和字段
        this.y = y;
    }

    public int ManhattanTo(Point2 other) => Math.Abs(x - other.x) + Math.Abs(y - other.y);
}

class Demo
{
    static void Main()
    {
        Point2 a = new Point2(1, 2);       // new 在这里不会在堆上分配
        Point2 b = a;                      // 复制一份
        b.x = 99;
        Console.WriteLine(a.x);            // 1，a 没变
        Console.WriteLine(a.ManhattanTo(b));// 98 + 0 = 98

        Point2 zero = default;             // 所有字段为 0
        Point2 c;                          // 不 new 也行，但必须先给全部字段赋值才能使用
        c.x = 3; c.y = 4;
        Console.WriteLine(c.ManhattanTo(zero)); // 7
    }
}
```

`struct` 的 `new` 只是调用构造函数初始化，不涉及堆分配，这点和 `class` 完全不同。成员访问修饰符（`public`）和方法的写法，将在第 3 章系统讲，现在认出形状即可。

## 值语义带来的行为

```csharp
Point2[] path = new Point2[3];
path[0].x = 5;                          // 数组元素可以直接改，因为是原地访问

var list = new List<Point2> { new Point2(1, 1) };
// list[0].x = 5;                       // 编译错误：list[0] 返回的是副本，改了没意义
Point2 p = list[0];
p.x = 5;
list[0] = p;                            // 必须取出、修改、再写回
```

这与 2.3 篇里 `transform.position.y` 不能直接改是同一个原因。Unity 的 `Vector3` 就是 struct，字段 `x`、`y`、`z` 都是 `public float`，而 `transform.position` 是一个**属性**（第 3.3 篇），返回的是副本。

## struct 还是 class？

| 情况 | 选择 |
| --- | --- |
| 小于约 16 字节、没有身份、创建频繁 | `struct` |
| 需要多个地方共享并修改同一份数据 | `class` |
| 需要继承和多态 | `class` |
| 需要放进集合，数量极大 | 优先 `struct`（数组连续，少 GC） |
| 字段多、复制成本高 | `class` |

游戏里的典型 `struct`：`Vector2/3/4`、`Quaternion`、`Color`、`Rect`、一个技能的伤害结果（伤害值、是否暴击、元素类型）。典型的 `class`：角色、敌人、道具实例、各种管理器。

```csharp
struct DamageResult
{
    public int amount;
    public bool isCrit;
    public int element;
}

static DamageResult Calc(int atk, int def, bool crit)
{
    DamageResult r;
    r.amount = Math.Max(atk - def, 0) * (crit ? 2 : 1);
    r.isCrit = crit;
    r.element = 0;
    return r;
}
```

用 `struct` 返回多个结果比 `out` 一长串参数更清楚，也不会产生堆垃圾。

## 与 C++ 的差别

| 方面 | C++ | C# |
| --- | --- | --- |
| `struct` 与 `class` | 仅默认访问权限不同 | 值类型 vs 引用类型 |
| 自定义析构 | 可以 | 不可以 |
| 继承 | 可以 | 不能继承类，只能实现接口 |
| 默认拷贝 | 逐成员 | 逐字节 |
| 放哪 | 看你怎么声明 | 由包含它的位置决定，不必关心栈或堆 |

## 在 Unity 里用到它

- `Vector2`、`Vector3`、`Quaternion`、`Color`、`Rect` 都是 `struct`，所以复制、传参都是拷贝，赋值不会互相影响。
- 自己的 `struct` 加上 `[System.Serializable]`，就能在 Inspector 里直接配置，非常适合"一条配置"这种小数据，比如掉落表的一行。

## 动手试试

```csharp
using UnityEngine;

[System.Serializable]
public struct DropEntry
{
    public string itemName;
    public int weight;
}

public class DropTable : MonoBehaviour
{
    [SerializeField] private DropEntry[] entries;

    void Start()
    {
        foreach (DropEntry e in entries)
            Debug.Log($"{e.itemName}：权重 {e.weight}");
    }
}
```

挂上后，在 Inspector 里把 `Entries` 的 Size 设为 3，填写三条掉落配置，运行查看输出。再把 `struct` 改成 `class` 并去掉 `[System.Serializable]`，观察 Inspector 的变化。

## 项目应用决策：结构体承载小型值数据

`DamageInfo`、`GridCell`、`DropEntry` 适合结构体，因为它们是可复制的值；`Health`、`Inventory` 和场景组件不是结构体，因为它们有身份、事件或生命周期。给结构体加 `[Serializable]` 是为了让 Inspector 配置它，不代表它自动适合保存任意引用。

结构体应尽量小、语义清楚、修改后整体写回。验收时修改一个掉落表条目的副本，确认原配置不被偷偷改变；如果结构体开始包含可变集合或频繁传递大字段，应回到 2.3 重新评估。

## 常见坑

- 以为 `struct` 和 `class` 一样可以直接共享修改，结果改的是副本。
- 做了一个很大的 `struct` 并频繁传参，拷贝开销反而比 `class` 大。
- 把 `struct` 当 `object` 或接口使用会发生**装箱**，在堆上产生副本。装箱在 4.2 篇讲。
- 在 `foreach` 里想修改 `struct` 元素：迭代变量只读，编译器直接报错。
