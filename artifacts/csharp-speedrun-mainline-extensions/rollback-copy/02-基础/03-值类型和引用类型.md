## 要点

- **值类型**的变量里直接装着数据，赋值是复制一份：`int`、`float`、`bool`、`char`、枚举、`struct`（含 Unity 的 `Vector3`、`Color`）。
- **引用类型**的变量里装着"指向对象的引用"，赋值只复制这个引用，两个变量指向同一个对象：`class`、数组、`string`、委托。
- 这是你从 C++ 转来最容易出错的地方。C++ 里对象默认是值，复制就是拷贝；C# 里 `class` 的变量更像一个自动回收的指针。
- 引用类型变量可以是 `null`，值类型不行（除非用 `int?` 这样的可空类型）。

## 一眼看懂的对比

```csharp
// 值类型：独立副本
int a = 10;
int b = a;
b = 99;
Console.WriteLine(a);        // 10，a 没变

// 引用类型：共享同一个对象
int[] x = { 1, 2, 3 };
int[] y = x;
y[0] = 99;
Console.WriteLine(x[0]);     // 99，x 和 y 是同一个数组
```

把它想成存档：值类型是"把存档复制成两份"，引用类型是"两个人拿着同一个存档的链接"。

![值类型变量复制内容各自独立；引用类型变量复制引用，指向同一个对象](/qmx-Gameknowledge/assets/csharp/value-vs-ref.svg)

## 游戏里最常见的例子

Unity 的 `Vector3`（位置、方向）是值类型，`GameObject` 和各种组件是引用类型：

```csharp
// 以下为 Unity 代码示意
Vector3 p = transform.position;      // 复制了一份坐标
p.y += 5;                            // 只改了副本，物体没动
transform.position = p;              // 写回去才生效

GameObject enemy = FindEnemy();
GameObject target = enemy;           // 两个变量指向同一个物体
Destroy(target);                     // enemy 也指向这个已销毁的物体
```

"明明改了 `position.y`，物体却没动"，几乎每个 Unity 新手都踩过这个坑，原因就是它是值类型，取出来的是副本。

![取出 position 得到副本，改副本不影响物体，必须写回](/qmx-Gameknowledge/assets/csharp/position-copy.svg)

## 参数传递

C# 的函数参数默认是**按值传递**，但"值"对引用类型来说就是那份引用：

```csharp
static void Heal(int hp)           { hp += 50; }                 // 改的是副本
static void Fill(int[] arr)        { arr[0] = 50; }              // 通过引用改了原数组
static void Replace(int[] arr)     { arr = new int[] { 7 }; }    // 只改了形参这份引用

int hp = 10;
Heal(hp);
Console.WriteLine(hp);            // 10

int[] bag = { 0, 0 };
Fill(bag);
Console.WriteLine(bag[0]);        // 50
Replace(bag);
Console.WriteLine(bag[0]);        // 50，调用方的 bag 没有被换掉
```

想让函数真的修改调用者的变量本身，要用 `ref` 或 `out`，见 2.4 篇。

![Fill 通过引用修改数组内容；Replace 只改了形参，调用方的引用不变](/qmx-Gameknowledge/assets/csharp/param-pass.svg)

## null：引用类型才会有的状态

```csharp
int[] arr = null;                  // 没有指向任何对象
// Console.WriteLine(arr.Length);  // NullReferenceException

if (arr != null) { /* ... */ }
int len = arr?.Length ?? 0;        // 空条件运算符：arr 为 null 就整体得 null，再用 ?? 给默认值

int? maybeHp = null;               // 可空值类型：int 加问号
if (maybeHp.HasValue) Console.WriteLine(maybeHp.Value);
```

`?.` 和 `??` 在 Unity 里要小心：它们不会触发 Unity 对"已销毁对象"的特殊判断（`UnityEngine.Object` 重载了 `==`），所以对 `GameObject`、组件最好仍写 `if (obj != null)`。

## string：引用类型，但像值类型一样工作

`string` 是引用类型，但它不可变，每次"修改"都得到新对象，所以不会出现"改了 `a` 影响 `b`"的情况：

```csharp
string s1 = "Hero";
string s2 = s1;
s2 += "!";
Console.WriteLine(s1);      // Hero
Console.WriteLine(s2);      // Hero!
```

## 与 C++ 对照

| 想法 | C++ | C# |
| --- | --- | --- |
| 自定义类型的变量默认是 | 值（复制整个对象） | `struct` 是值，`class` 是引用 |
| 两个变量指向同一个对象 | 指针或引用 | 引用类型默认如此 |
| 谁负责释放 | 你（或智能指针） | 垃圾回收器（GC） |
| 对象能为空吗 | 指针可以，对象不行 | 引用类型变量可以为 `null` |
| 想复制一份 | 拷贝构造 | 自己写 `Clone`，或手动逐字段拷贝 |

## 动手试试

在 `Lab.Start` 里亲自撞一次这个坑：

```csharp
// transform.position.y = 5;                    // 取消注释：Console 报 CS1612
Vector3 p = transform.position;
p.y = 5f;                                       // 改副本
Debug.Log(transform.position.y);                // 物体还没动
transform.position = p;                         // 写回
Debug.Log(transform.position.y);                // 现在是 5
```

再复现一次数组别名：`int[] a = {1,2,3}; int[] b = a; b[0] = 99;` 输出 `a[0]`。最后把 `b` 换成 `(int[])a.Clone()`，再看 `a[0]`。

## 项目应用决策：什么时候用 class，什么时候用 struct

用“是否拥有身份和生命周期”判断，而不是背“class 在堆、struct 在栈”：

- `PlayerStats`、`Inventory`、`Health` 需要被多个系统观察或修改，具有身份，使用 `class`；
- `DamageInfo`、`GridCell`、`DropEntry` 是小型数据快照，复制后彼此独立，使用 `struct`；
- `Vector3` 适合值语义，读取、修改副本后再写回，避免误以为改了 Transform 内部数据。

当一个结构体变大、频繁作为参数复制或包含可变集合时，应重新评估是否应改为 class 或使用 `in/ref`。验收时分别修改两个 `DamageInfo` 副本和同一个 `PlayerStats` 引用，确认前者互不影响、后者反映同一份状态。

## 常见坑

- 以为 `class` 的赋值会复制对象，结果两处代码改的是同一个。
- 取出 `transform.position` 后直接改 `.y` 或 `.x`：C# 编译器会报错 `CS1612`，因为改的是副本。
- 把大 `struct` 到处传参，拷贝成本高。
- 对可能为 `null` 的引用直接调用成员。
