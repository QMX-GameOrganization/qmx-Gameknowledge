> 标记：`【主线支撑】`。本篇不新增 C# 语法，目标是让语法文章有一个稳定的运行载体。

## 本篇完成什么

建立 `Dungeon` 场景和固定目录。后续文章中的 `PlayerController`、`Health`、`GameMath`、敌人和 UI 都放进同一个工程，不再每篇新建一个互相冲突的 `Lab` 类。

```text
Assets/Speedrun/
├── Game/           # 【主线必做】会被最终游戏使用的脚本
├── Labs/           # 【可选扩展】一次性语法实验
├── Scenes/
├── Prefabs/
├── UI/
└── Data/
```

## 场景对象和组件

创建以下对象：

| 对象 | 必要组件 | 作用 |
| --- | --- | --- |
| `GameRoot` | `GameBootstrap` | 场景启动和游戏阶段入口 |
| `Player` | `Transform`、Collider、Rigidbody、`PlayerController` | 玩家实体 |
| `Ground` | `Transform`、Collider | 可行走地面 |
| `Main Camera` | `Camera`、`CameraFollow` | 观察玩家 |
| `Canvas` | `Canvas`、`HUDController` | 显示血量和目标进度 |

`GameObject` 保存实体，组件提供能力，Prefab 保存可重复生成的组合。不要把“场景中唯一的对象”和“可以批量生成的敌人”都写成静态全局变量。

## 最小启动器

```csharp
using UnityEngine;

/// <summary>【主线支撑】只负责确认场景启动，不持有玩家战斗规则。</summary>
public sealed class GameBootstrap : MonoBehaviour
{
    private void Awake()
    {
        Debug.Log("Dungeon bootstrap: Awake");
    }

    private void Start()
    {
        Debug.Log("Dungeon bootstrap: Start");
    }
}
```

## 验收

- [ ] `Dungeon` 场景能被打开并加入 Build Settings；
- [ ] `GameRoot`、`Player`、`Ground`、`Main Camera`、`Canvas` 都能在 Hierarchy 找到；
- [ ] Play 后 Console 先出现 `Awake`，再出现 `Start`；
- [ ] 关闭或移除一个组件时，能从 Inspector 立刻看出哪个能力消失；
- [ ] 主线脚本只放入 `Assets/Speedrun/Game/`，一次性试验放入 `Labs/`。
