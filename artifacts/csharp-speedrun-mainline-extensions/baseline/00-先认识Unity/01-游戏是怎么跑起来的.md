> 适用版本：Unity 2021 LTS 到 Unity 6000.x。本篇不要求会 Unity，也不写 Unity 代码，只建立"游戏程序和普通程序有什么不同"的整体印象。

## 要点

- 控制台程序是**从头跑到尾**，跑完就退出；游戏是**一个一直转的循环**，每转一圈画出一帧画面。
- 每一帧大致做三件事：读输入、更新游戏状态、把画面画出来。
- **你写的代码不是整个程序，而是被循环反复调用的一小块**。循环本身由 Unity 提供。
- 帧率不固定，所以和时间有关的计算（移动、冷却）必须乘上这一帧耗费的时间 `Time.deltaTime`。

## 先看你熟悉的：普通程序

你在 C++ 里写过的练习大多是这样的：

```csharp
// 普通程序：顺序执行，执行完就结束
int hp = 100;
hp -= 30;
Console.WriteLine(hp);
// 程序到这里就退出了
```

游戏不能这样。玩家随时可能按键，敌人要持续移动，画面要不断刷新。程序必须**一直运行，一直响应**，直到玩家退出。

## 游戏循环

![游戏循环：启动一次，之后每一帧重复读取输入、物理、逻辑、渲染](/qmx-Gameknowledge/assets/csharp/game-loop.svg)

把这个循环自己手写出来，大概是这个样子（控制台示意，不是 Unity 代码）：

```csharp
bool running = true;
float lastTime = GetTime();

while (running)                              // 游戏循环：不断转圈
{
    float now = GetTime();
    float deltaTime = now - lastTime;         // 距离上一帧过了多久（秒）
    lastTime = now;

    ProcessInput();                           // 1. 读输入：按了什么键
    UpdateGame(deltaTime);                    // 2. 更新：角色移动、敌人思考、判定伤害
    Render();                                 // 3. 渲染：把当前状态画到屏幕上
}
```

画面每秒刷新的次数叫**帧率**（FPS）。60 FPS 就是一秒转 60 圈，一圈约 16.7 毫秒。一圈就是**一帧**。

**Unity 替你写好了这个 `while`，以及 `ProcessInput` 和 `Render`。你只需要写 `UpdateGame` 里的内容**：角色怎么动、怎么受伤、怎么死。Unity 会在每一帧调用你写的 `Update()` 函数，这就是为什么你不用也不能写 `Main`。

## 为什么要乘 deltaTime

假设你想让角色每帧向右移动 0.1 米：

| 机器 | 帧率 | 一秒移动 |
| --- | --- | --- |
| 高配电脑 | 120 FPS | 12 米 |
| 低配手机 | 30 FPS | 3 米 |

同一份代码，在不同机器上速度差四倍。正确做法是让**每秒移动固定距离**，再按这一帧过了多久来分配：

```csharp
// 每帧移动距离 = 每秒速度 × 这一帧的耗时
position += speed * deltaTime;                // 例如 speed = 5 米/秒
```

120 FPS 时 `deltaTime ≈ 0.0083`，每帧移动 0.04 米；30 FPS 时 `deltaTime ≈ 0.033`，每帧移动 0.17 米；一秒下来都是 5 米。在 Unity 里，这个值就叫 `Time.deltaTime`。

## 物理为什么单独算

物理模拟（碰撞、重力）需要**固定的时间步长**才稳定，不能随帧率抖动。所以 Unity 另有一个固定间隔的函数 `FixedUpdate`，默认每 0.02 秒执行一次（每秒 50 次）。一帧里可能执行 0 次、1 次或多次 `FixedUpdate`，取决于这一帧过了多久。

## 对你写代码的影响

1. **`Update` 每秒会执行几十次到上百次。** 里面的代码要尽量轻，别做耗时操作，别每帧创建大量对象。
2. **状态要保存在变量里。** 上一帧算出来的值，下一帧还要用，所以需要成员变量，而不是局部变量。
3. **"过一会儿再做某事"不能写 `sleep`。** 卡住 `Update` 会卡住整个游戏的画面。要用计时变量，或者后面学的协程（6.2）。
4. **一帧里的所有代码是顺序执行的。** 同一帧里，一个脚本改了数据，后执行的脚本能立刻看到。

## 项目应用决策：Update、FixedUpdate 和协程怎么选

方块地牢里有三类“随时间变化”的需求，不能都塞进 `Update`：

| 需求 | 选择 | 原因 |
| --- | --- | --- |
| 读取 WASD、更新玩家意图、刷新非物理状态 | `Update` | 输入按渲染帧读取，响应更及时 |
| 推进 Rigidbody、处理依赖物理步的移动 | `FixedUpdate` | 物理世界按固定步长计算，结果更稳定 |
| 等待 0.5 秒、攻击冷却、波次间隔 | 协程 | 表达“等待后继续”，不用自己累计计时变量 |

判断标准是**谁拥有时间和状态**：输入属于帧，物理属于物理步，等待属于流程。把“每帧扣一点血”写在 `Update` 会让结果随帧率变化；把 Rigidbody 移动放在 `Update` 又会让物理碰撞和视觉帧脱节。主线项目的验收是把游戏帧率限制到不同值，玩家移动距离和冷却时长仍接近设计值。
