## 最终游戏定义

游戏名暂定为“方块地牢”。玩家从起点进入一张小地图，移动、攻击或躲避敌人，收集指定数量的钥匙/水晶，抵达出口后胜利；血量归零时失败。失败和胜利都显示结果，并允许重新开始当前场景。

这份页面是最终阶段的验收合同。它不要求美术复杂，但要求状态闭环真实可玩：输入能改变玩家，玩家行为能改变世界，世界变化能触发胜负，胜负能回到可重复游玩的初始状态。

## 必须存在的 Unity 结构

- `GameRoot`：挂载 `GameBootstrap` 或 `GameSession`，负责场景级状态；
- `Player`：至少包含 `Transform`、碰撞体、移动脚本、血量/战斗脚本；
- `Enemy`、`Trap`、`Pickup`、`Exit`：通过组件组合各自能力；
- `Canvas`：显示血量、收集进度、胜利/失败面板；
- `Prefab`：至少把敌人或掉落物做成可重复生成的预制体；
- `Scenes/Dungeon.unity`：可以从启动场景直接进入并完成一局。

## 从 C# 知识到游戏行为

| 知识 | 最终项目中的真实用途 |
| --- | --- |
| 枚举 | 玩家状态、游戏阶段、敌人状态 |
| 数组/集合/泛型 | 敌人列表、掉落物、收集目标、波次配置 |
| 属性与封装 | 血量、分数和进度只能通过合法方法修改 |
| `static` 工具类 | 所有伤害、数值限制和距离判断复用同一份规则 |
| 接口/多态 | 攻击者只依赖 `IDamageable`，不关心目标是敌人还是陷阱 |
| 委托/事件 | 血量、得分和游戏阶段变化通知 HUD、音效和胜负系统 |
| 协程 | 攻击冷却、受击无敌帧、波次间隔、结果面板延迟 |
| 特性/序列化 | Inspector 配置数值、自动补组件、编辑器测试按钮 |
| 生命周期 | 订阅/解除事件、初始化依赖、场景重开时清理状态 |

## 可玩验收清单

### 启动与操作

- [ ] 从 Build 启动后进入 `Dungeon` 场景；
- [ ] WASD 或方向键移动玩家；
- [ ] 移动速度与帧率无关；
- [ ] 摄像机持续跟随，目标引用缺失时有明确错误或保护。

### 交互与战斗

- [ ] 玩家能攻击至少一种目标；
- [ ] 敌人或陷阱能对玩家造成伤害；
- [ ] 伤害计算通过共享的静态规则库；
- [ ] 血量变化能同时更新 HUD 和 Console/调试信息；
- [ ] 敌人死亡或受击状态有可观察结果。

### 目标与胜负

- [ ] 玩家能收集至少一种目标物；
- [ ] 收集进度显示在 HUD；
- [ ] 满足条件后到达出口进入胜利状态；
- [ ] 血量归零进入失败状态，玩家停止输入或行为；
- [ ] 胜利和失败面板不会同时显示。

### 重开与构建

- [ ] 点击重开或按约定按键后，玩家、敌人、收集物和 UI 恢复初始状态；
- [ ] 连续完成“启动 → 胜利”和“启动 → 失败 → 重开”各两次；
- [ ] Build 版本中没有依赖编辑器专用路径或只在 Editor 下成立的代码；
- [ ] Console 没有未处理异常，关键状态转移有可读日志。

## 交付标准

只有完成上面的清单，才能把专栏末尾写成“学完能做出完整小游戏”。如果某项只能在编辑器里演示、无法从启动玩到结果，应记录为未完成，而不是用“代码已经写好”替代运行验收。
