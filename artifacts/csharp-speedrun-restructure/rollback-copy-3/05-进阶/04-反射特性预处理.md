> 适用版本：C# 9.0。IL2CPP 平台的代码裁剪对反射的影响，见「C# 底层专栏」第 4 章。

## 要点

- **反射**：程序运行时查看和操作类型信息，如列出字段、按名字调用方法、动态创建对象。C++ 没有等价的内置能力。
- **特性（Attribute）**：写在方括号里的"标签"，给类、字段、方法附加元数据。Unity 的 `[SerializeField]`、`[Header]` 都是。
- **预处理指令**：以 `#` 开头，编译前决定哪段代码参与编译，最常见的是 `#if UNITY_EDITOR`。
- 反射慢、容易被裁剪、难以调试，**有更好办法时不要用**；知道它存在，能看懂框架里的用法就够了。

## 反射

```csharp
using System;
using System.Reflection;

class Monster
{
    public string name = "史莱姆";
    private int hp = 30;
    public void Roar(string tail) => Console.WriteLine(name + tail);
}

Monster m = new Monster();
Type t = m.GetType();                                         // 或 typeof(Monster)

// 列出所有字段，包括私有
foreach (FieldInfo f in t.GetFields(BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.Instance))
    Console.WriteLine($"{f.Name} = {f.GetValue(m)}");

// 按名字调用方法
MethodInfo roar = t.GetMethod("Roar");
roar.Invoke(m, new object[] { "!!!" });

// 按类型动态创建对象
object obj = Activator.CreateInstance(t);

// 读写私有字段
FieldInfo hpField = t.GetField("hp", BindingFlags.NonPublic | BindingFlags.Instance);
hpField.SetValue(m, 99);
```

游戏里的典型用途：存档系统遍历字段自动序列化、读配置表时按列名给字段赋值、编辑器工具、依赖注入框架、自动查找所有继承某接口的类。

缺点要知道：反射调用比直接调用慢几十倍甚至更多，参数还会被装箱；字符串写错了编译器发现不了；在 IL2CPP 平台上，没被直接引用的类型可能被**裁剪**掉，运行时找不到。

## 特性

```csharp
[AttributeUsage(AttributeTargets.Field)]              // 限制这个特性只能贴在字段上
class RangeLimitAttribute : Attribute                 // 类名以 Attribute 结尾，使用时可省略这个后缀
{
    public int min, max;
    public RangeLimitAttribute(int min, int max) { this.min = min; this.max = max; }
}

class Config
{
    [RangeLimit(0, 100)] public int hp = 150;
    [RangeLimit(1, 10)]  public int level = 5;
}

// 用反射读出特性，做数据校验
Config cfg = new Config();
foreach (FieldInfo f in typeof(Config).GetFields())
{
    var limit = f.GetCustomAttribute<RangeLimitAttribute>();
    if (limit == null) continue;
    int value = (int)f.GetValue(cfg);
    if (value < limit.min || value > limit.max)
        Console.WriteLine($"{f.Name}={value} 超出范围 [{limit.min},{limit.max}]");
}
```

特性本身不做任何事，要有代码（编译器、Unity、你自己的反射）去读它才生效。Unity 里常用的特性：

| 特性 | 作用 |
| --- | --- |
| `[SerializeField]` | 让私有字段显示在 Inspector |
| `[System.Serializable]` | 让自定义类/结构体能被序列化，在 Inspector 展开 |
| `[Header("标题")]`、`[Tooltip("说明")]` | Inspector 中的分组标题与悬停提示 |
| `[Range(0, 10)]` | 把数值显示成滑块 |
| `[RequireComponent(typeof(Rigidbody))]` | 挂这个脚本时自动补上依赖的组件 |
| `[CreateAssetMenu]` | 在 Project 右键菜单里创建 ScriptableObject |

## 预处理指令

```csharp
#define ENABLE_CHEATS                     // 必须写在文件最前面

#if UNITY_EDITOR
    Debug.Log("只在编辑器里编译");
#elif UNITY_ANDROID
    Debug.Log("只在安卓包里");
#else
    Debug.Log("其他平台");
#endif

#if ENABLE_CHEATS && !RELEASE
    GiveGold(99999);
#endif

#region 战斗逻辑                           // 仅供编辑器折叠，对编译没有影响
// ...
#endregion
```

常见用途：编辑器专用代码（菜单、调试绘制）放进 `#if UNITY_EDITOR`，否则打包时会因为引用 `UnityEditor` 命名空间而失败；按平台分流；开发版与发布版区分作弊功能。

和 C++ 的 `#define`、`#if` 不同，C# 的预处理器只能做条件编译和折叠，**不能定义带值的宏**，也不能做文本替换。

## 动手试试

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody))]
public class AttrDemo : MonoBehaviour
{
    [Header("移动")]
    [Range(0f, 10f)]
    [Tooltip("每秒移动的米数")]
    [SerializeField] private float speed = 3f;

#if UNITY_EDITOR
    void OnDrawGizmosSelected()
    {
        UnityEditor.Handles.Label(transform.position + Vector3.up, $"速度 {speed}");
    }
#endif
}
```

1. 把脚本拖到一个空物体上，观察 `RequireComponent` 是否自动加上了 `Rigidbody`，以及 Inspector 里 `Speed` 变成了带标题的滑块，鼠标悬停有提示。
2. 选中物体，Scene 视图里应出现"速度 3"文字。
3. 把 `#if UNITY_EDITOR` 和 `#endif` 两行删掉，尝试 Build（File → Build Settings）或者观察编译器提示，理解为什么编辑器专用代码必须包起来。

## 常见坑

- 在 `Update` 里用反射读写，性能下降很明显。至少缓存 `FieldInfo` / `MethodInfo`。
- 反射用的类型在 IL2CPP 打包后被裁剪，编辑器里正常，真机报找不到。可以用 `[Preserve]` 特性或 `link.xml` 保留。
- `#if UNITY_EDITOR` 里的代码漏了包起来，打包失败，报找不到 `UnityEditor`。
- 自定义特性忘记写 `AttributeUsage`，贴在不合适的位置也不报错。
