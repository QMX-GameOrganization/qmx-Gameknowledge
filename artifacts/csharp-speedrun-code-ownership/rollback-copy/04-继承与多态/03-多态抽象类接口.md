> 适用版本：C# 9.0。接口的默认实现（C# 8）在 Unity 里支持有限，这里不用。

> **本篇主线标记**：本篇的 `IDamageable` 和多态调用是 `【主线必做】`；攻击目标协议见[攻击目标与交互协议](../05-主线实践攻击目标与交互协议/)。

## 要点

- **多态**：父类变量调用同一个方法，实际执行的是对象真实类型的版本。
- 父类方法要写 `virtual`，子类用 `override` 重写，**两个关键字缺一不可**。C# 默认方法不是虚函数，这点与 C++ 相同；但 `override` 是强制显式写的。
- **抽象类**（`abstract`）不能 `new`，可以含没有实现的抽象方法，强制子类实现，相当于 C++ 的纯虚函数。
- **接口**（`interface`）只定义"能做什么"，一个类可以实现多个接口，是 C# 实现"多重继承"能力的方式。

## virtual 与 override

```csharp
class Skill
{
    public string name = "技能";
    public virtual int Damage(int atk) => atk;                 // 默认实现
    public virtual string Describe() => $"{name}：普通攻击";
}

class Fireball : Skill
{
    public Fireball() { name = "火球"; }
    public override int Damage(int atk) => atk * 3;           // 重写
}

class Slash : Skill
{
    public Slash() { name = "斩击"; }
    public override int Damage(int atk) => atk * 2 + 5;
    public override string Describe() => base.Describe() + "（附带破甲）";   // base 调用父类版本
}

Skill[] book = { new Fireball(), new Slash(), new Skill() };
foreach (Skill s in book)
    Console.WriteLine($"{s.Describe()} -> {s.Damage(10)}");   // 每个对象走自己的版本
```

调用点只写"遍历技能并计算伤害"，新增一种技能不用改这段代码，只需增加一个子类。这就是多态带来的扩展性。

## new 隐藏：容易出错，要认识

如果子类写了同名方法但没写 `override`，编译器会警告，并按**变量的声明类型**选版本：

```csharp
class Base  { public void Hello() => Console.WriteLine("Base"); }
class Child : Base { public new void Hello() => Console.WriteLine("Child"); }

Base b = new Child();
b.Hello();                 // Base，不是 Child：没有多态
```

原则：**不要用 `new` 隐藏方法**，想要多态就老老实实 `virtual` + `override`。

## 抽象类

```csharp
abstract class Weapon
{
    public string name;
    public abstract int Attack();                    // 没有函数体，子类必须实现
    public void Show() => Console.WriteLine($"{name} 攻击力 {Attack()}");   // 抽象类也能有普通成员
}

class Sword : Weapon
{
    public Sword() { name = "长剑"; }
    public override int Attack() => 25;
}

// Weapon w = new Weapon();                          // 编译错误：抽象类不能实例化
Weapon w = new Sword();
w.Show();
```

抽象类适合"有共同的数据和部分实现，同时留出必须由子类决定的部分"。

## 接口

```csharp
interface IDamageable
{
    int Hp { get; }                    // 接口可以声明属性
    void TakeDamage(int amount);       // 成员默认 public，不写修饰符
}

interface IInteractable
{
    void Interact();
}

class Barrel : IDamageable
{
    public int Hp { get; private set; } = 30;
    public void TakeDamage(int amount) { Hp -= amount; }
}

class Chest : IDamageable, IInteractable           // 一个类可以实现多个接口
{
    public int Hp { get; private set; } = 80;
    public void TakeDamage(int amount) { Hp -= amount; }
    public void Interact() => Console.WriteLine("打开宝箱");
}

static void Explode(IDamageable[] targets)
{
    foreach (IDamageable t in targets) t.TakeDamage(50);       // 不关心具体是什么，只要能受伤
}
```

接口**不含字段，不含实现**，只规定契约。命名惯例以 `I` 开头。Unity 里常见的写法是对碰到的物体问一句"你能受伤吗"：

```csharp
// 以下为 Unity 代码示意
if (other.TryGetComponent<IDamageable>(out var target)) target.TakeDamage(10);
```

这样子弹不需要知道对方是敌人、木桶还是 Boss。

## 密封方法

`override` 的方法可以再加 `sealed`，禁止子类继续重写：

```csharp
class Boss : Enemy
{
    public Boss() : base("魔王", 500) { }
    public sealed override string ToString() => "魔王";   // 子类不能再改
}
```

## 与 C++ 对照

| C++ | C# |
| --- | --- |
| `virtual` / `override`（可省略 override） | `virtual` / `override`（必须写） |
| 纯虚函数 `= 0` | `abstract` 方法 |
| 抽象基类 | `abstract class` 或 `interface` |
| 多重继承 | 单继承 + 多接口 |
| `final` | `sealed` |
| 虚析构 | 不需要 |

## 在 Unity 里用到它

- **接口**是 Unity 里让"不同物体用同一种方式交互"的主力：`IDamageable`、`IInteractable`、`IPoolable`。
- Inspector **不能直接序列化接口类型**的字段，所以常用 `GameObject` 或 `Component` 字段，运行时再用 `TryGetComponent<T>(out ...)` 查询接口。
- **抽象类**常用来做"一类东西的公共部分"，如抽象的 `Skill`、`Enemy`。

## 动手试试

```csharp
using UnityEngine;

public interface IDamageable
{
    void TakeDamage(int amount);
}

public class Barrel : MonoBehaviour, IDamageable
{
    public void TakeDamage(int amount) { Debug.Log($"木桶碎了，受到 {amount}"); }
}

public class Chest : MonoBehaviour, IDamageable
{
    public void TakeDamage(int amount) { Debug.Log($"宝箱出现裂痕，受到 {amount}"); }
}

public class Attacker : MonoBehaviour
{
    [SerializeField] private GameObject[] targets;

    [ContextMenu("攻击全部")]
    void HitAll()
    {
        foreach (GameObject t in targets)
            if (t.TryGetComponent<IDamageable>(out var d))     // 不关心具体类型，只要能受伤
                d.TakeDamage(10);
    }
}
```

场景里放一个木桶（挂 `Barrel`）、一个宝箱（挂 `Chest`）、一个普通 Cube（什么也不挂），都拖进 `Attacker.Targets`，右键 `Attacker` 组件选"攻击全部"。普通 Cube 会被安静地跳过。之后再加一个 `Door : IDamageable`，注意 `Attacker` 一行都不用改。

## 项目应用决策：多态替代重复的类型分支

攻击系统只需要 `IDamageable.TakeDamage`，不需要写“如果是 Goblin、如果是 Barrel、如果是 Trap”。当多个敌人共享移动骨架但只改变攻击细节时，用抽象基类；当对象来自不同继承树却共享能力时，用接口。

`virtual/override` 适合保留基类流程并允许子类改变一个步骤；接口适合定义调用契约。验收时新增一种可受伤目标，只增加实现和场景配置，攻击者核心代码保持不变。

## 常见坑

- 忘记在父类写 `virtual`，子类 `override` 报错。
- 用 `new` 隐藏方法而不是 `override`，多态失效。
- 在父类构造函数里调用虚方法：此时子类字段还没初始化，可能读到默认值。
- 为了"以后可能扩展"把什么都做成接口，实际只有一个实现，徒增代码量。
